# ADR-0000 — Short decision title

- Status: `Proposed`
- Owner: `<role>`
- Decision date: `Not decided`
- Effective version: `Not effective`
- Related Work Packages / modules: `<WP IDs and module names>`
- Source: `<authoritative section or accepted evidence>`
- Supersedes: `None`
- Superseded by: `None`

## Decision scope

State the architecture, Domain boundary, data ownership, dependency direction, or long-lived platform decision being considered. Name explicit non-goals.

## Context

Describe the observed problem and evidence without inventing business, legal, Provider, Store, account, production, or test facts.

## Decision

Record the decision or, while `Proposed`, the bounded current position. Include owners, invariants, compatibility, and what this decision does not authorize.

## Alternatives and decision drivers

List meaningful alternatives and the security, operability, simplicity, cost, compatibility, reversibility, and evidence drivers.

## Consequences

Record positive and negative consequences, affected modules/contracts, migration or replay impact, security/privacy impact, and operational impact.

## Validation and rollback

Define acceptance evidence, affected tests/checks, rollout/disable behavior, and a recoverable rollback or exit strategy.

## Revisit trigger

Name measurable evidence or an explicit business/architecture event. Time pressure or implementation convenience is not a trigger.
