# Release evidence intake

Authority: [release policy](../security/release-evidence-policy.json), Handoff 87.7.2 and the [existing gate](../../tooling/security/release-evidence-gate.mjs). The [empty template](release-evidence-template.json) contains nulls deliberately and must fail closed until real evidence is supplied. Never turn the template into a synthetic passing production bundle.

1. Release coordinator identifies the exact protected source commit, workflow/builder and immutable Linux/amd64 image digest. Bind all evidence to that candidate, not a branch name alone. Record retained changes separately; an uncommitted local candidate is not a protected release build.
2. Collect the policy's eight immutable tool pins with review references and nine required artifacts with status, subject digest and evidence digest. Security reviewers examine exploitability, licenses, provenance, signature and authenticated owned-route coverage. Safe references resolve to restricted retained artifacts; no tokens, raw customer/payment data or unrestricted identities enter Git or public logs.
3. Verify the required base image/digest, non-root hardened runtime, immutable/scanned registry and P256 asymmetric signature. Confirm staging and production promotion reference the same result digest. Do not populate `PASS`, zero findings or security booleans from expected defaults; use reviewed observations.
4. Keep the completed bundle and original artifacts in an authorized restricted evidence store. From the repository root run `node tooling/security/release-evidence-gate.mjs <restricted-evidence-path>` using a filesystem path that contains no secret. Exit 0 accepts the reported shape/conditions; exit 1 rejects reported conditions; missing input exits 2. Read/JSON failures are failures too.
5. Record command, toolchain, tested revision, candidate digest, artifact references, outcome and reviewer. On failure retain a safe diagnostic and route to Release/Security; do not promote or fabricate missing inputs. Recheck affected evidence after any bound input changes.

The local gate checks reported fields and bindings. It does not independently authenticate external signatures, inspect every artifact, run scanners, approve licenses or authorize deployment. Static validator tests, a valid real bundle, external review and production go/no-go are separate evidence stages. No actual release or external control is claimed by this guide.
