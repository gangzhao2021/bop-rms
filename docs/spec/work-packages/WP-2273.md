## Bounded behavior

Start and regenerate require current Staff evidence before any history read. Historical success is
not a new lifecycle write: an occupied Table may still return its authorized original start result.
Closed bounded snapshots capture Staff and repository evidence before later callbacks. Original
records must match operation, intent, scope, assignment and original result shape. Start also binds
the original Staff Actor. Regeneration's existing record contains no Actor/Brand field; do not invent
one or claim validation of unavailable history. It is scoped to the currently authorized Store/Table
and exact Session/assignment. Current regeneration state must match the exact requested Session and
Staff Brand/Store, with a coherent capability before generating anything.

Write results undergo the same validation. A concurrently committed original can return
AlreadyApplied without disclosing this attempt's unused raw credential; Issued is reserved for the
exact generated record. No raw credential is persisted. Owned conflicts retain bounded codes with
fresh error instances; unknown dependency failures remain redacted. Existing intent strings,
permission-code delegation and original timestamps remain unchanged.

Guest Join/Identity recovery, Table-assignment persistence, Session migrations, transport/UI,
permissions catalog, Event publication and live activation are separate owning work. No cross-domain
private storage or policy redesign is permitted.
