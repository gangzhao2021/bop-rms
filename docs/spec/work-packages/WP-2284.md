## Scope and acceptance

Persist the existing Move command using Dining-owned source/target Tables, Session and one immutable
operation table. Bind exact Tenant/Brand/Store and canonical command/digest, result, User Audit and
minimal Event record. Lock the scoped operation, both shared Table advisory locks in sorted order,
Table rows, then Session. Recompute the existing pure Move policy against locked current facts.
Expected versions and observation chronology must hold; preserve Session identity/Host/start facts.
Update both Tables and Session, insert original operation and append public Audit in one transaction.
Return the actual original commit receipt for an identical concurrent/retried operation.

The Move repository port therefore returns a closed Applied/AlreadyApplied record receipt. The
service validates the complete returned command, result facts, event and actor/scope Audit. Applied
acknowledgements match their Audit; AlreadyApplied returns the persisted original Audit, never a
new unpersisted attempt ID. Current authorization remains before any historical result. Unknown
acknowledgements and exceptions fail closed without leaking private dependency data.

Unit tests and actual PostgreSQL/public services prove atomic movement, scoped reads, same/different
operation competition, target conflict, Closing fence, old history, lost acknowledgement, Audit
rollback, read-only denial, foreign-store RLS, immutable/closed history and owned cleanup. Stable
Participants remain attached to the Session; Table aggregate versions remain distinct from the
prior assignment. Future Event publication, Join credential reissuance and shared Cart fencing are
separate; existing capability checks must continue denying stale Table scope.
