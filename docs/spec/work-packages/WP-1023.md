## Purpose

Implement the smallest Catalog-owned availability configuration model that proves:

1. one Brand default or exact Store overlay targets one Brand-owned SKU；
2. channel、order type and UTC effective period are explicit configuration scope；
3. exact Store scope outranks Brand default and priority resolves rules within one scope；
4. equal-priority conflicting decisions fail closed as `Indeterminate`；
5. fresh exact-scope Kill Switch and Inventory evidence is evaluated before configuration；
6. stale、future、expired、wrong-scope or indeterminate safety evidence fails closed；
7. authoring uses Brand Tenant Context、Permission、Audit、idempotency、fact validation and
   optimistic concurrency；and
8. persistence enforces Brand RLS、stable identity、valid periods and append-only operations.

## Adopted boundaries

- Availability Rule is Catalog-owned Configuration with lifecycle
  `Draft | Active | Inactive | Archived`.
- This minimum model targets `Sku` only. Bundle and other future Sellable types are gated.
- Empty channel/order-type lists mean all values within the resolved Store context.
- A Store rule is more specific than a Brand default regardless of the Brand rule priority.
  Priority `1–1000` applies only within the winning specificity.
- Equal-priority same-scope rules may coexist only when their decisions agree. Conflicting winners
  return `Indeterminate`; a stable rule-reference tie-break is used only for equivalent decisions.
- Safety evidence is injected, short-lived and exact scoped. Kill Switch `Blocked` and Inventory
  `Unavailable` override configuration. No inventory balance is stored or inferred by Catalog.
- Operation reference plus deterministic intent digest supplies replay; changed intent conflicts.
  Repository conditional commit remains the final aggregate-version guard.
- WP-1024 owns Menu publication/version semantics. This WP does not claim Published state,
  customer/menu projection, API, event, scheduler or UI behavior.
