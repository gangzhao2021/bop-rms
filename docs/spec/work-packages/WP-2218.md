## Scope

Persist the existing Ordering Add/Update/Remove commands through an opt-in, fixed Brand/Store
PostgreSQL repository. Lock the operation before the Cart; read lines after acquiring the Cart
lock; compare the expected version and preserve immutable Cart/Item attribution. Commit the
one Item change, Cart version/lifecycle, immutable 24-hour original operation result and public
Audit append in one transaction. Same-key concurrent requests converge on the original result;
different intents or expired reuse conflict. Unexpected database failures expose controlled errors.

Correct the command fingerprint to exclude server observation time while retaining canonical
client intent, expected version, action and operation reference. Reauthorize before replay.
Pickup Session and DineIn Participant checks remain in Ordering. Catalog validation remains a
public source contract; integration fixtures explicitly supply synthetic Catalog and Session facts.
No production credentials, Store policy, health fact or Provider evidence is supplied.

Non-goals: HTTP mutation composition, nonempty Cart DTO/pricing, browser/UI changes, standalone
Order submission, lifecycle commands, Quote/Payment/Worker wiring, new migrations, production
activation and external readiness. Default runtime and WP-2217 unsupported responses remain intact.

## Acceptance and evidence map

1. Add/update/remove survive fresh repository/pool reads with exact versioned Catalog evidence,
   stable attribution, one version increment and bounded lifecycle advancement.
2. Delayed and concurrent same-key retries return the original result without duplicate line,
   operation or Audit. Changed intent, expired replay and stale contenders fail closed.
3. Pickup/DineIn ownership, cross-Brand/Store RLS and restricted operation history are retained;
   post-Audit failure rolls back all writes. No partial success or sensitive error/log content.
4. Exact adapter ownership allowance retains adjacent-file/driver/foreign-owner denials.
   Frozen install, affected checks and complete local verification pass before a Done claim.
