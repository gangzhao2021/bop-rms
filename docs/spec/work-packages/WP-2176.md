# WP-2176 — Forward / Backward Traceability Explorer and Restricted Evidence Export

## Authority and scope

- Handoff Sections 40.18, 40.20–40.22, 40.25, 46.6, 48.5, 50, 87.11.2, 88.16 and
  88.21–88.30 define evidence classification, trace ownership, incomplete-chain behavior,
  restricted export and the canonical Screen contract.
- Exact local predecessor: verified WP-2175 commit `91f5a79`.
- Procurement, Inventory, Recipe, Kitchen, Ordering, Customer and Fulfillment retain their source
  facts. Compliance consumes stable references from an approved `compliance_*_v1` query projection;
  it does not copy or rewrite the transaction chain.
- Section 50 grants no Compliance schema or migration namespace. This WP adds no database object or
  runtime adapter and does not claim durable production operation.

## Acceptance contract

1. A Trace Run pins Tenant/Brand/Store, direction, one exact Supplier/PO/Receipt/Lot/Movement/
   Recipe/Batch/Order Item/Customer/Fulfillment seed, explicit UTC period, requested/completed time,
   projection version and source-as-of time.
2. Results form a bounded directed graph of stable references and closed relationship codes across
   the canonical Supplier/PO → Receipt/Lot → Movement → Recipe/Batch → Order Item → Customer/
   Fulfillment chain. Customer nodes remain Restricted and expose no identity/contact fields.
3. Completeness is `Complete | Partial`. Every missing, stale, permission-trimmed or unavailable
   source segment is an explicit Gap; a result with a Gap cannot claim `Complete`. Unknown input or
   dependency state fails closed and does not invent a link.
4. Every Query revalidates Tenant Context, purpose, `compliance.traceability.view`, exact scope and
   projection scope/version/time. Exact identifiers are never placed in URL query parameters,
   analytics, metrics or logs.
5. Pinning creates an immutable restricted Evidence Set bound to one authorized Run and exact Case.
   Selected references must exist in that Run, remain in scope, and be deduplicated. Revision,
   expected version, idempotency, permission and safe Audit evidence are mandatory.
6. Restricted export accepts only a pinned Evidence Set and Case binding, explicit purpose,
   retention-policy reference and legal-hold state. The export owner returns only an opaque artifact
   reference/digest and recorded time—never bytes, signed URLs, Customer identity or unrestricted
   object identifiers.
7. Opening a Recall from a Trace Run is delegated through an explicit owner port and records only
   the opaque Recall outcome reference. WP-2176 does not implement Recall lifecycle, scope
   calculation, notice, disposition or containment; those remain WP-2177.
8. `TRACE-EXPLORER` at `/app/compliance/traceability` exposes the Section 88 graph/timeline fields,
   exact filters/actions and explicit loading/denied/offline/stale/conflict/error/empty states.
   Strict UI contracts accept safe types, codes, references, digests and counts only.
