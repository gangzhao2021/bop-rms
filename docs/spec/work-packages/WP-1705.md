## Resolved contract and hard gate

The Order reference is a routing and display identifier, never a credential. WP-1225 requires the
server to authorize a usable Guest Session against the exact permanent Submission before reading
the customer-safe Ordering projection. No public Guest HTTP or realtime adapter currently exists,
and WP-0036 explicitly reserves its URL and authentication contract to this WP. This package does
not invent those missing external contracts.

WP-1705 adds the canonical route, a strict parser for the existing
`CustomerOrderStatusView`, and an injected browser controller. The default runtime is explicitly
unavailable and makes no fetch, EventSource or WebSocket request. A future approved adapter may
inject one canonical `load(orderReference)` Query plus a lossy subscription whose open, reconnect
and hint callbacks only trigger that same Query. A hint never carries authoritative Order state,
and reconnect never creates or replays a Command.

The UI renders only Ordering-owned facts already admitted by WP-1225. Payment remains
`NotReported`; Kitchen remains `Unavailable`; ETA remains unavailable. Fulfillment is shown as
complete only from the closed `Fulfilled + Completed` projection combination. Pickup proof is a
WP-1706 boundary and is not enabled here. Offline mode is read-only, keeps an already accepted safe
view in page memory, stops query/subscription activity, and performs no automatic refresh when the
connection returns.

## Acceptance and verification

- the canonical UUIDv7 route fails malformed references before any client call;
- strict parsing rejects extra, accessor, symbol-bearing, custom-prototype, inconsistent and
  oversized customer status results;
- initial load, explicit refresh, subscription open/reopen and lossy hint use the canonical Query;
- stale/rebuilding/failed freshness, permission denied, not found, unavailable, loading, offline
  read-only and accepted current/completed states are explicit and customer-safe;
- the default runtime exposes the missing public adapter and performs no network activity;
- no reference-only authorization, private source snapshot, Guest/Actor data, secret, raw error,
  inferred Payment/Kitchen/ETA fact, pickup proof or command replay is added;
- frozen install, Customer PWA/full affected tests, format/lint/typecheck/build, architecture,
  Screen Registry and security/privacy review are required locally.

Rollback is a reviewed revert/forward correction. Public Guest Query/realtime transport,
authentication/cookie interpretation, pickup proof, receipt/support adapters, external browser/UAT,
Provider/Pilot Store evidence and production remain gated and unclaimed.
