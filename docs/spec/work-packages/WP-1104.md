## Purpose and acceptance

Complete the bounded Price Lock lifecycle without changing an immutable WP-1103 Quote:

1. server UTC time before `expiresAt` keeps the exact existing Quote current;
2. the exact `expiresAt` instant is expired and requires authoritative recalculation;
3. requote creates a new immutable Quote for the same Brand, Store, Cart and Cart Version;
4. lower or unchanged total requires no reconfirmation;
5. higher total returns `ReconfirmationRequired` with exact signed minor-unit change;
6. the public Quote command can return a current or replacement Quote and exposes only the safe
   price-change decision; and
7. old Quote snapshots remain append-only and are never silently rewritten.

## Boundaries, risks and rollback

- Promotion, Coupon, Fee, inclusive-Pilot tax, Cart mutation/persistence, Checkout confirmation,
  Order, Payment, UI, Event, scheduler and Provider behavior are absent.
- Customer confirmation is not invented. This WP reports that reconfirmation is required; a later
  Checkout owner records and validates the action.
- Tax/legal/obvious-error immediate invalidation needs an authoritative invalidation fact and
  remains a future gate; ordinary expiry is not used to invent one.
- Requote scope or reused Quote identity fails closed. Amount comparison uses bigint minor units in
  one Currency and never floating point.
- Rollback is a reviewed Git revert. No destructive data rollback or external action exists.
