## Resolved local boundary

WP-2047 centralizes the currently composed Express API HTTP security boundary. Development,
Staging and test emit the deny-by-default CSP in Report-Only mode; production emits enforcing CSP
and the accepted one-year include-subdomains HSTS policy without preload. Every response receives
nosniff, strict-origin referrer, deny framing, same-origin opener/resource and explicit
camera/microphone/geolocation/USB/Bluetooth/payment denial. COEP and credentialed CORS remain off.

Each response gets a fresh CSP script nonce. The existing 64 KiB JSON parser and 15-second server
timeout remain unchanged. A new pre-parser boundary enforces 100 header fields, 16 KiB total
application headers and an 8 KiB request target, rejects duplicate/conflicting framing headers and
returns stable non-reflective 414/431 responses. The Node server retains the lower/equal parser
boundary and max-header-count setting.

The current API serves JSON rather than HTML and has no Stripe payment route or public-asset host;
therefore it adds no unproved Stripe origin or wildcard. The precached offline fallback is checked
for absence of inline executable content. Real browser CSP reporting, WAF/ALB request smuggling,
owned host/TLS readiness and payment-origin evidence remain External gates.
