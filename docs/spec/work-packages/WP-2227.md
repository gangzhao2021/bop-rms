# WP-2227 — Durable Pricing Quote Snapshots

## Authority and scope

Baseline `WP-2226@d687c78`; branch `codex/wp-2227`. Continued local implementation and verified
local commits are authorized. Composite Handoff 0.5.3 Sections 21, 27, 52, 87, 92–97,
WP-1103–1105, WP-2225 and WP-2226 govern immutable Quote facts and namespace-local migrations.

Add a nullable versioned snapshot column to the Pricing-owned Quote header and an optional scoped
repository using the existing codec. New records atomically insert header, line and tax evidence,
full snapshot and public Audit. Legacy rows remain untouched; no reconstruction from incomplete
relational evidence or mutable sources is permitted. No Customer command, HTTP or default runtime
wiring is part of this increment.

## Contract and acceptance

1. Server-resolved Brand/Store scope is fixed at factory construction. `load(Quote ID)` returns a
   fully validated independent immutable snapshot, null for an absent/inaccessible record, or a
   controlled unavailable result for a legacy/corrupt record. Read integrity checks all mirrored
   header/line/tax facts against the decoded snapshot. Money never crosses a JS number boundary.
2. `save({ snapshot, audit })` serializes concurrent same-Quote writes with a transaction advisory
   lock. Identical snapshots return the original, changed snapshots conflict. This is Quote-ID
   replay only; Customer operation idempotency, authentication and current Cart version checks
   remain the future Application boundary. Different Quote IDs may retain the same Cart line.
3. Audit is System / CUSTOMER_PWA / Restricted, action `PRICING_QUOTE_CREATE`, reason
   `AUTHORIZED_PRICE_QUOTE`, target `PricingQuote` at the snapshot creation instant, with matching
   Brand/Store/Quote and no summaries. The caller supplies authorized Audit context; the factory
   supplies new technical tax-row UUIDv7 references through an injected generator. No Event is
   invented. Replay appends no Audit or row IDs. Failures roll back the complete transaction.
4. PostgreSQL proves full evidence/precision/order, replay/concurrency/conflict, scoped RLS,
   immutable history, legacy refusal, corrupt mirror refusal and failure after Audit. Forward
   upgrade preserves legacy data. Exact-file ownership registration retains wrong-owner/schema/
   table, adjacent-file and driver refusal. Frozen install and full local verification pass.
