## Resolved contract and boundaries

WP-1205 already owns the complete `/cart` read/update/remove state machine and strict Customer Cart
HTTP transport. WP-1702 closes the remaining Customer UI path from WP-1701 Product Detail through
the contextual Configurator to create/add Cart Item. The Configurator uses only the exact Fresh
Published Menu snapshot retained in page memory. It sends public Sellable/Option references as
opaque server-validated command inputs and never treats client selection or displayed estimates as
Catalog, price, tax, availability or Cart success authority.

The existing published contract supplies min/max, enabled and default Option references but no
public Option labels, per-option quantity or conflict graph. WP-1702 adds those already-published,
non-price facts to Catalog's immutable Published Menu snapshot and field-minimized Customer Menu
DTO. The UI renders localized names, published defaults, quantity limits and conflicts, while
incremental price remains explicitly unavailable until the final Quote. The server remains final
authority for changed/unavailable selection. Plain notes are optional, bounded to 500 NFC
characters and explicitly reject allergy/medical narratives in favor of Staff assistance.

Cart creation and add use distinct in-memory Idempotency Keys, exact CSRF/session credentials and
server Cart Version. Unknown network outcomes retain the exact pending step/key for explicit
foreground retry; offline never calls, queues or replays a mutation. Conflict reloads the canonical
Cart and requires review. Success navigation to `/cart` occurs only from a validated server Cart
view containing the added Sellable.

No price inference, Quote, Checkout, clear command, persistent cache, Service Worker, Web Storage,
background replay, private table read, dependency, migration, deployment, analytics or Figma action
is authorized. The Catalog/API change is limited to the additive public configuration fields above.

## Acceptance and evidence map

- Product Detail exposes configure/add intent only for the exact current available Sellable;
- Configurator renders quantity, every published localized Option/rule, defaults, min/max,
  conflicts, allergen assistance, explicit price limitations and a bounded non-medical note
  boundary without raw references;
- client validation explains missing required and maximum selection before network access;
- server validation exposes bounded issue codes for conflict/changed/unavailable selection and never
  assumes success;

  operation key; explicit unknown-outcome retry reuses only the exact pending key;
- offline/session/conflict/rate-limit/unavailable/pending/success states are non-color, keyboard and
  screen-reader accessible with 44px targets and mobile/zoom/reduced-motion behavior;
- frozen install, affected/root format/lint/typecheck/test/build, architecture/Screen Registry,
  production audit, security/privacy review, exact-head CI, Section 91 review, authorized squash
  merge and exact-main CI are required.

## Risks, rollback and external boundary

Rendering opaque references, accepting money or Store scope, persisting credentials or drafts,
automatic reconnect replay, last-write-wins, allergen-free promises, medical free text, assuming a
lost response succeeded or expanding into Quote/Checkout stops this WP. Rollback is a reviewed
revert or forward correction; no Cart history is destructively rewritten. Production/UAT,
professional allergen/legal review, localization, real option labels/prices and External Evidence
remain gated and unclaimed.
