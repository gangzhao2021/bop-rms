## Purpose

Define the smallest Pricing-owned calculation contract that proves:

1. Money is signed integer minor units plus an explicit Currency Code and never binary floating
   point;
2. operations reject cross-Currency input and values outside PostgreSQL `bigint`;
3. Currency minor-unit metadata is versioned and digest-pinned for historical replay;
4. tax rates are canonical decimal strings converted to exact bigint rational values;
5. `HalfUp`、`HalfEven`、`TowardZero` and `AwayFromZero` rounding are deterministic for positive
   and negative amounts;
6. resolved exclusive and inclusive Tax instructions produce stable net、tax and gross Money;
7. every result preserves the exact jurisdiction、classification、treatment、rate、rounding、Tax
   Rule Version and Currency Metadata Version explanation；and
8. minor-unit allocation is exact、stable-key deterministic and correction-sign symmetric.

## Adopted decisions

1. **Money representation —** `amountMinor: bigint` is bounded to signed 64-bit range；
   `currencyCode` is explicit uppercase three-character text.
2. **Closed input —** public constructors reject missing/extra/symbol/accessor/prototype-bearing
   structures；raw JavaScript `number` amounts and rates fail closed.
3. **Decimal rate —** rate text is canonical non-negative decimal with at most twelve fractional
   digits and no exponent、sign、leading/trailing zero ambiguity.
4. **Checked arithmetic —** add/subtract/compare require equal Currency；overflow and Currency
   mismatch have stable safe error codes.
5. **Rounding —** signed rational rounding operates on bigint numerator/positive denominator and
   is symmetric around zero.
6. **Exclusive calculation —** input is net；rounded tax is added to produce gross.
7. **Inclusive calculation —** input is gross；tax is `gross × rate / (1 + rate)` under the pinned
   rounding mode, then subtracted to produce net.
8. **Historical evidence —** explanation stores exact rule/Currency version references and SHA-256
   digests, decimal rational, treatment、price inclusion and rounding mode.
9. **Allocation —** largest remainder allocation uses exact non-negative bigint weights；ties use
   stable allocation key lexical order；result sums exactly to the signed input.
10. **No configuration claim —** the resolved instruction is a synthetic public value only. It is
    not a Store Tax Config、published rule、legal fixture or permission to charge tax.
