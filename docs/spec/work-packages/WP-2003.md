## Contract and ownership

Payment owns one contract-validating anti-corruption wrapper around any accepted Provider adapter.
All five operations validate the closed Provider-neutral request before delegate invocation. Every
returned outcome is parsed through the strict normalized contract and bound back to the exact
Provider environment, Brand, Store, Payment Attempt and operation. Existing-intent operations also
bind the Provider Intent reference; create binds method, capture mode and exact CAD requested amount.

A thrown exception, malformed/raw response or cross-scope/mismatched outcome is contained and
returned as bounded `Unknown / Unknown / PROVIDER_OUTCOME_UNKNOWN` data. Raw Provider messages,
payloads, account details, SDK objects and exceptions never cross the boundary.

## Acceptance and verification

- create/retrieve/cancel/capture/refund validate before delegate invocation;
- normalized same-scope outcomes pass and remain deeply immutable;
- wrong Tenant, Attempt or Provider Intent fails closed to safe Unknown;
- thrown and raw/malformed Provider results expose no raw detail;
- Payment format/lint/typecheck/test/build and repository architecture gates pass;
- real Stripe sandbox/live, account, SDK and Provider evidence remains unavailable and unclaimed.
