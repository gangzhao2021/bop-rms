## Goal

Define the smallest transport-neutral reliability kernel that can later:

1. move a retryable parked Outbox delivery to a bounded future retry without a hot loop;
2. record durable Consumer failure-attempt evidence without breaking WP-0032's atomic Inbox/effect invariant;
3. terminate exhausted or non-retryable work in a Tenant-scoped dead-letter record;
4. preserve per-Aggregate ordering and require an authorized、audited decision before a dead head can release later work;
5. support idempotent manual retry/discard commands without exposing payloads or cross-Tenant facts;
6. emit bounded operational signals while leaving Provider/broker、UI、production tuning and deployment to later gates.

WP-0033 does not make delivery exactly once. Outbox remains at-least-once and Consumer effects remain transactionally deduplicated by WP-0032.

## Accepted reliability model

### Failure classes

Every accepted failure maps to one closed、versioned class:

- `retryable`: bounded transient failure eligible for a future attempt;
- `non_retryable`: invalid/unsupported/denied work that cannot succeed unchanged;
- `commit_unknown`: reconciliation by the same idempotency identity, never a fresh effect identity;
- `ordering_gap`: missing Aggregate predecessor; retryable but never allowed to skip the gap;
- `exhausted`: the accepted maximum actual handoffs has been reached;
- `operator_held`: an authorized operator deliberately prevents automatic progress.

Raw exceptions、SQLSTATE detail、Provider bodies、endpoint names and payload-derived values never become classification inputs persisted or emitted outside the trusted adapter boundary.

### Retry policy

A versioned policy resolves from a bounded technical failure category and path (`outbox` or `consumer`). Stored resolution facts are policy name/version、attempt number、next available instant、safe reason code and resolver version.

The policy must define:

- which safe codes are retryable;
- maximum actual handoffs;
- initial delay、multiplier、maximum delay and jitter rule;
- expiration/deadline behavior;
- ordering-gap treatment;
- terminal dead-letter reason.

Policy changes affect only future resolutions. Existing scheduled attempts retain their recorded resolution so history is reproducible.

### Outbox transition

1. WP-0031 conditionally records a sanitized failure and clears its lease.
2. WP-0033 locks the exact parked row under matching Tenant context and verifies the current attempt/fencing facts.
3. A retryable outcome records an append-only attempt decision and advances `available_at` to the resolved next-at while clearing only the retry-eligible safe error marker required by the WP-0031 claim predicate.
4. A terminal outcome creates one dead-letter identity and leaves the Outbox Event retained and non-claimable.
5. A concurrent scheduler/operator loses by expected-state/version condition and returns an idempotent conflict/already-applied outcome.

Published Events are never retried or dead-lettered. Active unexpired leases are never rescheduled.

### Consumer transition

1. The WP-0032 Consumer transaction returns/throws a safe outcome and rolls back completely.
2. Worker opens a separate Tenant-scoped technical transaction only after rollback.
3. WP-0033 appends one attempt record keyed by Consumer identity、Event identity and delivery-attempt identity.
4. Retryable work receives a recorded next-at; terminal work receives one dead-letter identity.
5. Redelivery always invokes WP-0032 with the same Consumer/Event idempotency key. A committed prior effect resolves as `duplicate_completed`.

The separate evidence transaction cannot assert that the Consumer effect failed if the original commit outcome is unknown. `commit_unknown` must first reconcile through the WP-0032 idempotency key.

### Dead-letter lifecycle

Accepted lifecycle:

- `open`: terminal automatic disposition recorded;
- `retry_scheduled`: an authorized retry command created a new bounded schedule;
- `discarded`: an authorized final decision permits no further attempt;
- `resolved`: retry completed/duplicate-completed or an approved discard action completed.

The dead-letter item is a technical control record, not a copy of the Event. It stores scoped identifiers、direction、safe class/code、attempt summary、policy version、timestamps and resolution references. Payload、business result、exception text、PII、Payment、health/allergy facts、credentials and Provider bodies are prohibited.

State changes require append-only action evidence containing bounded action/reason、Actor reference/purpose、expected version and timestamp. History is never deleted or overwritten.

### Ordering and release

- A failed or dead-lettered Aggregate head continues blocking later Outbox versions by default.
- Automatic retry never skips the head.
- An authorized retry retains the same Event/Aggregate identity.
- Releasing later Aggregate work after discard requires an explicit audited decision with expected version and a reason from an allowlist.
- No generic Consumer cursor、holdback queue or cross-Aggregate/global ordering is created.
- `AGGREGATE_ORDER_GAP` remains blocked until the predecessor becomes observable or an owning future policy explicitly authorizes compensation; WP-0033 does not invent missing business facts.

- Restricted content prohibited from retry/dead-letter records and telemetry: Event payload/result、free text、raw exception、stack、SQL/bind values、endpoint、Provider response、unrestricted object identifiers and Tenant discovery data.
- Credential、Payment、health/allergy and unnecessary PII: prohibited from source arguments、records、logs、metrics、traces、fixtures、screenshots and errors.

### Required controls and abuse tests

- application authorization plus exact forced Brand/Store RLS context;
- fixed parameterized SQL and allowlisted enum/code/policy values;
- expected version/state and idempotency key on scheduler and operator mutations;
- no retry of published/completed、active-leased or cross-scope work;
- bounded attempts、delay and batch sizes; injected database clock and randomness;
- one terminal dead-letter identity under scheduler races;
- retry/discard replay returns the same result without another action;
- operator Actor、permission、purpose and reason are required and audited;
- payload/sentinel redaction tests across record、error、log、metric and trace capture;
- crash before/after attempt/dead-letter/schedule commit converges without duplicate effect;
- Aggregate head remains blocked unless an accepted audited release transition commits;
- no PUBLIC privilege、owner/BYPASSRLS runtime or advance production grant.
