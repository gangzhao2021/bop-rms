# WP-2235 - Atomic Guest Binding Persistence

## Authority and scope

Owner authorizes sustained implementation and verified local commits. Baseline21dcdbb (WP-2234),
branch codex/wp-2235-binding-store. Identity owns candidate preparation, Session installation and
revocation; Ordering evidence is supplied through the WP-2234 public contract. Composite authority
and WP-1003 credential rules remain unchanged. Read the database guide; migration infrastructure
behavior is unchanged and the new owner migration is additive.

Add one forced-scope, append-only preparation-history table. Each operation has exactly revisions
1/2/3 for Prepared/Acknowledged/Activated. A predecessor Session row lock serializes transitions;
exact immutable snapshots and a self-referencing revision chain prevent history substitution.
Candidates remain outside the live Session table until activation. Activation atomically revokes
the predecessor, installs the candidate, appends Session/preparation history and invokes the required
transactional Audit port. The callback must use the public Audit owner on the same transaction;
Identity does not acquire an Audit-table write implementation or new synchronous Module dependency.

## Acceptance

1. Strict scoped reads and writes, candidate invisibility before activation, no plaintext credential
   fields, immutable revision history, forced RLS and no PUBLIC grants.
2. Exact preparation and acknowledgement retries preserve history. Wrong scope, proof, operation,
   predecessor version/status, expired preparation and missing owner evidence fail closed.
3. Concurrent activation consumes proof once. Lost COMMIT response completes through the installed
   candidate; a consumed proof or revoked predecessor cannot repeat activation.
4. Real isolated PostgreSQL tests cover the full state sequence, scope/RLS, history mutation denial,
   rollback after transactional Audit writes, concurrency and completion after lost response.
5. Pinned frozen offline install, Identity checks, database ownership/migration checks, existing
   identity-session PostgreSQL suite, full pnpm verify, pnpm test:integration and secret scan;
   final exact diff/migration/permissions/cleanup review. Never disable gates.

No transport, production credentials, real Store, deployment or external mutation. Caller-supplied
scope/owner evidence/Audit ports are trusted server composition inputs, not browser authority.
Preparation history retains keyed selectors only; it follows existing Identity privacy governance.
Rollback is a forward fix; applied migration bytes/history are never rewritten. Local commits are
authorized. Main merge, push, deployment and whole-project completion remain unclaimed.
