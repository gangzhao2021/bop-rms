## Acceptance and boundaries

1. Identity owns a public PostgreSQL entry persistence factory implementing only `create`,
   `resolve` and `resolveOperation` from its existing store port. It uses an injected dedicated
   transaction runner that commits before returning and never retries an unknown commit.
   API and database infrastructure do not own Session SQL or business facts.
2. Every call has one explicitly validated server-resolved Brand/Store scope, transaction-local
   context and explicit SQL scope filters. Existing forced RLS remains defense in depth. New
   records must be Active, version 1, ContextOnly and unrotated; no update/delete is supplied.
3. Store selector/intent hashes, never raw credentials. Parse all records through Identity's
   existing contract, bind SQL values, preserve UTC milliseconds/null fields and reject malformed
   results. Dependency errors are bounded, with no SQL/binds/driver errors in messages or causes.
4. Concurrent insert conflicts never return another attempt's credentials or silently overwrite
   a row. Existing operation resolution enables service-level AlreadyApplied replay; a failed or
   unknown commit has no automatic retry. No lifecycle journal, schema or Domain rule is invented.
5. Real loopback HTTP composes WP-2208 services with this adapter and isolated PostgreSQL. Prove
   persisted selectors/session state, reconnect/read and credential authorization, replay,
   concurrent insert conflict, rollback/unknown commit, different Store/Brand denial, forced RLS
   under a non-superuser test role, and no credentials/internal SQL in HTTP or logs.
6. Reuse the existing synthetic entry fixture outside production source. Retain all WP-2208 tests;
   integrate the new database test into the existing identity-session-store verification config,
   which is already included by root `pnpm test` and CI. Clean all owned databases/servers/roles.

## Risk and rollback

The injected runner must isolate connections, set finite transaction timeouts and complete COMMIT
before reporting success. Scope is trusted server context, never a browser selector. The entry
adapter does not implement the full Session lifecycle and must not be advertised as such. Remove
the opt-in factory to roll back; preserve existing Session/history rows and migration bytes.
External Store/Provider/production evidence remains gated and unclaimed.
