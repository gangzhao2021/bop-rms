# WP-1806 — Device / Output Failure View

## Metadata and authority

- Feature: `F18.1 — Merchant Web Flow`; candidate owning Domain: Device / Output
- Authority resolved by Section 0 precedence: Handoff Section 54.5 lists WP-1806, while later
  Sections 87.7, 88.17 and 88.21 plus accepted IDR-0039 govern its executable scope
- Stacked local baseline: locally verified WP-1805 head `185ebaa`; branch `codex/wp-1806`
- GitHub publication/integration: deferred by explicit Owner direction

## Resolved higher-authority decision

The Section 54.5 roadmap title does not authorize a new Screen, route, Projection or Device/Output
contract. Later accepted authority assigns the canonical Device list/detail and KDS profile screens
to WP-1408, WP-1808, WP-2180 and WP-2181. Section 88 contains no WP-1806 Screen mapping. IDR-0039
also fixes the first live Pilot to a named-operator browser KDS and immutable digital receipt;
Store Gateway, physical printer and offline command queue are disabled. Physical Output remains a
Future Trigger owned by WP-1500–1506 and real-device operations remain externally gated.

Creating `/operations/output-failures`, a client-only Output Job, a Printer retry/reprint action or
an invented Device projection here would conflict with the later accepted Screen Registry and
would weaken the Future Trigger. Existing WP-1803–1805 screens already render safe unavailable,
command-failed and offline/read-only states for their owned browser adapters without claiming
Device facts.

## Executable result

WP-1806 is closed as a superseded roadmap placeholder with no business-code mutation:

- no standalone route or Screen ID is introduced;
- no Device, Output Job, Attempt, printer, retry, reprint or fallback state is fabricated;
- no permission, Projection, Command, migration or fixture is introduced;
- real Device/KDS profile UI and UAT remain WP-1808; physical Output remains Future Trigger work;
- safe owned-surface failure states remain in WP-1803–1805 and are not relabelled as Device truth.
