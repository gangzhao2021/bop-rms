## Resolved contract and hard gate

WP-1602 provides strict Fulfillment proof policy and persistence but deliberately supplies no raw
proof generator, Customer HTTP adapter or UI. The Customer Order Status projection also does not
expose Ready or proof facts. WP-1706 therefore adds a contextual, injected browser controller while
keeping the default runtime unavailable and making no request. It does not invent a transport,
Guest authentication interpretation, raw-proof generator, pepper/KMS adapter or Store fact.

The panel may query proof eligibility only after an explicit Customer action on an authorized
Pickup Order screen. `NotReady` exposes no proof. `Ready` accepts one closed, exact-Order display
view containing the Order number, public Store display name, bounded pickup instruction, Ready
state, generation, proof kind/value, observation and expiry instants. A raw six-digit Human Code or
22-character Opaque proof lives only in controller/page memory, is never placed in a URL, cache,
storage, log, analytics or screenshot fixture, and is cleared on expiry, offline, close, failure or
component disposal.

Refresh is a side-effect-free re-query only. Issuance/regeneration, Complete Pickup, handoff,
Manager Override and any mutation remain unavailable; no retry or reconnect automatically reveals,
refreshes or replays anything. Proof possession is evidence only and never Fulfillment completion
authority.
