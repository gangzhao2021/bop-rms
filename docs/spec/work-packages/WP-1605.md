## Bounded outcome

WP-1605 adds Ordering's strict `FulfillmentCompleted.v1` consumer and advances the existing
Ordering-owned `ordering_order_status_v1` projection for the exact Pickup Order from
`Submitted + Open + fulfillment Unavailable` to `Fulfilled + Open + fulfillment Completed`.
The consumer trusts only the stable public Fulfillment Event, preserves Ordering ownership, writes
one newer immutable projection generation in the consumer transaction and exposes only the safe
completion time in the Customer view.

`Fulfilled` does not imply `Closed`. Payment settlement, refund/write-off, pending Amendment or
cancellation, critical exception tasks and a future Order close/reopen Action remain outside this
WP. No Fulfillment private-table read, Order Aggregate mutation, HTTP/UI/SSE/Worker wiring,
runtime activation or External Evidence is introduced.

## Closed contract

- Consumer: `ordering.fulfillment-completed:v1`, Store-scoped, aggregate-ordered, Inbox-idempotent,
  replay-safe and owned by `@rms/ordering`.
- Envelope and six-field payload are strictly parsed. Event, Tenant/Store, Fulfillment aggregate,
  Order reference and completed instant must match exactly; accessor/proxy/extra input fails closed.
- A projection must already exist, belong to the same Brand/Store/Order, and describe a Pickup.
  Missing source requests retry; cross-scope/type or conflicting completion is a business conflict.
- The next immutable generation increments the local projection source version, binds checkpoint and
  digest to the completion Event, records only Fulfillment/Event references and completion time, and
  keeps `closureStatus=Open`, Payment/Kitchen facts unchanged and ETA unavailable.
- Exact replay produces no second generation. A second or mismatched completion fact never replaces
  the first accepted fact.

## Acceptance, risks and rollback

Acceptance requires strict positive projection, Inbox replay idempotency, missing-source retry,
cross-Store/non-Pickup/conflicting completion rejection, safe Customer output, affected Ordering and
projection PostgreSQL regression, architecture/manifest/format/lint/typecheck/build, frozen install,
security/privacy review, exact-head CI and exact-main CI.

Hard stops are closing the Order from Fulfillment alone, querying Fulfillment private persistence,
accepting reference-only/cross-Store access, overwriting a prior fact, adding raw proof/recipient/PII,
runtime activation, WP-1700 UI work or invented evidence. Rollback is a reviewed revert/forward fix;
append-only accepted evidence is never deleted.
