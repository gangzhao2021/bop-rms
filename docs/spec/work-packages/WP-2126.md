## Owning facts and boundaries

Inventory owns Lot / Expiry tracking, exact scoped quantity projections, FEFO exceptions and an
append-only Hold decision record. Ledger Movements remain the quantity source. Compliance / Food
Safety owns its decision and case facts; Procurement owns Supplier / Receipt purchasing facts.
Inventory consumes only authorized public references and never joins either Domain's private tables.

## Acceptance contract

1. Define `inventory_lot_expiry_v1` with exactly one explicit Stock Scope and strict Item, barcode,
   Lot, expiry, received, Location, on-hand, reserved, Unit, Hold, Supplier / receipt trace and FEFO
   exception fields. Support bounded cursor results and the registered search / filter dimensions.
2. Authorize before projection, operation, repository, snapshot or cross-domain access. Supplier /
   receipt and Compliance trace fields are independently permission-masked; a restricted value is
   `null`, never inferred from absence.
3. Define an append-only Hold Aggregate with exact Tenant, Brand, Stock Scope, Location, Item, Lot,
   expiry, Balance snapshot, status, Compliance decision, reason, Actor, UTC and expected version.
   Quarantine and release append decisions; neither changes Balance nor invents a Stock Movement.
4. Every Hold command uses full-intent idempotency, exact `inventory.manage`, server-rebound scoped
   Lot / Balance / current-Hold facts, an active action-matching Compliance public decision, Audit and
   validated repository output. A Store / Site view still targets one exact Location.
5. Implement only `INV-LOT-EXPIRY` at `/operations/inventory/lots`, including all required fields,
   filters, freshness, mandatory states, quarantine / release controls and authorized trace handoffs
   to Waste, Transfer, Count and Compliance.
6. Section 50 assigns no Inventory schema and the Event Catalog contains no accepted Lot Hold event.
   Projection, persistence, Compliance and Audit adapters remain injected; no migration or Event is
   invented.
