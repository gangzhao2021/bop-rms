## Purpose and boundaries

Add the Ordering-owned Cart lifecycle contract with version-pinned idle and absolute expiration
policy evidence, explicit Customer abandonment, and System expiration. Existing Cart Item and
Quote attachment commands must fail closed when a Cart has legacy/missing lifecycle evidence, has
reached either exact UTC deadline, or is already terminal. Successful Item mutation advances the
idle deadline without passing the absolute deadline.

No Pilot duration is invented. The lifecycle constructor requires an authoritative versioned
policy snapshot supplied by the application composition boundary. Pre-WP rows remain representable
as `Legacy` in the database but cannot mutate or quote until an owning migration/action supplies
approved lifecycle evidence.

Out of scope: Cart create/read HTTP and PWA (WP-1205), scheduler registration, physical deletion,
Checkout/Order/Payment, retention/legal hold, notification, UI, real policy facts and External
Evidence.

## Adopted decisions and hard stops

1. Cart lifecycle is Ordering-owned and has `Active`, `Abandoned` or `Expired` state. `Legacy` is a
   database compatibility state represented as missing Domain lifecycle evidence and always fails
   closed.
2. Active state pins policy Version + digest, positive bounded idle/absolute durations, idle and
   absolute UTC deadlines. The idle deadline never exceeds the absolute deadline.
3. Exact boundary is terminal: `observedAt >= idleExpiresAt` or `>= absoluteExpiresAt` is expired.
   Absolute reason takes precedence when both deadlines are reached.
4. Add/Update/Remove require Active lifecycle. Exact idempotent replay still returns the committed
   historical result; a new mutation after a deadline is rejected even if the worker has not yet
   recorded Expired state.
5. Successful Item mutation advances idle expiry from server `requestedAt`, capped by absolute
   expiry, and advances Cart Version exactly once in the same commit.
6. Customer `Abandon` requires active exact Guest Session, Cart Version, idempotency and Audit;
   System `Expire` requires exact job authorization/Audit and a reached deadline. Both append one
   operation and advance Cart Version once; Cart Items and Quote attachments remain immutable
   history and are not physically deleted.
7. Terminal state is irreversible in this WP. Correction, retention cleanup and Cart recreation are
   later explicit actions, never silent updates.
8. Lifecycle operations use 24-hour exact idempotency. Reuse with changed action/session/intent or
   after expiry conflicts; replay does not repeat authorization side effects or mutation.
9. Hard stop: hard-coded Pilot duration, client time authority, resurrection, destructive cleanup,
   foreign private-table access, sensitive telemetry, invented business fact, or files outside the
   exact allowlist.
