## Goal

Materialize the workspace directory boundaries already discovered by pnpm so later Work Packages can add applications, reusable modules, and shared tooling without reopening repository ownership rules.

## Scope

- Create tracked `apps/`, `packages/`, and `tooling/` top-level directories.
- Document the ownership and dependency boundary of each directory.
- Keep the workspace graph empty until a later Work Package creates a real package.
- Extend the existing `bootstrap / verify` check with deterministic directory-baseline checks.
- Update the bounded repository specification index and root roadmap text for the active Work Package.

## Non-goals

- Application, worker, API, merchant web, or customer PWA skeletons
- Package manifests, TypeScript source, domain modules, public contracts, or module manifests
- TypeScript, ESLint, Prettier, Vitest, Playwright, or other quality-tool installation
- `infrastructure/`, `tests/`, database, Docker, migration, provider, Figma, or production setup
- Merge, deployment, or external Provider changes; commit, push, and Pull Request mutation remain separately authorized actions

## Verification

```bash
test "$(node --version)" = "v24.18.0"
test "$(pnpm --version)" = "11.13.0"
test "$(pnpm exec turbo --version)" = "2.10.5"
pnpm install --frozen-lockfile
test -f apps/README.md
test -f packages/README.md
test -f tooling/README.md
test -z "$(find apps packages tooling -mindepth 1 -name package.json -print -quit)"
pnpm list --depth 0
pnpm exec turbo run build --dry=json
git diff --check
```

Also verify that a second frozen install leaves `pnpm-lock.yaml` unchanged, all three workspace directories are tracked, Turbo still reports zero application packages, no source or secret-bearing file was introduced, and the existing GitHub Actions workflow retains the unique `bootstrap / verify` check with read-only permissions.
