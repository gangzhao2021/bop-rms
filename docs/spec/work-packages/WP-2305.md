## Acceptance and design

Add fixed POST /bff/customer/dining/join. Closed JSON contains joinCredential only; current Guest
HttpOnly cookie, exact CSRF and operation headers carry remaining transport input. Require exact
HTTPS Origin, same-origin/cors Fetch Metadata, JSON, no URL query or duplicate sensitive headers/
cookies. Framing accepts canonical128-bit22-character base64url invitation or six ASCII digits;
Dining remains the grammar/policy authority. No fixed QR substitutes for separate Join proof.

Require a trusted server-side request-context resolver to supply this request's abuse port after
transport validation. It must not derive a verdict/scope from browser body fields; missing/error
context is unavailable. Composition reauthorizes and Dining admits abuse before any owner lookup.
This resolver is a runtime injection boundary, not real canonical IP-device enforcement evidence.

Return only closed Joined/operationReference/admissionReference, validate echoed operation and
canonical admission. Never set/clear cookies, return raw credentials/internal facts or infer rollback
on failure. Use bounded400/503 and no-store/no-referrer/noindex. Optional app/server injection,
fixed telemetry route and default unavailable behavior; no production activation or new Cookie.

Actual PostgreSQL/HTTP acceptance proves lost Join acknowledgement returns bounded503, exact
retry returns original admission and one Join Audit. Feed that admission through existing production
binding client/coordinator over HTTP to rotate and bind once; no duplicate consumption/history.
Use explicit synthetic cookie/Fetch Metadata/QR/abuse inputs, not a real browser/TLS/Store claim.
