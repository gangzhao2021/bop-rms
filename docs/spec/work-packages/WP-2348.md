## Scope and acceptance

Define a closed lossless JSONB representation of the existing immutable Order Item snapshot.
Money amountMinor uses canonical signed decimal strings and restores only to bigint, never Number.
Encode/decode run the existing snapshot parser; preserve all original Catalog/Pricing/option/note
facts and reject malformed money, executable/sparse collections and legacy partial snapshots.
Capture plain inert bounded data before serialization; no getter/toJSON execution or PII error body.
Do not invent snapshot contents from today's Catalog/Pricing.

Add nullable legacy-compatible ordinal to order_item in a new immutable forward migration.
New complete writes will supply one-based ordinal 1..100, unique within scoped Batch, so original
item order need not be guessed from UUIDs. Existing rows keep null; no invented backfill or
history update. Existing append-only rules and RLS continue. Reader/writer adapters come next;
neither missing ordinal nor legacy partial JSON is represented as complete Order recovery.
