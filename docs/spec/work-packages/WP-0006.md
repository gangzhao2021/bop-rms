## Goal

Provide one deterministic root command that validates the local WSL/Linux environment and starts the already integrated PostgreSQL, API, Worker, Merchant Web, and Customer PWA skeletons. Provide bounded root status and stop commands, startup-time validation, and self-cleaning verification without claiming application database readiness or starting later repository, persistence, business, Provider, production, deployment, or design work.

## Local environment contract

- Repository commands run from the WSL2 Linux filesystem with Linux Git, Node, Corepack, pnpm, Docker, and Compose. The validator rejects `/mnt/*` checkouts and Windows executable resolution for required tools; Docker Desktop's selected-distribution Linux CLI bridge under `/mnt/wsl/docker-desktop/` is the accepted backend integration.
- Node is exactly `24.18.0`, Corepack `0.35.0`, pnpm `11.13.0`, and Turbo `2.10.5`; the existing frozen lockfile remains authoritative.
- `.env.example` contains only non-secret localhost defaults and the ignored secret-file path. `.env`, `.local/`, runtime state, logs, and the actual PostgreSQL password remain untracked.
- Required ports are numeric, unique, from 1–65535, localhost-only, and available before startup. Defaults are PostgreSQL `5432`, API `3000`, Merchant Web `5173`, and Customer PWA `5174`.
- The PostgreSQL password is read only through the WP-0005 Docker secret-file contract. Validation checks file existence, regular-file type, non-symlink identity, non-empty content, and Linux mode `0600` without reading or printing the secret.
- Brand/Store business configuration, credentials, Provider data, and production settings never become environment variables in this WP.

## Runtime and readiness contract

- One foreground root command starts PostgreSQL and all four skeletons, waits finitely for observable health, then remains attached as their supervisor.
- API, Merchant Web, and Customer PWA bind only to their documented localhost ports. Worker has no fake queue, timer, database access, or readiness endpoint; process survival after its existing lifecycle start is the only bounded startup evidence.
- API `/health` must be healthy. API `/ready` must remain HTTP `503` with database `not_configured`; starting local PostgreSQL does not create unauthorized application integration.
- Child exit or startup failure fails the root command. SIGINT/SIGTERM and the root stop command terminate only the supervisor's application children and stop only the selected local Compose PostgreSQL service while preserving its named volume.
- Status is truthful and non-mutating. Runtime state is accepted only when it names the current supervisor and configured ports; stale state is reported, not trusted.
