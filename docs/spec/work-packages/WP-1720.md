## Closed readiness contract

Email delivery fails closed unless Notification receives a current, exact external-evidence record
for the target environment. The record must attest an approved `ca-central-1` SES identity,
verified DKIM, aligned SPF, active staged-DMARC aggregate reporting, SES Production Access and a
regional review. It stores only opaque evidence/identity references and review timestamps; domain,
DNS values, AWS account data, credentials and Provider payloads never enter the contract.

The application does not verify DNS, request SES Production Access, mutate AWS or infer readiness.
A missing, expired, wrong-region or partial record blocks the adapter before destination resolution.
The approved evidence source and production wiring remain External Evidence and are not claimed.

## Acceptance and verification

- strict evidence parsing rejects open bags, accessors, identifiers outside the opaque-reference
  contract, wrong Region/environment, invalid time windows and partial authentication;
- Email delivery checks current readiness before destination resolution or adapter invocation;
- SMS/Push remain disabled by the existing Phase 1 route contract and cannot use SES readiness;
- missing/expired/unverified evidence returns the public unavailable error without Provider detail;
- Notification tests, format/lint/typecheck/build, architecture and security/privacy review are
  required locally; real DNS/SES/DMARC evidence remains blocked and unclaimed.
