## Purpose

Implement the smallest rebuildable Catalog-owned Published Menu Projection that proves:

1. a successful Menu publish emits the canonical `rms.catalog.MenuPublished.v1` fact in the same
   repository transaction；
2. an idempotent、aggregate-ordered consumer loads the exact immutable public snapshot and never
   reads Catalog private authoring tables；
3. the projection contains the exact Menu Version、scope、sections、Sellable snapshots and Option
   rules needed by the later Customer Query；
4. a duplicate Event produces no duplicate projection state；
5. an older aggregate version cannot replace a newer projection；
6. projection checkpoint、version、rebuild timestamp and freshness are explicit；and
7. projection failure never rolls back or rewrites the published source fact.

## Adopted boundaries

- The canonical Event is `MenuPublished` schema version `1`, owned and produced by `@rms/catalog`
  with consumer `catalog.published-menu-projection:v1` and Brand Tenant scope.
- Event payload carries only immutable release/snapshot/timing references and digests. Full Menu
  content is obtained through an injected public exact-snapshot contract.
- Projection records are read models, not Aggregate Roots. Only the projection builder writes them.
- Projection selection records Store、Channel、Order Type and effective period but WP-1026 owns the
  public query/filter/staleness policy and REST DTO.
- Pricing、tax display、allergen disclosure、real Media resolution、Search and UI are excluded.
- Rebuild uses a new generation and an atomic active-generation switch; source Catalog facts are
  never modified.
