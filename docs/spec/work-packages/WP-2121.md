## Owning facts and boundaries

Inventory owns the append-only Stock Ledger and immutable Movement facts. On Hand, Reserved,
Available and In Transit are rebuildable projections, never editable Movement fields. Item identity
and unit policy remain the WP-2120 Aggregate; Procurement owns PO / Supplier facts, Kitchen owns its
workflow, Recipe owns theoretical usage, and Accounting owns its ledger. A source error is corrected
only by an authorized inverse Movement linked to the original; the original is never changed or
deleted.

## Acceptance contract

1. Define a strict Movement fact containing Tenant / Brand / Item, type, exact signed quantity and
   Unit, base-unit conversion snapshot, source / destination Stock Scope, lot / expiry, business
   source, named Actor / UTC time, before / after projection snapshot, Audit reference and correction
   chain. Binary floating point, zero deltas and non-positive conversions are rejected.
2. List, detail and item-history queries authorize `inventory.movement.read` before projection access,
   require exactly one Store / Site / Location Stock Scope and reject foreign Tenant / Brand / Scope
   rows. The rebuildable projection reports freshness and partial state; scoped export stays disabled
   without an authorized Job adapter.
3. Correction authorizes the distinct `inventory.movement.correct` permission, binds operation
   idempotency to exact intent, checks eligibility / existing correction and current Balance version,
   creates Audit evidence before the write and accepts only one adapter-returned exact inverse with
   swapped scopes and an immutable link to the original.
4. Implement `INV-MOVEMENT-LIST`, `INV-MOVEMENT-DETAIL` and contextual
   `INV-ITEM-STOCK-HISTORY` with Section 60 / 88 fields, search / filters, source / evidence / Audit /
   correction chain, explicit scope, freshness and every mandatory universal state. Direct Edit /
   Delete and unconnected mutations are absent or disabled.
5. Section 50 assigns no Inventory schema or table and the Event Catalog registers no Stock Movement
   event contract. Persistence, atomic idempotency, Ledger posting, projection rebuild, source
   navigation and export remain injected ports; no migration or Event publication is invented.
