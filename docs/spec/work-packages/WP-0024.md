## Accepted bounded goal

Replace the WP-0020–0023 ad hoc test-database lifecycle with one test-only owner and API that can provision a unique、parallel-safe local PostgreSQL environment，bootstrap it through the unchanged WP-0020 migration runner，provide synthetic-only fixture primitives and deterministically remove every owned resource on success、failure、signal and timeout.

The framework must remain test infrastructure. It must not create business seeds、Tenant / Brand / Store facts、production accounts、Provider data or a general application persistence abstraction.

## Risks、rollback、External Evidence and non-goals

Risks include host-port races、PID reuse、partial Docker startup、hung clients、signal re-entry、cleanup masking the original failure、unsafe identifier interpolation、log disclosure and parallel tests deleting each other's resources. The proposed contract controls these with atomic claims、closed names / labels、registered targets、bounded phases、idempotent cleanup、primary / cleanup diagnostic separation and redaction.

Before integration, rollback is a normal Git revert and deletion of exact framework-owned synthetic resources. The WP creates no production migration or data rollback. An integrated contract change requires a later accepted authority revision；it must not be silently changed by a consumer test.

External Evidence remains gated and unclaimed: PostgreSQL 18.4 / Amazon RDS behavior outside local tests、Docker availability on every developer / CI host、production roles / grants、backup / restore、staging behavior、real Tenant / Brand / Store facts、Provider data and deployment approval. None may be invented or treated as local acceptance evidence.

Non-goals: business seed data；Tenant、Brand or Store bootstrap facts；production / staging accounts or connections；Provider fixtures or mutation；ORM / Repository / Domain objects；schema / migration changes；roles / logins / grants；backup / restore tooling；deployment；dependency upgrades；generic Docker orchestration；cleanup of any unowned resource.
