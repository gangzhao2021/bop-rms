# WP-2146 — Privacy Rights Request intake, verification, fulfillment and closure

## Authority and scope

- Handoff Sections 42.12, 48.3.17 and 87.10.2 define cross-cutting Privacy Governance while each
  Data Owner retains its facts. Accepted WP-2051 pins the four rights, proportional proof, 30-day
  target, encrypted single-use export up to 24 hours, legal-hold behavior and minimal tombstone.
- Section 88.14 defines `PRIVACY-REQUEST` at `/app/compliance/privacy-requests`.
- This WP introduces the runtime-inactive `@bop/privacy-governance` public contract. No accepted
  Privacy database namespace exists, so repositories, Jobs, owner commands and artifacts remain
  ports; no migration, legal result or real fulfillment is invented.

## Acceptance criteria

1. Tracked Brand-scoped Requests support Access/Portability, Correction, Consent Withdrawal and
   Deletion/Anonymization with proportional verification and a default 30-calendar-day target.
2. Lifecycle is append-only across Intake, Verified, Assigned, Collecting, In Review, Fulfilled or
   Denied, and Closed; Expected Version and idempotency protect every command.
3. Data-owner work items expose only scoped opaque references and immutable outcomes. Privacy never
   directly edits another Domain's private facts.
4. Legal Hold/statutory retention blocks erasure but records an approved reason; required financial,
   Audit and Compliance history is preserved.
5. Export evidence is encrypted, single-use and expires within 24 hours. Tombstones contain only the
   accepted opaque fields and are excluded from search/analytics.
6. Strict permission-trimmed UI implements intake, verify, assign, collect, review, fulfill/deny and
   close with stale/read-only states and no raw contact or unrestricted PII.
