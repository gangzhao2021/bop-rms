## Scope and acceptance

1. Add an opt-in Customer Entry composition factory using the existing Dining QR, Store profile,
   Store operating status and Identity Guest Session services through package public exports.
   Do not change CLI defaults, routes, browser contracts, Domain rules or private persistence.
2. Verify QR before Store reads, require matching internal Brand/Store scope across those reads,
   and require available published profile and open requested service mode before admission.
   Use the handler's server-generated request/operation references and trusted UTC time.
3. Require an explicit injected atomic admission/abuse port. Pass only verified context and scope;
   validate its evidence against this request, QR, scope and time before Identity can write.
   Never infer Allowed from a valid QR. Each request has a one-use Identity admission bridge;
   no shared mutable request context, retries or replacement credentials on replay/unknown commit.
4. Identity remains the credential and session write owner. Issue only ContextOnly sessions and
   minimize the public response; bound context expiry by QR, context evidence, admission and
   session expiry. Dependencies, denial, malformed/stale evidence and replay fail closed without
   exposing internal reasons, references, credentials or QR data in logs.
5. Test real Domain composition over synthetic port data and real loopback HTTP: successful
   signed QR to issued cookie/CSRF and stored session, signature/revocation/Store/admission denials,
   scope mismatch, failure/replay, concurrent request isolation and pre-port HTTP security gates.
   Generate ephemeral test keys; no external requests, real identities, seed or production facts.

## Risks and rollback

Cross-domain snapshots are evaluated at one trusted instant but do not create a distributed
transaction. Admission must atomically consume the request proof and enforce current abuse policy;
Identity storage retains its existing atomic/idempotent contract. Fail closed on drift or partial
failure, never retry issuance automatically. Removing the opt-in factory rolls back composition
without deleting session history or changing Domain schemas. Any wider contract change stops work.
