## Purpose

Implement the smallest Ordering-owned, read-only checkout validation boundary before Checkout
Session, Payment and Order creation. A successful validation proves that one authorized Guest
Session is still bound to the exact Active Cart; the caller supplied the exact Cart Version and
attached Quote; the Quote remains current; every Cart item and Option selection is still accepted
by Catalog with the same Menu/Product/rule versions; and an injected Store/fulfillment/capacity
authority accepted the same Brand, Store, Cart, Quote, Order Type and Channel scope.

The result is immutable, field-minimized evidence whose validity ends at the earliest of Cart,
Quote and fulfillment evidence validity. It is evidence for later WP composition, not an Order,
capacity allocation, Payment fact or authorization to enter Kitchen.

## Contract

1. Authorization runs before Cart or Quote data is loaded. Only an active, correctly scoped Guest
   Session for the exact Brand, Store, Cart context, Order Type and supported Customer channel may
   validate checkout.
2. Input is a closed object with UUIDv7 validation, Cart and Quote references, positive expected
   Cart Version and canonical UTC validation instant. The intent hash is dependency-generated and
   runtime-validated.
3. Cart must exist, match the expected Version, contain at least one item and have an Active
   lifecycle at the exact validation instant.
4. The attached immutable Quote must match Brand, Store, Cart, Cart Version, Quote reference and
   every line's Sellable, quantity, Menu Version and Product Version. The exact expiry instant is
   expired. Any mismatch requires Requote; no amount is recalculated by Ordering.
5. Every current selection is revalidated through Catalog's public contract. Unavailable Sellable
   and invalid Option paths fail closed. Changed Menu, Product, channel, order-type or rule evidence
   requires Requote.
6. Store open state, fulfillment support and capacity are owned by the injected public dependency.
   Ordering accepts only exact-scope, current, finite, hash/version-pinned evidence and maps
   `STORE_CLOSED`, `CAPACITY_UNAVAILABLE` and `FULFILLMENT_UNAVAILABLE` distinctly. This WP does
   not invent policy or reserve capacity.
7. Dependency failure, malformed dependency output or an unexpected extra field never becomes a
   successful validation. Returned evidence excludes contact data, customer notes, money detail,
   credentials, payment data and private object identifiers beyond required stable references.

## Acceptance criteria

1. Exact authorized Active Cart + current exact Quote + unchanged Catalog selections + accepted
   exact-scope fulfillment evidence returns frozen validation evidence capped at the earliest
   authority expiry.
2. Authorization denial happens before Cart/Quote reads. Missing/malformed/stale Cart, mis-scoped or
   expired Quote, changed line/version evidence, Catalog rejection, Store closure, capacity loss and
   dependency uncertainty each fail closed with stable safe codes.
3. The module continues to access Catalog only through its public contract and capacity only through
   the new injected port; no foreign private table or synchronous dependency is added.
4. Frozen install, affected tests/static/build checks, architecture/ownership checks, repository
   format/lint/typecheck/build, final scope and security/privacy review pass.
