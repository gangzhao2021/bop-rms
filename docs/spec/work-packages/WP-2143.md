# WP-2143 — Loyalty Account, Points Ledger, reservation and correction exception

## Authority and scope

- Handoff Sections 33.2 and 33.5–33.9 define independent Loyalty Accounts, append-only integer
  Points transactions, derived balances, TTL reservations, reversals, expiry batches and debt.
- Section 33.14 defines Account lifecycle; Section 88.14 defines `LOY-ACCOUNT-DETAIL` and
  `LOY-POINTS-REVIEW`. Sections 88.21–88.24 govern actions, projections and failures.
- This WP is runtime-inactive and port-backed because no accepted Customer & Loyalty persistence
  namespace exists. It does not invent a migration, live transaction feed or Provider result.

## Acceptance criteria

1. Account is Brand/Customer/Program scoped and stores bounded summaries, never an editable balance
   or an unbounded transaction array.
2. Ledger facts are immutable, exact integer Points and idempotent by source/operation. Earn,
   Activate, Reserve, Release, Redeem, Reverse, Adjust and Expire preserve original references.
3. Reserve is atomic against Available Points with TTL and unique redemption request; Redeem/Release
   reference the reservation. Refund shortage creates explicit Points Debt.
4. Correction recalculates from an authorized source and appends Reverse/Adjust; no direct balance
   edit, deletion or historical Order/Payment/Refund mutation exists.
5. Suspension/closure retain history and Debt; unsafe open reservations/adjustments block close.
6. Canonical pages strictly parse permission-trimmed projections and become read-only when stale.
