# WP-2155 — Delivery E2E, privacy, late / duplicate / Provider failure acceptance

## Authority and scope

- Handoff Section 88.25 assigns the Delivery acceptance package to WP-2155; Section 88.29 requires
  assignment-race, Provider timeout / duplicate, address cutoff, proof privacy, late / failed handoff,
  reroute / cancellation and Customer-safe status evidence.
- Exact local predecessor: verified WP-2154 head `678a9ad` on branch `codex/wp-2154`.
- This WP adds a synthetic, runtime-inactive acceptance suite across the already accepted WP-2150–2154
  contracts. It does not add a second Delivery model, persistence, Provider adapter, production data,
  external call, screen or migration.

## Acceptance criteria

1. One pinned Delivery Task proceeds through current assignment, custody handoff and validated proof;
   Delivered is authorized only by accepted proof.
2. Late assignment acceptance is rejected without mutating the original pending offer.
3. Duplicate Provider events are idempotent, terminal conflicts require an exception, and Provider
   create timeout remains Indeterminate until verified reconciliation.
4. Reroute and final failure fail closed when current address/instruction or all-item finality evidence
   is absent.
5. The acceptance fixture and serialized exception contain safe references only: no address, contact,
   precise location, Provider payload, credential, proof asset or unrestricted Customer data.
