# WP-2248 - Preserve Uncertain Customer Cart Intent

## Authority and scope

Owner authorizes sustained bounded implementation and verified local commits. Baseline88b7fc1,
branch codex/wp-2248-cart-retry. Composite Sections0–97 and WP-1205/1702 require exact in-memory
operation identity, server Version, explicit foreground retry and no offline/background replay.

Repair existing Cart/Configurator controllers which allow a settled unknown request to be replaced
by a new operation, mutable caller drafts to alter retry payloads, and refresh to discard pending
intent. Pin the original request snapshot. Only explicit retry may resend an unresolved operation;
new intent allocates no key or request until resolution. Offline rejects new mutations and retains
only an already-started foreground plan. Connectivity is rechecked between locate/create/add;
reconnection never sends a request. Cart query refresh may update
display but cannot settle a pending command or alter its original expected Version. Older reads
cannot replace later command state. A rejection before any unknown outcome retains existing review/conflict semantics. A later
rejection cannot prove that an earlier uncertain attempt did not commit; it retains that intent.

Browser mutation response corruption or service-unavailable response cannot prove no commit and
must remain outcome-unknown. Error codes require matching HTTP status before affecting session
state. Reads retain unavailable/not-found behavior. Existing transport timeout implementation is
unchanged; response-body deadline hardening remains separate. No success is inferred from a query.

## Acceptance and verification

   subsequent submit/change and refresh do not create a new intent or infer success. Mutable caller
   data cannot change a retry. Known rejection allows explicit new reviewed intent.
2. Offline/reconnect never sends or queues new mutations; pending foreground retry remains usable.
   Late query responses cannot discard command state. Disabled controls retain visible safe retry.
3. Malformed/unavailable mutation responses stay unknown; mismatched error status does not clear
   CSRF or produce a false definitive rejection. Existing valid server error semantics remain.
4. Pinned frozen install, affected format/lint/typecheck/unit/build, pwa-security:acceptance, full
