## Resolved contract and hard gate

WP-1600–1605 own the Pickup Aggregate, readiness, proof verification, atomic Handoff and completion
event contracts. They do not provide an accepted Merchant HTTP projection/client. This WP therefore
adds the canonical queue presentation through a strict injectable browser DTO; its default adapter
is unavailable and performs no request.

The queue exposes safe Order reference, deterministic wait/overdue, proof readiness, staging, claim,
exception, package count and a non-health allergen cue. Handoff requires an explicit exact-target
confirmation after proof readiness and remains disabled until a real adapter supplies fresh
expected-version/idempotency authority. Stale/offline data never authorizes a mutation.
