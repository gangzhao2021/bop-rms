## Bounded implementation

Add one API composition factory for development/test loopback use. It requires explicit fixed
Brand/Store scope, existing QR/profile/operating/admission/binding/credential ports, public menu
Store resolution, separate Session and read-only menu transaction runners, origin and clock.
Identity owns all Session SQL and credentials; Catalog owns all menu SQL and public query policy.
The API only composes their public exports with existing handlers and the server lifecycle.

Reject foreign QR scope before profile/admission/persistence and foreign menu resolution before
the menu transaction. Copy the trusted scope at construction. Keep anonymous menu behavior,
ContextOnly issuance, secure Cookie/CSRF, existing errors and unavailable pricing unchanged.
Reject production/unknown NODE_ENV values; bind only 127.0.0.1. Construction does not listen or
open a database. The caller owns injected pools/runners and closes them after HTTP shutdown.
Readiness stays on the existing unconfigured default until a later owning composition supplies
actual readiness evidence. Do not infer overall readiness from successful menu/entry requests.

## Acceptance and evidence map

1. Factory and real HTTP/isolated PG test: signed synthetic entry issues Cookie/CSRF and persists
   hashed Session facts; the same server returns the persisted public menu for that public Store.
2. Domain guards: bad origin/QR and foreign QR scope cause no Session write/admission; unresolved,
   inactive or foreign menu Store scope causes no menu read. Wrong scope cannot leak internals.
3. Dependency failure: Session transaction faults preserve existing bounded entry denial;
   menu faults/staleness preserve existing 503 and retry guidance, without fallback or raw cause.
4. Restart/cleanup: close and recreate HTTP runtime with the same persisted data and credential
   provider; existing Session authorization and menu reads still work. All owned HTTP/PG resources
   clean up on success/failure; structured logs exclude QR, Cookie/CSRF, selectors and SQL internals.
5. Retain default runtime fail-closed tests and existing persistence suites. Exact pins, frozen
   install, affected API/database checks, full verify and secret scan must pass. Delivery requires
   final diff/security review and exact-head/main CI; local success alone is not delivery.
