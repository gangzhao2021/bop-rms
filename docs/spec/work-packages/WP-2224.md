## Scope and Definition of Ready

DoR passes for documentation and source traceability only. WP-2223 implementation is already on the
baseline; its historical delivery snapshot is not reused as fresh CI evidence. The earlier automatic
implementation continuation is not resumed by this package.

1. Record a baseline coverage matrix connecting business scenarios, Domain owners, inputs/results,
   failure recovery, source WPs, current evidence boundaries and future acceptance scenarios.
2. Specify reviewable Cart/Session, Order/capacity/Payment and ordinary-refund handoffs while
   preserving accepted identity, ownership, concurrency, monetary and lifecycle invariants.
3. Specify canonical approval/work routing and an operating-day SOP proposal without creating a
   generic Approval, Finance, Workforce or device platform.
4. Specify cross-version compatibility, privacy-owner coverage and SLO/capacity acceptance inputs
   without inventing production thresholds, legal policy, real people or evidence.
5. Correct WP-1301's demonstrably mismatched attribution of ordinary refund workflow to WP-2045;
   document the actual security-review boundary and link the proposed follow-up contract.
6. Separate accepted baseline rules, documentation corrections, proposed decisions, unresolved
   source questions, implementation dependencies and External Evidence/Future Triggers.

No new WP number is assigned to hypothetical follow-up implementation. Proposal/scenario IDs are
local references within this documentation package; they do not change ownership or authorize
runtime behavior. Canonical Screen IDs, routes, permissions and the Screen Registry are unchanged.

future regression anchors, not evidence that the proposed scenario is implemented or verified.

## Risks, external boundaries and rollback

The primary risk is turning a source gap into an invented accepted rule. Status labels, explicit
source references and a decision register prevent that. Preserve the accepted Session rotation,
30-minute capacity rule, owner-local transactions, integer Money, immutable history, source-domain
approval and existing Pilot gates. Never introduce a cross-domain private-table transaction to
hide an unresolved atomicity requirement.

External Handoff reconciliation, professional policy, real capacity measurements, Provider/Store
evidence and deployment approval remain gated. Removing this package's documentation additions
and reverting its narrow index/attribution edits is the rollback; no data or runtime is affected.
