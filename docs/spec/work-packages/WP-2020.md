## Resolved test boundary

WP-2020 owns one deterministic, synthetic cross-layer acceptance scenario. It starts with a unique
signed QR token, establishes one Guest/Store context, reads the matching published Menu, creates a
versioned Cart, adds the selected Sellable, obtains a server Quote and invokes Ordering's existing
internal `CreateOrder` application API with the exact Cart/Quote intent. The scenario must assert
scope propagation, immutable Order snapshot facts, one atomic `OrderCreated.v1` fact and replay of
the same permanent submission without a second Order.

Accepted WP-1224 explicitly forbids an independent Customer Create Order HTTP route: Payment
orchestration owns that public command boundary. WP-2020 therefore does not add a route, enable the
Provider-gated Payment screen or claim Payment success. WP-2021 owns Payment Success E2E. Real QR,
Customer, Store, Provider, credential, database and deployment facts remain unavailable.
