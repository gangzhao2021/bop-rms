## Resolved contract and hard gate

The first Pilot is browser KDS only. Each actionable board requires one named low-privilege human
Session; shared credentials and unattended authenticated boards are prohibited. Visibility loss
locks the board, auto-lock is bounded to 60–900 seconds and handover locks/signs out before a fresh
named Session can act. Manager actions require a separate eligible Session and are not elevated by
the KDS profile.

This WP adds a strict injectable KDS profile browser contract and canonical profile route. The
default runtime is unavailable and performs no request. Publish/assignment remains disabled unless
the source is Fresh, no operator is active and accepted real UAT evidence is present. UAT `Passed`
is rejected unless accompanied by an exact evidence reference; synthetic tests use `NotRun` and do
not claim Store/device results. WP-2180/2181 retain persistence, enrollment and expanded UAT.

## Security and privacy review

- Actors/assets: named Kitchen Operator, Device/Store Admin, KDS profile, Session state and UAT ref;
- Trust boundary: same-origin authorized adapter into a closed browser DTO; no browser authority;
- Data classification: profile labels/procedure codes are Internal, stable references are indirect
  identifiers, Session state is Confidential; credentials/tokens and health narrative are excluded;
- Controls: exact Store/permission scope remains server-owned, fail-closed parsing, bounded lock,
  visibility lock, lock-before-rotation, disabled offline/stale actions and no command replay;
- Storage/logging/analytics/export: this view stores none and exposes no unrestricted identifier;
- Findings: zero unaccepted Blocker/High findings. External UAT/persistence and real Session/device
  composition are residual gates, not asserted evidence.
