## Closed token and recovery contract

The Notification worker mints a random base64url plaintext only immediately before a Delivery
Attempt. Persistence receives an opaque Token Record reference and SHA-256 digest, never plaintext,
rendered body or link. A Token Record is Order/purpose/Brand/Store/Attempt scoped and expires within
30 minutes. A second unexpired sibling may be minted only after the first Attempt is `Unknown`; a
third is denied. Consuming a token is one atomic repository operation that marks the matched token
Consumed and every active sibling Revoked before returning a one-time resume grant.

The delivery URL is an approved HTTPS origin plus the canonical receipt path and an exact
`#resume=<base64url>` fragment. The token never enters query/path. Customer recovery accepts only
that exact fragment, replaces browser history with the clean receipt path before returning the
token to the in-memory exchange caller, and rejects query tokens, extra fragment fields and invalid
references. No token is stored, logged, cached or exposed to analytics.
