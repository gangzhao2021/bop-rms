## Scope and acceptance

Add one internal Fulfillment append adapter for the existing capacity_hold table, with the
existing public Audit transaction API. Fixed Brand/Store, strict immutable Active Hold input,
permanent operation and intent digest are required. The caller supplies authorized owner facts;
the adapter grants no Guest authority, invents no Store configuration or Hold TTL and exposes no route.
System Audit records the internal authorized checkout operation without customer PII.
No capacity Event is currently specified: do not invent an Outbox event or activation.

Serialize the scoped operation with a transaction advisory lock before lookup, then use the
existing database slot lock/admission trigger. READ COMMITTED is explicit. Exact operation replay
returns the original acquisition snapshot even after expiry/terminal conversion; this is history,
not a current Active-state guarantee. Different immutable content or intent conflicts without writes.
Read back the exact stored slot and Hold fields before Audit; malformed or substituted database
responses fail closed. Hold and Audit must commit together. Unknown commit acknowledgement is an
unavailable result; retry recovers the original operation, with no TTL renewal or second Audit.

and database-access manifest; database ownership validator and its exact-path admission tests;
capacity-hold PostgreSQL acceptance and directly required synthetic fixture grants.
