## Resolved Screen contract

`CUST-ENTRY-CONTEXT` is a contextual Customer PWA screen, not a standalone discoverable route.
The accepted browser entry is the clean Customer root plus exact fragment `#qr=<compact-token>`.
The browser removes the fragment with `history.replaceState` before any network access, sends the
token only in the closed same-origin JSON body to WP-1004's `POST /bff/customer/entry`, and retains
the returned Guest/CSRF and public Store context only in page memory.

The screen shows published Brand and Store display names, fixed Dine-in/Pickup context, current
operating state, allowed service modes, locale and expiry, plus an always-visible accessibility and
allergen-assistance path. It never displays an internal/public Store/Table/Guest reference, QR,
credential or CSRF value. Store search/selection remains hidden because no safe selection policy is
accepted.

Applicable states are loading, missing entry, uniform invalid/expired/revoked/copied/unavailable,
Store closed/temporarily closed, service unavailable, command failed, offline read-only and
established. `Stale`, `Conflict`, `Permission Denied`, `Not Found` and `Feature Disabled` collapse
only through the accepted bounded public Error Contract; the UI never creates a cause oracle.
Keyboard/focus, visible labels, non-color status, live announcements, 44px touch targets, mobile
single-column reflow, 200% browser / 320% CSS zoom and reduced-motion behavior are mandatory.

## Contract evolution and boundaries

WP-1004's current success response lacks Section 88's required public Brand/Store labels and current
hours state. WP-1700 adds a strictly validated `schemaVersion: 2` success contract with exactly four
new public fields: `brandDisplayName`, `storeDisplayName`, `operatingState` and
`availableServiceModes`. The injected Customer-entry composition port remains responsible for
obtaining already-published Store profile/status facts through public Domain contracts; the HTTP
layer and Customer PWA do not read Store persistence or infer hours.

WP-1004 v1 error contracts, Cookie flags, Origin/Fetch Metadata/JSON admission, QR framing,
server-generated references, non-oracular failures and no-store/no-referrer/non-index controls stay
unchanged. No live composition adapter, Service Worker, cache, background replay, analytics,
external fetch, Menu UI, Cart mutation or production activation is added.
