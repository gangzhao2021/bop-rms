## Scope and adopted decisions

Ordering owns Create Customer Cart and current-Cart resolution. The new service accepts only an
operation reference and trusted UTC observation time for Create, and observation time for Current.
It accepts no client scope, Actor, Cart identity, price or lifecycle policy. Authorization supplies
an Identity Guest Session; composition supplies explicit versioned lifecycle policy and Qr/Web
creation attribution. Pickup requires ContextOnly and belongs to the Session. DineIn requires
DiningBound, Dining Session and Participant and shares one Cart across that Dining Session. Brand
and Store are always part of the ownership key. Source channel does not fork a shared Cart.

Authorization runs before repository access and replay. Every new successful create attempt is
recorded, including resolution of an existing current Cart. The fingerprint binds Session and owner,
excluding request time and generated Cart identity. Exact replay returns the original immutable
result for 24 hours; different intent or expired retained key fails closed. Replay grants no new
mutation authority. Reads do not create or renew. Terminal/elapsed and legacy lifecycle states
fail closed. Replacement, Session rotation transfer and shared-Cart batch clearing are later work.

The opt-in PostgreSQL adapter uses one dedicated, fixed Brand/Store transaction. It locks the
scoped operation key, then owner key, then live Cart row in a consistent order. Cart lines are read
in a separate statement after the row lock, avoiding mixed READ COMMITTED snapshots while waiting
for another writer. Bound SQL accesses only Ordering-owned tables; Audit is appended through its
public API. New Cart + immutable owner binding + original operation result + Audit/chain head commit
atomically. No automatic retry, arbitrary first-Cart selection or legacy adoption is introduced.

The forward expand migration adds `cart_customer_owner` and `cart_creation_operation`, with scoped
uniqueness/FKs, forced RLS, explicit PUBLIC revocation and immutable history guards. Old unmapped Cart
owners fail closed rather than gaining a duplicate Cart. Current reads reconstruct live Cart/line
state; operation replay reconstructs its original snapshot. Cart identity, note/health facts and
operation snapshots remain classified and absent from logs, URLs and telemetry.
