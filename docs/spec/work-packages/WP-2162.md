## Acceptance contract

1. A Report Run pins the exact published Report Version, Metric Versions, Tenant / Brand / optional
   Store scope, parameter snapshot digest, trigger kind/Actor and idempotency intent before queueing.
   Rerun always creates a new Run linked to its predecessor with the same pinned version and
   parameter digest; it never silently substitutes `latest`.
2. State progress is append-only and optimistic: `Queued` may become `Running` or `Cancelled`;
   `Running` may become `Completed`, `CompletedWithWarning`, `Failed` or `Cancelled`; terminal runs
   never transition. Completion records Data As Of, projection checkpoint, generated time, duration,
   row count and summary hash without copying source facts.
3. Artifact revisions are append-only metadata with an opaque Output Asset reference, controlled
   format, classification, created/expiry time and optional revocation fact. Regeneration creates a
   new revision. Expired or revoked artifacts cannot be authorized for download; download access is
   permission/scope checked and append-only audited without returning a URL from this Domain.
4. Every mutation requires exact Tenant Context, Actor, purpose, Permission, expected version,
   idempotency, Audit and atomic persistence/Event composition. Current authorization is revalidated
   for future access while historical Run facts remain immutable.
5. `RPT-RUN-HISTORY` exposes exact definition/version, scope/parameter metadata, state, row count,
   freshness, duration, artifact/expiry and safe error code plus ref/report/status/date/requester/
   trigger filters. Rerun, cancel, download authorization, revoke and error detail are permission
   gated; all universal Section 88 states are represented.
6. Forced Brand/Store RLS, explicit PUBLIC revocation, append-only run/state/artifact/operation
   records, ownership metadata, migration and isolated PostgreSQL acceptance pass without real
   report data, storage objects, signed URLs, recipients or external evidence.
