## Protocol and scope

Implement an additive Identity preparation state machine for initial Pickup Cart binding:
Prepared -> Acknowledged -> Activated. The candidate Session is not installed in the live Session
store until activation. It has a fresh Session identity, Session selector and CSRF selector. The
browser receives candidate credentials plus a separate one-time recovery proof before activation,
through future same-origin HttpOnly/no-store transport. Acknowledgement proves possession of all
three credentials and current predecessor authority; it grants no Cart access.

Activation consumes the recovery proof once, requires acknowledged delivery and exact public
Ordering preparation evidence, and produces a plan to atomically revoke the predecessor, install
the exact candidate and advance the preparation in an Identity-local transaction with Audit.
Ordering subsequently activates its own binding from the exact Identity receipt. If that response
is lost, the already-delivered candidate Session authenticates completion; the consumed proof and
revoked predecessor do not. No second rotation changes the immutable Pickup creator.

Preparation expiry is a required server-policy input, bounded by the predecessor's current
deadlines and a fifteen-minute technical ceiling. No production policy value is selected. A lost
preparation response occurs before Cart creation; the old Session stays usable and a new operation
can be started while the orphan preparation expires. No plaintext credential can be reconstructed
from persistence. Same-operation CAS retries return historical transitions only after fresh proof
and authority checks; concurrent writes require the exact preparation and predecessor versions.

## Acceptance and verification

1. Strict immutable preparation parsing binds operation, target, scope, predecessor/version,
   candidate and times. No raw credential is stored or emitted in errors.
2. Acknowledge only exact candidate Session/CSRF/recovery proof, current predecessor and expiry.
3. Activate only acknowledged preparation and exact fresh owner evidence; preserve candidate
   identity and provide atomic predecessor-revocation/candidate-install plan. Consumed proof cannot
   activate again; completion uses the active candidate and exact operation instead.
4. Test wrong proof/purpose/scope, revoked/expired/stale authority, missing acknowledgement,
   cross-operation evidence, clock/expiry boundaries, immutable history and response-loss recovery.
5. Pinned frozen offline install; Identity tests/lint/types; full pnpm verify; pnpm test:integration;
   pnpm secret-scan:check and final scope/diff review. Local synthetic evidence only.

This WP implements pure contracts and crypto, not a repository, endpoint or new active credential
path. The next WP must implement scoped CAS persistence and atomic Audit before runtime activation.
No main merge, push, deployment, external mutation or whole-project completion claim. Rollback
removes additive exports; persisted existing Session facts are unchanged.
