## Purpose

Map one WP-1304 verified, durably accepted Provider observation through a closed Payment state
machine into an append-only authoritative `PaymentSucceeded` or `PaymentFailed` fact. Persist the
normalized transaction fact, Restricted Audit input and matching public Outbox event atomically.
Duplicate, concurrent, delayed and out-of-order delivery must never duplicate or contradict a
committed Payment outcome.

The older Phase 1 catalog and Domain summary call the successful commercial fact
`PaymentCaptured`; the later Feature F13.1 Work Package title explicitly assigns
`PaymentSucceeded / Failed Event` to WP-1305 and therefore supersedes that shorthand here. The
success payload retains a closed `Captured` evidence kind; no alias event is published.

## Closed execution contract

1. Input is an internal normalized observation produced only inside WP-1304's transaction-owned
   mapper after verified durable receipt. It accepts no browser return, client status/amount,
   signature header, raw Provider object, route-supplied Tenant scope or unverified payload.
2. Payment resolves the existing Intent/Attempt by exact Provider, environment, Provider Account,
   Provider Intent, Brand and Store identity. Missing or mismatched ownership fails closed before
   an authoritative fact or Outbox append.
3. Success requires the normalized Payment state machine's terminal captured evidence, exact
   expected amount/currency and a server-authoritative verified-webhook or Provider-retrieval
   source. `Processing`, `Unknown`, authorization-only, timeout and redirect results never become
   success or failure.
4. Failure requires a terminal Provider failure mapped to one bounded internal reason and safe
   retry disposition. Provider status/message, payment-method detail and exception text are never
   public facts.
5. One Payment transaction identity is append-only. A first terminal outcome persists one
   transaction fact, Audit input and Outbox envelope atomically. Any write failure rolls all three
   back and remains replayable through WP-1304.
6. Idempotency is enforced by Payment Attempt plus terminal outcome identity and by Provider Event
   receipt. Same-fact replay returns the committed fact/event without another append; a conflicting
   second terminal outcome fails closed and is reserved for reconciliation rather than rewriting
   history.
7. `PaymentSucceeded.v1` and `PaymentFailed.v1` are stable, Payment-owned and Payment-produced,
   Store-scoped business-record events. Envelope identity/version, correlation/causation, Actor,
   classification and replay metadata must agree with the Event Catalog and runtime parser.
8. Public payloads are minimal. Both carry Payment, Intent, Attempt and Order references plus
   terminal occurrence time. Success carries exact integer-minor-unit Money and `Captured` evidence
   kind; failure carries only a bounded reason and retry disposition. Neither contains Provider
   account/event/object IDs, receipt/evidence digest, PAN/CVV, fingerprint, customer/guest data,
   raw payload or Provider message.
9. The authoritative fact occurrence time is the normalized Provider business instant. Publication
   time remains Outbox transport metadata. Delayed and out-of-order observations are independent;
   no arrival cursor may suppress a valid first terminal fact.
10. Ordering is only a declared public consumer. This WP neither changes Order status nor reads or
    writes Ordering private persistence. WP-1306 owns Payment status projection; later WPs own
    reconciliation, kill switch, watchdog, compensation and operational UI.
11. Audit/telemetry expose only bounded internal references, outcome/reason codes, timestamps and
    Money where authorized. No secret, credential, raw evidence, Provider message or unnecessary
    personal/payment identifier enters logs, analytics, metrics, URLs or public errors.
12. No public HTTP deployment, Stripe SDK/API call, real account/credential, Provider retrieval,
    Order confirmation, ledger posting, refund, reconciliation job, UI or External Evidence is
    authorized.
