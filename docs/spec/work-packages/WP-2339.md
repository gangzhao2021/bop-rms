## Scope and acceptance

Add immutable Hold terminal, Allocation and Allocation terminal facts in rms_fulfillment.
Preserve original Hold provenance through scoped owner foreign keys. All writes use the same
slot lock and READ COMMITTED contract. Hold conversion and Allocation creation must commit together;
deferred reciprocal foreign keys prevent a committed half-conversion. Conversion cannot decrement
occupancy twice or resurrect an expired Hold. Original configuration/units remain unchanged.

Release/expiry and conversion are mutually exclusive terminal Hold outcomes. Allocation release
before consumption returns units; consumption at the earlier slot-start/authoritative InProgress
instant never returns units. A unique terminal row prevents double release and terminal reopening.
Capture explicit operation identity/intent digest and append-only timestamps; error payloads stay bounded.

Replace the admission trigger through a new forward migration so occupancy includes live
nonterminal Holds plus all Allocations except explicitly Released ones, even after original Hold TTL.
Test conversion versus a waiting contender, full-slot conversion, release versus conversion,
half-conversion rollback, original TTL expiry, consumption and response-loss retry uniqueness.

This is owner storage, not a public command. Authoritative Fulfillment InProgress evidence must be
supplied by the future owner service; null cannot substitute unavailable evidence.
Application Actor/purpose/permission, Audit/Outbox, permanent replay responses, reschedule coordination,
Payment30-minute binding/watchdog, final Inventory and Provider composition remain gated.
No production capacity/Store fact or cross-domain transaction is invented.
