# WP-2181 — Managed KDS Profile and Store UAT Expansion

## Authority and scope

- Handoff Sections 36.1–36.6, 36.22–36.25, 54.5 F18.1, 87.11.1 and
  88.17/88.21–88.30 define the Device-owned KDS profile, Store UAT gate and canonical screen.
- Exact local predecessor: verified WP-2180 commit `c33a0d8`.
- `@rms/printing-device` owns KDS Profile identity, immutable Versions, effective-dated Device
  assignment and Store UAT run/check/result facts. Device remains the Device identity/health owner;
  Store/station, Identity Session, Kitchen work and Evidence bytes remain owner references only.
- WP-1808 supplies the existing safe browser view. This WP adds durable Domain/persistence contracts
  and expands that view without weakening its named-operator, lock or external-evidence gates.

## Acceptance contract

1. KDS Profile is Brand/Store scoped and has `Draft | Published | Revoked` lifecycle. Immutable
   Versions capture managed Chromium, at least 1024×768 logical resolution, wake/power, bounded
   60–900 second auto-lock, visibility lock, lock-before-handover, notification, network continuity
   and replacement procedure codes.
2. Assignment history is effective-dated and append-only. Assignment requires an Active
   `KitchenDisplay` Device in the same Store with validated touch/order-acknowledgement capability;
   it never mutates Device, Store, station, Identity Session or Kitchen facts.
3. A UAT Run pins Profile Version, Device, Store/station, browser/app version, resolution and
   checklist Version. Checklist results are append-only and cover managed browser, resolution,
   wake/power, auto-lock, visibility lock, named-session handover, notification, network loss,
   replacement and accessibility.
4. `Passed` requires every mandatory check to pass plus an accepted stable Evidence reference from
   the Evidence owner boundary. Missing or rejected evidence leaves UAT `NotRun | InProgress |
Blocked | Failed`; code never manufactures real Store/device evidence.
5. Publish requires a current Passed UAT for the exact Profile Version/assignment, Fresh Device
   eligibility, no active named operator Session and exact permission/purpose/version/idempotency/
   audit context. Revoke is append-only and stops future eligibility without rewriting history.
6. `DEV-KDS-PROFILE` `/app/integrations/kds-profiles` exposes list/detail-safe profile, assignment,
   checklist, UAT due/status and explicit loading/empty/denied/offline/stale/conflict/error states.
   Credentials, operator identity/name, raw device logs and unrestricted identifiers are excluded.
7. IDR-0039 remains active: browser KDS only. Physical output, Store Gateway, vendor adapters/SDKs,
   application Offline Queue and browser command replay remain excluded.
8. No new public Domain Event is invented. WP-2181 records audited Device-owned operations; any
   future external consumer contract requires accepted Event Catalog authority.
