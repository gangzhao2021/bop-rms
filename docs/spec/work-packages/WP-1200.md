## Purpose and boundaries

Create the smallest Ordering-owned Cart aggregate and Cart Item entity contract. A Cart is a
Store-scoped, versioned, temporary purchase intent and remains separate from Order. It has exactly
one order type (`DineIn` or `Pickup`), one source channel, immutable Tenant/Store/context identity,
UTC creation/update facts, and zero or more Product-owned Cart Items. Each Item stores only opaque
Sellable/Option references, integer quantities, adding Actor, optional/required Participant
attribution by order type, and UTC added time. Client price is structurally impossible.

This WP establishes `@rms/ordering` and the first `rms_ordering.cart/cart_line` migration with
forced Brand + Store RLS, immutable identity guards, closed database ownership, migration catalog,
and isolated PostgreSQL acceptance.

Out of scope: Create Cart transport/application command, Add/Update/Remove command and idempotency
(WP-1201), current Sellable/Option validation (WP-1202), Quote attachment (WP-1203), lifecycle
expiration/abandonment (WP-1204), API/PWA (WP-1205), Checkout, Order, Event, Projection, UI,
customer note, price/tax/payment facts, cross-Domain private reads, and real business evidence.

## Adopted decisions and hard stops

1. Cart is the Aggregate Root; Cart Item cannot be committed outside its Cart version.
2. Dine-in requires one opaque Dining Session and every Item's Added By Participant; Pickup
   forbids Dining Session context and may omit Participant attribution.
3. Quantity is a bounded positive integer (`1..999`); money is absent and binary float fails.
4. Option selections are a closed, unique ordered list of opaque Option ID + quantity. Their
   Catalog validity is deliberately not claimed until WP-1202.
5. Cart and Cart Item stable identity/scope/created attribution are database-immutable. Later
   commands change content only through optimistic Cart version control.
6. Store RLS requires exact server-established Brand and Store context on both tables.
7. Cart/object/Actor/Participant IDs are indirect identifiers: logs, URLs, analytics,
   screenshots, and non-synthetic fixtures are prohibited.
8. Hard stop: Order/Quote/API/Event creation, client price trust, Dine-in without Participant,
   cross-Store access, non-integer quantity, foreign/duplicate Item identity, unvalidated external
   evidence, or any file outside the allowlist below.
