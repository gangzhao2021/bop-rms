## Scope and acceptance

Add a Catalog application query combining its scoped rule reader with two injected owner evidence
ports, one KillSwitch and one Inventory. Construction does no I/O. Capture fixed caller-authorized
Brand/Store and closed SKU/channel/order/UTC observation input before awaits. Query input is internal,
not a public authorization mechanism. Use only public ports; no new synchronous Domain dependency.

Copy plain rule/evidence data immediately after each await. Require exactly the expected safety kind,
matching Brand/Store/SKU, observedAt no later than query observation and exclusive expiry beyond both
query observation and the final server clock. Missing evidence returns Indeterminate. Malformed,
foreign, duplicate rules or wrong-kind evidence fail with bounded dependency errors. Preserve owner
negative/indeterminate decisions and the existing rule specificity/priority/ambiguity policy.
Capture rules before evidence waits and safety evidence before later awaits; deny executable/sparse
collections and accessors. Reject clock reversal and future request observations.

Return the existing resolution fields plus the explicit requested observedAt. This is an observation
result, not an authorization lease or assertion that configuration cannot change during/after reads.
Recheck returned rule applicability with the final clock and return Indeterminate if the observation's
rule winner changes/expires while awaiting evidence. Unknown future/unqueried rule updates are not
inferred. Consumers must perform their existing final authority checks; selection/publication,
commercial inputs and checkout remain separate.

Real Inventory/KillSwitch producer wiring, SKU-to-inventory mappings, TTL policy, schema, writes,
HTTP, browser, pricing and production authority are non-goals. Synthetic injected safety evidence
proves composition only, never real Store sellability.
