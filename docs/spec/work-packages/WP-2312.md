## Acceptance and design

Capture the shared opaque CSRF generation after this entry attempt's own reset. Before reading and
publishing a response, require that generation to remain current and the client to remain online.
Older clients and same-value/null ABA changes cannot publish stale credentials or Established state.
A failure never clears a newer credential. Concurrent start/retry calls on one in-flight client share
one request; a subsequent explicitly requested retry remains possible. Preserve settled start behavior;
no automatic re-entry or claims of cross-document/Cookie recovery.

Use fixed relative same-origin/no-store/redirect-error Entry POST and the current closed HTTP response
contract. Enforce a15-second whole-response deadline including body reads, actual UTF-8 byte limit,
JSON/no-store envelope, fatal UTF-8 decode and exact status/error mapping. Choose a bounded16 KiB body
limit to accommodate maximum allowed Unicode public labels within the existing contract. Cancel late,
rejected and oversized response streams; abort-unaware fetch/read promises cannot hold the UI forever.
Retain existing missing/invalid/offline/closed/error states and fragment removal. No storage, raw error
or proof output, Cookie writes, shared helper changes, API policy or dependency changes.
