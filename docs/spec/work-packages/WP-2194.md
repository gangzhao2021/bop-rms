# WP-2194 — Store / Platform Live Gate Evidence Workflow

## Authority and scope

- Handoff Sections 48.3.14, 80.11, 87.11–87.13 and 88.7/88.18/88.21–88.30 define the
  production evidence boundary, Publishing ownership and canonical Store/Platform screens.
- Exact local predecessor: verified WP-2193 commit `85bfaa5`.
- `@bop/publishing` owns Live Gate workflow status and immutable decision history. Evidence bytes,
  legal/provider/Store facts and owner-Domain outcomes remain with their external or Domain owners;
  this package stores only controlled references, applicability, validity and review metadata.

## Acceptance contract

1. A Live Gate has a stable canonical gate ID, exact Tenant/Brand/Store/environment scope, version,
   lifecycle, owner, last review and explicit blocking reasons. Missing applicable evidence always
   resolves `Blocked`; an unavailable source is never interpreted as satisfied.
2. Checklist requirements are versioned and categorized. Each records applicability, evidence
   owner, approved evidence reference/version, validity/expiry and status without copying evidence
   bytes, secret values, unrestricted PII or professional conclusions.
3. Attach reference, request review, independently approve/reject and reopen require exact scope,
   purpose, permission, expected version and idempotency. Submitter/approver segregation is enforced.
4. Approval is possible only when every applicable requirement has current accepted evidence.
   Expiry/revocation appends a reopen decision and blocks live operation; no prior history changes.
5. The canonical Pilot gate `STORE-LIVE-GATE-CA-ON-TOR-001` remains `Blocked` in synthetic fixtures
   because IDR-0037 external evidence is unavailable. Provider-neutral development/UAT may continue;
   production PII, Payment, legal receipt and public ordering remain disabled.
6. `STORE-LIVE-GATE` and `PLT-LIVE-GATE` expose checklist/category/owner/status/expiry/blocking
   reason/history with complete loading/empty/denied/not-found/offline/stale/conflict/error states.
7. This WP creates no real Store, Tenant, evidence, legal/tax/provider conclusion, professional
   approval, production enablement, external mutation or new cross-Domain Event.
