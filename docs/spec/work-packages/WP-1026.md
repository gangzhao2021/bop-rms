## Purpose

Implement the smallest customer-safe Published Menu Query that proves:

1. the canonical `GET /api/v1/public/stores/{storePublicId}/menu` endpoint reads only the
   Catalog public Application Query contract；
2. public Store resolution occurs behind an injected Store Reference contract；
3. only one exact Brand / Store / Channel / Order Type / current-effective Published Menu
   Projection may be returned；
4. `Stale`、`Rebuilding`、`Failed` or ambiguous projection state fails closed；
5. Hidden and configured-unavailable Sellables are never returned；
6. localized name search is bounded and cannot become an unrestricted ingredient or SQL-like
   query；and
7. the response identifies its projection version、checkpoint、as-of time、scope、freshness and
   partial state.

## Adopted boundaries

- The only HTTP path added is the canonical Section 52.13 Menu resource. Optional `q` and
  `section` filters use that resource; no invented search or item-detail route is added.
- `channel`、`orderType` and `locale` are required finite query parameters. Effective time comes
  from the server clock and cannot be supplied by the caller.
- The accepted Catalog projection freshness state is exactly `Fresh`; the declared target is
  `5,000 ms` from Section 88.22. Stale state returns `503` with bounded retry guidance.
- Query scope uses an opaque public Store reference. The REST layer neither derives Brand scope
  nor reads Store or Catalog private tables.
- Display Price and Tax Display Context fields are present but explicitly `Unavailable` with
  `PRICING_NOT_INTEGRATED` / `FINAL_QUOTE_REQUIRED`. WP-1100–1103 own calculation and Quote；this WP
  does not fabricate money or tax facts.
- Dietary and allergen filters/disclosure remain WP-1028. Customer PWA rendering remains outside
  this transport WP.

## Acceptance

- one exact current projection returns stable public DTOs and immutable source metadata；
- wrong Store、Channel、Order Type or effective time returns uniform Not Found；
- stale or multiple matching generations fail closed without selecting one arbitrarily；
- unknown/repeated/open query fields are rejected before Catalog is called；
- provider/database errors and malformed adapter status never leak payload or internal details；
- Hidden and unavailable Sellables remain absent；and
- no price、tax、allergen、private-table access、mutation、UI or External Evidence is claimed.
