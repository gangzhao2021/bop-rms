## Goal and acceptance contract

Turn the existing WP-2204 Customer preview browser evidence into one repeatable, fail-closed local
and GitHub acceptance command without changing the application being tested.

1. One root command starts the exact local Customer demo through a Playwright-managed,
   loopback-only, strict-port server and executes Chromium with one worker and zero retries.
2. The command verifies these 11 accepted routes at `1440x900` and `390x844`: entry, menu, search,
   sellable detail, Cart, Checkout, Payment handoff, Checkout result, Order status, Delivery status
   and Receipt.
3. Every development route renders its expected accepted heading and the visible local
   synthetic/read-only notice, has no application API fetch/XHR, makes no non-loopback request,
   emits no uncaught page error or error-level console message, and has no horizontal overflow.
4. At least one accepted path is exercised through visible keyboard-reachable navigation instead
   of direct URL entry; the main landmark and existing focus behavior remain available.
5. A production build made with `VITE_BOP_LOCAL_CUSTOMER_DEMO=1` excludes the bounded demo modules
   and fixture markers. Its browser preview never displays synthetic demo authority on any covered
   route.
6. Development and production preview processes use finite startup/test timeouts, do not reuse an
   unknown CI server, are stopped on success or failure, and leave neither owned port listening.
7. The unique `bootstrap / verify` workflow installs only the already pinned Chromium engine and
   runs both Merchant and Customer root acceptance commands. Browser startup, assertion and cleanup
   failures fail the job; no retry may convert a failure into acceptance.
8. Browser traces, screenshots and reports are untracked, failure-only diagnostics containing only
   synthetic data. No credential, token, real Tenant/Store/Actor, payment data, health fact,
   delivery location or unnecessary PII is introduced.

## Risks, rollback and external boundary

- Risk: a second browser suite pushes CI beyond its finite budget. Reuse the installed pinned
  Chromium, one worker and the existing WP-2202 45-minute limit; timeout is a failure, not authority
  to weaken coverage.
- Risk: PWA build artifacts or local Vite transport create noisy observations. Reject application
  fetch/XHR and non-loopback traffic in the demo project while treating production exclusion as a
  separate emitted-asset and browser-authority assertion.
- Risk: selectors drift with presentation. Prefer roles, accessible names, accepted headings and
  visible synthetic labels over CSS structure or snapshots.
- Rollback: revert the single WP-2205 integration to remove only Customer browser automation and CI
  wiring; WP-2204 behavior remains unchanged.
- External Evidence: unavailable and unclaimed. No real Guest Session, Store, Customer, Cart,
  Quote, Payment, Order, Delivery, Receipt, Provider result or production activation is required.
- Owner authorization covers this bounded brief, implementation, verification, commit, push, PR,
  review, merge and exact-main verification. Deployment and Provider actions remain excluded.
