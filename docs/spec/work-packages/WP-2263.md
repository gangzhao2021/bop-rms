## Scope and contracts

Ordering owns an append-only v1 expiry resolution, keyed by Brand/Store/original operation and
bound to Guest, Cart/version, Quote identity/input digest and original Pricing request digest/times.
The caller must authorize the current Session/CSRF/binding and supply original public Pricing
history; this infrastructure WP does not create that future reconciliation service or HTTP receipt.
Expiry and attachment serialize on the same Cart row lock. Existing matching attachment wins;
otherwise an expired original Quote can produce one immutable expiry record plus Audit atomically.
A committed expiry rejects late attachment, including a writer carrying a formerly valid timestamp.
Replays return original history without extending validity or duplicating Audit. Different intent
conflicts. No operation key is freed. No Cart state/version or Pricing history is changed.

The record contains only scoped indirect references, version, digests and UTC instants. Minimal
System Audit uses ORDERING_CART_QUOTE_EXPIRE / QUOTE_VALIDITY_ENDED. It emits no Event because
no existing consumer contract requires one. Both records remain append-only and Brand/Store RLS
protected. No foreign private SQL. Store/Provider/legal facts remain synthetic and gated.
