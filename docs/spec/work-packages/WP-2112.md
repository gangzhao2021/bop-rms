## Owning facts and boundaries

Dining owns Store-scoped Dining Areas, stable Tables, versioned Table configuration, temporary
operational blocks, Dining Session phase and current Table assignment. Ordering owns Order / Batch
facts; Payment owns financial finality; Reservation and Waitlist own their party / handoff facts;
Identity and Public Capability own browser Session and join-credential boundaries. The Floor Board
may project only authorized, privacy-minimized public summaries from those Domains. Dining never
mutates their private tables, infers a payment outcome or copies contact, allergy / health or raw
credential data into a board row, Event, URL, log or analytic label.

## Acceptance contract

1. Create Table Draft, Replace Draft, Publish Configuration, Issue / Revoke QR, Set / Clear
   Temporary Block and Move Active Dining Session are explicit idempotent Commands with Tenant,
   Brand, Store, Actor, purpose, permission, Expected Version, append-only Audit and minimal Events.
2. Table stable label, Area, positive capacity, controlled accessibility attributes, QR lifecycle,
   operational state and current Session are strict, versioned facts. Configuration publication is
   append-only; physical deletion, arbitrary state selection and client-provided active Session are
   forbidden.
3. Session move requires an Active Session, exact current source assignment, an eligible target
   Table in the same Store, target capacity / policy evidence and no conflicting active Session.
   The move preserves Session identity and history. Closing continues to use the accepted WP-1007
   invariant and exception-task contract; this WP does not weaken or duplicate financial finality.
4. Five minimal Store-scoped future Event records cover Table configuration, QR lifecycle,
   operational availability and Session movement behind the injected repository transaction port.
   The Floor / Table client consumes a rebuildable-query contract carrying only stable references,
   controlled state, elapsed/freshness values and privacy-minimized owner summaries. Section 50 and
   accepted WP-1006 / WP-1007 provide no Dining schema or migration namespace, so this WP must not
   invent database or Event-catalog authority.
5. `DIN-FLOOR-BOARD` and `DIN-TABLE-LIST` implement every Section 88 field, filter, action and
   mandatory state. Existing Staff Session start / closing controls remain visibly disabled without
   an authorized command-capable BFF; realtime remains a requery hint only.
