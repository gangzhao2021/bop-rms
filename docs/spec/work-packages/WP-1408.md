## Purpose and bounded outcome

WP-1408 closes the Kitchen-owned continuity contract for the named-operator browser KDS:

1. one deterministic state model composes canonical queue freshness, connection state, named
   operator Session evidence and recovery status;
2. only `Online + Fresh + active exact-scope named operator + no pending recovery` enables a
   Command intent; Stale, Reconnecting, Offline, locked/expired Session and recovery-required modes
   are explicit read-only states and never queue a browser Command;
3. operator handover is an append-only record that requires the prior Session to be locked/ended
   before a distinct next named operator becomes active; and
4. recovery compares the last viewed snapshot/checkpoint with a fresh authoritative source read and
   records either no-action convergence or an authorized-resolution requirement. It never replays
   Accept, Start, Complete, Ready, Payment or Handoff.

No Merchant Web component, browser storage, Service Worker, HTTP/SSE adapter, Identity Session
mutation, managed-device profile, auto-lock timer, physical printer/Gateway, manual runbook content,
real Store UAT or external continuity receipt is introduced. WP-1804/WP-1808 retain page/device
composition and UAT; each owning Domain retains post-recovery business Commands.

## Resolved Screen contract

- `KIT-KITCHEN-QUEUE`: standalone `/operations/kitchen`, named Kitchen Operator,
  `kitchen.operate`, `kitchen_*_v1`, Store/Actor/purpose scope.
- `KIT-WORK-ITEM`: standalone full-screen child `/operations/kitchen/work-items/{id}`, same
  permission and privacy-minimized detail contract.
- `KIT-EXCEPTION`: contextual child of the Queue, Kitchen Lead / Store Manager, same canonical
  permission.
- Applicable states: Loading, Empty, Permission Denied/Lost, Not Found, Feature Disabled, Stale,
  Reconnecting, Conflict, Command Failed and Offline Read-only.
- Stale/disconnected states display timestamp, explicit non-color status and manual-continuity
  reference; they never move a card or complete a fact locally. Every later action re-queries Source
  and revalidates Expected Version.

## Persistence, privacy and scope

Migration `1500_006` adds `kds_operator_handover` and `kds_recovery_reconciliation` as Kitchen-owned,
append-only, forced-RLS Store records. They contain only indirect Session/Actor/source references,
controlled status/reason values, timestamps and semantic digests. They contain no credential,
Customer/health narrative, Payment/Provider data, manual card data, raw incident sheet or command
payload. Cross-Domain Session and runbook evidence remain opaque references.
