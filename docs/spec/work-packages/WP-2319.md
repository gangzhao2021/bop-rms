## Contract and acceptance

Compose current Dining Cart reads, safe display, atomic owner selection and request-local CSRF
Identity authorization. Every Identity check surrounding selection calls the public authorize
contract with the exact captured Cookie/CSRF pair and fresh owner observation. Credentials never
enter owner commands, public results, database operation history or display dependencies.
Creation accepts the existing closed transport context only. Parse the internal receipt and then
read the same Cart through current safe display; require DineIn and current version at least the
receipt version. Map Create to Applied/201 and Select to Current/200. Lost post-effect reads remain
Unavailable and the original operation can be retried; a historical receipt alone is never a view.
Map bounded permission, lifecycle and idempotency errors without metadata or raw errors.

Route the existing Cart port by freshly resolved Identity channel under fixed Brand/Store and clock.
Do not fall back after permission failures or use client order type. Preserve Pickup behavior and
keep Dining item mutations unavailable until their current-authority composition exists. The router
is not a membership grant; each downstream service independently enforces its current authority.

Add an explicit optional Dining Cart configuration to the local runtime. Require Cart read transactions
and a separate supplied selection write runner. Reuse its fixed scope, current Identity store, clock,
Catalog display and public Store profile. Caller retains resource ownership. No automatic opt-in,
new endpoint, fabricated policy, production enablement or external mutation.

Unit/HTTP acceptance covers status codes, security headers, closed inputs, CSRF denial before owner
write, current channel selection, same-operation recovery, safe failures and unavailable Dining item
mutations. Actual PostgreSQL composition uses explicitly synthetic current Identity/Dining/profile
providers with real Ordering stores to prove shared selection, safe current display and no duplicate
operation/Audit on original retry. It does not claim production or fully persisted Identity providers.
