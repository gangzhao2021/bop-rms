## Owning facts and boundaries

Inventory owns low-stock evidence, Replenishment Need identity and acknowledgement/dismissal history.
Procurement owns Supplier selection, Offering, Requisition and Purchase Order facts. Inventory may
retain a public preferred-mapping reference and authorized summary, but never queries Procurement
private tables or selects a Supplier. The handoff can create only a Draft Purchase Requisition and
uses Replenishment Need ID as its stable idempotency/source key.

## Acceptance contract

1. Define strict `inventory_replenishment_v1` results for exactly one Stock Scope with Need and Item
   references, available quantity, threshold and forecast snapshots, suggested base-unit quantity,
   required-by date, urgency, authorized preferred Supplier summary, status, version and freshness.
2. Support bounded item/code search and Store, status, urgency and supplier/unmapped filters. Apply
   authorization before the projection and independently mask/filter Supplier summary fields.
3. Define a versioned Replenishment Need Aggregate with append-only acknowledgement, dismissal and
   Requisition-draft-link decisions. Dismissal requires a controlled reason and never changes ledger
   quantity or deletes the original Need evidence.
4. Revalidate the exact Tenant, Brand, Stock Scope, Item, policy, Balance and forecast snapshots for
   every mutation. Reject stale Expected Version, mismatched scope and changed source evidence.
5. Make every command idempotent by operation reference and intent hash. Use the Need ID as the
   Procurement handoff idempotency/source key and accept only a same-scope `Draft` Requisition.
6. Never approve a Requisition, create/approve/issue a Purchase Order, select a Supplier, or cancel
   existing Procurement work when a Need disappears. Those actions remain Procurement-owned.
7. Implement canonical `INV-REPLENISHMENT` at `/app/supply/replenishment`, with all registered
   fields, filters and actions, explicit stale/partial read-only behavior and the Section 88.24 state
   matrix. Buttons are omitted when permission is absent and blocked with an adjacent explanation
   when current source state/freshness prevents the action.
8. Keep PII, supplier contacts, price/cost, credentials, unrestricted object identifiers and raw
   dependency errors out of logs, URLs, fixtures, analytics and page errors.
