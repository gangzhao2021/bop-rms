   transaction, compare selector and positive expected version and update only last-seen, idle

2. Validate hash, canonical UTC instants and exact four-hour idle duration before SQL. The update
   requires Active state, nondecreasing last-seen and strictly unexpired idle/absolute/closure
   bounds. Invalid input/dependency failure is bounded unavailable; absent/stale/denied update
   returns null. Never resurrect a terminal/expired Session or retry unknown commits.
3. Preserve explicit Brand/Store SQL predicates, transaction-local context, existing forced RLS,
   parameter binding and parsed scoped results. Returned version/time/selector must match the
   requested transition. No driver detail, raw credentials or unrestricted identifiers in errors.
4. Unit and real isolated PostgreSQL tests prove service Interactive versus Background behavior,
   reconnect, unchanged immutable fields, concurrency/version loss, backward time, half-open
   expiry, terminal states, cross-scope/RLS denial, rollback and unknown commit. Test role gains
   only UPDATE on the three allowed columns. Retain all WP-2209 HTTP acceptance.
