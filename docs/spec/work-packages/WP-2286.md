authorization and unified original-operation replay remain first. The existing same-assignment
reader/writer remains compatible. Only if the normal current-scope reader returns null may the
configured moved path resolve the current Session, latest capability and committed latest Move.
An absent provider, absent/currently ineligible facts, wrong scope or malformed data fails closed.

Validate complete captured Move command/digest/result/Audit/Event using its separately configured
Table hash contract, never the unrelated credential hash. Match current Session identity/start,
Brand/Store, Table/assignment and Move version no later than current Session; exact same versions
must carry identical Session facts. The prior capability belongs to the same Store/Session and a
different assignment. Staff evidence must match current eligible Table, Active Session and exact
command versions. The owner adapter binds Tenant explicitly on every read/write; existing public
TenantContext has no Tenant reference field and none is inferred from Brand or Store.

Generate a fresh current-pepper replacement at the new assignment and invoke WP-2285's policy.
The writer locks the shared scoped regeneration operation, current Table, Session and latest
capability in established order. Under these locks it verifies the latest committed Move and exact
current facts, recomputes the transition, updates only prior Active capability to Revoked, inserts
new capability and unified regeneration history linked to the same Session's Move, and appends
public current-Staff Audit in one transaction. Original retries converge; changed intent/Actor
conflicts. No raw credential is recovered from history or persisted.

Forward migration1001_007 adds numeric unique Move-result Session version indexing and a scoped
Session/Move identity index. A nullable move_operation_id on existing regeneration history has a
Tenant/Brand/Store/Session/Move foreign key. Legacy normal operations retain null and unchanged
record JSON. Existing migrations/history remain immutable. No new table or Domain owner is added.

Tests prove actual Move -> fresh generation -> Guest Join, stable existing Participant/Host,
old-credential denial, subsequent normal generation, several Moves between generations, current
authority/pepper/terminal lifecycle, concurrent retry/version conflicts, Closing/new-Move fences,
Audit rollback/lost acknowledgement, foreign scope/RLS/proof FK, closed data and owned cleanup.
