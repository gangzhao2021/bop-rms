# WP-2183 — API Client Scope, Credential Lifecycle and Audit

## Authority and scope

- Handoff Sections 48.3.2, 52.3–52.8, 56.12–56.13, 56.23, 87.5.2, 87.6 and
  88.17/88.21–88.30 define API Client identity, server-derived scope, credential handling and the
  canonical screen.
- Exact local predecessor: verified WP-2182 commit `580d71e`.
- `@bop/identity` owns API Client identity, lifecycle and credential-reference metadata. Tenant owns
  Brand/Store scope; Permission owns grants; Approval/Audit own decision and audit facts; the managed
  secret service owns credential value issuance/rotation. Identity stores stable references only and
  cannot self-grant business permissions.

## Acceptance contract

1. API Client is Tenant/Brand scoped with optional bounded Store scope, safe name code, owner
   reference, environment `Sandbox | Production`, lifecycle `Requested | PendingApproval | Active |
Suspended | Revoked`, version and created/updated facts. Physical deletion is forbidden.
2. Requested scope/grants are closed, bounded, least-privilege codes. Activation requires an exact
   current Permission grant-set reference and independent Approval evidence; Identity never evaluates
   or creates the grant itself.
3. Credential value/secret/token/private key never enters Domain input, persistence, response, log,
   URL, fixture or analytics. Identity stores only managed-secret reference, credential version,
   issued/expiry/revoked metadata and last-use timestamp. Rotation goes through the secure credential
   port, preserves Client identity and invalidates the superseded version per accepted workflow.
4. Request, submit approval, activate, suspend, rotate and revoke require exact permission, purpose,
   Tenant/Brand/Store scope, expected version, idempotency and append-only Audit evidence. Revoke is
   terminal; correction uses a new Client.
5. `INT-API-CLIENT` `/app/integrations/api-clients` exposes safe name/owner/scope/grant/environment/
   status/credential-age/expiry/last-use/audit-reference metadata, bounded filters and explicit
   loading/empty/denied/not-found/feature-disabled/offline/stale/conflict/error states.
6. This WP creates no public API endpoint, OAuth authorization server, JWT/token format, runtime
   credential, secret-manager object, Provider account, external grant, production enablement or new
   Event. Those require separate accepted contracts and evidence.
