## Acceptance and design

Add an owner-level joinCurrent command accepting closed guestSessionReference, joinCredential,
operationReference and requestedAt. Read versions from the existing single coherent owner Session/
Capability snapshot only after the same abuse and current ContextOnly Guest gates. Never accept
client-supplied versions in this new command. Keep original explicit-version join unchanged.
Both commands share exactly the existing owner validation, original-operation identity/recovery,
current scope/Table/assignment/lifecycle fences, and atomic writer. No duplicate abuse admission,
extra preflight read or broad raw capability exposure.

Owner-selected versions are still exact expected versions passed into atomic persistence; a state
change after the read must fail rather than bypass optimistic concurrency. This is a command
convenience for an explicit Guest Join, not a lease or guest self-start. Original same-Guest/
capability operation recovers the original participant/admission without duplicate effects;
current authority and state are checked before historical results. Existing explicit stale-version
behavior and all Staff/regeneration commands remain unchanged.

Capture closed inputs before asynchronous work. Unknown/wrong/expired/moved/Closing/cooldown
states remain uniformly unavailable. No raw join credentials in history, errors, URLs or results;
no Identity rotation, public mapping, HTTP/UI activation or Ordering power is added here.
