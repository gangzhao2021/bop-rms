## Scope and acceptance

Add a closed four-field internal consume command: guestSessionReference, admissionReference,
operationReference and requestedAt. Resolve and validate current exact ContextOnly DineIn Guest
before owner facts or operation history; enforce bound Store and current internal Table context.
Capture a coherent owner snapshot containing current Session/Participant/admission/Table and the
complete immutable original Join plus its Guest reference. Validate original record grammar,
original Guest/Join digest, immutable current identities, scope and chronology. Current eligible
Dining facts are required even on original operation recovery.

Use WP-2288 for the proposed transition. A distinct consumption operation digest binds exact
Guest and admission; original admission operation/hash remain the original Join. Closed immutable
consumption records contain operation reference/hash, Guest reference and terminal admission.
The writer receives the complete captured snapshot and proposed record; it must eventually
revalidate under shared locks and append consumption history and SystemRestricted Audit atomically.
Define explicit Applied/AlreadyApplied writer receipts and validate the actual returned record.
Original retry retains consumedAt; changed intent conflicts; consumed admission without the same
operation cannot issue another result. Missing/malformed/currently denied facts fail closed.

No raw credential is generated or returned. This application protocol is not a persistence lease,
Identity evidence or a public route. Tenant remains explicit in the future owner adapter; application
scope binds Brand/Store. Public Table mapping and validUntil require separate authoritative
composition, and no TTL or public/internal Table equivalence is inferred.
