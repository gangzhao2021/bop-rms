## Owning facts and boundary

Catalog owns `RMS-CAT-BUNDLE` as a Brand-scoped, versioned sellable Aggregate. A Bundle owns its
localized content, component groups, choice bounds, eligible Product/SKU references, upgrade rules,
price mode and publication lifecycle. It references published Sellables and Option Set versions
through Catalog public facts; it never reads Pricing, Availability or Menu private tables.

Nested Bundle depth remains zero under ADR-0021. Published versions are immutable. Correction is a
new Draft/version; suspension, discontinuation and archive preserve history. Money is a currency plus
integer-minor-unit string. UTC instants are stored explicitly; Store/channel effective resolution is
owned by the existing Availability/Menu contracts.

## Public contract

- Commands: `CreateBundleDraft`, `ReplaceBundleDraft`, `ValidateBundleDraft`,
  `PublishBundleVersion`, `SuspendBundle`, `DiscontinueBundle`, `ArchiveBundle`
- Every write carries Tenant/Brand, Actor, purpose, `catalog.bundle.manage`, Expected Version where
  applicable, idempotency reference, UTC request time and append-only Audit input.
- `PublishBundleVersion` additionally requires Pricing approval when a fixed or upgrade money field
  is present, a stable validation digest and exact referenced published Sellable/Option Set facts.
- Events: `BundleDraftCreated:v1`, `BundleDraftReplaced:v1`, `BundleVersionPublished:v1`,
  `BundleLifecycleChanged:v1`; emitted through the
  transaction Outbox with Tenant/Brand scope and no localized content or unrestricted identifiers.
- Queries/projections: `query.cat_bundle_list`, `query.cat_bundle_editor`,
  `catalog_bundle_search_v1`, `catalog_bundle_detail_v1`, and published Bundle facts consumed by the
  Menu/effective-menu projection. Projection consumers are idempotent and rebuildable from facts.
- Stable errors: invalid input/reference, permission denied, version/idempotency/code conflict,
  lifecycle conflict and dependency unavailable. Unknown dependency or simulation facts fail closed.

## Screen contract

- `CAT-BUNDLE-LIST` at `/app/commerce/bundles`: name/code search; lifecycle, Menu and price-mode
  filters; create, duplicate, edit, validate, publish, suspend and archive actions.
- `CAT-BUNDLE-EDITOR` at `/app/commerce/bundles/{id}/edit`: identity, localized content, component
  groups, bounds, eligible Sellables, upgrade rule, price source, availability and history;
  Sellable/Option picker; save, validate, simulate and review/publish actions.
- Applicable states: loading, empty, permission denied, not found, feature disabled, stale, conflict,
  command failed and offline read-only. Server permission and version checks remain authoritative.
- Section 88.4 and 88.27–88.30 apply: reflow without horizontal workflow loss, keyboard-equivalent
  ordering, visible focus, associated validation, non-color state, localization/zoom/reduced-motion
  support and minimum touch targets. Analytics uses only allowlisted Screen/action/result codes.

## Acceptance criteria

1. Bundle parsing rejects nested Bundle references, duplicate identities, invalid bounds, malformed
   decimal/minor-unit money, unsafe localized markup and inconsistent price modes.
2. Simulation is deterministic, enforces each group bound and eligibility, uses exact integer money,
   and fails closed for missing/stale Pricing or Availability evidence.
3. Create/replace/publish/lifecycle operations enforce scope, permission, Expected Version,
   idempotency, append-only Audit and transactional Outbox behavior.
4. Publish requires exact reference validation and Pricing approval for money-bearing rules; Menu
   integration consumes only the published Bundle fact and cannot mutate the Bundle.
5. Both Screen IDs expose the complete permission/state/responsive/accessibility contract with
   synthetic, privacy-safe behavior tests.
