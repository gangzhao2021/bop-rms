## Acceptance and design

Add an independent stateless browser Join client. Closed own-data input captures operationReference,
csrfToken and joinCredential before awaits. Transport framing accepts canonical six ASCII digits or
22-character128-bit base64url; Dining remains policy authority. Fixed relative POST
/bff/customer/dining/join with same-origin credentials, no-store, redirect error and no-referrer.
No Cookie access, browser storage, CSRF setter, automatic retry or inferred success.

Bound response headers and body by a configurable1..15000ms deadline and4096 actual UTF-8 bytes.
Cancel late/rejected response bodies. Parse exact Joined/operationReference/admissionReference with
canonical UUIDv7 references and exact operation echo. Only exact HTTP400/503 Join errors are known;
other malformed/wrong-purpose/network outcomes remain bounded unknown. Offline never sends.
Returned admission is short-lived caller memory, not rendered or persisted authority.

Replace WP-2305 synthetic direct fetch at the actual PostgreSQL/HTTP boundary with this production
client and an explicitly synthetic Cookie/Fetch Metadata adapter. Lost acknowledgement is unavailable;
explicit same-input retry recovers original admission, then existing binding coordinator rotates once.
Retain actual response assertions with response clones and existing one-Join/one-consumption history.
This is not browser/TLS/production Store evidence.
