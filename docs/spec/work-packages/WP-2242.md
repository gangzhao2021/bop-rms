# WP-2242 - Version-Pinned Catalog Selection Display

## Authority and readiness

Owner authorizes continued implementation and verified local commits. Baseline3929e96,
branch codex/wp-2242-selection-display. Composite Sections0–97 remain unchanged. WP-1025/1026,
WP-1201/1202/1205, WP-2219 and WP-2241 supply the accepted Catalog snapshot, Cart selection evidence,
scoped reader and safe display boundaries. BC-02 remains incomplete.

Cart Items retain Menu/Product/OptionSet versions but no display names. Current menu queries cannot
provide faithful historical names after a publication change. Add an internal public Catalog query
for display-only names from the exact pinned Menu/Product/OptionSet evidence. It grants no current
availability, price, allergen safety, selection validity or transaction authority. Ordering must
first authorize the Cart and supply its own saved evidence. No new browser endpoint is introduced.

Extend the existing scoped Catalog projection adapter with a separate version-candidate method over
Active or Retired generations; Building generations never qualify. Retain the current checkpoint
reader unchanged. Require exact Brand, Store applicability, Menu version and source checkpoint
integrity. No foreign/private authoring tables, writes, history changes or invented fallback names.
The public query additionally checks channel/order type, Product and all saved active-rule versions
(the WP-1202 evidence subset, without requiring inactive conditional rules),
selected option membership, localized names and consistency across matching historical candidates.
Ambiguous display evidence fails unavailable; absent matching evidence returns NotFound. Historical
names never imply current eligibility. Public product disclosures remain internal and are omitted
from the result, along with scope, credentials, evidence digests and other unrelated fields.
