## Acceptance and design

Add a distinct Dining-owned GuestSessionBinding query and read-only PostgreSQL adapter. One coherent
scoped read supplies current Session, Participant, Table and its unique original consumed Identity
admission. Exact Tenant/Brand/Store/Session/Participant relations, Active Participant, eligible Table,
current assignment, consumed admission, original admission Table/assignment and canonical timing
must agree. Preserve the original assignment check even if a Session moves away and back to the
same Table. Query inputs are closed and captured before awaits; returned facts are narrow/frozen,
contain no Guest credentials, original Guest lookup authority, capability, hash or raw private history.

Allow Active and Closing identity continuity, never Closed/Cancelled. Closing still denies new
Cart/Batch writes through existing Active-only gates; do not reuse the Cart purpose as Identity
proof or prevent an otherwise-current Host from cancelling Closing. These are current read facts,
not permission, a write lease or a persisted revocation. Require independent current Identity
Session/CSRF authority; rotated candidate Guest IDs are not compared to original Join Guest IDs.

Require this public Dining reader in API binding composition for DiningBound Sessions, in addition
to the existing current Session binding policy and Dining-owned public-context validation. Verify
exact Session/Participant and expected internal Table through owner contracts. No recursive
Identity authorization in its own binding callback, no shared request state and no private cross-
domain SQL. ContextOnly admission preparation/consumption keeps its existing current gates.
