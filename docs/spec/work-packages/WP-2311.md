## Acceptance and design

One current mounted client generation owns pending entry results. Both start and explicit retry
handle synchronous throws and asynchronous rejections through the existing ServiceUnavailable state.
Late results from replaced clients or unmounted screens never update UI or publish established context.
Duplicate in-flight retry does not launch extra work. Callback identity changes use the latest callback
without restarting the client. StrictMode cleanup preserves only the current generation's authority.
Preserve missing/offline/invalid/closed states, menu navigation, contextual Dining admission, current
server authority and privacy. No background retry, storage, raw error rendering or new route.

Use deterministic demo-only deferred clients to exercise actual React lifecycle in desktop/mobile
Chromium. Verify stale initial and retry completions after unmount/replacement, rejection and throw,
latest callback, duplicate retry and retained navigation. Synthetic controls must be absent from
production builds; no credentials or operation payload in URLs/artifacts. Existing browser suite,
real database-backed Dining lab and all owning verification remain required.
