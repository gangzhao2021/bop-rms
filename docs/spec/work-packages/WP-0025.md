## Accepted repository contract

- Restore never targets an existing database instance and never overwrites、renames、adopts or repairs an existing environment。
- Source、restore point、AWS account / Region、target identifier、network、KMS key、IAM authority、data classification、expiry and cleanup approver must be externally verified before mutation。
- The restored target remains private、isolated from Customer / Provider traffic and unavailable to normal application runtimes until all verification gates pass。
- Staging must not receive an unmasked production restore。A source containing production or unnecessary PII is a hard stop rather than permission to copy it。
- Repository verifiers run read-only against the restored target through the accepted Section 94 password-file and `verify-full` TLS contract。No `apply`、DDL、repair、baseline、force、mark-applied or checksum bypass is part of recovery verification。
- Evidence records bounded safe references、UTC timestamps、measured durations、result codes and cleanup state。It never records credentials、DSNs、SQL、row contents、unrestricted object IDs、PII、payment、health / allergy or Provider payloads。
- A repository change cannot claim AWS、RDS、KMS、PITR、backup、restore、RPO or RTO evidence。Only observed results from the separately authorized target may be recorded as such。

## Risks、rollback、External Evidence and non-goals

Primary risks are wrong-target restore or deletion、PII propagation、credential or DSN disclosure、unsafe public/network access、KMS / Region incompatibility、restore verification that mutates history、old-backup resurrection of deleted data and a false production RPO / RTO claim。The runbook controls these through explicit target evidence、new-target-only recovery、traffic fencing、read-only verification、bounded evidence、privacy stops and separately approved cleanup。

Repository rollback is a normal reviewed Git revert before integration。No migration or database state is changed by the allowlisted implementation。A real restored target is never “rolled back” through broad deletion；it is quarantined and removed only through the exact approved cleanup action for that observed target。

External Evidence remains gated and unclaimed：actual AWS account / Region、RDS PostgreSQL 18.4 support、Multi-AZ / PITR / backup retention、KMS keys、IAM roles、private network path、TLS CA、source classification、backup identity、restorable window、restore result、measured duration、cleanup result、cost approval and professional security / privacy review。

AWS public-documentation preflight on `2026-07-21` confirms that Amazon RDS publishes PostgreSQL `18.4` and automated-backup replication support for currently available RDS for PostgreSQL versions。Authenticated per-account、per-Region、engine/class、KMS、network and target evidence remains mandatory and unclaimed。
