## Bounded contract and acceptance

Add a dedicated pure Public Capability transition for a fresh Join generation after a committed
Dining Move. Existing same-assignment regeneration remains unchanged. A closed assignment fact
carries Move operation, Store, Session, target Table, assignment version, resulting Session version
and movedAt. This is data, not an authorization token or proof of storage: a later Dining application
and owner transaction must obtain and verify it against committed Move history/current Session,
current Staff permission and exact Tenant/Brand/Store scope before invoking this policy.

Require same Store/Session/kind, a changed Table/assignment pair, replacement matching the supplied
assignment, exact next generation, fresh reference/hash, version1/Active, current configured pepper
metadata and canonical issuance at the observation time within the existing15-minute lifetime.
Move time cannot be later than issuance. Table assignment versions are not globally ordered across
Tables; a lower version at a different target is valid. Returning to an earlier Table requires a
changed assignment. Several Moves can occur between generations; the prior credential need not
match the most recent Move's source Table.

Prior Active becomes Revoked with version increment; Consumed/Expired remain immutable and cannot
have future terminal times. Revoked remains denied. Neither old expiry nor old scope is rewritten.
All inputs are parsed/copied/frozen, unknown or malformed shapes and numeric overflow fail closed.
Only synthetic policy tests run; this WP does not claim the facts are backed by a current database
read or grant Staff/Guest authority. Dining service/storage composition is the next owning WP.
