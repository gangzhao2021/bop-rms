## Bounded design

Add a Catalog-owned opt-in adapter implementing the existing CustomerMenuQueryPorts projections
port. Bind trusted Brand and Store at construction; reject mismatching requests before database
access. An injected runner owns a dedicated read-only transaction/connection and cleanup. Set only
transaction-local Brand context and clear Store context as required by the existing Brand-only RLS,
while Store applicability remains an explicit SQL/query parameter. Then use one parameterized read statement for an atomic
checkpoint/generation/header/section/sellable snapshot. Never query authoring or foreign tables.

The active checkpoint selects one generation per Menu. Require matching Brand/Menu/generation and
source checkpoint/version, preserve freshness metadata, and strictly parse each hydrated result.
Missing/corrupt selected content, unsafe versions, dependency faults and scope drift fail with the
existing bounded CATALOG_DEPENDENCY_UNAVAILABLE error without raw cause/SQL/data. Public Store
resolution, Channel/OrderType/effective/localization/visibility/freshness and ambiguity policies stay
in the existing query service. Empty results remain empty; no fabricated fallback or prices.

This is a read-only public-menu purpose with anonymous customer access after trusted Store resolution.
No Actor mutation, command/version/idempotency write, audit/event/outbox emission or source-fact change
occurs. UTC instants and existing IANA zone metadata are preserved; pricing remains explicitly unavailable.
Allergen fields are public product disclosure snapshots, never personal health facts.
