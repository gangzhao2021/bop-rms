## Scope and contracts

Ordering composes a safe view of an authorized, active, unquoted Cart: Pickup nonempty Carts and
changed-empty Carts. Nonempty DineIn remains unavailable because Guest Session binding alone does
not establish Host/Participant visibility of shared contents and restricted notes (Section 24.5). Require an explicit fixed-scope database proof that the supplied Cart version
is still current and no Quote attachment exists. Lock the Cart before querying attachments; missing,
stale, mismatched or already-quoted state is unavailable. Never hide a stored Quote behind null.
The proof is read-only and contains no Quote amounts or unrestricted history.

Read names/configuration through Catalog's existing public Customer Menu Query. Bind public Store,
locale, channel/order-type codes, effective instant, freshness, Menu/Product versions and selected
Binding/Option Set evidence. Reject missing, ambiguous, stale or malformed source data. Never send
Customer Note, Guest credentials, Actor, Cart or Item identifiers to Catalog. Public menu pricing
is explicitly not integrated; preserve its unavailable-price semantics without inventing zero,
estimates, taxes or totals. Quote remains null only with database absence evidence.

Add an optional presentation dependency to the existing API composition for GET current/reference
reads only. Existing pristine creation and original creation replay behavior remain unchanged.
Identity Background reads do not renew the Session; foreign Cart references remain uniform 404.
Missing presentation retains existing fail-closed behavior. No Item HTTP writes are enabled here. Identical repeated Menu placements may share one Cart
line view; conflicting displayed facts fail closed.

Non-goals: Item HTTP composition, Pricing/Quote integration, lifecycle mutations, browser/UI/Screen
changes, real Store/Catalog publication, runtime activation, Order/Payment/Worker or external evidence.

## Acceptance

1. Safe view preserves persisted quantity/configuration/notes, exact public names and unavailable

   Catalog/display sources remain explicitly labelled test evidence, not real Store readiness.
4. Frozen install, affected format/lint/typecheck/tests/build, ownership and complete local verify
   pass; default runtime, existing routes and publication authority remain unchanged.
