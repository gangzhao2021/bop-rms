# WP-2182 — Provider Adapter Admin, Webhook / Retry / Kill Switch Evidence

## Authority and scope

- Handoff Sections 42.18, 52.18–52.19, 56.12–56.13, 56.23, 58.25–58.26, 86.8–86.9 and
  88.17/88.21–88.30 define Provider anti-corruption boundaries and the two canonical screens.
- Exact local predecessor: verified WP-2181 commit `3c121a6`.
- The admin surface is a rebuildable, permission-trimmed integration Projection. Payment, Identity,
  Notification, Storage, Delivery and other owning modules retain Provider configuration, webhook,
  Inbox, retry, Kill Switch, credential-workflow and incident facts. The Projection never becomes a
  generic Provider Aggregate or cross-domain mutation path.
- Accepted first-Pilot Providers are AWS Canada/Cognito/S3/SES and Stripe Canada/Terminal. Disabled
  candidates and Future Triggers remain unavailable unless their accepted IDR/evidence gate changes.

## Acceptance contract

1. `provider_integration_admin_v1` is a strict Brand/Store-scoped rebuildable Projection containing
   safe Provider/adapter code, owner module, capability, environment, lifecycle/effective enablement,
   contract/version/region, Store scope, last success/safe error, webhook/endpoint health, bounded
   rate/quota/retry/DLQ summaries, credential age/expiry metadata and stable evidence references.
2. No raw Provider payload/message, SDK object, endpoint URL, account identifier, signature, secret,
   token, PAN/payment method, Customer/Employee identity or unrestricted object identifier is allowed.
3. Enable intent is emitted only when the accepted Provider/region/environment/Store policy and
   required evidence gates are explicitly satisfied. Unknown or disabled Providers remain blocked;
   UI visibility never authorizes execution.
4. Disable/Kill Switch, sandbox test, credential rotation, eligible Inbox replay and incident intents
   name the owning module, permission, purpose, expected version, idempotency and audit boundary.
   They never directly edit another Domain table or infer an external outcome.
5. Webhook signature/replay/Inbox facts remain Payment/Eventing-owner summaries. Replay is eligible
   only for an authenticated, deduplicated durable Inbox item under its existing contract; raw payload
   is never displayed or accepted by this surface.
6. `INT-PROVIDER-LIST` `/app/integrations/providers` and `INT-PROVIDER-DETAIL`
   `/app/integrations/providers/:id` expose exact Section 88 fields/actions, bounded filters and
   loading/empty/denied/not-found/feature-disabled/offline/stale/conflict/error states.
7. No new Provider, credential, webhook route, Event, database table, SDK, external call, feature
   enablement or production/live evidence is created by this WP.
