## Purpose and boundaries

Add the Catalog-owned public `Validate Selection` contract and require Ordering Add/Update Cart
Item Commands to consume it before mutation. Catalog resolves the current Sellable configuration
for the exact Brand, Store, source channel, order type and UTC instant; validates enabled Options,
per-Option and total quantities, binding min/max, conditional trigger activation and conflicts; and
returns version-pinned Menu, Product, Binding and Option Set evidence. Ordering verifies the result
is an exact echo of its server-owned context and requested selection, then stores that evidence on
the Cart Item. Remove does not need a fresh Catalog decision.

Out of scope: price/tax/Promotion, Quote attachment (WP-1203), Cart expiration (WP-1204), HTTP/PWA
(WP-1205), Checkout, Order snapshot, Catalog authoring/private-table access, Inventory/Recipe,
allergen/legal correctness, real Store/Menu facts and External Evidence.

## Adopted decisions and hard stops

1. Catalog owns selection validity; Ordering consumes only the public contract and never reads
   Catalog persistence.
2. A current snapshot must exactly bind Brand, Store, source channel, order type, Sellable and
   observed UTC instant. Missing, stale, unavailable, mismatched or malformed evidence rejects.
3. Selection is a unique Option-reference list with positive integer quantities. Every selected
   Option belongs to exactly one active Binding rule and remains within per-Option and total limits.
4. Always-active rules and selection-triggered rules enforce exact min/max. Inactive triggered
   rules cannot receive selections. Selected conflicts reject.
5. Accepted evidence pins Menu Version, Product Version and each active Binding + Option Set
   Version. Add/Update stores the exact evidence; idempotent replay returns the original result
   without consulting a changed Catalog snapshot.
6. The forward migration keeps pre-WP rows representable with nullable validation evidence, while
   every WP-1202 Add/Update result requires complete evidence. Later Checkout must reject legacy
   unvalidated rows rather than infer facts.
7. Money and client price are absent. Catalog validation does not calculate price, tax or Promotion.
8. Hard stop: foreign private-table access, cross-scope evidence, disabled/unknown/conflicting
   Option, unsatisfied/overfull rule, stale/missing Catalog authority, invented current Store/Menu
   fact, sensitive telemetry, or files outside the exact allowlist.
