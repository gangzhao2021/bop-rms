# WP-2191 — Brand Configuration, Store Membership and Inheritance

## Authority and scope

- Handoff Sections 42.3–42.4, 44.6.2–44.6.3, 48.3.3, 52–58, 67–72, 87.5–87.7 and
  88.7/88.21–88.30 define Brand ownership, immutable published configuration, bounded overlay
  inheritance and the canonical screens.
- Exact local predecessor: verified WP-2190 commit `d148d38`.
- `@bop/tenant` owns Brand identity/lifecycle and Store-to-Brand membership. Each business Domain
  owns its configuration values and merge/validation semantics; Publishing owns publication facts;
  Media/Catalog own referenced assets and catalog snapshots; Permission/Audit own authorization and
  evidence. Tenant coordinates stable references and inheritance policy only.

## Acceptance contract

1. Preserve the existing CAD Brand Aggregate and immutable Store Brand identity. A Store may be
   added/removed from Brand administration through append-only effective membership evidence, but
   this WP cannot silently move a Store across Brands or rewrite historical Store scope.
2. Brand configuration versions contain default locale plus bounded supported locales, Media/theme
   references, Catalog source reference, configuration-source references, effective period,
   override-allowed field codes, base compatibility, reason, author/approver and supersession.
   Published versions are immutable; correction creates a new version.
3. Inheritance is explicit `PlatformTemplate -> BrandBase -> StoreOverride -> RuntimeContext` with
   Value Reference + Source + Effective Period. Tenant stores no foreign Domain value and performs no
   generic merge. Store override is allowed only for Brand-declared fields, must name a compatible
   base version and cannot weaken a Platform Hard Requirement; ambiguous same-priority resolution
   fails closed.
4. Create/edit Draft, submit/independently approve, publish/schedule, activate/archive and Store
   membership commands require exact Brand scope, permission, purpose, expected version,
   idempotency and append-only Audit/operation evidence. Submitter cannot approve; external
   Publishing/Media/Catalog results are validated references, never inferred.
5. Public query contract `brand_admin_v1`, `ORG-BRAND-LIST` `/app/organization/brands` and
   `ORG-BRAND-DETAIL` `/app/organization/brands/:id` expose safe identity/status/locale/Store count/
   Catalog source metadata, Media/theme refs, effective membership, visible inheritance source and
   history. Loading/empty/denied/not-found/feature-disabled/offline/stale/conflict/error states and
   responsive/accessibility behavior are explicit.
6. This WP creates no Store setup/service configuration, capability/Feature Flag, Catalog/Media
   object, foreign configuration value, production publish, Provider, new Event or cross-Brand move.
   Those remain owner-Domain or later WP-2192/2193 responsibilities.
