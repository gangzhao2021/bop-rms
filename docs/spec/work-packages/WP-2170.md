## Acceptance contract

1. A closed `compliance_dashboard_v1` Query pins Tenant/Brand/optional Store scope, generated and
   source-as-of instants, completeness/freshness disposition and a stable projection version.
2. Dashboard signals are bounded to Open Case, Expiring License/Permit, Overdue Corrective Action,
   Unverified Finding, Temperature Excursion, Missing Cleaning Record, Employee Qualification
   Expiry, Allergen Publication Block and Recall Scope. Each item exposes only an opaque owning
   reference, type, exact `Observation | Minor | Major | Critical | ImmediateDanger` severity,
   due/overdue state, evidence-required/present counts and an authorized navigation target.
3. Evidence coverage uses non-negative decimal-string counts and derives exact complete/missing
   totals without inventing Evidence. Due state is derived from UTC instants at the pinned Query
   observation time; severity and due are independent and sorting is severity, due, then stable ID.
4. Query execution revalidates Tenant Context, Actor, `compliance.dashboard.view` permission,
   purpose, scope and Projection freshness. Cross-Store leakage, restricted incident/allergy
   details, contacts, health facts, authority payloads and raw Evidence are rejected from the
   Dashboard contract.
5. `CMP-DASHBOARD` exposes canonical Store/scope, case type, severity and due/overdue filters,
   fields for open cases, expiring permits/qualifications, temperature/cleaning exceptions,
   allergen/recall blocks and Evidence completeness, plus permission-gated owning-record navigation
   and alert acknowledgement. All universal loading/error/offline/stale/empty states are explicit.
6. The Projection is explicitly rebuildable and read-only. Acknowledgement is navigation-alert
   presentation state only; containment, quarantine, Kill Switches, qualification suspension,
   Case changes and Regulatory Records remain owning-Domain Commands in later WPs.
