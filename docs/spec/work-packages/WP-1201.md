## Purpose and boundaries

Add Ordering-owned application Commands that add, update, and remove Cart Items for an authorized
Customer Guest Session. Every mutation binds the exact Brand, Store, Cart, order type, session and,
for dine-in, Dining Participant; requires the caller's exact Cart aggregate version; records one
restricted Audit input in the same repository commit contract; and uses a 24-hour idempotency
operation with an intent digest and the original result. The same operation and intent returns that
original result without a duplicate mutation, while a changed intent fails closed.

Add accepts Sellable reference, integer quantity, Option selections, and a bounded Customer Note.
Update may change only quantity, selections, and note. Remove removes one authorized Item. Stable
Item identity, Sellable, creator/session, Participant, and added time remain immutable. Customer
Note is restricted PII and possible health text; it is prohibited from logs, URLs, analytics,
screenshots, Audit summaries, and non-synthetic fixtures.

Out of scope: staff/POS mutation, public HTTP/PWA transport (WP-1205), Catalog Sellable and Option
validity (WP-1202), Quote/price attachment (WP-1203), expiration and abandonment cleanup
(WP-1204), Checkout/Order, Events/Outbox, client price, foreign private-table reads, and real
business evidence.

## Adopted decisions and hard stops

1. Ordering owns Cart mutation. Identity supplies the public Guest Session contract; Audit supplies
   its append contract. No foreign Domain private table is read or written.
2. Pickup Items can be mutated only by the exact Guest Session that created the Cart. Dine-in Items
   can be mutated only by their exact bound Participant in the Cart's Dining Session.
3. Optimistic concurrency is exact: every successful Command advances the Cart version once;
   stale versions return `CART_VERSION_CONFLICT`.
4. Idempotency is exact for 24 hours. The same operation, Actor/session, Cart, action and canonical
   intent returns the original result; changed or expired reuse returns `CART_IDEMPOTENCY_CONFLICT`.
5. The repository commit boundary includes Cart state, append-only operation result, expected
   version and validated Audit input. Adapters must commit these atomically.
6. Money is absent. Any extra field, including client price, is rejected before mutation.
7. Store RLS is forced on the operation table. Cart and operation scope, Item attribution, note
   bounds, operation retention, and append-only history are enforced in Domain/database evidence.
8. Hard stop: missing/mismatched Guest Session or Audit authority, cross-Store/Cart/Participant
   mutation, stale version, operation-key intent change, unvalidated price/Catalog claim, sensitive
   telemetry, external evidence claim, or any tracked file outside the allowlist below.
