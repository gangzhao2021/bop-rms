## Purpose and boundaries

Expose the existing Ordering Cart command/query boundary through strict same-origin Customer HTTP
contracts and integrate the `/cart` PWA with an in-memory, server-authoritative state machine. The
API transports create/current/read/add/update/remove intent only; it never accepts Brand, Store,
Actor, price, tax, total, lifecycle deadline or Quote result from the browser. The public Cart view
may compose only an Ordering-owned safe Query DTO supplied through the injected application port.

The PWA reads the current Cart through a session-bound BFF query, renders Cart Version, service
mode, items/configuration, server line estimates, warnings, Quote summary and expiry, and sends
mutations with the server Version and one retained in-memory Idempotency Key. Conflict refreshes
canonical state. Offline is read-only and never queues or automatically replays a mutation.

Out of scope: concrete repository/runtime composition, Service Worker or private caching, Menu and
Configurator UI (WP-1701/1702), atomic clear command, Checkout (WP-1220+), real policy values,
analytics backend, visual production sign-off and External Evidence.

## Adopted decisions and hard stops

1. Canonical resource routes are `POST /api/v1/carts`, `GET /api/v1/carts/:cartId`, and the
   Section 52 item routes. `GET /bff/customer/cart` is the same-origin session-bound current-Cart
   Query needed for the clean `/cart` route and refresh convergence; it performs no mutation.
2. Guest credential comes only from the exact HttpOnly Cookie. Mutations additionally require
   same-origin fetch metadata, JSON where a body exists, an in-memory CSRF credential,
   Idempotency-Key and quoted `If-Match` where the Aggregate already exists.
3. Create and item commands carry no client price, tax, amount, Brand, Store, Actor, lifecycle or
   Quote fact. Unknown keys, accessors, malformed identifiers and non-canonical versions fail
   before the application port.
4. API output is runtime-validated, no-store, field-minimized and never exposes Customer credential,
   internal Brand/Store identifiers, Catalog evidence digests, Audit data or unrestricted notes in
   errors. Missing/unauthorized Cart is a uniform `404`.
5. PWA transaction state remains in memory. It does not use Web Storage, IndexedDB, Cache Storage,
   a Service Worker, background sync or reconnect replay. The exact operation key remains available
   for explicit foreground retry only.
6. `409` preserves draft input and refreshes canonical Cart; `422`, `429`, session loss, not-found,
   unavailable, Quote-expired and offline states remain distinct and accessible.
7. Checkout and atomic clear remain visibly disabled with a reason until their owning Domain
   commands exist; the UI does not simulate them through partial client-side operations.
8. Hard stop: credential persistence/exposure, client-derived money or success, cross-origin
   credential flow, background mutation replay, silent last-write-wins, invented policy/business
   fact, foreign private-table access, or files outside the exact allowlist.
