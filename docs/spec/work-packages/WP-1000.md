## Purpose

Add the smallest provider-neutral、synthetic `@rms/store` Public Query contract that proves:

1. a safe public Store reference can resolve one exact Brand/Store scope without accepting an
   internal Store ID、name、address、route parameter or QR payload as authority；
2. only an active Tenant-owned Store with one published、currently effective Store Profile can be
   returned；
3. the returned profile contains only an exact Public-classification allowlist and rejects unknown
   or extra source fields；
4. requested-locale selection is deterministic from an explicit supported-locale set and immutable
   localized content, with exact fallback to the declared default locale only；
5. an optional logo uses a pinned immutable Media Asset Version reference and never exposes binary、
   signed URL、storage locator or upload authority；
6. malformed input is distinct from a valid-but-unavailable Store, while every existence、
   lifecycle、scope、publication、effective-period、media and dependency failure is externally
   uniform；
7. evaluation uses an explicit canonical UTC instant and never the host clock；and
8. telemetry is bounded to stable operation/outcome/reason codes and excludes public references、
   Tenant scope、names、addresses、contacts、locale values、media references and source digests.

WP-1000 establishes only `GetPublicStore`. WP-1001 owns Operating Hours and Store Operating Status；
WP-1002–1004 own QR resolution、Customer Session context and invalid/expired QR behavior. The
canonical `CUST-ENTRY-CONTEXT` Screen remains Section 88 authority, but this WP adds no route or UI.

## Ownership and Domain boundary

`@rms/store` owns the Store Profile Query contract、the immutable public-profile source shape、
allowlisted public-field validation、locale selection and query result/error semantics. It does not
own Brand/Store identity、publication lifecycle、effective timing or Media lifecycle.

- `@bop/tenant` remains the sole owner of Brand/Store identity、scope and lifecycle.
- `@bop/publishing` remains the sole owner of Release status and immutable Release evidence.
- `@bop/effective-period` remains the sole owner of timing validation and unique effective-version
  resolution.
- `@bop/media` remains the sole owner of Asset/Asset Version state and access capability.
- collaborating facts enter only through public contracts or injected exact-shape ports；Store
  never reads another Domain's private table.
- no cross-Domain write、shared ORM entity、private schema join or database trigger is permitted.

The query result is a read-only customer-safe projection. It grants no Permission、Customer Session、
QR capability、ordering authority or Merchant access.

## Adopted decisions

1. **Package and layer —** create exact RMS package `@rms/store` with module name `store` and
   lifecycle `Phase 1`.
2. **Query only —** implement a pure Public Query service over injected evidence. No Command、
   mutation、expected-version write、idempotency ledger、Audit append、Event、Outbox or Inbox is
   required because this WP changes no fact.
3. **Public reference —** input uses a strict UUIDv7 `publicStoreReference` distinct from the
   Tenant-owned Store ID. It is a lookup handle, never a credential or authorization grant.
4. **No internal lookup —** the contract never accepts Brand ID、Store ID、Store code、name、
   address、coordinates or unrestricted search as public input.
5. **Exact scope —** injected resolution evidence must bind one active Tenant-owned Store to its
   exact Brand and the requested public reference. Cross-Brand、mismatched or inactive facts are
   unavailable.
6. **Published source —** one source candidate contains immutable profile/reference/version、
   `sha256:` content digest、exact Tenant scope、Publishing Release evidence、Effective Period
   metadata and Public fields only.
7. **Unique current version —** explicit `evaluatedAt` resolves exactly one published effective
   candidate. Zero、overlap、conflict、future or expired candidates are externally unavailable；
   array order and “latest wins” are prohibited.
8. **Public field allowlist —** output may contain only:
   - public Brand and Store display names；
   - default and selected BCP 47 locale；
   - exact `CAD` currency code；
   - one IANA Store time-zone identifier；
   - public country/region/locality/postal/address lines；
   - optional public business phone and HTTPS website without credentials、query or fragment；
   - optional pinned logo Asset Version reference；
   - immutable profile version、release and content-digest evidence needed for cache/integrity
     composition.
9. **No operating truth —** weekly/exception hours、open/closed status、temporary closure、channel
   enablement、service mode availability、cutoff、lead time and Business Date remain WP-1001 or
   later Store configuration work.
10. **No legal/private data —** Legal Entity、tax、license、receipt registration、bank、employee、
    Customer、security contact、internal note、delivery range and exact coordinates are excluded.
11. **Locale —** caller supplies one normalized requested locale and explicit evaluation instant.
    Exact supported locale wins；otherwise the declared default locale wins. Language-only or host
    locale guessing is prohibited.
12. **Plain values —** localized names and address/contact fields are bounded typed plain strings.
    HTML、Markdown、script、control characters and unvalidated arbitrary objects are invalid.
13. **Media —** optional logo evidence must be `Pinned` to one Clean + Ready Asset Version and exact
    Tenant scope. Dynamic references、binary、URL、bucket/key、upload session and Provider metadata
    are prohibited.
14. **Uniform unavailable —** missing source、inactive scope、unpublished/archived Release、
    non-effective/conflicting version、invalid Media evidence、source shape drift and dependency
    exception all return the same public `StoreUnavailable` result with no existence detail.
15. **Malformed request —** invalid UUIDv7、locale、UTC instant or purpose returns the bounded
    `InvalidRequest` result without calling dependencies.
16. **Explicit purpose —** query purpose is the closed code `CustomerEntry`. This query is not a
    generic directory/export/search capability.
17. **Privacy classification —** every output field is explicitly `Public` under Section 87.10.
    Unknown/unclassified fields fail closed. Synthetic fixtures contain no real Store/contact fact.
18. **Telemetry —** labels are limited to `operation=GetPublicStore`、outcome and stable reason.
    Identifiers、names、address/contact values、locale/time-zone values、digests and Media references
    are prohibited.
19. **No cache/transport —** this package defines no HTTP route、CDN、ETag header、Service Worker、
    browser cache、rate limiter or abuse-control implementation. Later adapters must apply the
    Section 87 public-cache allowlist and WP-2042/2048 controls.
20. **No persistence —** no `rms_store` schema/table/view、migration、RLS、repository adapter、
    runtime grant or seed. Store configuration persistence remains later owning work.
21. **No API/UI —** no Customer PWA route、Screen component、navigation、search or Merchant
    authoring workflow.
22. **External Evidence —** no real Store、address、phone、website、hours、Media、publication、
    Customer traffic、load、staging or production evidence is available or claimed.
23. **Hard stop —** internal-ID lookup、unrestricted Store discovery、unpublished/ambiguous
    content、unknown fields、non-pinned Media、PII/private/legal data、operating-status claim、
    persistence、production API/UI、Provider/resource or allowlist-external tracked file stops
    implementation.

## Public contract

The implementation candidate defines:

- `GetPublicStoreRequest`
  - `publicStoreReference`
  - `requestedLocale`
  - `evaluatedAt`
  - exact purpose `CustomerEntry`
- `PublicStoreResolutionEvidence`
  - exact Brand/Store scope and active Tenant lifecycle evidence
  - immutable lookup-evidence reference and validity instant
- `PublicStoreProfileCandidate`
  - exact scope、profile/version/release references、content digest and classification metadata
  - immutable Publishing and Effective Period evidence
  - exact localized Public field map and optional pinned Media evidence
- `GetPublicStoreResult`
  - `Available` with one validated selected-locale `PublicStoreProfile`
  - `InvalidRequest`
  - uniform `StoreUnavailable`

The service calls each dependency at most once per query, validates exact closed shapes, resolves
one current candidate deterministically and returns immutable values. It never retries、mutates、
fetches external URLs or reveals dependency errors.

## Risks、rollback and next action

- Public profile scope creep could expose private Store、legal or operational facts；the exact
  field allowlist and classification check fail closed.
- A public reference could be mistaken for authorization；the contract explicitly grants only a
  published read and no later capability.
- Locale、Publishing、Effective Period or Media drift could create inconsistent output；exact-shape
  evidence and uniform unavailability prevent silent fallback.
- Rollback before merge is deletion of these two readiness files/edits. After merge, correction is
  a forward documentation/implementation change；accepted history is never rewritten.
- Next allowed action is implementation exact-head pinned-Linux CI followed by Section 91 review.
  Merge、post-merge verification and cleanup occur only after that exact SHA passes.
