## Closed receipt contract

Ordering owns a versioned immutable digital-receipt chain. Version one captures the actual
Operating Entity, Store, Order, tax, Payment/refund and template facts supplied by approved source
ports at issue time. Later Correction, Void, Refund and Reissue records append a linked version and
retain the original snapshot; they never regenerate an older receipt from current configuration.
Money is integer minor units with one currency for the complete snapshot.

Customer retrieval is side-effect free and requires either the exact usable Guest Session bound to
the receipt or a separately verified one-time resume grant. `orderReference` is a locator, never a
credential. A lost anonymous Session has no remote recovery path. Resume-token minting, hashing,
sibling revocation and delivery remain WP-1723. Manager reissue admission requires the future
merchant composition to prove a named authorized Manager, recent MFA and two matching transaction
facts; this WP exposes no weaker Customer-side bypass.

The Customer screen renders the immutable chain, actual merchant/Store snapshot, line/tax/total and
Payment/refund state, delivery status and support eligibility. Accessible browser print uses the
same accepted snapshot. Request-email/fresh-resume and cancellation/support are explicit unavailable
or eligible intents; the page does not pretend that WP-1720–1724 delivery is active.

## Acceptance and verification

- strict parsers reject open data bags, accessors, unsafe integers, mixed currency, broken links and
  non-monotonic versions;
- original facts remain byte-for-byte stable across Correction, Void, Refund and Reissue records;
- Customer query authorization binds exact Order, Brand, Store and Guest Session or an already
  verified single-use resume grant, and fails closed on dependency drift;
- the standalone receipt route covers loading, permission denied, not found, feature disabled,
  stale, command failed, offline read-only and successful accessible-print states;
- no order/payment/pickup secret, contact detail, raw Provider payload or resume token enters the
  route, DOM fixture, log, analytics or cache contract;
- affected tests, format/lint/typecheck/build, architecture, Screen Registry and security/privacy
  review are required locally.
