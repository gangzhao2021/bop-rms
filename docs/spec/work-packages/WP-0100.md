## Problem and bounded intended outcome

The repository has accepted Audit Actor references and future Tenant/Permission consumers but no owning Identity contract. Without one, later middleware could treat provider subjects、email addresses、browser values、Brand/Store IDs or role labels as interchangeable authorization identities.

WP-0100 establishes the smallest executable Identity boundary:

- one canonical、opaque Actor reference and closed Actor/account classifications;
- one provider-independent Authentication Session lifecycle and policy snapshot;
- strict construction/validation with privacy-safe stable failures;
- active-session resolution and idempotent revocation ports;
- closed minimal `SessionRevoked` and `CredentialCompromised` event facts;
- synthetic contract evidence proving that Identity cannot grant Tenant or business access.

This WP does not authenticate against a real Provider、store a Credential or Session、set a Cookie、resolve Tenant Context or evaluate a Permission. It creates no migration、database object、runtime integration、UI、AWS resource or production action.

## Ownership and boundaries

`@bop/identity` owns stable User/Actor identity and the provider-independent Authentication Session contract. It may authenticate or resolve who an Actor is; it cannot decide where that Actor may operate or what the Actor may do.

The public contract therefore excludes Brand、Store、Operating Entity、Membership、Role、Permission Grant、Tenant Context and object authorization. WP-0101 owns Brand/Store/Operating Entity; WP-0102 owns Membership/Store Assignment; WP-0103 owns Tenant Context; WP-0104 owns permission decisions; WP-0105 owns grants and explicit deny/allow. WP-0106–0109 own real integration scenarios、Cognito/BFF、PostgreSQL Session Store、CSRF、invite/MFA/recovery/revocation policy composition、Store switch and cross-Tenant evidence.

Provider subject、email、phone、username、Cookie value、Token、authorization code、state、nonce、PKCE verifier、client secret、TOTP seed and encrypted token bundle are never Actor references and do not appear in this public contract.

## Adopted Recommended Owner Decisions

1. **Module identity —** create exact Phase 0 BOP Module `identity` / `@bop/identity`, owned by the Identity Engineering Owner and generated through the accepted WP-0011 layout.
2. **Contract-only increment —** WP-0100 creates types、validators、ports、events and tests only. `bop_identity` schema/table creation and Session Store implementation remain WP-0107 because WP-0020 correctly default-denies business persistence until its owning persistence contract is explicit.
3. **No synchronous business dependency —** the module has no synchronous Module dependency in this WP. Audit/Event publication is a later composition through public ports; Identity never imports a foreign repository or private path.
4. **Actor classification —** reuse the accepted closed Audit vocabulary `User | System | Service`. `User` and `Service` require an opaque Actor reference; `System` has none.
5. **Actor reference —** a named Actor reference is an opaque lowercase UUIDv7 string. It is stable across Session rotation and contains no PII、provider identity or authorization fact.
6. **Account kind —** use `Customer | Workforce | Platform | Service | System` solely as identity separation. `Platform` is not a Platform Admin role and no account kind grants a permission.
7. **Actor shape —** valid pairs are User with `Customer | Workforce | Platform`, Service with `Service`, and System with `System`. Unknown fields and invalid combinations fail closed.
8. **Identity status —** public resolvable User/Service identity status is `Active | Suspended | Disabled | Merged`. Only `Active` may produce an authenticated Actor. Historical Actor references are never rewritten after merge/disable.
9. **Authentication methods —** the provider-independent closed methods are `Oidc | ServiceCredential | System`. Password、TOTP、Cognito and Guest capability details are not exposed as public Actor facts.
10. **Verification level —** use `SingleFactor | Mfa | RecentMfa` as a server-produced fact. `RecentMfa` requires an exact server UTC instant and is re-evaluated by the consuming policy; a client timestamp cannot grant it.
11. **Session reference —** a Session reference is a distinct opaque lowercase UUIDv7, never the raw browser Cookie、Token or database selector. Rotation creates a new reference and makes the former reference unusable.
12. **Session lifecycle —** use `Active | Revoked | Expired`. Resolution succeeds only for `Active` within both idle and absolute expiry and an active Actor; every other state returns a closed failure.
13. **Time contract —** all instants are canonical UTC ISO-8601 with exact milliseconds. `authenticatedAt <= createdAt <= lastSeenAt <= idleExpiresAt <= absoluteExpiresAt`; no Business Date or client clock participates.
14. **Policy snapshot —** a Session carries only the applied policy code、positive active-session limit and idle/absolute durations. Accepted profiles are `WorkforceStandard` (5、30m/12h)、`Privileged` (2、15m/8h) and `NamedKdsOperator` (5、60m/12h). Role/Membership policy selects a profile later; Identity does not infer it.
15. **Revocation reasons —** the closed reasons are `Logout | GlobalLogout | MembershipDisabled | RoleRemoved | StoreAssignmentRemoved | CredentialReset | CredentialCompromised | Recovery | ConcurrentLimit | RiskChange | Administrative`. The command requires Actor/purpose/reason/correlation/idempotency facts but contains no free text.
16. **Idempotent revocation —** repeated revocation for the same Session and idempotency key returns the same terminal fact. Revocation never restores or mutates an older history fact.
17. **Immediate observation —** an authenticated request resolves the current Session through the owning port. A stale caller-provided Actor snapshot cannot override revocation、expiry、identity disable or Session rotation.
18. **Closed errors —** use stable privacy-safe codes for malformed input、unknown/revoked/expired Session、inactive Actor、policy mismatch and version conflict. Errors contain no lookup value、email、subject、Token、Cookie、Provider payload or existence oracle.
19. **Minimal events —** `identity.session-revoked.v1` contains only Session/Actor safe references、reason、occurred-at and correlation; `identity.credential-compromised.v1` contains Actor safe reference、credential-reference hash surrogate、occurred-at and correlation. Neither event contains raw credential/provider data.
20. **Concurrency —** mutating Session commands require a positive expected version. Conflict fails closed; no last-write-wins or client-provided version elevation.
21. **Data classification —** Actor/Session references and risk facts are at least `Internal`; credential compromise and verification facts are `Restricted`. Logs、URLs and analytics prohibit all raw identity/session/credential values; fixtures are synthetic-only.
22. **No persistence or Provider claim —** no migration、Repository adapter、Cognito configuration、OIDC library、Cookie、CSRF endpoint、KMS envelope encryption、Secrets Manager、email/SMS or AWS SDK is added.
23. **Dependency and lockfile discipline —** use TypeScript/Vitest already pinned by the repository. Add no external dependency; `pnpm-lock.yaml` changes only for the new empty workspace importer.
24. **Future composition —** the complete Section 52.6 request `ActorContext` is composed later from this authenticated Identity fact plus server-resolved Tenant/Membership/Permission references. This WP must not add placeholder Brand/Store/Role fields.

## Security、privacy、risk and rollback

- **Provider identity becomes authorization:** provider subject/email/token never appears as an Actor or Tenant grant; only the owning resolver emits a stable Actor reference.
- **Identity grants access:** public types contain no Brand、Store、Membership、Role or Permission; later server composition must supply them.
- **Session replay/fixation:** reference rotation and current resolver state make former references unusable; browser entropy/hash/storage evidence remains WP-0107.
- **Revocation lag:** the port contract requires current-state resolution and rejects stale snapshots; real load/cache behavior remains later evidence.
- **Enumeration/leakage:** strict validators and closed errors never echo lookup values or sensitive payloads.
- **Role-policy confusion:** profile facts do not identify a role and Identity cannot select privileged access.
- **History rewrite:** merge/disable/revoke facts never rewrite historical Actor references or restore an old Session.
- **Rollback:** before any later persistence exists, a reviewed Git revert removes this contract. Once consumed, compatibility requires additive versioning; no data/provider/cloud rollback exists in WP-0100.
