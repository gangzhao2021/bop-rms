## Owning facts and boundaries

Inventory owns Adjustment intent, impact, approval decisions and the resulting immutable Movement.
The Stock Ledger remains quantity truth. The browser supplies the scoped delta, controlled reason and
evidence references; current Balance, conversion, Item lifecycle / lot and negative-stock policy come
from an authorized server port. Adjustment never overwrites a Balance or edits an earlier Movement.

## Acceptance contract

1. Define a versioned Adjustment Aggregate with one explicit Stock Scope, Item / lot / Location,
   exact signed delta and conversion snapshot, controlled reason, evidence references, source Balance
   version, before / projected impact, negative-stock decision and append-only workflow decisions.
2. Validate authorizes before the source snapshot, rejects foreign scope / Item / lot facts, enforces
   lot / expiry and Item lifecycle policy, blocks prohibited negative stock and requires explicit
   override authority for Manager Override. Browser input cannot author current quantity, conversion,
   policy or Balance version.
3. Submit / approve / reject / cancel have exact permissions, expected aggregate version, Audit and
   exact-intent idempotency. High-risk approval is always independent; the submitter cannot approve.
4. Post accepts only Approved Adjustments and an atomic adapter result containing the exact command,
   Audit, Posted Aggregate and one validated immutable `Adjustment` Movement bound to scope, Item,
   lot / expiry, delta / conversion, reason, source Balance version, before / after impact and Actor.
5. Implement contextual `INV-ADJUSTMENT-WIZARD` and historic `INV-STOCK-ADJUSTMENT` alias with
   exact Item / barcode / lot context, current projection, delta / Unit, reason, evidence, impact,
   approval / segregation, freshness and every mandatory state. No second standalone route is added.
6. Section 50 assigns no Inventory schema and the Event Catalog registers no Adjustment event.
   Persistence, source validation, projection and atomic Adjustment + Ledger posting remain injected;
   no migration or Event publication is invented.

## Security and privacy review

- Trust boundaries: untrusted Merchant command / query and BFF projection, Stock-Scope workforce
  authorization, server-owned Item / Balance snapshot, authorized cross-domain evidence resolver,
  injected Adjustment repository, atomic Ledger posting, Audit producer and rebuildable projection.
- Classification: Item, quantity, location, lot, reason, evidence and Actor references are Internal
  operational evidence. Secrets, unrestricted object IDs, supplier contacts, customer PII, payment
  data, allergy / health facts and unrestricted text are prohibited from commands, projections,
  fixtures and UI states.
- Controls: descriptor-safe closed parsing, UUIDv7 / UTC / date / controlled-code validation,
  authorization before any read, exact action permissions and Stock Scope, exact decimal conversion,
  authorized evidence binding / masking, negative-policy enforcement, four-eyes approval,
  exact-intent replay, expected Aggregate / Balance versions, Audit-before-write, atomic posting and
  exact adapter-output validation.
- Findings: Blocker `0`, High `0`, Medium `0`, Low `0`. Residual live Item, Balance, Store / Location,
  lot, Evidence, Actor, approval, permission and Ledger evidence remains gated on authorized adapters
  and is not claimed here.
