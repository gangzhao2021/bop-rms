## Resolved contract and hard gate

WP-1225 owns the currently available Ordering projection. It supplies Store-scoped Order identity,
number, type/channel, phase, submission time, immutable Batch/item counts and explicit freshness.
Its contract deliberately reports Payment as `NotReported` and Kitchen, Fulfillment/ETA, claim and
exception facts as unavailable unless Ordering has an accepted fact. WP-1900 owns the later
cross-Domain `merchant_order_*_v1` operational projection; no Merchant Order HTTP/BFF or realtime
composition currently exists.

This WP adds canonical queue/detail routes, strict closed parsers and injectable browser clients.
The default runtime is unavailable and performs no request. The queue uses exact Order number or
reference search over the already-authorized Store list, derives age deterministically from the
projection timestamp, labels every absent source and makes any non-fresh board visibly read-only.
Claim and accept/reject controls are explicit disabled action intents: no arbitrary status picker
or projection-authorized mutation is introduced.
