# WP-2160 — Operational Dashboard scope / freshness / drill-down

## Authority and scope

- Handoff Sections 88.15, 88.22–88.30 define `RPT-OPS-DASHBOARD` at
  `/app/reports/operations`; WP-1900–1905 own the accepted operational source Projections and
  `reporting_operations_dashboard_v1` Query.
- Exact local predecessor: verified WP-2155 commit `e990926`.
- Reporting owns the permission-trimmed derived dashboard view only. Ordering, Payment, Kitchen and
  Fulfillment remain owners of their facts and source pages.

## Acceptance criteria

1. The standalone Merchant route renders exact Tenant / Brand / Store scope, Business Date, IANA
   timezone, CAD currency, channel / order-type filter snapshot and authorized Store choices.
2. Every KPI exposes its Metric Version; CAD amounts remain base-10 minor-unit strings and are
   rendered without binary floating point.
3. Generated/data-as-of time, completeness and each source checkpoint/freshness state are explicit.
   Missing sources render unavailable rather than zero; partial/stale data is read-only.
4. Drill-down is permission-trimmed to a fixed allowlist of owning source routes. It never edits a
   transaction or accepts a URL/provider payload from an untrusted response.
5. Loading, empty, permission denied, not found, feature disabled, stale, conflict, command failed,
   offline and unavailable states are represented with keyboard-readable, non-color text.
6. Save view, export and schedule affordances are permission-gated and disabled on incomplete data;
   their persistence, artifact and scheduler behavior remains WP-2161/2162/2196 rather than invented.
