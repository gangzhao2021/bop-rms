## Scope and behavior

Current abuse admission must be exactly Admitted; current Guest evidence must match the requested
Guest reference, ContextOnly/DineIn, current observation and exact Store/Table before any history
access. The resolved Session/capability must be coherent, Active Session/current assignment, exact
selector/kind/scope and non-future chronology. Original consumed-capability replay remains possible
with current ContextOnly authority; expired outstanding credentials cannot start new joins. Closed,
reassigned or unauthorized current contexts fail with the existing generic unavailable response.

The complete original Join record is bounded/copied/frozen before digest callbacks and validates
operation/hash, Session/Participant/admission/capability identity, versions, scope, Host, chronology,
and immutable consumed capability. Original history does not become current state or issue raw
credentials. Write acknowledgements receive the same structural validation and must equal the exact
computed join or return a coherent committed original without generating another admission. Safe
conflict codes are preserved; malformed dependencies and synchronous/asynchronous failures are
redacted. Existing intent strings and expected-version semantics remain unchanged.

The descriptor snapshot from WP-2273 moves into a concrete shared Session snapshot helper used by
both Staff and Join records. No generic framework, permission code, public endpoint or database
adapter is added. Staff behavior and its59 regression cases must remain green.
