Closing operation table in rms_dining. Bind Tenant/Brand/Store and exact Session/operation IDs.

Session field. Update phase/version, append operation history and public Audit in one transaction.

stale versions fail closed. Session row locking serializes with existing Join/regeneration.
No implicit Table release, cleaning state, capability revocation or Participant deletion is added.

intent rejection, version/phase conflicts, original replay, failed writes and redacted errors.

competing operations, lost acknowledgement, Audit rollback, read-only denial, foreign-store RLS,
immutable history, strict shape and owned cleanup. Synthetic financial/Host evidence is not live

## Discovered prerequisite defect

The existing migration scanner misclassifies quoted Begin data, CASE END expressions and quoted
HH24:MI date formats as transaction control/template substitution. The minimal required catalog
correction masks quoted data/comments for executable transaction and colon-placeholder checks,
recognizes END transaction statements rather than CASE expressions, and retains template markers,
unsafe non-function dollar bodies and real transaction/DDL denials. Catalog tests verify both
acceptance and retained rejection. This is a prerequisite of the scoped migration, not permission
to bypass verification, add dynamic SQL or change migration execution/ownership semantics.
The exact allowlist therefore includes catalog.ts (17 files total).
