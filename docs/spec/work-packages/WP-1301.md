## Purpose

Create the smallest Payment-owned anti-corruption contract through which later Payment application
services can invoke the accepted Stripe baseline without importing Stripe SDK objects, raw payloads,
credentials or Provider status semantics into Domain/Public contracts. WP-1301 defines and runtime
validates normalized requests, results and failures only; it performs no Provider call.

## Closed execution contract

1. New Phase-1 module `@rms/payment` owns the `rms_payment` namespace and depends synchronously only
   on the public `@rms/pricing` Money contract. This WP creates no database object.
2. Provider identity is closed to `Stripe`; environment is explicit `Test | Live`, but a `Live`
   value is descriptive only and never supplies credentials or activation authority.
3. The adapter surface is closed to `createIntent`, `retrieveIntent`, `cancelIntent`,
   `captureIntent` and `refundPayment`. WP-1303 separately owns raw webhook verification and is not
   smuggled into this interface.
4. Every mutation carries one server-owned BOP operation reference, Payment Attempt reference,
   Brand/Store scope, purpose, deterministic Provider idempotency key and expected Money where the
   operation requires it. Retrieve carries the same scope and Attempt identity but no mutation key.
5. Create is closed to `OnlineCard | TerminalCard | TerminalInterac`. Online Card requires
   `Automatic`; Terminal Card requires `ManualPreferred`; Terminal Interac requires
   `ManualPreferred` but its normalized result is single-message captured.
6. `captureIntent` is valid only for `TerminalCard`. Any Interac capture request is rejected before
   an adapter can observe it. Refund remains bounded to the original method; later policy owns
   eligibility, approval, allocation and cumulative balance.
7. Adapter results are normalized to closed Provider-safe references, method, capture mode,
   `RequiresCustomerAction | Pending | Authorized | Captured | Cancelled | Failed | Unknown`,
   requested/authorized/captured/refunded Money, observed UTC instant and an evidence SHA-256
   digest. Impossible status/amount/method combinations fail closed.
8. Failures are data, not raw exceptions. Codes are closed to `Declined`,
   `AuthenticationRequired`, `InvalidRequest`, `Conflict`, `RateLimited`, `Unavailable` and
   `Unknown`, plus a retry disposition and bounded safe reason code. Provider message, stack,
   request body, response body and unrestricted metadata are prohibited.
9. All public constructors/parsers reject extra fields, accessors, custom prototypes, malformed
   references, non-CAD Money, binary floating point, unsafe strings and invalid state combinations;
   returned values are deeply immutable.
10. No Stripe SDK/version pin, secret, client secret, PAN/CVV, card fingerprint, Radar data, raw
    Provider payload, HTTP, webhook, persistence, Event, Payment Aggregate, Provider simulator call,
    real account fact or External Evidence is authorized.

## Later boundaries

- WP-1302 owns Payment Intent/Attempt state and create/retrieve orchestration through this port.
- WP-1303/1304 own raw webhook signature verification, durable acceptance and idempotency.
- WP-1305/1306 own Payment facts/events and projections.
- WP-1307–1310 own reconciliation, Kill Switch, capture watchdog and paid-without-fulfillable
  compensation. WP-2045 owns refund workflow/approval.
- Exact Stripe SDK/API pinning belongs to the first infrastructure implementation that invokes the
  Provider and must revalidate SPIKE-1300's mutable public evidence.

## Scope and acceptance evidence

Allowlist:

- generated `@rms/payment` package/manifest/README/config;
- Payment adapter contracts, strict runtime policy/parser, exports and synthetic tests;
- root acceptance script and lockfile importer only as required for the new workspace package;
- this brief, spec index and SPIKE-1300 exact integration evidence.

Acceptance must prove every operation shape, strict closure/deep immutability, Money/scope/purpose /
idempotency requirements, method/capture rules, Interac capture rejection, normalized status/amount
invariants, safe failure mapping and rejection of raw/sensitive/extra Provider fields. Frozen install,
module/import/Domain architecture, package format/lint/typecheck/test/build, workspace regressions and
security/privacy review are required.
