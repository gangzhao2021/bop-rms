## Canonical title、responsibility and dependencies

The authoritative backlog title is:

**`WP-0035 — Event Catalog Tooling and Contract Test`**

WP-0035 owns the repository-level mechanism that:

1. defines one Zod-first source shape for Event Catalog registrations;
2. generates deterministic JSON Schema and an AsyncAPI `3.0.0` Event Catalog document from that source;
3. validates the generated document with both `@asyncapi/parser` and `@asyncapi/cli`;
4. detects generated drift and conservative backward-compatibility violations;
5. provides a dedicated acceptance command and makes the gate part of root verification;
6. records catalog governance without registering an unsupported concrete business Event.

Dependencies are closed public contracts only:

- WP-0030: immutable generic Event Envelope、`schemaVersion` naming、minimal payload/classification and mandatory pre-producer registration;
- WP-0031: transport-neutral at-least-once dispatcher and the rule that Event-type telemetry is unavailable until catalog registration bounds cardinality;
- WP-0032: static Consumer registry、exact Event type/version matching and replay-safe Consumer identity;
- WP-0033: retry/dead-letter metadata-only state、safe classification and no business semantics;
- WP-0034: immutable restricted Correlation/Causation identity and no trace/logging expansion.

WP-0035 does not reopen or replace those contracts. It validates catalog declarations before they may integrate through their public interfaces.

## Accepted Owner Decisions

The Owner directed that all Recommended decisions be accepted. The following decisions are accepted without modification:

1. **Package boundary** — Recommended: create private workspace `packages/contracts` named `@bop-rms/contracts-events`, with Event Catalog source under its `events/` subtree and no `exports` field. This follows the existing `packages/*` workspace glob and Section 46.8 without changing workspace discovery. It is a Contract build/test package, not a new runtime/public application API.
2. **Source of truth** — Recommended: registration entries are authored in TypeScript with Zod payload schemas; JSON Schema、AsyncAPI and human-readable catalog output are generated, never hand-maintained as competing authorities.
3. **Concrete registration boundary** — Recommended: the initial committed catalog is empty. Synthetic entries exist only inside tests. Phase 1 names from Section 52.16 are not registered until an owning Domain WP supplies the exact payload、consumers、classification、retention and replay approval.
4. **Registration identity** — Recommended: exact identity is `eventType + schemaVersion`; Event type is stable PascalCase and version is a positive integer. A version suffix is not embedded in `eventType`.
5. **Required metadata** — Recommended: every future registration requires owner/producer module、stability、consumers、Tenant scope、data classification、compatibility mode、retention category、replay semantics、deprecation and replacement metadata.
6. **Compatibility policy** — Recommended: adding a new Event or new version passes; removal of an existing identity、removal/change of an existing payload field、new required field、owner/producer/scope/classification/retention/replay mutation or Consumer removal fails. A new optional field in the same version passes. Unrecognized schema constructs fail closed.
7. **Generation determinism** — Recommended: canonical key ordering and final newline are mandatory; `--check` compares exact bytes and never rewrites during verification.
8. **AsyncAPI boundary** — Recommended: generate AsyncAPI `3.0.0` JSON with messages/components only and no server/channel binding. Transport selection、broker addresses、credentials and runtime publication remain excluded.
9. **Runtime validation boundary** — Recommended: WP-0035 validates catalog declarations and generated payload schemas at build/test time. It does not replace WP-0030’s accepted generic envelope validator or change dispatcher/consumer runtime state machines.
10. **Metric allowlist** — Recommended: only actually registered Event identities are bounded label candidates. Because the initial catalog is empty, WP-0035 enables no Event-type production metric label.
11. **Security/privacy** — Recommended: catalog metadata and schemas must not contain examples/defaults/descriptions with real or synthetic-secret-like values；payload schema keywords cannot weaken object closure；credentials、Payment、health/allergy and PII require future owner/security acceptance and remain unregistered here.
12. **Acceptance command** — Recommended: add root `pnpm event-catalog:acceptance`, include `pnpm event-catalog:check` in `pnpm verify`, and retain every WP-0030–0034 regression acceptance unchanged.
13. **Dependency exception** — Recommended: install only exact runtime/tooling packages `zod@4.4.3`、`@asyncapi/parser@3.6.0` and `@asyncapi/cli@6.0.2`, plus exact declaration-only `@types/node-fetch@2.6.13` required by parser `3.6.0` under repository `skipLibCheck:false`. Because CLI `6.0.2` brings `@asyncapi/generator-react-sdk@1.1.3` with stale `@babel/core@7.12.9` while its resolved Babel plugins require `^7.13.0`, apply exact path-scoped transitive override `@asyncapi/generator-react-sdk@1.1.3>@babel/core = 7.29.7`. Explicitly deny lifecycle scripts for `@asyncapi/cli`、the four introduced `@hyperjump/*` packages、`@scarf/scarf`、`protobufjs` and `yarn`; the CLI postinstall is prohibited because it writes shell startup files. No other direct dependency、override、version change or strict-gate downgrade is accepted.
14. **No persistence** — Recommended: no migration、database object、runtime role/grant、table、retention job or schema registry service. The catalog is version-controlled repository data.

## Security and privacy gates

### Actors、assets and trust boundaries

- Actors: Contract author、reviewer and CI process only.
- Assets: registry metadata、Zod payload schemas、generated JSON Schema/AsyncAPI/Markdown and compatibility baseline.
- Boundary: authored TypeScript → local generator → committed artifacts → parser/CLI/CI.
- Production impact: none. No runtime、network endpoint、broker、database、Tenant inventory or credential is created.

### Classification and controls

- Event identity、owner/producer module、Consumer aliases、stability and compatibility metadata: internal engineering metadata.
- Payload field names and schema structure may reveal future business design and are treated as internal.
- Real IDs、Tenant/Store/Actor facts、examples/defaults、free text、credentials、Provider data、Payment、health/allergy and unnecessary PII are prohibited in the WP-0035 catalog.
- Generated output is exact-source-derived and contains no timestamps、host paths、environment data or network result.
- Errors use stable field paths/codes and never echo rejected values or schema content.
- Parser/CLI run only against the repository-owned generated local document; no remote reference resolution is allowed.

Security acceptance requires `0` open Blocker and `0` open High. External production approvals are not substituted by local or CI evidence.

- Before merge: revert the unintegrated files normally.
