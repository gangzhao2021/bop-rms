## Acceptance

1. Database infrastructure exposes a query-only scoped transaction runner compatible structurally
   with Identity's existing port, without importing or owning Identity facts. Reuse the existing
   Tenant Context helper. Require bounded pool acquisition/query timeouts; set finite transaction
   statement/lock/idle limits. Commit before returning; never auto-retry an uncertain result.
2. Escaped query handles fail after callback completion. Driver errors are bounded and contain no
   SQL, binds or cause; business callback errors retain existing behavior. Failed transactions
   discard their connection, including failed rollback/commit, and thrown undefined is not success.
3. Real HTTP/Identity/PostgreSQL acceptance uses the production pool runner for normal paths;
   retain explicit synthetic rollback/unknown-commit injection. Prove pooled context clearing and
   cleanup, with non-superuser scoped roles and all existing lifecycle/concurrency tests retained.
4. Unit tests cover timeout validation, successful commit/release, expired handles, query errors,
   rollback failure, unknown commit, release failure and callback failure. No migration or API route.
