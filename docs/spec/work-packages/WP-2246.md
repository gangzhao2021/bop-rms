# WP-2246 - Browser Cart Binding Credential Transport

## Authority and readiness

Owner authorizes continued bounded implementation and verified local commits. Baseline c4ee047,
branch codex/wp-2246-binding-browser-client. Composite Sections0–97, WP-1003/1205/2228/2234/2240
and WP-2245 supply credential preparation, original-operation continuation and current Cart reads.

Add an independently testable Customer PWA transport for the existing prepare/activate/complete
BFF. Explicit input carries operation reference and CSRF/proof only; raw Session credentials remain
in browser-managed HttpOnly cookies. Fixed relative routes, same-origin credentials, no-store cache,
standard cors Fetch Metadata required by the BFF, redirect rejection, exact JSON/input validation, operation/CSRF echo checks and a finite deadline
cover both headers and response body. Credential response bodies are bounded to4096 bytes.

Prepared returns the candidate CSRF/proof and expiry only to the calling in-memory coordinator.
No global credential replacement, storage, UI state, logging, analytics or automatic retries occur.
Local validation/offline failure causes no request. Recognized server400/503 stays bounded; unknown,
malformed, oversized, redirected or timed-out results remain outcome-unknown. A503 does not prove
activation failed; callers must retain the original operation/candidate and cannot infer rollback.
Server time/authorization remains authoritative; the client validates timestamp syntax only.

This is a transport prerequisite, not the browser creation/recovery coordinator. CUST-CART remains
Phase1 /cart with Guest/exact Store scope and existing fields, permissions, loading/empty/denied,
conflict/failure/offline states and accessibility profile. No route/React/CSS/Screen/Figma change,
new storage, service-worker cache, mutation replay, cancellation or page-reload recovery is enabled.
