## Application contract and acceptance

Extract WP-2313's current authorization into one internal helper shared by reads and selection. Preserve
its exact Identity/Dining/Identity checks before owner access and again afterward, invocation-local
monotonic clock, closed/frozen dependency capture, original binding requirement, exact scope, Guest,
assignment and membership-version comparison. Capture the complete authority snapshot before handing
it to an owner callback. Existing read behavior and tests must remain compatible, including absent
results and effective expiry. Errors expose only bounded Cart codes.

Add a selection application service accepting only a raw Guest credential and operation reference.
Derive owner command scope, Dining Session, Guest/Participant and observation from current authority;
never accept Cart IDs, policy or Actor facts from the caller. Move the existing owner command type to
the Domain contract so application code does not depend on private infrastructure. Parse and freeze
the owner receipt before final authorization callbacks, validate exact command linkage, and require
receipt time within the same Guest lifetime/current observation and the original 24-hour validity.

Current authority precedes all historical retries. A Closing/Move/revocation/rotation or membership
drift after a committed effect prevents publication; it never causes compensation or another Cart
creation. The original operation can be retried only after fresh current authorization. Preserve
recognized owner lifecycle/idempotency errors with fresh bounded error objects. A returned receipt
is an internal historical fact, not a current Cart view, item permission or Closing write lease.

Actual PostgreSQL acceptance composes this service with the real WP-2316 writer and explicit synthetic
Identity/Dining authority providers. Verify two current participants sharing one persisted Cart,
denial before database access, and post-effect authority loss followed by exact original recovery
without duplicate Cart/operation/Audit. This does not claim real Staff/Join/Identity provider composition.
