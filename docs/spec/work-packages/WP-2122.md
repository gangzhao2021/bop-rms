## Owning facts and boundaries

Inventory owns Count intent, authorized Stock snapshot reference, assignee progress, recount,
variance, approval decisions and the resulting immutable Count Adjustment Movements. The Stock
Ledger remains quantity truth. Expected quantity is captured by an authorized server port and is not
browser-authored; a blind assignee cannot see it before submission. Count never overwrites a balance
or edits a Movement.

## Acceptance contract

1. Define a versioned Count Aggregate with exactly one Stock Scope, Full / Cycle / Spot type, blind
   visibility, freeze / snapshot policy, unique Item + lot + Location lines, exact non-negative
   quantities, source Balance version, assignee, due time and append-only workflow decisions.
2. Create captures expected quantities from an injected Stock snapshot only. Assigned Actor alone can
   start, enter / scan and save; every line is required, exact variance is derived without binary
   floating point, non-zero variance requires a controlled reason, and rejected submission reopens
   the Workbench for recount.
3. Submit / approve / reject use distinct permissions and expected aggregate version. Segregated policy
   prevents submitter self-approval. Posted / Cancelled history cannot be edited, and every mutation is
   Audit-backed and exactly idempotent.
4. Post accepts only Approved Counts and an atomic adapter result containing exactly one validated
   `CountAdjustment` Movement per non-zero line, bound to Count source, reason, Item / lot / Location,
   Unit, snapshot Balance version, Actor, Audit and operation. Zero-variance lines create no Movement.
5. Implement `INV-COUNT-LIST`, `INV-COUNT-WORKBENCH` and the `INV-STOCK-COUNT` alias with explicit
   scope, snapshot / freeze, progress, blind visibility, variance / conflict, segregation and every
   mandatory state. Actions stay disabled without an authorized command-capable BFF.
6. Section 50 assigns no Inventory schema and the Event Catalog registers no Count event contract.
   Persistence, snapshot / movement freeze, projection and atomic Count + Ledger posting remain
   injected; no migration or Event publication is invented.
