## Contract and ownership

Add an Ordering application entry around the existing Cart Quote attachment service. Input is a
closed immutable copy of sessionCredential, csrfCredential, cartReference, expectedCartVersion and
operationReference; all are validated before I/O. Server time is read internally. Authorize current
Pickup Session/CSRF, query its current binding, then authorize again at a fresh nondecreasing server
instant, including absence. Require identical Session/public Store/QR/revocation identity and exact
Brand/Store/Pickup creator ownership. Missing or another bound Cart yields CART_UNAVAILABLE.
Malformed/foreign bound facts and infrastructure failures are redacted. Reject future Cart facts.
The subsequent owner repository read must not regress the bound version/time, alter immutable
creation/channel identity, or supply different content for the same version. Compare only in memory.

Only then delegate to the existing attachment service, preserving current authorization before
operation-history lookup, original replay, lifecycle/version checks, option denial and minimal Audit.
The Pricing port receives the existing server-owned PricingCartInput plus frozen operation/Guest
Session identity. Raw credentials never leave authorization. This enables a later application
composition to use Pricing's scoped request store without importing Ordering into Pricing.
Current facts and transaction recovery remain explicit dependencies; no source fact is fabricated.

Constructor is I/O-free and copies scope. Each request owns its authorization/identity closure;
concurrent calls cannot share it. All non-domain dependency errors are fixed redacted errors.
This entry returns the owner-internal attachment result, not a public HTTP DTO. No HTTP wiring,
Pricing producer, SQL/migration, selected-option pricing, DineIn or new transaction boundary.
No main merge, push, deploy, real Store/tax/Provider facts or readiness claim.
