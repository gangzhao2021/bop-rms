## Scope

Provide a finite opt-in interactive acceptance lab, launched with an explicit repository command.
Reuse the existing synthetic entry fixture, real scoped API runtime, isolated PostgreSQL lifecycle,
Session credential provider and menu projection seed. Serve the existing Customer PWA through
loopback Vite with same-origin proxying. Supply a synthetic entry token through a same-origin
POST response in memory, never a printed URL, log, screenshot or persistent browser storage.
Keep the existing contextual entry, Continue to menu and menu navigation contracts and states.
Label the lab synthetic, local and limited to entry/menu; pricing remains unavailable, readiness
remains 503. The standard development and production startup remain unchanged.
The lab has a finite lifetime and closes HTTP, Vite, browser, pool and isolated database resources
on success or failure. No normal database or real Store is seeded.

## Acceptance

1. A documented explicit command starts an interactive loopback lab using a disposable database.
2. Automated desktop/mobile Chromium follows entry to menu over real HTTP, observes the secure
   HttpOnly Session cookie and persisted Session record, and reads the seeded PostgreSQL menu.
3. Missing/invalid bootstrap origins and paths fail closed. No application response interception,
   synthetic browser HTTP response, token-bearing URL, trace or screenshot supplies success.
4. Runtime readiness remains 503; unavailable prices remain explicit. Production HTML never selects
   the lab entry. Existing default startup, entry, menu and demo tests remain passing.
5. Exact pins/frozen install, affected checks, full verify, browser acceptance and final scope and
   security review pass before delivery. No unrun external integration is claimed.
