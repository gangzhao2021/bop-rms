## Resolved test boundary

WP-2021 owns one synthetic cross-layer Payment-success scenario. A verified, exact-scope Provider
observation is processed by Payment's real terminal service into one minimal `PaymentSucceeded.v1`
fact. A synthetic public adapter then exposes only the authoritative operation status and Order
reference to the real Customer PWA payment-result controller. The scenario verifies terminal replay,
exact amount/currency/Brand/Store/Intent/Attempt ownership and clean success navigation.

The Provider IDR, real account/API/SDK, public Guest Payment transport and client-secret delivery are
still unavailable. The production browser runtime remains Provider-gated; this WP does not enable a
payment method, trust redirect/query/fragment claims or claim real Payment/PCI evidence.

- a captured exact-amount observation creates one `PaymentSucceeded.v1` with the intended Order;
- exact replay returns the first terminal fact without a second logical outcome;
- amount/currency or scope mismatch fails closed before success publication;
- the PWA result controller accepts only the minimal same-operation success observation and ignores
  URL/redirect claims;
- Provider account/event/object/evidence/raw payload and payment method data do not cross the public
  observation;
- focused/affected/full local gates pass; GitHub, real Provider and production evidence are skipped
  and unclaimed.
