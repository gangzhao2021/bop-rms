# WP-2199 — Trusted diagnostic authorization time and browser request resilience

## Authority and scope

- Handoff Sections 50.7, 87.3, 87.6, 87.7 and 88.18 require fail-closed, purpose-bound Platform
  Support access and complete customer/merchant failure states. Section 80 remains the security
  remediation baseline.
- Exact local predecessor: WP-2198 commit `0d7ecba`.
- This corrective WP is limited to the reviewed authorization-time, diagnostic-grant atomicity,
  browser-request timeout and duplicate-write findings. It does not reopen accepted Domain or
  screen decisions.

## Acceptance contract

1. Support authorization and diagnostic-grant expiry decisions use a trusted application clock;
   caller-supplied command timestamps cannot move the authorization window.
2. A diagnostic action commit revalidates the exact Case, Actor, Tenant/optional Store, purpose,
   delegated permission, Case state, expiry and revocation status in the same repository
   transaction as the append-only operation/action record. A preliminary application check is not
   authority.
3. Diagnostic access resolution obtains one atomic active-grant snapshot and fails closed on an
   invalid clock, dependency failure, mismatch, expiry or revocation. Any later diagnostic
   execution must revalidate at its own execution boundary; this resolver is not a reusable token.
4. Customer PWA cart, checkout, entry and menu requests and Merchant Web workspace requests have a
   finite 15-second client timeout while preserving caller cancellation.
5. Concurrent cart, configure and checkout write submissions are coalesced into the existing
   in-flight promise. They create only one idempotency key and one network request; a deliberate
   retry after settlement remains possible under the existing outcome rules.
6. Timeout and other transport failures remain explicit recoverable/unknown UI states. There is no
   automatic background replay of customer writes.
7. Error payloads, logs, fixtures and tests add no secrets, tokens, request/response bodies,
   diagnostic commands, payment data, health/allergy facts or unnecessary PII.
