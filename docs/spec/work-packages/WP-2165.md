## Acceptance contract

1. Every Pipeline Run pins Pipeline, Pipeline Version, Transformation Version, input checkpoint,
   output Dataset/partition, scope, environment, logical batch idempotency digest, execution kind and
   replay classification. Accepted kinds are `Load`, `Retry`, `PipelineCorrection`, `Backfill` and
   `Rebuild`; retry/replay cannot masquerade as a new business fact.
2. Run state is append-only and follows `Queued → Running → Succeeded | SucceededWithWarning |
Failed | Cancelled`. Each state records sequence, occurred time, watermark and bounded decimal
   string counts for read/written/late/rejected records. Successful states require a Data Quality
   Result; failure requires an opaque Error reference. A Pipeline failure never rolls back or edits
   a source business transaction.
3. Pipeline Correction pins correction reason and code/rule Version. Backfill/Rebuild pins an
   approved request and pre-run Reconciliation; success requires post-run Reconciliation. No Raw
   Source Fact is updated, and material publication changes remain revision/correction-notice
   responsibilities of Report/Output owners.
4. Backfill requests version a closed lifecycle `Requested`, `Approved`, `Rejected`, `Running`,
   `Completed`, `Failed`, `Cancelled`. Requester and approver are distinct actors; approval pins
   range/scope, Dataset/partition and Pipeline/Transformation Versions. The approved request can bind
   one logical idempotent Run without inventing real data or approval evidence.
5. Every mutation revalidates Tenant Context, Actor, purpose, Permission, expected version/sequence,
   idempotency and Audit and composes strict `AnalyticsLoadCompleted`, `AnalyticsLoadFailed` or
   `AnalyticsBackfillCompleted` Events atomically. Unknown source schema/raw payload processing,
   arbitrary SQL/rules and live execution remain behind unavailable adapters.
6. `BI-PIPELINE-RUN` exposes canonical pipeline/version/run/watermark/status/late/rejected/duration/
   lineage fields, filters, retry/backfill/approval/incident actions, permission gates and all
   universal states. Forced Brand/Store RLS, PUBLIC revocation, append-only history, ownership,
   migration and isolated PostgreSQL acceptance pass with synthetic references only.
