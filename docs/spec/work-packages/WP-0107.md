## Responsibility and bounded intended increment

WP-0107 materializes the browser-to-Identity security boundary that WP-0100 deliberately deferred:

1. provider-independent same-origin BFF start、callback、session-bootstrap、CSRF-protected request
   and logout orchestration;
2. one Identity-owned PostgreSQL `authentication_session` table storing only keyed selectors、
   canonical references、bounded risk facts and opaque authenticated ciphertext;
3. one Identity-owned one-time `oidc_authorization_transaction` table storing keyed state/auth
   selectors、opaque authenticated ciphertext、exact redirect URI、allowlisted post-login path、
   expiry、consumption state and optimistic version;
4. strict Cookie descriptors for `__Host-bop-auth` and `__Host-bop-merchant`;
5. injected ports for OIDC exchange/logout、selector hashing、random credential generation and
   token-envelope encryption/decryption;
6. synthetic OIDC and synthetic envelope-crypto acceptance plus real isolated PostgreSQL evidence;
7. fail-closed same-origin、Fetch Metadata、CSRF、fixation、replay、expiry、rotation、version conflict、
   concurrent-limit and database-compromise scenarios.

The implementation does not create or call a real Cognito User Pool、app client、Secrets Manager
secret、KMS key、WAF、AWS account/resource or production database. It does not claim real
`openid-client` interoperability. WP-2040 owns the concrete Cognito/cloud adapter and external
threat evidence; this WP freezes the provider-neutral port and BFF behavior that adapter must obey.

## Ownership、trust boundaries and data classification

- `@bop/identity` owns Authentication Session and OIDC authorization-transaction facts、their
  lifecycle、optimistic versions and persistence contract.
- `apps/api` remains transport/composition only. It may parse exact same-origin HTTP inputs、emit
  bounded Cookie/header/redirect outputs and call injected Identity/OIDC/crypto ports. It owns no
  authentication rule、Provider SDK object or private Identity query.
- A future infrastructure adapter may implement OIDC through the accepted Cognito +
  `openid-client 6.8.4` profile, but Provider objects never enter the Identity public contract.
- `packages/database` owns only isolated-test plumbing. The migration is owned by Identity through
  its Module Manifest; database infrastructure does not become the business-fact owner.
- `authentication_session` and `oidc_authorization_transaction` are enumerated pre-Tenant Identity
  tables. They contain no Brand/Store authorization fact and cannot require route Tenant Context
  before authentication. They are not an RLS bypass: application authorization remains mandatory,
  PUBLIC is revoked and production runtime principals/grants remain WP-2005/2040 evidence.
- Raw Cookie value、CSRF token、authorization code、state、nonce、PKCE verifier、access/refresh/ID
  Token、client secret、HMAC pepper、plaintext data key and KMS plaintext are `credential` /
  `Restricted`. They are prohibited from source、database plaintext、URL other than the unavoidable
  one-time callback code/state boundary、logs、metrics、traces、analytics、fixtures and error bodies.
- Actor、Session、Membership、provider-subject surrogate、client reference and risk metadata are at
  least indirect/sensitive identifiers. Tests use deterministic synthetic values only.

## Adopted Recommended Owner Decisions

1. **Two-table owner —** create schema `bop_identity` in Stage DB-1 migration
   `migrations/0200-bop-identity-tenancy/0200_004_create_identity_session.sql` with exact tables
   `authentication_session` and `oidc_authorization_transaction`.
2. **No Actor persistence widening —** User/Actor、Credential/External Identity Link and invite
   persistence remain future Identity work. These two tables retain only validated opaque
   references; no email、username、phone or raw Provider subject is stored.
3. **Browser credential boundary —** generate 256 random-bit opaque auth/session/CSRF selectors.
   Cookie values are never UUIDs or public Session references.
4. **Keyed lookup —** persistence stores only fixed 32-byte HMAC-SHA-256 selector hashes produced by
   an injected environment-keyed port. Plain selectors and pepper never enter SQL or logs.
5. **Envelope boundary —** token and authorization secret bundles are opaque authenticated
   ciphertext plus key/cipher metadata. Encryption context binds environment、record ID and Actor
   where present. Decrypt/authentication failure revokes or consumes the record and returns a
   bounded failure.
6. **Synthetic crypto claim —** local/CI uses an ephemeral synthetic AES-256-GCM port only to prove
   contract behavior and ciphertext non-impersonation. It is explicitly `SYNTHETIC / NOT KMS`.
7. **OIDC transaction lifetime —** authorization transaction expiry is exactly 10 minutes.
   Callback atomically consumes it before code exchange; unknown、expired、replayed、cookie/state
   mismatch or version conflict returns one generic failure and clears the ephemeral Cookie.
8. **Exact redirect and return paths —** configuration supplies one exact same-origin redirect URI
   and a finite allowlist of clean relative post-login paths. Request input cannot supply a scheme、
   host、protocol-relative path、backslash or encoded redirect escape.
9. **OIDC port contract —** start requires Authorization Code + PKCE S256、fresh state/nonce and
   exact issuer/client/redirect configuration. Callback requires issuer、audience、nonce and code
   validation through the injected port and canonicalizes only the minimum Actor input.
10. **Raw ID Token disposal —** the port returns canonical minimum claims and an opaque encrypted
    token-bundle input. Raw ID Token and Provider payload never enter the public result、Session
    object、database fixture or log.
11. **Session policy —** reuse unchanged WP-0100 profiles and server UTC clock. Standard
    `5 / 30m / 12h`、Privileged `2 / 15m / 8h` and Named KDS `5 / 60m / 12h`; background/SSE activity
    never extends idle time.
12. **Rotation and versioning —** login creates a fresh Session; fixation candidate is ignored.
    Login、MFA completion、privilege/Store-context elevation、recovery and risk change rotate the raw
    selector and public Session reference atomically. Former selectors are immediately unusable.
13. **Concurrent limit —** successful creation beyond the exact policy limit revokes the oldest
    active Session in the same transaction with deterministic ordering. No last-write-wins exists.
14. **Cookie contract —** auth Cookie is `__Host-bop-auth; Secure; HttpOnly; SameSite=Lax; Path=/;
Max-Age=600` with no Domain. Session Cookie is `__Host-bop-merchant; Secure; HttpOnly;
SameSite=Lax; Path=/` with no Domain and never readable by browser JavaScript.
15. **Same-origin gate —** every state-changing BFF request requires exact configured HTTPS Origin、
    accepted Host and Fetch Metadata `same-origin`; missing/ambiguous/multiple/malformed values fail
    closed. Credentialed CORS is never emitted.
16. **CSRF contract —** a Session-bound CSRF selector is returned only by a no-store bootstrap
    response for page memory and supplied as exact `X-BOP-CSRF`. Its keyed hash is compared in
    constant time after Session resolution. Rotation rotates CSRF state.
17. **No-store and clean failures —** start、callback、bootstrap、logout and protected responses use
    `Cache-Control: no-store`. Callback immediately redirects to a clean allowlisted path. Public
    failures reveal no code/state/subject/Session/Actor/selector/Token or which validation failed.
18. **Session resolution —** browser selector hash resolves at most one active record; every request
    checks Actor status、idle/absolute expiry and revocation at server time before WP-0106
    authentication composition. Bounded last-seen coalescing cannot extend from background traffic.
19. **Logout ordering —** local Session revocation is authoritative and idempotent. The injected
    Provider port is asked to revoke/logout before Cookie clearing; unknown Provider result never
    restores local authority. Complete global/role/Membership revocation composition remains
    WP-0108.
20. **Database invariants —** positive version、UTC `timestamptz`、finite ciphertext/metadata sizes、
    unique selector hashes、valid status/revocation shapes、one-time consumption and expiry ordering
    are database constrained. No JSONB Provider payload、raw query、secret or unrestricted text
    column exists.
21. **Least privilege —** migration revokes PUBLIC schema/table/sequence access and creates no
    login、runtime role、credential、default grant、`SECURITY DEFINER` function、trigger、dynamic SQL
    or BYPASSRLS principal.
22. **Forward-only recovery —** migration bytes/history are immutable. Before integration use Git
    revert; after application, correct only through an approved forward migration. No down/repair.
23. **No Redis/cache —** PostgreSQL is authoritative. No in-memory/global Session cache、Redis、
    Web Storage、IndexedDB or Service Worker persistence is added.
24. **No real route enablement —** BFF handlers are tested through an isolated synthetic Express
    app and are not registered in production `app.ts` until WP-2040 supplies reviewed environment
    configuration and real Provider adapter evidence.
25. **Observability —** acceptance proves no raw identity/session/provider value reaches response、
    error、log or metric label. Real alert routing for decrypt/refresh anomalies remains external
    integration evidence.
26. **Future split —** WP-0108 owns invite、TOTP、recovery and lifecycle-driven global revocation.
    WP-0109 owns Store switch、object authorization and full cross-Tenant negative composition.
27. **Hard stop —** any need for a real Provider network call、`openid-client`/AWS SDK dependency、
    `app.ts` production registration、IaC/config/credential、external resource、real workforce fact、
    allowlist-external tracked file or weakened control stops implementation for exact review.

## Security/privacy findings、risks and rollback

Readiness findings: Blocker `0`、High `0`、Medium `0`、Low `0`.

- **Database theft:** only keyed selectors and authenticated ciphertext persist; compromise tests
  must prove rows cannot directly form Cookie、CSRF or OAuth credentials.
- **Login CSRF/code injection:** auth Cookie + keyed state + nonce + PKCE + exact redirect + atomic
  consume are all required; any mismatch collapses to one safe failure.
- **Session fixation/replay:** caller Session candidates are ignored on login and former selectors
  become unusable on every rotation.
- **Cross-site command:** exact Origin/Host/Fetch Metadata plus Session-bound CSRF are mandatory;
  SameSite alone is not acceptance.
- **Token disclosure:** raw tokens/codes/selectors never enter public types、SQL plaintext、logs、
  analytics or fixtures. Callback query visibility remains a real ALB retention/configuration gate.
- **Cross-Tenant confusion:** Identity authenticates only; Session and Provider facts grant no
  Brand、Store、Role、Permission or object access. WP-0106/0109 remain authoritative.
- **Concurrency:** row version、atomic consume/rotate and deterministic active-limit enforcement
  reject forked token/Session chains.
- **Provider uncertainty:** local revocation remains deny-first when Provider logout/refresh outcome
  is unknown. No success is inferred from a timeout.
- **Rollback:** before migration use reviewed Git revert. After migration, tables/history are not
  deleted or down-migrated; use a reviewed forward fix. No external rollback exists because this WP
  creates no Provider/cloud resource.

Residual risk is explicitly deferred to WP-0108 invite/MFA/recovery/global revocation、WP-0109
Store/object/cross-Tenant composition、WP-2005 production DB roles and WP-2040 real Cognito/KMS/
Secrets Manager/WAF/deployment evidence.
