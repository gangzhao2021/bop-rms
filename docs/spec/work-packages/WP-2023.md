## Resolved test boundary

WP-2023 promotes the existing isolated PostgreSQL Outbox Dispatcher failure paths into one focused
acceptance. A transport rejection must persist one bounded error, clear the lease, retain the
unpublished immutable event and prevent immediate re-claim. A simulated Worker crash must allow
lease-expiry recovery; a stale lease cannot publish, the replacement lease completes, and the
Outbox retains one published row.

WP-0033 owns Retry/Dead-letter policy. This scenario does not clear a terminal error by direct SQL,
invent a retry schedule or add an external broker. It exercises only the accepted Dispatcher and
database functions.

## Acceptance and verification

- publish rejection records `TRANSPORT_REJECTED`, one attempt, no publication and no active lease;
- the failed event is not immediately reclaimed by the Dispatcher;
- expired crash lease is reclaimed with attempt `2`;
- stale lease completion returns `lost_lease`, replacement completion returns `completed`;
- one immutable published Outbox row remains and Tenant/Store RLS remains enforced;
- focused/affected/full local gates pass where isolated PostgreSQL is available; unavailable
  external/CI evidence is recorded without invention.
