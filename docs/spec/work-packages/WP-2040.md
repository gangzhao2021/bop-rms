## Resolved local boundary

WP-2040 materializes the repository-owned Authentication threat model for the accepted Merchant /
Admin same-origin BFF and server-side Session design. It enumerates assets, actors, data flows,
trust boundaries, misuse cases, mitigations, executable evidence and residual/external gates. A
deterministic validator prevents removal of mandatory threats or accidental conversion of external
gates into local pass claims.

The existing provider-neutral contracts and synthetic acceptance remain authoritative local
evidence. This WP does not register production routes, add a Provider SDK, create Cognito/WAF/KMS/
Secrets Manager resources, access credentials, use real workforce facts or claim a penetration
test. Those are External Evidence gates for production authentication enablement.

## Acceptance and verification

- the threat model identifies every authentication actor, sensitive asset, flow and trust boundary;
- STRIDE/misuse threats cover login CSRF, code injection, fixation, credential/token leakage,
  enumeration/credential abuse, MFA/recovery, expiry/revocation, Store/role changes, concurrent
  Sessions, cross-Tenant denial, Provider logout and storage compromise;
- every threat has preventive/detective controls, local evidence, owner and residual disposition;
- Cognito Plus, Threat Protection, WAF, KMS/Secrets and penetration evidence remain explicit gates;
- a focused validator and affected/full repository gates pass.
