# WP-2250 - Foreground Pickup Cart Creation Coordinator

## Authority and scope

Owner authorizes sustained bounded implementation and verified local commits. Baseline3482b4c,
branch codex/wp-2250-pickup-creation. Composite Sections0–97 and WP-2234–2237/2240/2245–2249
supply initial Pickup binding, current reads, private browser transport and exact foreground retry.
WP-2234 explicitly permits a new preparation operation after a lost preparation response because
prepare cannot create a Cart. After activation starts, the original candidate must be retained.

Add an opt-in in-memory coordinator exposing only CustomerCartClient.createCart. Require explicit
binding transport, safe current-Cart reader, CSRF get/set adapter, fresh UUIDv7 preparation factory
and online status. First read an existing authorized Pickup Cart. Otherwise prepare with a distinct
technical operation; retain delivered candidate CSRF/proof privately; activate and install candidate
CSRF only after the exact confirmed response, then read the safe server Cart. No raw Session Cookie
is readable by this coordinator. No authority or lifecycle success is inferred from the client clock.

Only explicit calls drive progress. Same logical operation coalesces during flight. Unknown prepare
may use a fresh preparation on a later explicit call; unknown activation first attempts completion
with the original candidate. If completion cannot finish and original context remains current, one
foreground attempt may activate the same candidate (covering activation that never reached server).
A completion failure never permits a new preparation/Cart after activation began. Failed post-
activation reads retry reads only. Reconnect causes no action; recheck online between each stage.
Different logical intent cannot replace a possibly activated operation. An unrelated CSRF context
is never overwritten. Duplicate completed logical intent reauthorizes through a current read.

CUST-CART and contextual CUST-SELLABLE-CONFIGURE keep their fields/routes/permissions/accessibility
and rendered states. This is an opt-in create adapter, not default App activation, item writes,
shared DineIn or general reload recovery. Credentials/proof stay in private closure memory and
never appear in returned Cart DTOs, storage, logs, analytics, URLs or errors. Existing Owner policy,
Audit, Session revocation and append-only history remain controlling.
