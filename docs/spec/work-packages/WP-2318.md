## Contract and acceptance

Extend the restricted Dining read snapshot with a closed, frozen viewer-authority tuple containing
current Guest/version, Participant/version, Dining Session version, Table/assignment, public Table,
QR/revocation version. This internal tuple is never a public DTO or permission lease. Preserve existing
Cart selection, attribution, null/expiry behavior and all read checks.

Provide a Dining customer display factory alongside the existing Pickup factory, sharing the safe
Catalog/Store display projection. Factory mode is fixed by composition, never client input. Dining
snapshots must be DineIn Qr/Web with lifecycle and a valid viewer tuple; Pickup behavior stays intact.
Re-read current authority and Cart after public dependencies return and deny Cart/context/viewer drift
or backward time before publishing. Closed parsing captures values before later asynchronous calls.

Expose only existing schema1 customer fields with DineIn service mode. Products, option names and
quantities are shared; only the current Participant's note is included. Other items return null note
and bounded OTHER_PARTICIPANT_ITEM warning. No internal Guest/Participant/Table/QR/scope, attribution,
Catalog evidence, raw credential or Audit information enters the public result or display requests.
The warning is a display hint, not server mutation authority. Dining Quote is null until its owning
composition exists; never load a Pickup creator-bound Quote or invent prices/taxes/line estimates.

Tests must cover two viewers of one immutable Cart, own-note minimization, exact public fields,
malformed and foreign snapshots, stale Cart/viewer/assignment/locale, expiry, dependency failures,
mutable capture, authority failures and unchanged Pickup/real PostgreSQL read regressions.
