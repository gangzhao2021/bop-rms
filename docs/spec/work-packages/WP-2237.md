# WP-2237 - Initial Pickup Cart Binding Owner

## Authority and scope

Owner authorizes sustained implementation and verified local commits. Baseline ecff48c, branch
codex/wp-2237-pickup-cart-binding. WP-1204 Cart lifecycle and WP-2234–2236 credential preparation
govern an additive Ordering owner for initial Pickup binding. Composite authority is unchanged.
Identity supplies acknowledged candidate context and a completion receipt through its public port;
Ordering never reads Identity tables or receives credentials or selector hashes.

Prepare creates an empty Cart with the immutable candidate Session as creator and an append-only
Prepared binding in one transaction with public Audit. Activate appends Active binding and Audit
from the exact Identity completion receipt. Only Active bindings are current. Replays preserve
original Cart identity, policy, timestamps and Audit. Delayed completion does not renew Cart expiry.
Required server configuration supplies versioned lifecycle policy, validity and source channel;
no actual Store configuration is invented. Authorization remains the caller's current Identity gate.

Multiple acknowledged candidates may prepare empty Carts for one predecessor. Identity's atomic
predecessor revocation selects one winner; Ordering additionally allows one Active binding per
predecessor. Unactivated expired preparations stay invisible and cannot block a new preparation.
Their historical rows are retained; cleanup/replacement and recovery of an existing basket remain
separate work. This WP does not implement DineIn, HTTP transport or application runtime registration.

The new append-only binding record serializes competing preparations before Cart insertion. Its
scoped Cart foreign key is deferred until the same transaction commits; a missing Cart rejects the
whole transaction. Existing Cart identity rules remain unchanged. This avoids unsupported upsert
against the existing ruled Cart table. Activation locks the Cart and appends only binding/Audit.
