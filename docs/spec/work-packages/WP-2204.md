## Goal and acceptance contract

Provide one explicit local-only Customer PWA preview that makes the accepted core journey
inspectable without creating or implying real Customer, Store, Cart, Quote, Payment, Order,
Delivery or Receipt facts.

1. One root `pnpm demo:customer` command starts the Customer PWA on strict loopback with a dedicated
   exact development flag and a finite process lifecycle controlled by the caller.
2. The exact flag selects a separate development entry only for Vite `serve`; normal development,
   normal production build and exact-flag production build continue to use the existing production
   entry and service-worker behavior.
3. The preview covers the canonical entry, menu, search, sellable detail, Cart, Checkout,
   Payment/result, Order status, Delivery status and Receipt routes using deterministic synthetic
   values and existing Screen components.
4. Every preview route displays a persistent `Local synthetic preview` / `Read-only training data`
   notice. Fixtures contain no real credential or token, real Tenant/Brand/Store/Actor, payment
   data, health fact, delivery location or unnecessary PII; the synthetic entry response uses only
   a non-secret required-shape CSRF placeholder held in page memory.
5. Menu add/configure actions are unavailable; Cart is visibly read-only; Checkout may display an
   immutable server-shaped Quote but payment remains disabled; Payment remains Provider-unavailable;
   Order, Delivery and Receipt projections expose no mutation.
6. The preview performs no fetch/XHR, Provider SDK call, service-worker registration, persistence,
   background replay, analytics or non-loopback request and never treats a route/reference as
   authorization.
7. Normal runtime behavior and every accepted failure/offline/security boundary remain unchanged.
   Production emitted assets contain no demo module, fixture marker or local preview authority even
   when `VITE_BOP_LOCAL_CUSTOMER_DEMO=1` is supplied.
8. Focus, landmarks, navigation, narrow-screen reflow, non-color state labels and existing
   accessibility semantics remain available. Browser automation is a later bounded WP, not evidence
   invented here.

## Risks, rollback and external boundary

- Risk: a demo dependency leaks into production. Use a separate entry selected only by Vite
  `serve`, dynamic import the demo module and scan both normal and exact-flag production assets.
- Risk: synthetic screens imply mutation authority. Keep all actions disabled or read-only and keep
  the persistent notice outside route content.
- Risk: fixture drift from accepted parsers. Reuse exported public types and exercise the existing
  page/controller contracts in tests.
- Rollback: revert the single WP-2204 integration to remove the demo entry, fixtures and scripts;
  normal Customer behavior is otherwise unchanged.
- External Evidence: unavailable and unclaimed. No real Guest Session, Store, Customer, Cart,
  Quote, Payment, Order, Delivery, Receipt, Provider result or production activation is required.
- Owner authorization covers this bounded brief, implementation, verification, commit, push, PR,
  review, merge and exact-main verification. Deployment and Provider action remain excluded.
