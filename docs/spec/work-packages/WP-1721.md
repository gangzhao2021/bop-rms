## Closed template contract

Notification owns one deterministic transactional-receipt renderer for `en-CA` and `fr-CA`. Its
strict typed input contains only already-approved receipt display facts: Store display name, Order
number, issue instant, immutable line summaries, tax and total. Money is non-negative bigint minor
units and Phase 1 email is CAD-only. The localized subject is fixed and contains no Order, Store,
recipient or Payment detail.

React DOM Server escapes every dynamic HTML value. Plain text uses the same validated values. The
HTML has a single semantic heading, language declaration, labelled receipt table and owned inline
styles. The renderer exposes no raw-HTML input and emits no image, remote font, URL, link, script,
form, tracking pixel or marketing content. Header values are fixed from the locale allowlist and
cannot contain caller-controlled CR/LF.

## Acceptance and verification

- input parsers reject open bags, accessors, controls, unsupported locale/currency, unsafe quantity,
  inconsistent totals and oversized content;
- HTML and plain-text alternatives contain equivalent immutable receipt facts in localized labels;
- injection fixtures are escaped and cannot create script/form/image/link/event-handler markup;
- subject and headers are non-sensitive fixed values with no CR/LF or recipient field;
- Notification tests, frozen lockfile, format/lint/typecheck/build, architecture and
  security/privacy review are required locally.
