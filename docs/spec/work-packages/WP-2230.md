## Implementation and acceptance

1. Expose an Ordering-owned, scoped read-only adapter for the existing Cart Item operation port.
   Bind Brand, Store and operation references as SQL parameters; set transaction-local Tenant scope.
2. Reconstruct and freeze the original result snapshot, fingerprint and timestamps without reading
   current Cart contents, renewing expiry, granting authority or changing historical records.
3. Validate returned operation identity, snapshot/header Cart and scope, aggregate version,
   action/item consistency and exact 24-hour retention. Corruption yields a bounded dependency error.
4. Unit regressions cover absent rows, mismatched/malformed data, frozen scope/results and safe
   failures. Real isolated PostgreSQL tests prove restricted role/RLS scope, historical snapshot
   reconstruction across adapter recreation and read-only behavior. No production data is used.

The caller must authorize before invoking this adapter and recheck Session/item scope and operation
expiry through the existing command service. The adapter returning a historical record does not
mean its replay is currently permitted. Notes in snapshots remain restricted internal data and
must never become logs, URLs or unrestricted API payloads. No migrations, writers, Cart creation,
Session binding, recovery credentials, UI, dependency changes or external action.
