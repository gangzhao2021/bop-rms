## Bounded storage decision

Exactly two owner tables are added: dining_table (current aggregate) and dining_table_operation
(append-only complete operation result, including the existing minimal future Event fact). Each carries
Tenant/Brand/Store scope; critical keys/FKs include scope. Brand/Store RLS is enabled and forced,
PUBLIC has no privileges, runtime grants remain test-only. Versions use bigint constrained to the
existing Domain's safe integer range; quantities, QR state, UTC instants and lifecycle retain their
accepted meanings. Operation records preserve every configuration result; no history is overwritten.

A scoped owner adapter implements only loadTable, resolveTableOperation and commitTable. It performs
exact canonical Command-intent and result validation, operation serialization, expected-version
comparison, Table change, immutable operation append and public Audit append in one transaction.
Canonicalization uses parsed Table facts, so property order cannot change an otherwise identical
operation. Request-time and retention semantics are unchanged. Concurrent same-key requests converge;
changed intent and competing versions conflict. Lost acknowledgement is recovered from original
history, and Audit failure rolls back the entire owner write. Existing Table/Move replay guards remain.
Shared bounded record-snapshot helpers are extracted only for these two concrete consumers.

This stores the existing future Event payload as part of its owner operation record; it does not
register, publish or dispatch an Event/Outbox message. Session/Participant/Join/Move/Closing persistence,
current participation snapshots, shared Cart binding and HTTP activation remain separate owning work.
