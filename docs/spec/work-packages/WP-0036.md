## Canonical identity、ownership and responsibility

The canonical title is:

**`WP-0036 — same-origin SSE Realtime Hint Transport、Scope Revalidation and Reconnect Contract`**

The owning boundary is Platform / API transport, with mandatory Security、Frontend and Operations review. `apps/api` owns HTTP/SSE composition and lifecycle only. It does not own authentication、Session facts、Tenant/Store membership、business permissions、Projection facts or browser screens.

WP-0036 delivers the smallest provider-neutral kernel that:

1. exposes the canonical Merchant route `/bff/realtime` as a same-origin credentialed SSE endpoint;
2. fails closed until an injected server-authoritative Session/scope adapter is configured;
3. derives Brand、optional Store、permission and session kind from that adapter and permits a client filter only to narrow the authorized Store scope;
4. emits only validated, minimal, lossy Realtime hints and never a Domain Event、Command、Audit fact or source-of-truth snapshot;
5. sends 15-second heartbeats、enforces a maximum two-hour lifetime and revalidates authorization at least every 60 seconds plus an injected Store/role change signal;
6. enforces three streams per Merchant Session and two per Guest Session through an injected shared connection-registry port;
7. drains on graceful shutdown with `system.reconnect` when possible and no new admission after readiness begins failing;
8. defines the browser reconnect/query-refresh contract with exponential full-jitter delay bounded from 1 to 30 seconds and no command replay;
9. proves cross-Store denial、revocation closure、duplicate/missed recovery、no-buffer headers、limits、drain and synthetic multi-instance behavior.

This WP consumes no Eventing table and changes no WP-0030–0035 public contract. A future Projection owner may call the narrow hint publisher only after its own Work Package authorizes a concrete hint type/resource and permission mapping.

## Accepted Owner Decisions

The composite authority did not uniquely fix the following implementation details. The Owner's instruction accepts every recommendation:

1. **Owning boundary** — Recommended: keep the kernel in private `apps/api`; do not create a new Domain package or change `@bop/eventing`. Impact: SSE remains an HTTP composition concern and cannot become a second Event bus.
2. **Route boundary** — Recommended: implement only canonical Merchant `/bff/realtime` now. Model Merchant and Guest limits in the kernel, but defer the unspecified Guest Session URL and real Customer mounting to its owning future WP. Impact: avoids inventing a public Customer route.
3. **Authentication boundary** — Recommended: require an injected async authorizer/revalidator returning a server-derived opaque session key、kind、Brand、optional Store、permission and revision. Missing adapter returns safe `503`; denial returns stable `401/403` without scope detail. Impact: proves the transport without inventing Identity facts or credentials.
4. **Same-origin proof** — Recommended: require exact configured Origin plus `Sec-Fetch-Site: same-origin` and `Sec-Fetch-Mode: cors`; reject missing/mismatched metadata. No OAuth、Guest token or Session identifier may appear in query or `Last-Event-ID`. Impact: fails closed and remains compatible with credentialed native `EventSource`.
5. **Scope filter** — Recommended: optional `storeId` filter may only equal the server-authorized Store；Brand-wide subscriptions cannot be requested by a Store-scoped Session, and no client Brand filter exists. Impact: prevents cross-Store discovery and arbitrary subscription.
6. **Hint contract** — Recommended: one validated envelope containing `messageId`、stable bounded type、positive version、UTC `occurredAt`、authorized scope、resource type/ID and positive projection version；no open `data` bag in WP-0036. Impact: minimizes leakage while concrete hint catalogs remain with WP-1405/WP-1705.
7. **Initial/reconnect refresh** — Recommended: stream admission emits a transport control `system.refresh` instruction rather than a business hint；the browser contract immediately runs its canonical Query on every open/reopen. `Last-Event-ID` is validated only as a bounded opaque diagnostic and never replayed or authorized. Impact: missed/duplicate delivery converges without storing replay history.
8. **Connection ownership** — Recommended: use an injected atomic connection registry with acquire/revalidate/release; ship a bounded in-memory implementation for local/synthetic evidence only. Multiple API instances can share the same injected registry in tests. Production distributed coordination and measured capacity remain External Evidence. Impact: defines exact semantics without a migration、Redis or broker.
9. **Excess/supersession** — Recommended: return `429` with bounded `Retry-After` when the per-Session limit is reached. WP-0036 never guesses which stream to replace；explicit supersession remains unavailable until a future browser contract supplies a safe native-EventSource-compatible mechanism. Impact: complies with “replaces only an explicitly superseded stream” by replacing none implicitly.
10. **Timing and lifecycle** — Recommended: fixed defaults of 15-second heartbeat、60-second revalidation、two-hour maximum lifetime and 25-second drain deadline; tests may inject bounded shorter timers. Revalidation also runs immediately on an injected revision-change signal. Impact: deterministic acceptance without environment variables or deployment configuration.
11. **Reconnect policy** — Recommended: pure client policy with full jitter over exponentially increasing caps from 1 to 30 seconds, reset after a successful open; reconnect always queries and never replays a Command. Native EventSource integration remains with the consuming frontend WP. Impact: closes the behavioral contract without editing a screen.
12. **Readiness/drain** — Recommended: the kernel exposes readiness and `beginDrain`; admission returns `503` after drain starts, active streams receive `system.reconnect` when writable and then close, and all timers/listeners/leases release idempotently. Impact: process entry can compose it later without hidden globals.
13. **Observability** — Recommended: expose only bounded counters/outcomes through an injected sink: session kind、operation、safe result code、count/duration bucket. Prohibit Session/Tenant/Store/resource/message IDs、URLs、payloads and raw errors. Impact: supports safe acceptance while production telemetry remains WP-0040–0045.
14. **Persistence/dependencies** — Recommended: no migration、database object、runtime grant、new dependency or lockfile change. Impact: avoids unauthorized ownership changes and external coordination.
15. **Dedicated gate** — Recommended: add root `pnpm realtime:acceptance`, run it in owning Linux CI, and retain all WP-0030–0035 dedicated regressions. Impact: exact-head evidence is repeatable and cannot hide behind the general suite.

## Permission、Tenant/Store and data contract

- Primary authorization is the injected server-side adapter. RLS is irrelevant because this WP owns no database access.
- The adapter must return an opaque bounded session key and authenticated kind (`merchant` or `guest`), Brand ID、optional Store ID、permission and revision. The transport does not parse cookies、tokens or identity claims.
- `/bff/realtime` requires a Merchant session and exact `realtime:subscribe` permission. A Guest result on the Merchant route is denied.
- A Store-scoped session may subscribe only to that Store. Brand-wide scope is allowed only when returned directly by the authorizer and a client cannot widen to it.
- Every emitted business hint scope must exactly match the active server-derived scope. Cross-Brand or cross-Store hints are rejected before writing.
- Revalidation compares active、permission、kind、Brand、Store and revision. Any revocation or widening/change closes before another business hint.
- Identifiers are internal scoped references and are never logged、used as metric labels or exposed in errors.

## Security and privacy gates

### Assets and trust boundaries

- Browser → same-origin API: untrusted Origin、Fetch Metadata、query and `Last-Event-ID`.
- API → authorizer/revalidator: trusted injected Application port; no credential material returned.
- Projection owner → hint publisher: untrusted until schema and active-scope validation pass.
- API instance → connection registry: atomic lease/limit boundary; production implementation remains externally gated.

### Required controls

- exact same-origin and Fetch Metadata validation before stream admission;
- no query token、authorization value、cookie parsing or `Last-Event-ID` authorization;
- safe bounded error envelopes before streaming and no internal error after headers commit;
- `Content-Type: text/event-stream`、`Cache-Control: no-store, no-transform`、`X-Accel-Buffering: no` and no compression middleware;
- CR/LF-safe SSE field encoding and bounded frame fields;
- no arbitrary `data` payload、free text、contact、note、payment、allergy/health、credential、token or unrestricted PII;
- low-cardinality telemetry only;
- all timers、listeners and leases released on denial、abort、revocation、expiry and drain.

## Error、rollback and recovery

- Before stream admission: stable `400/401/403/429/503` JSON errors with no reflected identifier or authorization detail.
- After headers commit: never switch to JSON or expose an exception. Stop business hints、best-effort send a bounded control frame when allowed, release resources and close.
- Authorizer、registry or telemetry failure denies admission or closes safely; telemetry failure never authorizes or keeps a revoked stream open.
- Missed/duplicate hint recovery always re-runs the canonical Query. No replay store、cursor authority or command replay exists.
- Before merge: normal reviewed Git revert.
- After merge but before live wiring: revert the route/kernel composition and retain no data because WP-0036 owns no persistence.
- After future live wiring: rollback stops new streams、drains existing streams and falls back to explicit stale/manual refresh behavior owned by consuming screens. It must not invent current Projection state.
