## Acceptance contract

1. A stable Metric Definition owns Metric ID/code, owner Domain / Business Owner and lifecycle.
   Every semantic change creates an immutable Version pinning display/definition codes, formula or
   expression reference, base Fact reference, grain, allowed dimensions, required filters, time and
   currency semantics, inclusion/exclusion rules, null policy, effective period and snapshot digest.
   No SQL, executable expression, source row, amount or unrestricted prose is accepted.
2. Lifecycle is `Draft → InReview → Certified → Deprecated → Archived`. Certified publication
   requires passing validation plus accepted, current Business Owner and Data Owner approvals from
   distinct authorized Actors who are not the Version author. Semantic changes return through a new
   Draft Version; history is never rewritten.
3. Certified Lineage pins Dataset, transformation, expression/query and dependency references plus
   build/freshness/quality metadata. Impact validation occurs before certification. Lineage is
   metadata only and never queries another Domain's private table or claims a successful real build.
4. Deprecation preserves historical use and may point to an existing Certified replacement Metric;
   it never substitutes historical Report/Dashboard Version references. Every mutation carries
   exact Tenant Context, Actor, purpose, Permission, expected aggregate version, idempotency, Audit
   and atomic Event composition.
5. `BI-METRIC-CATALOG` exposes ID/name, definition, grain, owner, lifecycle/certification, version,
   lineage and SLO with canonical filters/actions. `BI-METRIC-DETAIL` exposes semantic contract,
   dimensions/exclusions, time/currency rules, controlled examples, lineage, validation and history.
   All universal Section 88 states and permission-gated actions are represented.
6. Forced Brand/Store RLS, explicit PUBLIC revocation, append-only Versions, lineage, approvals and
   operation records, ownership metadata, migration and isolated PostgreSQL acceptance pass without
   real Warehouse data, source facts, KPI targets, Data Quality results or external evidence.
