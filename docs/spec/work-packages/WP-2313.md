## Acceptance and owner contracts

Ordering owns an internal read service for one current shared Dining Session Cart. Closed input is
current sessionCredential plus optional cartReference filter; the reference never grants authority.
Current Identity must resolve an active usable DineIn/DiningBound Session in exact fixed Brand/Store
with Participant and public Table. The public purpose-Cart Dining query must return exact fresh coherent
participation scope, Session/Participant/Table and versions. Resolve Identity again after the Dining
await before any Cart lookup. The context must still be the same; no Activity renewal or credential
rotation is requested. Repeat this authorization after Cart lookup, including absence, and reject
identity, assignment, Session/Participant version or temporal drift before returning anything.

The Cart lookup receives only fixed Brand/Store, authorized Dining Session and observation time. Parse
and freeze owner data before subsequent asynchronous calls. Require DineIn, exact scope/Session,
Qr/Web source, valid existing lifecycle and nonfuture timestamps. Sharing deliberately does not require
Cart.createdByActorReference to equal the current Guest: immutable creator/item attribution remains.
Optional foreign Cart filter and missing current Cart return the same null outcome after authorization.
Compute effective expiry for display without mutating stored history. Result is restricted owner-internal
Cart/context/status, not a public HTTP DTO, membership grant, write lease or new owner fact.

Read/query only: no migration, Cart creation, persistence implementation, shared item writes, host
override, Closing write fence, generic Pickup changes, API/UI, dependency changes or deployment.
Existing purpose-Cart Dining query denies Closing; do not reuse it for Identity, which has distinct
Closing semantics. Actual table mapping and consumed-admission authority remain Identity's contract.
