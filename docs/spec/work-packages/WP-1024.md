## Purpose

Implement the smallest Catalog-owned Menu publication lifecycle that proves:

1. an immutable Menu Version snapshot moves through Draft、In Review、Approved and Published；
2. validation and independent approval evidence are exact-snapshot、exact-scope and fresh；
3. publish creates an append-only release plus an approved effective period；
4. overlapping effective releases in the same Menu/scope fail closed；
5. publishing a replacement supersedes the previous release without mutating its snapshot；
6. archive ends serving eligibility while retaining release history；and
7. Brand Tenant Context、`catalog.menu.*` permission、Audit、idempotency and optimistic concurrency guard every command.

## Adopted boundaries

- `RMS-CAT-MENU` is a Catalog-owned Configuration scoped to one Brand plus explicit Store、Channel
  and Order Type selectors already captured in the immutable Menu Version snapshot.
- Published versions are immutable. Correction or rollback is represented by a new approved
  version/release; no published snapshot is edited in place.
- Effective time is explicit and overlap is rejected for the same Menu and scope.
- Menu inheritance remains at most one level and is validated before review.
- WP-1025 owns the Published Menu Projection. WP-1026 owns customer-facing API behavior and
  WP-1027 owns the publish screen. This WP adds no Projection、API、Event、scheduler or UI.

## Acceptance

- exact snapshot evidence is required for review and approval；
- expired、future、wrong-scope or mismatched evidence is rejected；
- illegal lifecycle transitions and mutations of a published snapshot are rejected；
- publish is atomic、idempotent and optimistic-concurrency guarded；
- same-scope effective overlap is rejected；
- Brand RLS is forced and command/release history is append-only；and
- WP-1020–1023 database acceptance remains green.
