## Acceptance and design

Add a Dining-owned current-context assertion and an API composition using public Identity and Dining exports only, with explicit scoped owner
stores, credentials, current Session binding, recovery provider, preparation lifetime and clock.
A current Guest context provider returns the existing closed QrTableContextEvidence for this
Session and observed time. Validate exact Brand/Store/public Store/public Table/channel/revocation,
active lifecycle/assignment/QR state and finite future validity; never equate public and internal
Table IDs, reconstruct signed QR payloads or invent expiry. No default production policy.

Each prepare/activate/complete invocation creates its own credential/context closure. Identity
performs actual Session/CSRF authorization; Dining Guest resolution reauthorizes that same exact
Guest/session version before resolving current context. No shared request state or reference-only
lookup bypass. Raw credentials stay inside Identity-facing invocation memory and are never sent to
Dining/context owner requests, logs or persistence. Context provider receives only parsed Session.

Map real read-only Dining reservation to exact Identity target evidence using the validated public
context, then map real consumed admission to Allowed Identity evidence only after current context
and Guest revalidation. Keep all owner writes/retries inside existing owner services/stores. Unknown,
stale, cross-scope or malformed evidence denies with a fresh bounded Identity error. Activation and
lost-response recovery retain the original delivered candidate; current bound Dining authorization
remains an explicit Session binding port. Query observations are not write leases.
