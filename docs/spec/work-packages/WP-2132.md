## Owning facts and boundaries

Procurement owns the Brand-scoped Supplier Item Offering identity, append-only purchasing
configuration Versions and append-only Supplier Price Records. Supplier and Inventory Item facts
are consumed only through public, version-bound eligibility snapshots. Inventory owns Item identity,
base unit and stock facts; Procurement never reads its private tables. Purchase Orders consume an
approved Offering/Price snapshot but are not implemented by this package.

## Acceptance contract

1. Model Supplier Item Offering as a stable Aggregate Root referencing exactly one Supplier and one
   Inventory Item. Identity changes create a new Offering; configuration changes append a Version.
2. Version supplier item code/name, purchase unit, exact decimal pack-to-base conversion, MOQ, order
   multiple, lead time and restrictions. Reject zero/negative values and binary floating-point input.
3. Keep Supplier Price Record identity and Versions separate from Offering configuration. Version
   currency, exact decimal unit cost, price unit, quantity tiers, Effective Period, source and scope;
   never overwrite historical price evidence.
4. Enforce Draft → Submitted → Approved → Published workflow with distinct submitter/approver,
   Expected Version, approval reference and exact Supplier/Item/qualification/conversion validation.
   Publish is unavailable when Supplier, Item, qualification, price or conversion inputs are stale.
5. Resolve an approved price deterministically by the Section 31.19 precedence, Effective Period,
   scope, currency and quantity tier. Same-priority ambiguity fails closed; manual line price is absent.
6. Define strict `procurement_offering_v1` list/editor projections with Brand scope, 30-second
   freshness, cursor pagination, permission-trimmed cost/qualification/history and no fabricated
   zero/null dependency facts.
7. Authorize before idempotency, repository, dependency, policy, impact or audit work. Commands bind
   Actor, purpose, permission, operation reference and Expected Version, with atomic Audit and strict
   Tenant/Brand/Offering replay ownership.
8. Implement canonical `SUP-OFFERING-LIST` and `SUP-OFFERING-EDITOR` routes, registered fields and
   filters, explicit stale/partial read-only states, omitted unauthorized actions and adjacent blockers.
