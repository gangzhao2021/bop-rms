## Scope and contracts

Add an opt-in API composition using the real Identity service and Ordering public service. Cookie
and CSRF verification remain Identity-owned; read requests use Background resolution and never
renew the Session. Per-request scoped dependencies derive from the authorized Session, never from
client IDs or mutable shared request state. The existing transport keeps Origin/Fetch Metadata,
Cookie/header/body checks, output validation, no-store and bounded error contracts unchanged.

Ordering owns the safe Customer Cart DTO. Move the existing DTO type there without changing its
wire shape and add a strict builder for a pristine version-1 empty Cart. It exposes only the
existing public fields. Scope-bound, purpose-labelled public display content is an explicit source
port; its real Store adapter remains a prerequisite for activation. Do not relabel Store's existing
CustomerEntry-only query as CustomerCart. Missing/mismatched content fails closed. No display label,
service mode, money, Quote or catalog result is synthesized by production code. Non-pristine/nonempty
Carts fail unavailable until their Catalog/Pricing-backed query increment exists.

Create/current/read-by-current-reference use the new composition. Foreign references return uniform
NotFound. Add/Update/Remove remain explicitly unavailable; no partial fake mutation is exposed.
Create and original-result replay map to existing 201/200 semantics; authorized Session is rechecked
before every replay. The domain still owns lifecycle/ownership/idempotency/Audit. Readiness remains
unconfigured unless an environment supplies dependencies. No UI or Screen contract changes.

## Acceptance

1. Strict Ordering DTO builder checks scope, lifecycle, display purpose and allowed fields; rejects
   nonempty/non-pristine Carts and leaks no internal scope, Actor, policy digest, credentials or audit.
2. API composition uses public Identity/Ordering contracts, isolates overlapping requests, rechecks
   Cookie/CSRF/binding, preserves non-mutating reads and controlled errors, and returns uniform 404
   for a foreign Cart reference. Missing display or dependencies never produce synthetic success.
3. Real HTTP plus isolated pooled PostgreSQL prove valid Session -> create -> fresh read -> replay,
   denied Cookie/CSRF/origin, another Session, audit/Cart atomicity and safe responses. Test credentials
   are ephemeral; Store/display/policy admission inputs are explicitly synthetic source fixtures.
4. Retained API tests, ownership/domain/contracts/migrations, frozen install and full local verify
   pass. No skipped/unrun check is represented as passed; no new external readiness is claimed.
