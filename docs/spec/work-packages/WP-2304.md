## Acceptance and design

Compose real Identity Session authorization and Dining joinCurrent through public ports. Closed
input is sessionCredential/csrfCredential/joinCredential/operationReference; server supplies time.
Capture inputs and fixed Brand/Store scope before awaits. Require current ContextOnly DineIn Guest
with a public Table and current base Session policy. Dining-owned current QR-context assertion
checks public-to-internal Table mapping, scope, lifecycle, revocation and validity; never fabricate
signed QR data. Reauthorize the same captured Guest/Session when Dining asks for Guest evidence,
and before returning the narrow result. No request-global mutable identity or credential state.

Each invocation separately requires a trusted server-side abuse port, already bound to the request's
canonical IP-device context. Capture its admit method before awaits. It is a distinct server argument,
never a field trusted from browser JSON. No default Admitted, raw IP/device, caller-supplied abuse
scope or invented production provider. Dining keeps its existing one abuse admission before reads
and history; actual IP-device policy production remains an explicit runtime gate.

Supply only join store operations/credentials to the composition; unexposed Staff/start/regenerate
operations deny. Owners retain all policy/effects and atomic versions. Return only Joined plus exact
operationReference/admissionReference after current authority checks. No internal Session/Table/
Participant/Host, raw credential/hash, version plan or Identity rotation in the result. Unknown,
revoked, wrong scope/context, cooldown or dependency failures remain bounded. A post-commit denial
is not rollback; current original-op retry may recover its admission.
