# WP-2164 — Data Quality and cross-domain Reconciliation Workbench

## Authority and scope

- Handoff Sections 38.14–38.19, 38.31–38.33, 48.4–48.7, 50.2–50.3, 88.15 and
  88.22–88.30 define append-only Data Quality results, cross-domain Reconciliation exceptions and
  the `BI-DATA-QUALITY` / `BI-RECONCILIATION` screens.
- Exact local predecessor: verified WP-2163 commit `3839f3d`.
- `@rms/business-intelligence` owns Check definitions/results, Reconciliation Run/Exception and
  investigation/resolution metadata in `rms_reporting`. Source Domains own every compared Fact,
  Ledger and Snapshot; access is through public, permission-trimmed observations only.

## Acceptance contract

1. Versioned Data Quality Checks use the closed first-version kinds `Completeness`, `Uniqueness`,
   `ReferentialIntegrity`, `ValidRange`, `Timeliness`, `Reconciliation`, `SchemaCompatibility` and
   `CurrencyTimezoneConsistency`. Definitions pin Dataset/partition references, rule/expectation
   codes, severity, owner, scope, effective period and idempotency without SQL or executable rules.
2. Each execution creates an immutable Result with exact Check Version, Dataset/partition, expected
   and actual controlled observations, severity, status, detected time and affected period/scope.
   A Critical failure may record `BlockFormalReporting`; it never blocks business transactions or
   mutates a source Domain. Acknowledge, assignment, incident and backfill-request intents are
   append-only metadata; WP-2165 owns actual Pipeline/backfill execution.
3. Reconciliation Runs pin one accepted control (`OrderItemTotal`, `PaymentLedger`,
   `InventoryLedger`, `PurchaseOrderReceipt`, `LoyaltyLedger`, `OutputAttempt`), period, scope and
   exact public source observation references. Expected/actual/difference values are signed base-10
   strings with an explicit unit/currency code and never binary floating point.
4. A non-zero difference creates an immutable Reconciliation Exception. Investigation and
   resolution record safe codes and evidence references without editing source facts. Resolution
   requires a new rerun Result; all previous Runs, differences and findings remain queryable.
5. Every mutation revalidates Tenant Context, Actor, purpose, Permission, expected version/sequence,
   idempotency and Audit and composes strict Events atomically. Cross-domain private tables, raw
   payloads and source identifiers are prohibited.
6. `BI-DATA-QUALITY` and `BI-RECONCILIATION` expose the canonical fields, filters, actions,
   permission gates and all universal Section 88 states. Forced Brand/Store RLS, PUBLIC revocation,
   append-only persistence, ownership metadata, migration and isolated PostgreSQL acceptance pass
   without real source facts, real differences or external evidence.
