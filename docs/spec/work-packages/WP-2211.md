## Acceptance and decisions

1. Add a forward-only Identity-owned operation-result table with typed copies of the existing
   Guest Session record fields, unique operation ID, forced Brand/Store RLS and database-enforced
   append-only update/delete/truncate rejection. Store only existing selector/intent hashes and
   bounded state, never raw credentials or arbitrary JSON. No backfill or invented historical fact.
2. The existing opt-in factory implements the full store port. Creation and rotation atomically
   insert the new Session and immutable operation result; revoke atomically records the terminal
   state and operation result. Touch never edits history. Existing Session operation ID/intent
   remain unchanged by revoke. All SQL is scoped and parameterized on a dedicated transaction.
3. Rotation locks and validates the current Active, usable, expected-version record and fresh
   version-1 replacement with new credentials/reference, exact predecessor and same Brand/Store.
   DiningBound replacements preserve existing context and require BindingChanged. Revoke permits
   an expired-by-time Active record but never a terminal record or backward time. CAS conflicts
   are bounded. Failed/unknown commits never retry or issue credentials for a different insert.
4. Resolve operations from immutable results, with read-only fallback for pre-journal rows.
   Legacy rows without an original journal result remain readable/touchable but lifecycle writes
   fail closed. No claim that unavailable original history can be reconstructed. Deploying across
   old/new writers or migrating such rows requires a separately reviewed rollout, not this WP.
5. Fix service rotation replay ordering to check exact operation intent before rejecting the
   now-revoked predecessor. Replays return AlreadyApplied without credentials; changed intent
   conflicts. No new browser route, admission fact, authorization or production activation.
6. Unit and isolated PostgreSQL acceptance cover creation/history, reconnect, touch immutability,
   rotate/revoke/replay, credential invalidation, competing writes, scope/RLS, terminal/version
   guards, rollback/unknown commits, append-only enforcement and no raw credential persistence.
