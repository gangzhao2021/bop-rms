## Scope and acceptance

Allowlist: this brief, docs/spec/README.md, packages/rms/fulfillment/src/index.ts,
packages/rms/fulfillment/src/domain/scheduled-capacity.ts and
packages/rms/fulfillment/src/tests/scheduled-capacity.test.ts.

- Capture exact inert scoped slot, Hold and Allocation data. Reject getters, unknown fields,
  invalid UTC instants/references, fractional/unsafe units and invalid lifecycle histories.
- Preserve Brand/Store tenancy, type, slot/config version, immutable units/rule input digest,
  Cart and operation provenance. Approved upstream slot resolution owns IANA zone/Business Date;
  these functions receive the resolved UTC slot and never infer local scheduling facts.
- Check expected versions and exact scope before proposing a transition. Conversion returns both
  terminal Hold and new Active Allocation with zero occupancy delta, preserving original Hold.
- Expiry is exclusive; release/expiry returns Hold units once. Allocation consumption begins at
  slot start or authoritative Fulfillment InProgress, whichever is earlier. Consumed capacity
  is never returned; terminal objects never reopen.
- Admission arithmetic fails closed on insufficient capacity including configuration reductions.
  This arithmetic is not a concurrency guarantee: future owner persistence must lock the slot,
  include all committed occupancy, append history/Audit/Outbox and enforce permanent idempotency
  in the same transaction. Pure functions neither perform replay lookup nor claim durable facts.

No database/schema/migration/API/Provider/UI change. No ASAP policy, TTL extension, Manager adjustment,
payment clock/expiry producer, reschedule coordinator, permission grant or final Inventory evidence.
Actor/purpose/permission/current tenant context, operation replay and audit are mandatory at the
future application/persistence boundary; these pure proposals are not exposed customer commands.
All identifiers are internal Confidential references; bounded errors disclose no raw input.
