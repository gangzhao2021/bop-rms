## Resolved implementation boundary

WP-2048 adds the accepted shared `security.abuse_bucket` atomic PostgreSQL boundary. It stores only
a purpose-separated 32-byte keyed hash, closed bucket class, fixed time bucket, policy limit/count
and UTC expiry. One atomic upsert decides admission under concurrency; policy changes within an
active bucket fail closed. Raw buckets expire after 24 hours through a separately permissioned
cleanup function.

The focused matrix composes the existing strict capability/token scope suites and proves eight
concurrent Pickup attempts yield exactly five admissions, over-budget results have a bounded retry
delay, Order Resume uses an independent keyed scope, runtime has execute-only access and no raw
IP/device/contact/Order/Fulfillment identifier enters the table. Application routes must fail closed
when this dependency is unavailable; public-read WAF degradation and real trusted-proxy/pepper/load
evidence remain external composition gates.
