## Manifest contract

Each future business Module root will own a `module.manifest.ts` that uses the tooling contract and declares:

- module name, `BOP | RMS` layer, and `Phase 0 | Phase 1 | Later` lifecycle;
- public export subpaths and allowed synchronous Module dependencies;
- consumed and published event contract names;
- future database schema/table ownership declarations only;
- owned jobs, feature flags, kill switches, PII classification, and an accountable owner role.

Arrays are deterministic sets: duplicates are invalid. A Module cannot synchronously depend on itself, and a BOP Module cannot declare an RMS synchronous dependency. Public exports must be package export subpaths and cannot expose source, private, internal, Domain, infrastructure, persistence, adapter, ORM, or database paths. Data classification is an explicit closed vocabulary with safe handling declarations; `none` cannot be combined with another class, and sensitive classes cannot be declared safe for logs, URLs, analytics, or non-synthetic fixtures.

Owned database fields are metadata for future ownership enforcement only. Validation never connects to a database and creates no schema, table, migration, model, seed, or Repository.

## Risks, rollback, and boundaries

- Risk: a contract that is too permissive would defer unsafe declarations to later WPs. Mitigation: closed vocabularies plus schema and semantic validation with negative fixtures.
- Risk: this WP could accidentally become WP-0012 or WP-0013. Mitigation: validate only supplied/committed Manifest values; do not scan imports, module directories, database catalogs, migrations, or ORM code.
- Rollback: normal reviewed Git revert. There is no data, Provider, deployment, or Figma rollback.
- External Evidence: real Module owners, actual schemas/tables, business events/jobs/flags, Provider/account/legal/Store facts, production readiness, and future architecture-test results remain later-WP or external gates.
- Next allowed Work Package: `WP-0011` only after WP-0010 is integrated and separately authorized.
