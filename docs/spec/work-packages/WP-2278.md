## Bounded transaction

Implement resolveJoinState, resolveJoinOperation and join over Dining-owned storage. A coherent
selector-hash reader binds Tenant/Brand/Store, returns current Active Session plus the exact matching
capability (including consumed history for exact replay), and fails closed on multiple matches.
It exposes no raw credentials or automatic HumanCode reuse/recovery rule.

Create scoped Participant, Identity admission and immutable Join-operation tables. Opaque Guest
Session references occur only in restricted owning operation history for intent verification and
same-Guest/Session duplicate prevention; no account/device/contact inference is made. Admission
issuance is a Dining fact; consumption and Identity credential rotation are separate work.

Validate copied closed record, exact canonical Guest/capability intent and expected versions. Use
operation lock, shared Dining Table lock/row, Session row and capability row in that order. Recheck
current Published/Available occupied Table, exact Active Session assignment/version and expected
capability/version. Recompute public capability consumption and exact next Session, Participant and
admission invariants. Consume credential, advance Session once, assign first Host only, insert one
Participant/admission/original operation and append public Audit in one transaction. Same operation
and Guest/intent converges; changed intent, stale state or competing Guest consumption conflicts.
The same unrotated Guest Session cannot create duplicate participants within one Dining Session.

The injected bounded Audit factory creates a validated System actor record for DINING_SESSION_JOIN,
DiningSession target, CUSTOMER_PWA source and Restricted classification, with no before/after
summaries. It never labels the Guest Session as a workforce User. Audit appends through the existing
public in-transaction contract; failure rolls back every write. Public service remains responsible
for current Guest context and abuse admission; the adapter is not an authorization API.
