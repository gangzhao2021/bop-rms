## Contract and ownership

The Projection Builder may rebuild one exact Tenant / Brand / Store / Business Date generation from
an immutable source checkpoint. The Command requires exact `projection.rebuild` permission and is
idempotent, names the expected
active generation, target Projection version, source cutoff, bounded batch size, Actor and purpose.
It writes only a new shadow generation. Source pagination must retain one checkpoint; shadow
validation must complete before the persistence adapter atomically switches the active generation
and appends the linked Audit. Any failure abandons the shadow and leaves the active generation
available.

This contract never deletes or changes source facts, treats `domain_event_log` as the sole source,
allows Reporting Role writes, or authorizes a Projection to decide business or financial finality.
Durable `platform_projection` persistence, lease/job registration, Worker composition, database ACL
and real rebuild drill remain unavailable and unclaimed; WP-2025 owns the failure-injection scenario.
