## Contract and transaction

Add one owner-scoped append adapter accepting a complete v1 Quote and required minimal Audit.
Copy/validate all inputs before I/O. Exact Brand/Store, action PRICING_QUOTE_CREATE, target type
PricingPriceQuote/Quote reference, reason AUTHORIZED_CART_QUOTE, System actor, CUSTOMER_PWA,
Restricted classification and Quote-created timestamp are required. Disallow before/after summaries,
correction and device fields. Caller owns current authorization and retention-policy evidence;
these checks do not turn synthetic or stale inputs into authorized current pricing facts.

Within one caller-supplied transaction runner, set local RLS scope and insert root with complete
snapshot text. A root identity conflict waits for its winner; resolve through the existing reader
and return Existing only for byte-identical complete evidence. Different evidence fails with a fixed
snapshot conflict. Partial or foreign-scope history stays unavailable. No UPDATE or DELETE occurs.
The newly inserted root owns fresh UUIDv7 physical child IDs, line/tax rows and one public Audit
append in that same transaction. Validate returned write witnesses. Read back the root snapshot
before success; any child/read/Audit failure must roll back everything. No direct Audit-table SQL.

A repeated Cart quote reuses logical Cart line references, so they must not be physical child PKs.
Add one forward Pricing migration with nullable source_cart_line_id and scoped per-Quote uniqueness
on existing price_quote_line. New writes preserve each logical source reference and allocate distinct
physical IDs; old rows stay null, without backfill or rewritten migration bytes. Two Quotes of the
same Cart line can coexist. This append identity behavior is not end-user operation-key persistence;
application idempotency, authorization and concurrency with current Cart mutation remain future work.
