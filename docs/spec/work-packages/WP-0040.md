## Accepted decisions

1. **Package and version** — create private workspace package `@bop-rms/observability` and relocate the existing exact Pino `10.3.1` dependency from API and Worker to it. No dependency version or package beyond the existing Pino pin is added.
2. **Centralized closed schema** — the package exports a bounded logger interface instead of raw Pino. Configuration and records are runtime-validated；unknown fields、unregistered event names、free-form messages and unsafe codes fail closed. Common output is limited to Pino level/time plus environment、service、module、event and explicitly accepted bounded operational fields.
3. **Output boundary** — production composition roots use the default stdout destination only. A synchronous injected destination exists solely for synthetic/local/CI verification. No transport、pretty-printer、file or network sink is configured.
4. **Reference minimization** — Tenant、Store and Actor references are not part of the WP-0040 record schema. No real identity、Session、Token、contact or unrestricted object identifier can be logged. A later owning decision is required before any accepted safe-reference allowlist may be added.
5. **Correlation/Causation** — the logger may consume only an already verified WP-0034 trusted in-process context. It validates and copies only `correlationId` and optional `causationId`. It does not read a header、create an identifier、use AsyncLocalStorage or implement `traceparent`、`tracestate` or OpenTelemetry.
6. **Redaction and error serialization** — raw credential、Authorization、Token、Cookie、payment、health/allergy、free text、payload/body/header、SQL、bind values、request data and unnecessary PII never reach Pino. Callers provide a stable safe error code and an unknown error value only to the centralized serializer. The serializer discards error messages and path/function text, emits only bounded sanitized stack-frame positions, and never exposes a raw error object.
7. **Safe failure** — invalid startup configuration throws before runtime starts. A schema、redaction or serialization failure disables that logger's leaking path and attempts one constant safe `LOG_REDACTION_FAILED` signal. A destination write failure is swallowed and reported through the bounded local failure hook when present. Logger/telemetry failure never changes or rolls back an already committed business transaction and never expands authorization.
8. **Composition roots** — `apps/api/src/server.ts` and `apps/worker/src/index.ts` construct the shared logger with a closed service-specific event allowlist. They no longer import or configure Pino directly.
9. **Acceptance command** — root command `pnpm structured-logging:acceptance` runs package redaction/failure tests and API/Worker runtime-composition integration tests.
10. **Deployment** — `NOT APPLICABLE / NOT PERFORMED`. This WP has no deployable cloud/runtime mutation.
