# WP-2225 — Quote Requote Line Identity

## Authority and scope

Verified local WP-2224 baseline `f4ac897`; branch `codex/wp-2225`. Continued local
implementation and verified local checkpoints are authorized. Composite Handoff 0.5.3,
Sections 21, 27, 52, 87, 92–97; WP-1103–1105 and ADR-0029/0031 govern this increment.

The full Pricing persistence investigation found a prerequisite: Domain requotes preserve Cart
line references, but `price_quote_line` currently makes that reference globally unique and
`price_quote_tax_component_unique` omits Quote identity. Correct their relational identity
through one new forward migration. Never modify previously applied migration bytes or rows.

## Acceptance

1. A fresh Quote can preserve the same line reference and tax component as a previous Quote.
   Both immutable histories survive. Same-Quote duplicate lines/components still fail.
2. Preserve composite scoped foreign keys, forced Brand/Store RLS, append-only rules and
   monetary constraints. Cross-Quote or cross-Store tax references without a matching scoped
   line fail. No new runtime privileges or public/domain contract changes.
3. Existing synthetic Quote records survive applying the new migration; the authorized runner
   revision permits namespace-local appends and preserves checksum rules. Local isolated PostgreSQL verifies the identity,
   duplicate, foreign-key and history invariants. Existing Pricing and full local gates pass.

## Implementation and verification

four-column scoped unique constraint and child foreign key remain. Include Quote identity
in tax component uniqueness. The tax row's independent technical primary key stays unchanged.
DDL is transactional with finite lock/statement timeouts; recovery is a forward fix, not a
history rewrite or destructive down migration. Deployment requires separate authority and
lock assessment; only disposable local databases are authorized here.
