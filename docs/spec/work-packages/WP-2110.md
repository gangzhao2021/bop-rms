## Owning facts and boundaries

Ordering owns the append-only Order Amendment request, its controlled state, reason, Actor,
Expected Version and resulting Order-item effect. Pricing supplies a versioned Quote and exact money
delta; Kitchen, Fulfillment, Payment and Inventory expose public impact facts or consume the minimal
applied Event. Ordering does not query their private tables, accept an employee-entered price, mutate
historical Order Item snapshots or claim a refund / kitchen stop / inventory movement occurred.

## Acceptance contract

1. Add Item, Reduce / Void Item, Replace Item Configuration and Update Note are explicit,
   idempotent Commands with Tenant, Brand, Store, Actor, purpose, `ordering.order.amend`, Expected
   Version, append-only Audit and atomic persistence.
2. Fulfilled / Closed Orders fail closed. Destructive changes after Kitchen start remain Pending
   until Kitchen confirmation; Kitchen completion may reject them without changing the source item.
3. Repricing comes only from a pinned Pricing Quote. Currency and original amount must match the
   Order fact; delta uses integer minor units and no arbitrary price field exists.
4. Policy-required approval uses `ordering.order.amend.approve` and a distinct Actor. Applied
   Amendments emit a minimal idempotent Event for Payment, Kitchen, Inventory and the Order view.
5. `OPS-ORDER-AMEND` implements every Section 88 field, action and mandatory state; without an
   authorized BFF all mutation controls are visibly disabled.
