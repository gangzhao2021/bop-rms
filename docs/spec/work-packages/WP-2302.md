## Acceptance and design

Add opt-in foreground-only Dining coordinator with explicit binding client, current-CSRF get/set/
capture, online and fresh technical preparation-reference ports. Closed bind input carries logical
operationReference and admissionReference; capture synchronously before callbacks/awaits. Same
logical/admission coalesces in flight; altered admission or conflicting intent cannot replace a
possibly activated plan. Before acknowledgement, lost read-only preparation may use a fresh
technical reference on explicit retry. No new preparation once activation begins.

Keep candidate CSRF/proof and phases private. Mark recovery before activation. Explicit retry
first completes the original candidate; if completion cannot finish and the original context is
still current, one foreground activation of that same candidate is allowed. Recheck online and
opaque current-context generation before/after every await; same-value and ABA resets invalidate
old plans. Never overwrite a newer context or publish success from a stale result. Confirm exact
operation/CSRF echo before installing candidate CSRF; capture its new generation and clear proof.
Confirmed repeated intent reauthorizes via completion instead of returning cached authority.

Return only frozen Bound plus logical operation reference. No raw Session, CSRF, recovery proof,
admission, participant or private state in the result/error. This confirms binding only, not Cart
write authority or lifecycle extension. Construction/reconnect causes no requests. No background
retry, WebStorage, reload recovery, timers, analytics or default UI/runtime activation.

Extend actual PostgreSQL acceptance with an independent synthetic Guest/Table and production
coordinator/client/HTTP/Identity/Dining stack. Lost Identity acknowledgement preserves candidate;
explicit retry after preparation expiry and repeated confirmation converge without duplicate
consumption/history/Audit. Preserve existing raw HTTP, Closing and Move-away/back regressions.
