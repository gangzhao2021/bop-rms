## Bounded outcome

WP-1603 owns the Fulfillment Domain decision for `CompletePickupHandoff`: explicit staff Actor,
`fulfillment.pickup.complete` permission, purpose, expected version and idempotency; an exact current
validated WP-1602 proof; positive actual quantities that never exceed each Ready remainder; and one

runtime grants, public Event and Projection are excluded. WP-1604 retains public handoff/completion

## Closed contract

- Owner: `@rms/fulfillment`; screen permission: `fulfillment.pickup.complete`.
- Source is locked, Store-scoped, Pickup, `Ready` or `InProgress`, with full Ready quantities and
  non-negative cumulative handed-over quantities.
- Proof must be `Validated`, current-generation, same Brand/Store/Fulfillment and no later than the
  handoff. It is evidence, never authority by itself.
- Recipient data is reduced to `Customer` or `Delegate` plus a bounded pre-masked display value.
  Pickup location and managed-device values are opaque scoped references.
- Same idempotency returns the immutable original effect at the future repository boundary; a new
  command requires exact expected version and appends history. No last-write-wins.
- Public failures are bounded: invalid input, permission denied, not ready, verification failed,
  already completed and version conflict.
