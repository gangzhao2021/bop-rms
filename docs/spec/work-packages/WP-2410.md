## Scope and invariants

Tenant owns a minimal Brand-scoped metadata projection of all registered Store
identities: ID, lifecycle, exact version, UTC creation/update instants. No name,
address, locale, legal entity, currency, tax configuration or Membership facts.
A generation/count header and root triggers update atomically with owner writes.
Backfill the existing roots without changing them or weakening private Store RLS.
Derived projection maintenance is not a business Command or new history authority.
The existing immutable root identities and no-delete rule remain binding.

Projection tables have explicit Brand keys, FORCE RLS and no PUBLIC privileges.
Trigger maintenance uses static owner-schema SQL, a fixed pg_catalog search path,
no externally callable write API, and restores transaction-local scope after its
minimal metadata writes. No runtime BYPASSRLS, generic private-table reader,
new role, grant, dependency, money calculation, external service or live migration.
An incomplete/malformed/over-budget snapshot is unavailable, never an empty list.
Count/generation and the transaction-scoped shared/exclusive fence must prevent a writer committing a changed registry
while a source callback relies on that registry. Actor, purpose, original intent
and complete Brand-level permission/field coverage remain required owner ports;
a reference snapshot does not itself grant access. Partial Store permissions
cannot establish complete Brand coverage. Consumers use only the Tenant public API.
