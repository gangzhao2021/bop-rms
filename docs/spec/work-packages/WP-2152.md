# WP-2152 — Courier / Provider adapter status and acceptance boundary

## Authority and scope

- Handoff Sections 34.54–34.58 define Provider Account/Health separation, operation-scoped circuit
  breakers, authenticated append-only webhook envelopes, canonical status mapping and Quote/Final
  Cost separation.
- This WP adds runtime-inactive `@rms/fulfillment` Provider boundary contracts. It does not connect
  credentials, call a Provider, accept a real courier/job/quote, or activate an account.

## Acceptance criteria

1. Provider eligibility requires Active lifecycle, usable Health, verified activation evidence,
   Store/service/package scope and a closed/approved operation breaker.
2. Webhooks require signature/timestamp/replay proof and append immutable payload-hash envelopes;
   Provider Account + Event ID is the idempotency key and raw payload is excluded.
3. External statuses map only through a pinned mapping version. Unknown values quarantine, out-of-order
   facts cannot regress canonical state, and terminal conflicts open an exception.
4. Create timeout/unknown remains indeterminate and reconciles by safe idempotency/external-job evidence;
   it cannot produce a duplicate job or be guessed as Accepted/Rejected.
5. Provider Quote/final cost use integer minor units, expiry and variance policy; they never mutate the
   Customer Delivery Fee.
