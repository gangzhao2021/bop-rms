## Artifact contracts

### ADRs

- File names are `ADR-xxxx-short-kebab-title.md`; IDs are unique and contiguous from `0001` to `0028`.
- Status is one of the accepted status vocabulary. ADR-0001–0017 remain `Proposed`; ADR-0018–0028 remain `Accepted`.
- Proposed ADRs record the accepted current position and do not authorize the future capability. Accepted ADRs preserve their canonical decision and consequence/revisit semantics.
- Each ADR records context, decision/current position, consequences, affected modules, owner, revisit trigger, source, and supersession relationship without inventing Reviewer, legal, Provider, Store, or execution evidence.

### Module and developer setup templates

- The module template is guidance for later module-generating WPs; it creates no module, manifest, migration namespace, persistence adapter, or business behavior now.
- Developer setup uses the current exact pins and existing repository commands, keeps commands inside one Linux/WSL toolchain, references only synthetic/local configuration, and states truthful API readiness.
- Templates use portable repository-relative paths and placeholders that cannot be mistaken for observed production facts.

### Project skills

- Each skill lives at `.agents/skills/<name>/SKILL.md`, has precise name/trigger metadata, required inputs, ordered workflow, hard stops, output/evidence, external/destructive boundaries, and positive plus boundary smoke scenarios.
- Skills reference the repository specification index and current WP rather than embedding the complete Handoff Package.
- Skills guide execution; they do not replace `AGENTS.md`, accepted decisions, CI/tests, explicit user scope, or external-action authorization.
- No skill auto-commits, pushes, merges, deploys, publishes, writes Figma, accesses credentials, mutates Providers, or accepts risk.
