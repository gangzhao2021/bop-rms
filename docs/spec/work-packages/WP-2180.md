# WP-2180 — Device List / Detail / Health / Assignment / Lifecycle

## Authority and scope

- Handoff Sections 36.1–36.6, 36.15–36.17, 36.21–36.25, 44.13, 48.4.7, 50.2–50.7,
  80.6.3, 87.11.1 and 88.17/88.21–88.30 define the Device Aggregate, persistence ownership,
  events and canonical screens.
- Exact local predecessor: verified WP-2178 commit `81a3e36`.
- `@rms/printing-device` owns Device identity, lifecycle, configuration versions, assignment,
  validated capabilities, append-only health signals/current projection and Device Exceptions.
  Identity owns human Sessions; Store owns Store/station facts; Payment owns Payment facts; Kitchen
  owns work facts; Task/Compliance own their records. Cross-domain facts remain stable references.
- Section 50 explicitly grants `rms_device` and migration namespace `1600-rms-device`.

## Acceptance contract

1. Device identity is physical/logical-device stable and Tenant/Brand/Store scoped with exact Device
   type/code, lifecycle, configuration version, safe label/location/network/adapter codes, locale,
   IANA zone, profile reference and credential **reference metadata only**.
2. Lifecycle is `Draft | Provisioning | Active | Suspended | Inactive | Retired`. Only Active is
   routing-eligible; state changes use exact expected version/idempotency/audit; physical deletion is
   forbidden; Retired can move only to Inactive and must re-enter Provisioning before Active.
3. Capability sets are versioned and validated against an approved model/adapter allowlist port.
   Self-reported capabilities never directly become trusted facts; unsupported/changed capability
   creates no foreign business outcome.
4. Assignment is effective-dated and append-only with Store/station/profile/configuration source,
   named-operator Session summary reference only and assignment history. Assign/unassign validates
   Store ownership and never edits Identity, Store or Kitchen facts.
5. Health and Connectivity remain independent from lifecycle. Timestamped signals are append-only;
   current state is a rebuildable projection. Missing heartbeat yields `Unknown`/`Offline`, never
   Healthy. Health cannot change Payment, Order, Kitchen or Fulfillment status.
6. Quarantine/disable/revoke/retire records only Device facts and safe opaque incident/credential
   outcome references. No secret/token/certificate/PAN/PIN/Provider payload/raw log is accepted,
   displayed, logged or published.
7. Only committed canonical facts publish `DeviceProvisioned`, `DeviceActivated`,
   `DeviceSuspended`, `DeviceRetired`, `DeviceCredentialRevoked`, `DeviceHealthChanged` and
   `DeviceCapabilityChanged`; payloads contain safe scope/device/version/status/time facts only.
8. `DEV-DEVICE-LIST` `/app/integrations/devices` and `DEV-DEVICE-DETAIL`
   `/app/integrations/devices/:id` expose Section 88 fields/actions and explicit loading/empty/denied/
   offline/stale/conflict/error/not-found states through strict closed DTOs.
9. IDR-0039 remains active: browser KDS is the only Pilot Device output mode. Physical printer,
   generic POS peripheral, Store Gateway, vendor SDK/adapter, application Offline Queue, real
   pairing/credential issuance and output execution are excluded.
