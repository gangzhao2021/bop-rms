## Resolved test boundary

WP-2026 exercises two authorized Cart Item Commands that independently read aggregate version `1`
and race to commit different intents against the real Ordering application service. The repository
compare-and-set boundary may commit exactly one record and advance the Cart once. The loser must
receive `CART_VERSION_CONFLICT`; it cannot append an operation or merge its stale intent.

An exact replay of the winner returns the stored result without revalidation or mutation. Retrying
the losing intent with its stale expected version continues to fail closed. The scenario uses the
existing deterministic repository fixture; no distributed lock, durable database adapter, browser,
production load or conflict-resolution UI is invented.
