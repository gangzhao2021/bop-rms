## Purpose and bounded outcome

WP-1407 closes the Kitchen-owned portion of the Pilot allergen-assistance safety chain without
inventing professional policy, Store training or live Compliance evidence. It adds:

1. an exact Order-item configuration review containing only controlled allergen references,
   policy / Recipe version references, a named reviewer and `Accepted | CannotSafelyAccommodate`;
2. separate append-only named-operator acknowledgements for `BeforeStart` and `BeforeHandoff`;
3. a short-lived `KitchenStartAdmissionDecision` derived only from a current accepted review and
   matching `BeforeStart` acknowledgement;
4. a persistent high-priority KDS cue with text + icon semantics and no color-only dependency; and
5. an immutable Incident link that is valid only with both a Compliance Case reference and an
   availability Kill Switch action reference plus exact configuration / Recipe / handling digests.

No Customer UI, KDS screen implementation, Payment mutation, Compliance Case aggregate, Catalog
Kill Switch command, Pickup handoff command, API, Worker, realtime payload or production activation
is introduced. WP-2027 retains modifier propagation, Checkout / Payment blocking and full E2E;
later Compliance, Catalog, Pickup and UI composition retains its own Domain actions.

## Closed safety contract

- The review is Store-scoped, configuration-specific, time-bound and `Restricted`. A changed
  configuration, expired review or `CannotSafelyAccommodate` outcome fails closed.
- Allergen and Recipe inputs are non-empty, sorted, unique controlled UUID references. Free text,
  medical narrative, symptoms and Customer notes are not accepted or persisted.
- The Start admission Actor is exactly the named `BeforeStart` operator. The decision digest binds
  the review semantic digest, acknowledgement, accepted Kitchen operation and exact Ticket / Work
  Item versions. WP-1404's existing admission verification remains authoritative.
- `BeforeHandoff` is distinct evidence and cannot authorize Start. The KDS cue persists after either
  acknowledgement and exposes which stage remains required.
- Incident records do not assert liability. They require an existing Compliance Case reference and
  Catalog availability Kill Switch action reference and preserve only immutable snapshot digests.
- Default retention cannot exceed the 24-month bounded window. Any later incident, legal-hold or
  professionally approved extension must be an explicit retention-policy action outside this WP.

## Persistence and privacy

Migration `1500_005` adds exactly three Kitchen-owned append-only records:

- `rms_kitchen.kitchen_allergen_review`;
- `rms_kitchen.kitchen_allergen_acknowledgement`; and
- `rms_kitchen.kitchen_allergen_incident_link`.

All three tables use composite Brand + Store keys, forced RLS, revoked PUBLIC privileges,
append-only UPDATE triggers and no-op DELETE rules. Cross-Domain Case, policy, Recipe and Kill
Switch identities remain opaque references; no foreign key reaches another Domain's private table.
No unrestricted object identifier, contact data, medical narrative, Money, Payment or Provider data
is stored.
