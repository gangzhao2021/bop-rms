# WP-2252 - Foreground Cart Response Session Isolation

## Authority and scope

Owner authorizes continuing bounded implementation and verified local commits. Baseline381bb3b;
branch codex/wp-2252-cart-context. Composite Sections0–97 and WP-2248/2249/2250 retain private
memory-only Session/CSRF state, foreground-only writes, bounded response processing and uncertain
mutation intent. CUST-CART /cart and CUST-CONFIGURE routes/permissions/fields/states remain unchanged.

A Cart request currently clears global CSRF on a valid401 even if a newer Entry/binding already
installed another credential. A late200 may likewise return the old private Cart in a new context.
Introduce an opaque memory-only context revision advanced on every credential installation/reset,
including same-value and null transitions. A request captures a predicate for its original revision;
it must reject header/body/error results after any intervening change. Never return stale private
Cart data or clear a newer credential. A still-current valid401 retains existing clearing behavior.
Use bounded network_unknown for stale results, preserving possible committed-write uncertainty.
Keep existing timeout/body limit/abort cleanup, strict error-status mapping and explicit retries.
No persistence, logging, timers, automatic replay or new transport endpoint is introduced.

Only Cart consumes the context predicate in this package. Other clients, Entry response ordering,
App orchestration, recovery across reloads, shared DineIn and current Catalog eligibility remain
separate. No business ownership, schema, permission or accepted activation decision changes.
