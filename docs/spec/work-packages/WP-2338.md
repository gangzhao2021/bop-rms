## Acceptance and failure semantics

- Forced RLS and PUBLIC denial cover all tables; no foreign private-table dependency.
- Append-only records reject update/delete/truncate. Scoped foreign keys prevent cross-Store links.
- Slot-level database locking serializes both configuration publication and Hold creation.
  Each configuration appends the next version; reduced limits preserve previous Holds.
  The Hold trigger rechecks the latest version, database time and total live Hold units after waiting.
- Enforce READ COMMITTED for these writes. Reject unsupported transaction isolation instead of
  assuming a row lock refreshes a repeatable snapshot. A future adapter must preserve this contract.
- Concurrent contenders for the final unit produce one committed Hold; rollback restores admission.
  Permanent scoped operation uniqueness prevents duplicate occupancy; semantic replay mapping is
  a future application responsibility. The schema does not fabricate a replay acknowledgement.
- Expired Holds remain history but no longer occupy capacity; new writes cannot claim expired or
  future-created facts. Missing/wrong configuration and insufficient capacity fail closed.
- This initial acquisition slice must be extended to include Allocation occupancy before conversion
  or production integration; no consumer uses it yet. No TTL duration or extension is invented.
