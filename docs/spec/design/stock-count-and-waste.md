## 盘点（DEC-INV-STOCK-COUNT）

沿用已有的盘点领域与服务（`stock-count`：创建、指派、开始、逐行录入、提交、审核、过账；盲盘；提交人与审核人分离），
补齐持久化、接口与页面，并修正两处不符合门店实际的规则：

1. **差异原因由审核人填写**：盲盘时清点人看不到账面数量和差异，原规则却要求提交前为每个差异写原因。改为：提交只要求每行都已清点；
   审核人（不能是提交人）逐行选择原因（以前盘错、漏记损耗、漏记进货、配方用量差异、损坏变质、丢失被盗、放错位置、无法解释），
   全部有原因才能批准。
2. **库存在盘点后变动**：营业中销售、进货或损耗会使账面变化。过账时逐行核对账户版本，若某些行在快照后变动则整单拒绝并指出这些行；
   审核人退回后，清点人用“刷新变动的行”取当前账面数量（这些行的已清点数清空，其他行保留）并重新清点。建议在打烊后盘点。
3. 盘点范围为一个库位：快照包含该库位全部库存账户（含批次），以及没有账户、不按批次管理的启用配料（账面 0，可盘出意外存货）。
   每个库位同时只能有一张未完成的盘点。批准与过账在同一事务完成（“批准并过账差异”），差异以 `CountAdjustment` 流水入账，
   不会动用已被订单预留的库存。目录没有单独的过账权限，过账属于 `inventory.count.approve`。

## 盘点低于在途订单预留（DEC-INV-COUNT-SHORT，2026-10-18）

状态：**Accepted（实现决定，取代上文第 3 条“不会动用已被订单预留的库存”及迁移 `1900_003` 的表约束 `reserved<=on_hand`）**。
协调人按 Owner 商用原则与技术选择授权作出，Owner 可推翻；迁移按 Owner 2026-10-14 常设批准（“我都批准，之后不需要问我”）执行。

v15 实测（2026-10-18）：实物盘点 0.1 L、在途订单已预留 0.26 L，过账触发 `stock_balance_check`，页面只显示“The count changed meanwhile”，
真实门店少于预留的实物无法入账。规则改为：

1. **实物盘点是事实，必须能过账**：`CountAdjustment` 可以使账户低于在途预留（`available` 为负，`on_hand` 仍不小于 0），
   已接单订单的预留全部保留（顾客已付款、订单已承诺）。账户此时为“对在途订单短缺”。
2. **短缺不能被加深**：除盘点外，任何流水都不得使可用量降到 0 以下（新预留、损耗、手工调整、更正）——新订单不能预留缺少的库存，
   损耗与调整不能动用已被订单占用的库存。由账本触发器执行（迁移 `2000_088`，以“可用量低于 0 且低于变动前”为拒绝条件），
   应用层同样拒绝（库存候选把负可用量视为 0、损耗按可用量拒绝/记缺口）。
3. **订单照常处理**：释放（取消、退款）与消耗已占用的库存不降低可用量，始终允许。厨房完成一份订单而现存不足时，
   先以 `Adjustment`（原因 `USED_BEYOND_COUNT`，业务来源为该预留、执行人为厨房员工、单独审计 `INVENTORY_STOCK_USED_BEYOND_COUNT`）
   记录“超出盘点的用量”，再照常消耗——菜已做出说明库存存在（盘点漏计或进货未登记）；`on_hand` 永不为负，账本逐笔连续、可对平。
4. **经理提醒**（`INV-COUNT-LIST` 与已过账的 `INV-COUNT-WORKBENCH`）：“Counted less than open orders need”逐项列出品项/批次/库位、
   盘点数、在途占用、短缺量及占用的订单号（链接订单），并说明处理方式：登记进货、用现有库存做出后再盘点、或取消订单（顾客退款）；
   “Used more than was counted”列出超出盘点的用量，提示再盘点。两者自动消失：前者在进货、订单完成或取消后，
   后者在该账户再次过账盘点（快照晚于该调整）后。过账结果附带短缺品项数。
5. **错误文案精确**：只有真正的并发修改（版本冲突）显示“Someone else changed this count meanwhile…”；来源读写失败显示
   “This could not be done right now and nothing was changed…”（503 `Unavailable`，原映射为 409 Conflict）。

运营连续性：网络或主机故障时无法过账，盘点表保留纸面数量，恢复后录入；短缺提醒由当前账本即时计算，无后台任务依赖。

### 修订：短缺时仍可报损（2026-10-18，取代上文第 2 条中“损耗……不能动用已被订单占用的库存”及下文 DEC-INV-WASTE 第 1 条“不能超过可用量”）

v15 实测（`67572c15`，缺陷 D1）：牛奶对在途订单短缺（可用量为负）时，损耗表单直接不列牛奶且无说明；员工洒掉、倒掉的牛奶无法登记，
现存一直偏高。协调人按 Owner 商用原则决定（Owner 可推翻；迁移 `2000_089` 按 Owner 2026-10-14 常设批准“我都批准，之后不需要问我”执行）：

1. **损耗与盘点一样是实物事实**：页面记录的损耗可以达到现存（`on_hand`，永不低于 0），即使这会使账户对在途订单短缺或短缺加深；
   不改动任何订单的预留（`reserved` 不变，订单仍保留其占用）。超过现存的数量仍拒绝（“比这里的现存多”）。
2. **账本规则**：触发器把 `Waste` 与 `CountAdjustment` 一同列为可使可用量降到 0 以下的流水；新预留、手工调整与更正仍不得动用被占用的库存，
   新订单在短缺时仍无法预留（顾客端显示售罄）。`on_hand>=0` 列约束不变，账本逐笔连续。
3. **表单**：列出所有有现存的配料，显示“X in stock, Y held for open orders”；动用占用库存时直接提示
   “Held for open orders — recording this waste makes the shortage bigger; receive stock or recount.”（部分占用时说明未被占用的数量），
   只阻止超过现存的数量。审计记录 `heldForOpenOrdersLines` 标记动用了占用库存的行数。
4. **提醒随之更新**：短缺提醒由账本即时计算，标题改为“Less in stock than open orders need”（短缺可能来自盘点或损耗），按现存列出。
5. 厨房重做的损耗仍按可用量记录、其余作为“短缺”留给经理复核与再盘点（未改）。

另（缺陷 D2）：盘点中“Refresh lines where stock moved”只在确有行在快照后变动时出现，并标出这些行（“stock moved”）；
刚开始的盘点没有变动行，不再显示该按钮（原先点击得到 409“当前状态不可执行”）。服务端规则不变：没有变动行的刷新仍拒绝。

## 损耗（DEC-INV-WASTE）

已有的损耗领域要求“先审批后扣库存”，审批期间系统仍显示已经扔掉的库存，订单可能预留这些不存在的库存。改为门店单据：

1. **记录即扣减**：前台、厨房（`inventory.waste.record`）按行记录配料、库位、批次（按批次管理时必选，显示到期日与可用量）、数量、
   原因（过期、变质、损坏、掉落、制作失误、质量、顾客退回、其他〔须备注〕）；每行一条 `Waste` 流水，不能超过现存（2026-10-18 修订：可动用订单占用的库存，见上文“短缺时仍可报损”）。
2. **价值与复核**：按本店最近进货/开业单价计算价值（作废的收货不计）。单据价值达到 25.00 加元或含成本未知的配料时，需由记录人以外、
   有 `inventory.waste.approve` 的人复核：确认，或以“录入错误/重复录入/实际未损耗”作废——作废以 `Correction` 流水把数量放回库存。
   任何单据都可由他人复核作废。
3. 记录、复核只追加；记录人可查看自己的单据，完整列表需要 `inventory.waste.read`。
