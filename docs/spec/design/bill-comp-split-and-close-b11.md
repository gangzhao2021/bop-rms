## 1. 分单后全部免单锁死桌台（BLOCKER）与 TM2 的 BR C (TEST)

**根因（v15 只读 SQL 确认）**：订单 `01a1ce09-…`（BR C，第 141 单）三轮各 $14.13，分单时系统规则记下这张账单的
税额取整 −$0.01（版本 1，一行在第 1 轮）；随后两道菜免单，免单记录（`order_item_price_reduction`）合计 4,239 分 =
三轮全部金额。Ordering 的计价总额 = 提交 4,239 − 减免 4,239 + 已记取整 −1 = −1 < 0，`order-priced-amount-source` 拒绝
（`ORDER_PRICED_AMOUNT_UNAVAILABLE`），于是 table-bill、tea-charge、订单详情全部 503，结账不能取消，桌不能关。
TM2 另一条“每次刷新 503”的发现是同一张桌（全库只有这一张订单的已记取整使计价为负）。

问题不在规则本身，而在**已记版本过期**：取整“付款前由系统规则记下，账单变了就记新版本”，但免单和删菜这两个改账单
的命令从来不记新版本，只有下一次规划分单或收款才记。记下的 −$0.01 对应的是免单前的账单。

**决定**：

- 账单读取在**没有任何付款**时，Ordering 的计价总额不含已记取整（`taxRounding: "Excluded"`），加上这张账单现在算出的
  取整。已记版本过期也绝不让账单读不出来。已有付款（或核销）时照旧读已记版本（那是收过钱的数）。
- 改账单的命令在同一事务里重新记取整（`refreshBillTaxRounding`，只有已记过版本、且没有付款时才记；与上一版相同则不记）：
  免单/折让、付款前删菜。开始结账、取消结账、完成关桌也先做这一步，所以已经卡住的桌（v15 的 BR C）在店员按“取消结账”
  或关桌时自愈，不需要数据修补。
- 核销（客人没付就走了）像付款一样把账单定下来：先按账单现状记取整（没记过也记），核销金额 = 店员看到的账单。
- 锁顺序：免单和删菜先取整张账单的围栏（持有账单的订单在前），和收款命令同序。

## 2. 跨营业日仍坐着的桌，菜不在厨房屏上，付完款关不了桌（MAJOR）

**根因**：营业日翻过后，前一天的厨房单在厨房屏上被归入“之前营业日的单”，在工作台里只给经理一个“关闭这张单”，
不能标做好/上菜；上菜要求厨房已做好，所以这桌永远“1 道菜还没上”，关不了。v15 的 BR A/E/D（11 月 11 日 23:35–23:53
下单）就是这样。

**决定**：同一桌客人还坐着（用餐会话 Active 或 Closing；被并桌的看主桌）时，这一轮仍是这桌今天的工作——夜宵、跨零点
的桌是真实餐厅的常态。厨房查询给这些菜标 `atSeatedTable`，厨房屏把它们放在今天的工作里，照常做、标好、上菜，不再
问“这是之前营业日的单吗”，也不能当作过期单关闭。报表里这一轮仍属于它下单的营业日（营业日记录不改）。桌已经关了的
之前营业日的单照旧放在一边，由经理关闭。

“完成关桌”在还有菜没上时不再答 503“我们没能确认结果”，而是 409 `dining_session_not_ready`，订单页说“这桌还不能关：
还有菜没上。请先上菜，或在“桌台”页处理这道菜，再关桌。”

## 3. 一个税额（结账 = 打印的已付账单 = 客人付款面板）

店员结账面板原来写“税 $2.92 + 税额取整 $0.01”，打印的已付账单写“税 $2.93”。现在结账面板和客人手机上的付款面板都
只写一个税额 = 整张账单的税（取整已在里面），不再另列“税额取整”；结账里的每一轮写账单向这一轮收的金额（含它分到的取整，
和“按轮分单”一样），各轮相加 = 含税合计。桌台面板和订单页的“这桌的订单”不变（合计按点单、免单折让与取整另列，
见 [tax-whole-receipt](tax-whole-receipt.md)），客人桌页的“取整（税额按整单计算）”一行也不变。

## 4. 其它

- 免单/折让的金额在 1024 和 390 宽不再把“−”单独折到一行：金额不折行，菜名和说明折行。
- 客人页面的负数一律用排版减号“−”（U+2212），与“店家减免 −$14.13”和员工端一致，不再是 ASCII “-”。
- 店员“取消结账”的审计原因记为 `CHECKOUT_CANCELLED`（和随之结束的分单记录同一个原因），不再是 `CUSTOMER_FINISHED`。

## 断网与故障

没有新做法：断网时按断网指引的账单收款，恢复后补录。账单读取不再因过期的取整失败；真正读不到时仍是原来的“读不到，
正在自动重试”。
