# 已付账单打印、隔天待接单、订单记录措辞（v15 batch 7，2026-11-11）

状态：协调人按 Owner 商业原则决定（WP-2423 v15 batch 7 实测 print-orders-records）。只改界面和读取，无迁移、无新授权。

## 1. 打印已付账单（M50）

- 打印内容是给客人的纸：门店名、桌号、付款时间（门店时区），每道菜（数量 × 菜名、金额，免单/折让另一行），然后小计、税、
  税额取整、小费、现金取整、实付、付款方式、收到现金和找零。门店名、桌号、时间和菜单只在纸上出现，屏幕上结账区已经列出各轮。
- 仍然叫“已付账单”，不叫收据：还没有营业税号（M48 未结），屏幕阅读器标签也改为“已付账单”。
- 打印样式不再把打印区绝对定位：不含打印区的元素一律不排版（`display:none`），打印区所在的容器（桌台右侧的粘性、带滚动的
  面板）打印时变成普通块，所以账单总从第一页顶部开始，后面没有空白页。今日汇总的打印用同一套。

## 2. 隔天仍待接单的已付轮次

- 客人已付款、店员没接单的轮次不会自动退款（DEC-DINE-IN-PAID-ROUND-WAIT），只能由店员接单或“做不了 · 退款”。所以订单页第一页
  和今天的订单一起列出**以前营业日**里还有这种轮次的订单（与隔天仍占库存、仍未完成的自取单同一做法，最早的在前）；读不到时
  订单页照常显示，不会空白。
- 桌台面板有这种轮次时给出“打开订单去接单”，直接到该订单（不论哪天、哪一页）；超过 5 分钟的提示写明“接单，或选择做不了 · 退款”。

## 3. 订单记录措辞

- 吃完再付的桌，轮次在送出时由系统自动接单，记录写“送出后自动接单（这桌最后结账）”，不再写“付款后自动接单”（那时还没付款）。

## 4. 免单后的应付与并桌取整

- 免单列表下的数字是整桌账单（所有轮次和并入的桌），写“整桌账单减免后应付”，并桌时写明含哪几桌；被并入的桌不显示自己的应付。
- 并桌账单的税额取整记在主桌订单上，被并入桌订单的合计就是它点的菜（详见 [DEC-TAX-WHOLE-RECEIPT](tax-whole-receipt.md)）。

## 5. 其他

- 订单列表行里“桌上付款 · 客人手机 · 已退 $5.00”在本列内换行，1024 宽度打开订单时页面不再左右滚动；金额不再断成两行。
- 异常页按订单结束原因命名（如“被拒 · 售罄 · 已退款”）：原因读到了，但接口序列化时漏掉；读原因失败现在会记日志。
- “创建二维码”后行不更新：产品代码按返回行更新，浏览器测试（新加桌、名称带括号）通过；实测所见是测试脚本按桌名找行的
  正则不匹配以“)”结尾的名称，不是产品问题。
