# Full Option candidate rule satisfiability

WP-2421 adds `evaluateCatalogOptionSetRuleSatisfiability` for the complete local rule and pinned trigger graph supplied in [full editor content](./option-set-editor-content.md). Handoff71.5 requires satisfiable rules and a finite trigger graph. The existing direct structural contradiction checks remain unchanged. This evaluator answers whether a complete supported candidate has a feasible selection; every result retains `eligibility: NotEvaluated`.

## Input and identity

The closed request contains Brand, exact root Set/version and full content bodies. Descriptor-safe copying rejects accessors, sparse arrays, extra fields and unsupported values before reading candidate data. Each body passes the existing full editor parser. Foreign Brands, duplicate exact nodes, duplicate stable Option identities and unrelated nodes refuse. Complete structural reachability includes disabled trigger metadata.

Each target requires its exact pinned version body. An absent root, missing target or different pin returns `Indeterminate / IncompleteTriggerGraph`. More than one supplied version for one Set returns `Indeterminate / AmbiguousTriggerVersion`: simultaneous multi-version evaluation is not implemented. No target is substituted from today's Draft, a different version, a fixed mapping or a caller's Ready flag. The candidate envelope accepts at most32 Sets; larger arrays are invalid rather than truncated. More than128 total Option variables returns `Indeterminate / ComplexityLimit`.

The detached result binds Brand/root/version and each complete source aggregate version, source/content/configuration digest. A canonical graph digest includes these sorted identities. Changing prose changes the content/graph identity even if the feasible selection is unchanged. These hashes bind supplied content, not authenticated current sources or permission. No Actor, actual readiness, approval or private source body is added to the result.

## Mechanical semantics

Minimum/maximum selection and maximum total quantity count units, following the existing selection resolver. A Draft/Active Option is either absent or selected with an integer quantity from `max(1, minimumQuantity)` through `maximumQuantity`. A zero quantity means absence. A per-Option minimum does not force every Option to be selected. Inactive/Archived Options stay absent.

The root Set is active. Another Set is active exactly when at least one selected parent Option triggers it. Shared children activate once; untriggered branches have zero selected quantities and impose no minimum. An active Set's selected quantities satisfy its minimum and both available total maxima. Positive when-all conditions require positive presence of every consequent; they do not assign client selections. All-member conflicts exclude only the full listed combination, and existing asymmetric pair conflicts also exclude both members. Presence implications propagate transitively across the local rules.

Any cycle in the complete structural trigger graph returns `Unsatisfiable / TriggerCycle`, including disabled edges, matching the existing conservative cycle rule. Otherwise bounded presence search propagates constraints and completes exact integer intervals for each active Set. A satisfiable result includes a frozen, deterministic witness with exact Set/version, activation and positive Option quantities. No feasible model after complete search returns `Unsatisfiable / NoSelection`. Server search budget must be an integer1–65536; exhaustion returns `Indeterminate / SearchLimit`, never a guessed no-solution or permission grant. All supported totals remain bounded safe integers; no money calculation occurs here.

## Qualification boundary and next integration

This is a pure candidate contract, with no database or ordinary page. It accepts parsed complete editor bodies, including an original Draft body retained in an immutable snapshot; it does not retrieve or authenticate that snapshot. [Immutable storage](./option-set-publication-storage.md) supplies internal Frozen history with NotEvaluated content. A current owning producer must separately load and hold exact current or qualified pinned graph sources, actual reference state, purpose/field authority, scope/topology/effective period, policy, independent approval, Product Binding overrides and defaults. Media/Pricing/Inventory/Recipe existence or eligibility is not proven by a feasible witness. Present defaultEligible metadata is not an actual Product default selection.

The future publishing writer must retain current source barriers, late refusal, CAS, Audit/Outbox and original recovery. This evaluator neither seals a version nor publishes it. Missing actual sources, unsupported multi-version graphs or unknown evaluations remain unavailable in that composition. No current Published resolution, sale eligibility, real IAM, UAT or launch evidence is established here.

## Explicit Product Binding defaults

`evaluateCatalogFullProductOptionBindingRules` adds a separate closed `{ graph, binding }` request; the existing graph-only evaluator keeps its original behavior. Binding passes the existing exact parser and unchanged legacy validator against the root's supplied source. Wrong Set/version, unknown or Archived enabled choices, disabled/default-ineligible defaults, asymmetric default conflicts, invalid quantity totals and widened overrides refuse with `CATALOG_INPUT_INVALID`. Missing supported graph pins and evaluation limits retain the graph evaluator's explicit Indeterminate results.

Root selection is the exact explicit `defaultSelections`: every other root choice remains absent, including an enabled choice whose metadata is defaultEligible. Root quantities are fixed rather than increased to satisfy a rule. Allowed min/max overrides narrow the root bounds; source total maximum still applies. A selected default outside its full positive per-Option interval, missing conditional consequent or full forbidden combination returns Unsatisfiable. Root conditions never silently insert another default. Legacy malformed/default/override refusal remains distinct from full-rule infeasibility.

Triggered children use the existing mechanical feasible-completion semantics, activating once for any selected parent. Their witness is a possible completion, not automatic Product defaults or a page selection. Complete structural closure and cycle checks still include unselected/disabled trigger metadata. The result retains the original graph identities/digest and separately binds the exact parsed Binding reference/digest, including its scope/SKU/channel metadata; that metadata is fingerprinted, not applicability-qualified. Every output remains NotEvaluated.
