# DEC-CLOSING-SUMMARY：当天营业小结（WP-2423 剩余工作 8 ②）

状态：已实现（2026-10-28），待部署实测。来源：Owner 顺序第 3 步；Figma `2HV29YwoDoBLjscYHeU1Q4` 页面 47-2；
2026-10-28 “按建议”及三处补充：(a) 示例数字要能加总并有测试；(b) 刷卡机批次对账提示；(c) 注明钱箱里也有商家收银机的现金。

## 决定

1. **同一来源**：`GET /merchant/reports/tonight` 就是报表“今天到目前为止”——同一组来源（`loadStoreSalesReportSources`）、
   同一计算（`computeStoreSalesReport`）、同一事务，再加两项只读：还没结账的桌（每桌自己的账单 `readDiningTableBill`）
   和当天取消/删掉的菜（`listStoreCancelledDishes`，只列出，不算销售）。权限与报表相同（`reporting.sales.read`）。
2. **内容**：营业额（毛销售、经理免单/折让、折扣、净销售、税）；按付款方式的笔数、小费、实收，现金另列取整、现金退款与
   “本系统记下的桌台现金（不是钱箱总数）”；合计实收、退款、净实收；还没结账的桌与核销；退款、付款前删掉的菜、付款后取消的菜、
   未付款取消的轮次和订单；与日结对得上的说明。
3. **(b) 刷卡机**：提示打烊时做批结，批结单总额应等于刷卡机实收减刷卡退款。
4. **(c) 钱箱**：说明钱箱里还有商家自己收银机的现金，这里只算本系统记下的桌台现金，两者分开数（与 2026-10-27 决定 1 一致）。
5. **(a) 加总**：示例（`tonight-summary.fixtures.ts`，Figma 示例用同一组数）由每种付款方式的数字推出所有合计；单元测试
   用正式解析器读入并核对：毛销售 − 折扣 − 免单 = 净销售；净销售 + 服务费 + 税 + 小费 + 取整 = 实收；各方式相加 = 合计；
   实收 − 退款 = 净实收；各桌欠款相加 = 合计。解析器也拒绝欠款合计不等于各桌之和的回答。
6. **放在哪里**：报表页加“今天的小结”标签并默认打开，原报表在“按时段报表”（那里的“今天”快捷键还是选日期，不是另一份东西）。
   首页给有报表权限的人显示打烊提醒：几桌没结账、金额、今天净实收、“查看今天的小结”。“今晚”改名是因为它指整个营业日
   （默认 04:00 切日），午餐也算在内；计算、来源和路由 `reports/tonight` 都没改。
   **何时显示（2026-11-02 修订，取代“门店打烊时间不在首页读取”）**：按门店这个营业日已发布的营业时间（含节假日和临时例外，
   用门店 IANA 时区换算），取当天最后一段的结束时间，可以跨午夜。打烊前 60 分钟到打烊后 60 分钟显示：打烊前一小时桌子还来得及
   结账，打烊后一小时是收尾对账的时间。之后到营业日结束，只在还有没结账的桌时显示；当天不营业也一样。这个时段继续读取，所以
   没结账的桌不会漏。读不到营业时间或完全没有发布时，退回原规则（营业日最后 8 小时），不沉默。午餐和晚餐之间的休息不算打烊。
7. **断网**：读不到时保留上次数字并写明时间，说明之后的刷卡和现金还没算进来、打烊时用批结单和钱箱里本系统记下的桌台现金对照纸单，
   纸单补录后本页与次日日结都会算上；运行手册断网流程新增 5b。
8. **与日结对得上**：受限角色验收证明“今天的小结”与当天报表逐项相同、各付款方式与当天日结相同。

## 不改变

报表与日结的计算口径、营业日切分、权限目录。
