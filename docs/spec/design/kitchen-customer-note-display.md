# DEC-KDS-CUSTOMER-NOTE — 厨房屏显示顾客备注

状态：**Accepted（实现决定）**。2026-10-10，在 Owner 的商用原则与技术选择授权下作出（Owner 回复“按你建议做”）。
执行工作包：[WP-2423](../work-packages/WP-2423.md)（扫码点餐痛点核对 Q2）。

## 背景

WP-1401 把顾客备注定为可能含健康信息的受限数据；WP-1403 不让它进入厨房队列投影；WP-1804 要求看板“不含顾客备注或健康事实”。
真实厨房必须看到“不要洋葱”“少冰”这类备注，否则做错菜；顾客写了备注却不被执行，比不收集更糟。本决定取代上述“看板不显示备注”的部分，
受限数据的其余约束不变。

## 决定

1. **只显示、不扩散**：厨房屏（KIT-KITCHEN-QUEUE 卡片与 KIT-WORK-ITEM 详情）在请求时从 Kitchen 自己的 `kitchen_work_item.customer_note`
   读取并显示，仅限持有 `kitchen.operate` 的已登录会话。备注不进入队列投影、事件、审计摘要、日志、URL、分析标签、错误载荷或浏览器存储；
   响应为 `no-store`。测试与截图只用合成备注。
2. **不解释**：备注原样显示为“Note: …”，不被当作过敏处理依据；过敏原仍以菜单披露（Q3）与 WP-1407 结构化复核为准。顾客端继续拦截
   含过敏原词的备注（已有）。
3. **其余不变**：WP-1407 不接收自由文本的规定、WP-1401 对事件/日志的禁止保持有效。

## 同时决定（Q2 的其余部分）

- 卡片显示订单号与桌号（堂食，Dining 当前桌台标签）或“Pickup”，同一订单的工作项相邻成组；不显示顾客姓名（厨房不需要）。
- 选项直接显示在卡片上，不只在详情页。
- 已完成项不再显示从创建起累计的等待分钟数。
