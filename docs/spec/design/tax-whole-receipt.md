# DEC-TAX-WHOLE-RECEIPT — 吃完再付的整桌账单，税只取整一次

状态：**协调人决定、Owner 授权（WP-2423 2026-10-30 A 第一步、第二步）**。系统规则代码 `DEC_TAX_WHOLE_RECEIPT`
v2（2026-11-11 v15 batch 9，迁移 `2000_800_alter_order_tax_rounding_rule_carrier` 放开 `rule_version IN (1,2)`；v1 已记的版本不改），
记录表来自迁移 `2000_132_create_order_tax_rounding_adjustment`。本文件补上代码里一直引用、但之前没有的决定文件，
并记下 2026-11-06 修正（v15 `07b7a1b7` 实测：桌台面板 $27.06，结账 $27.05）。

## 规则

1. 每份报价（每一轮）按税种对这份报价的应税额合计取整一次（HalfUp），分摊到各行，各行相加等于这份报价的税。
   自取、柜台单、先付再吃的桌：每一轮就是一张收据，到此为止，没有账单取整。
2. 吃完再付的桌（这次用餐的付款时机是 PayLater，订单有“吃完再付”的轮次确认）：整张账单是一张收据。每个税种的税
   = round_half_up(整张账单的应税额 × 税率)，应税额已减去免单、折让和删掉的菜。和各轮报价已收的税之差就是这张账单的
   **税额取整**（可正可负），按各轮精确份额的最大余数分到各轮（同余数按轮次）。
   规则 v2（并桌）：账单含被并入桌的订单时，整张账单的取整只分到**持有账单的主桌订单**的那几轮（在这几轮之间仍按精确份额
   的最大余数），被并入桌的各轮按点单时的税，取整为 0。主桌在某税种上没有应税的轮次、或承担后某轮税额会小于 0 时，
   这一税种退回 v1 的做法（分到所有轮次）。只有一张订单的账单，结果与 v1 相同。持有账单的订单写进取整的依据摘要，所以
   v2 上线后还没付款的账单在下一次规划分单或收款时记一个新版本；已付款的账单保留 v1 记录。
3. 记录：付款前（整桌付、规划分单、客人手机付）由系统规则先记下取整（只追加，账单变了就记新版本覆盖上一版）；一旦有付款
   （或核销）就用已记的版本，不再重算。报表、收据、Ordering 的计价总额都读已记版本。
   b11（[bill-comp-split-and-close-b11](bill-comp-split-and-close-b11.md)）：免单/折让、付款前删菜、开始/取消/完成结账在同一事务
   里重新记取整（已记过且未付款时）；核销前按账单现状记下；未付款的账单读取用现在算出的取整，不读可能过期的已记版本。
4. 一次读取从不记录。
5. b16（[comp-bill-cent-b16](comp-bill-cent-b16.md)，DEC-COMP-BILL-CENT）：免单、折让和积分抵扣不改变账单的税额取整。整单的税因减免
   多变或少变的那一分记在这次减免的菜的税上（`tax_rounding_minor`），所以减免记录合计 = 账单减少的钱，减免合计 + 还欠的 = 原账单，到分。
   并桌时那一分先放在持有账单的单的菜上；放在并入的单的菜上时，这一分在该菜所在轮的取整里还回去（并入的单其余仍按点的收）。

精确地说（batch 9 复审后）：订单详情的“合计”始终是**点了多少**（各行合计），任何免单折让——这张订单的、还是被并入桌的——
都不会让它变。取整永远另列（和客人页一样），所以 **合计 − 这张订单的免单折让 + 税额取整 = 这张订单在账单里的份额**，没有免单、
只有一张订单时就是“整桌账单应付” = 结账含税合计。原先“没有免单时合计含取整、有免单时不含”，免单前就有取整的账单在免单后
合计会差一分：三轮各 $12.50（13%，每轮税 $1.63，共 $4.89；整单税 $4.88，取整 −$0.01），合计 $42.38，经理免掉或打折任何一道菜后
变成 $42.39；并桌主桌（L5）$14.12 在被并入桌那道菜免单后变成 $14.13——主桌自己没有免单，合计却因为别的桌的免单变了。
现在两种情况合计都是 $42.39 / $14.13，取整 −$0.01（或免单后算出的新取整）列在下面。2026-11-06 修正针对的“桌台面板 $27.06，
结账 $27.05”：面板合计仍是 $27.06（点了多少），紧接着“税额取整 −$0.01”和“整桌账单应付 $27.05”，店员读到的应付和结账是同一个数。
删掉的菜和因付款失败取消的轮次不计入（界面已从合计里减去，取整也是删菜之后算的）。

并桌（2026-11-11 v15 batch 7 修正，见 [print-orders-records](print-orders-records.md)）：账单的取整是**整张账单的一行**，
记在持有账单的主桌订单上；被并入桌的订单详情不带取整，合计就是那一桌点的菜。原先按轮分摊会把 −$0.01 落到被并入桌的
那一轮，那张订单就显示 $14.12，而它点的是 $14.13。两张详情的合计相加仍 = 主桌面板上的“整张账单” = 结账。

batch 9 修正（原 L5 实测仍失败）：batch 7 只改了订单详情的读法，结账、“各付各的轮次”分单和已记的取整仍按 v1 分到所有轮次，
于是同一个结账面板里被并入桌那一轮写 $14.13、它那一份写 $14.12，客人手机上也是“第 2 份 $14.12”。现在取整的**分配本身**
（规则 v2）就放在主桌订单的轮次上，订单详情、桌台、结账各轮、分单各份、客人手机、已记版本和报表都读同一组取整行：
主桌 $14.12、被并入桌 $14.13，到处一样。订单详情的读法也改成“这张订单那几轮的取整行之和”（被并入桌读它所在账单），
不再按“是不是被并入”另算。

## 订单详情怎么取得取整（`readOrderBillRounds`，b15 起按轮给出账单金额）

- 这张订单没有“吃完再付”的轮次确认 → 0，不再读别的（自取、柜台、先付再吃）。
- 持有账单的订单（被并入桌：它所在的那张账单）已有付款、线上付款或核销 → 已记版本里**这张订单那几轮**的行相加；不读桌台，
  桌台关了很久也一样。付款早于这条规则、没有记录的账单 → 0（和结账一致）。v2 下主桌得到整张账单的取整，被并入桌为 0；
  v1 时已付的旧账单按当时记下的行显示（和当时收的钱一致）。
- 还没有付款 → 和结账同一个读法（`readDiningTableBill`，不记录），取这张订单那几轮的取整份额。
- 两者都读不到才失败（“读不到这桌的订单”，面板已有的重读）；绝不显示不含取整的合计。

  其余 52（0）。

## 取消结账时的分单（batch 9）

分单属于这一次结账。员工按“取消结账”（客人要加菜）时，桌台的分单方案记为新的“整桌付”版本（只追加，记经手人，审计原因
`CHECKOUT_CANCELLED`；原来的分单留在记录里），下一次开始结账从整张账单开始，客人要分再分。原先旧的“第 1 份 / 第 2 份 ·
0/2 份已付 · 还差 $28.25”和“账单在分单后变了，请重新分单”会出现在新的结账开头，直到员工按“一起付”才显示含税合计。
账单为 $0（全部免单）时没有可付的分单，不记新方案（`bill_minor` 必须大于 0）。为此（batch 9 复审）账单读取本身也按“分单属于
这一次结账”：分单方案记录在这张桌**最近一次开始结账或取消结账之前**、而且它的任何一份都没有付款、也没有在客人手机上开始付款，
就不算这张账单的分单，结账从整张账单开始。所以先分单、再在结账中把账单免到 $0、再取消结账，下次开始结账也不会出现旧的
“第 1 份 / 第 2 份”和“请重新分单”。已经有一份付了款的分单照旧（取消结账本来也不允许）。读法：Dining 的
`readDiningCheckoutLastStartOrCancel`（`dining_closing_operation` 里 Begin/Cancel 的最近时间，api 已有 SELECT 授权，无新授权）。

## 上线时正在结账、已按 v1 分单的并桌账单（batch 9 复审，明确接受）

v2 上线时，若某张并桌账单正在结账、已经“各付各的轮次”等方式分好单、还没有任何一份付款，并且账单有取整，这次分单是按 v1
（取整落在被并入桌那一轮）算的。新代码按 v2 重算，那一分钱从被并入桌那份移到主桌那份，分单显示“账单在分单后变了，请重新
分单”，店员需要再分一次（或改“一起付”）。钱不会收错：旧的分单在重新分单前不能收款。这是有意接受的一次性代价，上线前（重启前）
步骤要求：先把正在结账的并桌账单收完款，或通知当班店员上线后这些桌要重新分单。已付了一份的分单保留 v1 已记版本，不受影响。

## b22 每个数到分都对得上（2026-11-16，v15 live21 实测）

来源：`.local/integ-tools/b22/money-cent-consistency.json`。分支 `codex/fix-money-cent-consistency`，基于 `78501b1a`（第 1–21 批）。
收的钱不变（取整的算法、已记的版本、结账、分单、删菜和免单的金额都不改），只改各处怎么拿这些数来显示。无迁移、无新授权。

- **客人页“点单合计”就是这张收据**：吃完再付的桌，`summary.ordered` 的税和合计加上整张账单的税额取整（各轮按点单的税加起来
  会多或少一分）。所以 已付 − 已退 − 退款中 + 还欠 + 店家减免 + 积分 = 点单合计，到分（TM2：3900 → 3899；删掉凉拌黄瓜后
  3193 → 3192）。取整不再另给一行 `taxRounding`（一个税额）；旧页面仍能读旧服务端的那一行。
- **每轮的数相加就是账单**：每轮按账单写的金额（含这一轮分到的取整，按整单税额的最大余数分，同余数按轮次，见上文规则 2）。
  一轮的明细因下单时的折扣或附加费对不上、只能按点单写时，它的税和本轮合计也加上它分到的取整（服务端按轮给出
  `roundTaxRounding`），所以客人页每张轮次卡相加仍 = 整桌合计。店员订单页、桌台面板读的是同一组按轮金额。
- **某一轮的数为什么会变一分**：取整是整张账单的，别的轮删菜或加菜后，那一分可能换到另一轮（实测：删掉第 3 轮后，第 1 轮
  从 $14.13 变成 $14.12，第 2 轮从 $10.73 变成 $10.74）。任何一刻各处（客人页、订单页、桌台、结账）都是同一组数，相加 = 账单；
  不为“轮次的数不动”改变取整的分法（会改变已记版本、分单和收款）。
- **删菜面板里每道菜写“账单减 $x”**：就是只删这一道时账单少多少（服务端预览，与按钮同一个算法），不再写下单价“价格 $7.07”
  旁边按钮“删掉 $7.06”。读不到预览时才写下单价，并写明是“价格”。几道菜一起删、或整轮删时，账单减的钱可能和各道菜的数相加
  （或这一轮的数）差一分；这时面板写一行“税按整张账单算一次，所以账单减 $x。”，按钮写的就是 $x。
- **订单页和订单工作台**：“从第 N 轮删菜”放在这一轮的菜下面（与桌台同一个位置，`OrderLineRounds.action`），不在轮次标题和菜之间；
  工作台读到菜时就在工作台里打开面板，不再链到完整页面；读不到菜时链到订单页，用页面跳转状态（只有轮次号，不进 URL）在到达时
  打开那一轮的面板并把焦点放在面板上，返回或刷新不会再打开。
- **面板按钮没勾菜时**：写“请选要从第 N 轮删的菜”（不能按），不再写没有轮次的“从账单删菜”。

## b23 有免单时各个数怎么对上（2026-11-16，v15 live22 实测）

来源：`.local/integ-tools/b23/money-comp-and-takeoff.json`。分支 `codex/fix-money-comp-and-takeoff`，基于 `27e27887`（第 1–22 批）。
收的钱不变：取整、已记版本、结账、分单、删菜和免单的金额都不改；无迁移、无新授权。

- **定义（不改，写清楚）**：客人页 JSON 里有两个“店家减免”。`summary.takenOff` 是账单因免单/折让**少收的钱，含税**
  （减免记录的 `total_minor`，含 b16 记在减免上的那一分）；`summary.bill.takenOff` 是打印账单上的那一行，**税前**
  （菜品 − 店家减免 − 积分 = 小计；小计 + 税 = 合计）。`summary.ordered` 是“点了多少”：被免单的菜仍按点的价算在里面，
  税按整张账单算一次。所以：
  - 已付 − 已退 − 退款中 + 还欠 + `summary.takenOff` + `summary.pointsUsed` = `summary.ordered.total`，到分；
  - `summary.bill.total` + `summary.takenOff` + `summary.pointsUsed` = `summary.ordered.total`。
  - 不能拿 `summary.bill.takenOff`（税前）去对 `ordered`（含税）：live22 报告的“少 42 / 81 分”正是这一差（免单那道菜的税）。
- **live22 的两个例子（单元测试照抄）**：TM2 四轮（牛肉面 / 豆浆 + 拍黄瓜 / 牛肉面 / 豆浆 + 拍黄瓜）。
  ① 删第 2 轮拍黄瓜、删掉整个第 3 轮、免第 4 轮豆浆：点单合计 2853，`takenOff` 367（税前 325 + 税 42），还欠 = 账单 2486；付款后已付 2486。

## b26 删掉的菜按删的那一刻账单减了多少算（2026-11-17，v15 live25 实测）

来源：`.local/integ-tools/b25/b25live-result.json`（tables-checkout-polish）。分支 `codex/fix-takeoff-cent-and-round-lines`，基于
`b58fd6fb`（第 1–25 批）。收的钱不变：取整、已记版本、结账、分单、删菜和免单的金额都不改；无迁移、无新授权。

- **规则**：“已从账单删除 · 不收费”的金额 = 每次删菜当时账单减少的钱之和。不另记录：免单、折让和积分抵扣的记录
  就是它当时让账单减少的钱（b16），所以删菜合计 = 点了多少（全部送出的菜、不减免，税按整张账单算一次）− 现在的账单
  − 各条减免记录的合计。先删后免、先免后删结果都一样。于是员工看到的 **合计 + 免单/折让（含税）+ 已从账单删除（+ 积分）
  = 点了多少**，到分。原先用“今天的减免”把账单重算一遍（全部菜的账单 − 留下的菜的账单），后来的免单会让它差一分。
- **live25 的例子（单元测试和受限角色验收照抄）**：TM2 三轮，每轮豆浆 $3.25（税 $0.42）+ 拍黄瓜 $6.25（税 $0.82），
  账单 $32.21。删第 1 轮豆浆（账单减 $3.68 → $28.53），删掉第 2 轮（减 $10.73 → $17.80），再免第 1 轮拍黄瓜 $7.06
  （net 625、税 81，账单那一分 −1）→ $10.74。原来显示删除 $14.40（10.74 + 7.06 + 14.40 = 32.20）；现在 $14.41，
  10.74 + 7.06 + 14.41 = 32.21。
- **并桌**：每张单的份额仍按账单顺序算（先删的单先算），最后一张有删菜的单拿“总删除额 − 前面各单的份额”，各份额相加
  仍 = 整张账单的删除合计。
- **每轮自己加得上**：结账、桌台“这桌的订单”和订单页里，一轮写菜（税前）、免单/折让（税前，结账写在那道菜旁边，订单页
  写一行“免单/折让（税前）”）、最后一行“税”（这一轮在账单上的税，含它分到的取整），相加 = 这一轮的金额。含税的免单金额
  （−$7.06）仍在“免单/折让”记录里写“（含税）”，用来对“点了多少”。菜的明细对不上账单（下单时的折扣或附加费、旧服务端
  没给税前减免）时不写这几行，只写这一轮的金额。
- **顾客页**：桌已付款（或整张账单为 $0）时，账单上 $0 的一轮（免单、或剩下的菜都删了）付款写“无需付款”，不再写
  “记入本桌账单”；积分付清的写“已付款”。已付款的一轮被厨房整轮拒做、没有删除也没有退款时，写“已付款”和“这一轮
  已付款，还没有退款。请问店员。”，不再说“款项正在退回付款的银行卡”；有退款在进行（这轮的菜或这张单）才写退款中。
- **桌台关台提示**：吃完再付的桌没有“在订单页取消”这个操作；未上的菜改写“在上面点‘已上’。如果顾客不要了，本桌还没付款，
  后厨也还没开始做，可在‘这桌的订单’里把它从那一轮删掉。”（先付后吃的桌照旧）。
