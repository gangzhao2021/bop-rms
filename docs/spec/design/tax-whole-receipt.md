# DEC-TAX-WHOLE-RECEIPT — 吃完再付的整桌账单，税只取整一次

状态：**协调人决定、Owner 授权（WP-2423 2026-10-30 A 第一步、第二步）**。系统规则代码 `DEC_TAX_WHOLE_RECEIPT`
v1，记录表来自迁移 `2000_132_create_order_tax_rounding_adjustment`。本文件补上代码里一直引用、但之前没有的决定文件，
并记下 2026-11-06 修正（v15 `07b7a1b7` 实测：桌台面板 $27.06，结账 $27.05）。

## 规则

1. 每份报价（每一轮）按税种对这份报价的应税额合计取整一次（HalfUp），分摊到各行，各行相加等于这份报价的税。
   自取、柜台单、先付再吃的桌：每一轮就是一张收据，到此为止，没有账单取整。
2. 吃完再付的桌（这次用餐的付款时机是 PayLater，订单有“吃完再付”的轮次确认）：整张账单是一张收据。每个税种的税
   = round_half_up(整张账单的应税额 × 税率)，应税额已减去免单、折让和删掉的菜。和各轮报价已收的税之差就是这张账单的
   **税额取整**（可正可负），按各轮精确份额的最大余数分到各轮（同余数按轮次）。
3. 记录：付款前（整桌付、规划分单、客人手机付）由系统规则先记下取整（只追加，账单变了就记新版本覆盖上一版）；一旦有付款
   （或核销）就用已记的版本，不再重算。报表、收据、Ordering 的计价总额都读已记版本。
4. 一次读取从不记录。

## 各处显示什么（2026-11-06 修正后）

| 地方                              | 显示                                                                                            |
| --------------------------------- | ----------------------------------------------------------------------------------------------- |
| 结账（员工）                      | 每轮按点单时的金额（不含取整份额）；小计；税；“税额取整”一行；含税合计 = 付款金额               |
| 桌台面板“这桌的订单”、订单页详情  | 小计；税（各行税之和）；“税额取整”一行（不为 0 时）；合计 = 各行合计 + 这张订单那几轮的取整份额 |
| 免单和折让（桌台面板）            | 另列；“免单后待付” = 账单（付款方的数字）                                                       |
| 并桌：主桌的“整张账单”            | 整张账单（两桌合计，含全部取整）                                                                |
| 分单（按轮分）                    | 每轮**含**取整份额，因为各份加起来必须等于账单                                                  |
| 断网指引（页面和 `offline.html`） | 每轮按点单金额，“税额取整”一行，待收 = 账单；与结账同一组数字                                   |
| 客人桌页、收据、日报              | 原样（已有“税额取整”一行，读已记版本）                                                          |

精确地说：订单详情的“合计”是**免单和折让之前**的各行合计，加上**免单之后**算出的取整。所以
**合计 − 免单折让 = 免单后待付 = 结账含税合计**；没有免单时，合计就等于结账含税合计。删掉的菜和因付款失败取消的轮次
不计入（界面已从合计里减去，取整也是删菜之后算的）。

并桌：每张订单的详情只含它自己那几轮的取整份额；主桌的详情是主桌自己的部分，被并入桌的详情是那一桌的部分；两张详情的
合计相加 = 主桌面板上的“整张账单” = 结账。

## 订单详情怎么取得取整（`readOrderTaxRoundingShare`）

- 这张订单没有“吃完再付”的轮次确认 → 0，不再读别的（自取、柜台、先付再吃）。
- 账单（被并入的订单跟到它所在的账单）已有付款、线上付款或核销 → 已记版本里这张订单的行相加；不读桌台，桌台关了很久也一样。
  付款早于这条规则、没有记录的账单 → 0（和结账一致）。
- 还没有付款 → 和结账同一个读法（`readDiningTableBill`，不记录）。
- 两者都读不到才失败（“读不到这桌的订单”，面板已有的重读）；绝不显示不含取整的合计。

## 例子（v15 实测，火锅店 6 × 酱料台 $3.99，分 5 轮，13% HST）

- 各轮：第 1 轮 7.98 × 0.13 = 1.0374 → 1.04；第 2–5 轮 0.5187 → 0.52；合计 3.12。
- 整张账单：23.94 × 0.13 = 3.1122 → **3.11**；取整 −0.01；合计 **$27.05**。
- 分摊：精确份额 103.74、4 × 51.87；先取整数 103 + 4 × 51 = 307，余下 4 分给余数最大的第 2–5 轮 → 第 1 轮 103（−1），
  其余 52（0）。
- 修正后：面板和订单页 小计 $23.94、税 $3.12、税额取整 −$0.01、合计 $27.05；结账 第 1 轮 $9.02、第 2–5 轮 $4.51，
  税额取整 −$0.01，含税合计 $27.05；分单（按轮）第 1 轮 $9.01。

## 断网

没有新做法：断网时店员按断网指引上最后看到的账单（与结账相同的数字）用刷卡机或现金收款，恢复后补录（运行手册
“Store outage procedure”）。断网指引在修正前保存的旧数据最长保留 12 小时，其中每轮金额仍含份额、没有取整行；合计（待收）不受影响。
