# DEC-MENU-STORE-PRICE-AND-LISTING — 本店价格、上架与各门店是否开卖

状态：协调人决定（2026-11-11，依 Owner 常设授权；Owner 可推翻）。来源：v15 第 5 批实测 menu-authoring-prices 的 5 条发现。
不改变 [DEC-BRAND-MULTI-STORE](./brand-multi-store.md) 修订取舍 7、[DEC-SINGLE-STORE-MENU](./single-store-menu.md)、
[DEC-OWNER-DEFAULTS-2026-11-06](./owner-defaults-2026-11-06.md)。

## 决定

1. **“只改本店”的价格保存即生效，屏幕照实说。** 真实连锁店里，店长调本店价格当场生效、记下是谁调的
   （修订取舍 7 规则 1，价格页的“本店价格”同样如此）；上架只管品牌层的内容（菜名、新菜、全店价格、加料价格、过敏原）。
   所以保留“立即生效”，把错的是提示：保存后写“{菜}：本店客人从现在起付 $X。”，并说明其他改动要上架，或者“其他内容没有改动，无需上架”。
   只改了本店价格的保存不再打开菜单草稿（不会出现“有改动还没上架”却没有可上架内容）。
   打开草稿放在第一笔需要上架的写入之前，中途停住的保存再保存时，已写入的改动仍会等上架。
2. **品牌上架后，新菜在菜单服务的每家门店都开卖。** 品牌老板（持有品牌层“商品供应”权限）上架时，
   菜单上在某家门店从未决定过的菜，在那家门店也开卖；门店自己隐藏过或停过的菜保持门店的决定。
   没有品牌层权限的人上架时不替别的门店开卖，“将要上架”会写明这些菜在其他门店仍隐藏、要各店自己“显示给客人”。
   “将要上架”在多店品牌下列出这些菜，并说明哪家店不卖就在那家隐藏。
3. **保存没得到回答，原样再按“保存”就是同一次保存。** 同一操作、同样内容、与当时发送时相同的“看到的价格”重发，
   服务器按同一操作补完，不会记两次改价；表单改动过才要求关掉重开（WP-2423 第 10 项）。
4. **“将要上架”列出加料价格。** 每个等待上架的加料价格写成“{菜}，{选项}：+原价 → +新价”，新选项写“（新）”。
   改了菜名、说明、照片的逐项对比仍是暂缓的 M72，本次不做。
5. **客人菜单列表里的菜品缩略图 alt 为空不是缺陷。** 列表卡片的图片是装饰（链接已带菜名），
   店员填写的照片描述用在菜品详情页的大图上（`MenuPage.tsx` 的 `decorative` 与 `MenuPhotoPicture`，
   客户端单测已覆盖）。

## 边界

- 价格以分计；本店价格变更照旧记入 `rms_pricing.store_price_change`（原价→新价、操作人），只追加。
- 替其他门店开卖写的是各门店自己的供应规则（`rms_catalog.availability_rule`，品牌范围），审计记为 `BrandListing`；
  不新增迁移、不新增授权。
