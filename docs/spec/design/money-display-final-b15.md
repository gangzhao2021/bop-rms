# b15 金额读数一致（money-display-final）

状态：协调人按 Owner 常设指示（商业保真、技术选择自行决定、2026-11-06 默认）决定，Owner 可推翻。来源：v15 第十四批
实测 2026-11-13（`.local/integ-tools/b15/money-display-final.json`）。分支 `codex/fix-money-display-final`，基于
`38320596`（第 1–14 批）。无迁移、无新授权、无目录或角色变更。延续 [b13 账单与退款读数](bill-and-refund-display-b13.md)
与 DEC-TAX-WHOLE-RECEIPT。

## 1. 全部免单的桌关台后也有收据

实测：L14 BRD 2 全部免单、关台后，客人页只有“谢谢光临”，收据读取 404（服务端只给已付清或分单付清的桌收据）。
决定：关台、没有核销、有菜、每一轮合计都是 $0.00 的桌，也给收据：菜品逐行标“店家减免”，实付 $0.00，没有付款行，
客人页写“无需付款：餐厅已全部免单。”（b13 已有的客户端文字）。这种收据 `split` 为 false。核销的桌、没点菜的桌
仍没有收据。受限角色验收 `dining-pay-later-round`（comped in full）新增该断言。

## 2. 店员也只看一个税额（取代 b13“订单页保留舍入行”）

实测：桌台面板写“税 $4.89 / 合计 $42.39 / 税额取整 −$0.01 / 整桌账单应付 $42.38”，客人、结账和打印的已付账单
写“税 $4.88 / 合计 $42.38”。决定：凡是最后一起付的桌的订单（桌台面板和订单页同一组件），这张订单分到的整单
税额取整直接算进它的“税”和“合计”，不再单列“税额取整”，也不再重复一行“整桌账单应付”；只有合并了别的桌
（整桌账单不等于本单合计）时才另写“整桌账单应付（含 X 桌）”。已付后同样（税、合计等于已付账单）。
本单有免单时，上面仍是下单时的金额，免单列表里那一分钱写“减免后整单重算的税差”（订单页与桌台用同一说法）。
断网时保存的上次账单每轮按账单金额（含舍入份额）保存，各轮相加就是应付，不再有舍入行；旧页面保存的值照旧显示。
未改：桌台面板每一轮标题仍是下单时的金额（舍入份额只有整单数，没有逐轮数）。

## 3. 收回 0 元

表单输入 0：写“请输入收回的金额，必须大于 $0.00。没有记录。”（与服务端 422 同一句），不发请求。服务端对
收回被拒（0 元、超过已退、现金非 5 分整数等，`RefundRecoveryError` 除 `REFUND_RECOVERY_UNAVAILABLE` 外）的日志
为 level 30、`resultCode: "REFUSED"`，不再是 level 50 告警；读不到记录仍是 level 50。

## 4. 订单页“记录”里的现金退款

实测：退款 $5.09、钱箱退还 $5.10 的柜台现金单，“记录”写“退款 $5.10”。决定：柜台现金付款上、来自退款请求的
退还，按该请求的金额写“退款 $5.09”，旁边写“现金，从钱箱退还 $5.10”（两数相同时只写现金）；与付款页同一规则
（每个请求按它自己的金额）。服务端“记录”每条退款都带 `cashGivenBackMinor`（字符串或 null）；客户端兼容没有该
字段的旧服务端。

## 5. 付款页上的轮次被取消

实测：员工“取消未付款轮次”后，客人仍在付款页，点确认得到 503“付款服务暂不可用”约 30 秒，最后写“付款没在
时限内完成”。决定：

- 付款结果读取：付款因取消而失败、且这一轮的取消记录（`order_batch_checkout_cancellation`，按结账的付款操作）
  是 `STAFF_CANCELLED_UNPAID` 时，结果写 `CancelledByStaff`；系统超时取消仍是 `NotCompleted`；读不到 Ordering 时照旧。
- 确认付款（模拟确认、继续付款）：原本会答 503 时，先看这次付款的结果；已因员工或系统取消而失败，答
  409 `payment_round_cancelled`，不再让页面按“服务不可用”重试。
- 客人付款页：显示刷卡（或模拟确认）时每 10 秒读一次付款结果；结果是员工取消、超时取消或付款人停止，就转到
  结果页。结果页写标题“这一轮已取消”，“餐厅在付款前取消了这一轮。没有扣款。”，“没有送到厨房，如果还想要，
  请找店员。”；不显示“换一张卡”。已提交卡后不再读。
- 断网：读结果失败不改变页面，确认时仍按原来的不确定流程处理。
