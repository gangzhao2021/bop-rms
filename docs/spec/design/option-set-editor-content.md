# Full Option Set version content

WP-2421 software design supplies the missing Handoff71.4/71.5 fields. `CatalogOptionSetEditorContentV1` combines the actual parsed owning supported root/Draft with explicit additional version fields. The older Draft DTO and `CatalogSupportedOptionSetDraftContentV1` remain compatible and cannot silently become full content.

Every stable Option, including inactive/archived entries, has exactly one additional detail. Quantity limits are nonnegative minimum and positive maximum, narrowed within the Set per-Option/total/repetition limits. Optional Media pins reference/asset/version and localized alt text; optional Pricing pins rule/reference version. Optional Inventory or Recipe consumption pins the corresponding owner reference/version plus positive exact decimal quantity and unit. No rate, amount, Ready, Satisfied, approval or current-source result is stored in the candidate. A triggered Set requires an explicit pinned target version; the actual owning source later verifies the pair and current graph.

Conditional rules are bounded positive conjunctions: when all listed options are explicitly selected, all listed required options must also be selected. They never auto-insert selections. Conflict rules forbid selecting a listed combination together. All references are within this version; identities and canonical combinations are unique. Direct require-versus-forbid contradictions, including existing pair conflicts, are rejected structurally. Complete satisfiability, defaults in each Product Binding, cross-Set trigger cycles and all conditional reachability still require a current owning RuleSatisfiability check. A structural parse is not that proof.

Scope uses the accepted Brand/Store/StoreGroup/Region/Channel/OrderType selector semantics, canonical channel/order restrictions and no invented membership. Period uses the public BOP EffectivePeriod contract for IANA zone, explicit offset/local wall time, canonical UTC and half-open end. Actual current policy chooses precedence/backdate/approval behavior; current Tenant topology and eligibility remain separate. Bound one hundred options/details/rules/selectors, reject oversized input instead of truncating. Decimal consumption uses canonical strings and integer string arithmetic, never binary-float quantities or money.

Full source/content/configuration fingerprints include the complete core and additional fields. Media alt text contributes to content but not rule/reference configuration. `CatalogFullOptionSetDraftContentV2` preserves the supported immutable snapshot, full details and whole-record fingerprint; its successor keeps all stable IDs with a distinct Draft version. Stored recovery verifies both profiles/body/fingerprints and cannot substitute a later mutable Draft. Both preparations carry `NotEvaluated` eligibility. A valid UUID or recomputed fingerprint authenticates neither a caller nor a publication.

The next forward Catalog1102 writer must persist full Draft details and immutable V2 content/original operation result through the accepted owning transaction, with current action/field authority, actual validation/approval/reference sources, version CAS, Audit/Outbox, source barriers and late refusal rollback. Published/pinned reads use the frozen full record; CurrentPublished additionally resolves current scope/period/lifecycle and held validation. Ordinary Product publishing cannot use legacy V1 or client-provided reference status to close full Option qualification. No actual SQL/current writer/HTTP/UI acceptance is supplied by this contract milestone.

A successor at the final legal int32 root revision remains readable with its complete additional content. Supported-content identity derivation has an additive read/preparation entry point for that revision; legacy publication-only derivation and sealing retain their refusal when another root revision cannot be allocated.
