# b13 账单与退款读数一致（bill-and-refund-display）

状态：协调人按 Owner 常设指示（商业保真、技术选择自行决定、2026-11-06 默认）决定，Owner 可推翻。来源：v15 第十二批
实测 2026-11-13（`.local/integ-tools/b13/bill-and-refund-display.json`）。分支 `codex/fix-bill-and-refund-display`，基于
`ed787e9c`（第 1–12 批）。无迁移、无新授权、无目录或角色变更。延续 [DEC-TAX-WHOLE-RECEIPT](receipt-tax-and-privacy.md)、
[b12 免单后分单](split-bill-after-comp-b12.md) 与 [柜台现金](counter-cash.md) b12 节。

## 1. 一张账单，一个税额（DEC-TAX-WHOLE-RECEIPT）

实测：店员结账和打印的已付账单写“小计 $22.50 / 税 $2.93 / $25.43”，客人“整桌合计”却写“税 $6.51、店家减免 −$31.09、
舍入 $0.01”，店员账单摘要也多一行“税额舍入 $0.01”。金额一样，读法不同。

决定：凡是一桌“最后一起付”的账单，读法都和纸质账单一样——菜品（税前）、店家减免与积分（税前）、小计、**一个税额**
（整张账单减免后算一次，含舍入）、合计。

- 账单读取（Payment 的 `readDiningTableBill`）已按轮给出减免后的小计、含舍入份额的税和合计；客人桌页的读数
  `readCustomerTableBillFacts` 直接汇总这些数（整张账单 `bill`，每轮 `rounds`），不再用菜品原税加一行舍入。
- 客人“整桌合计”：有减免时“菜品 $50.00 / 店家减免 −$27.50 / 小计 $22.50 / 税 $2.93 / 合计 $25.43”；没有减免时只写
  小计、税、合计。不再出现“舍入（按整单计税）”一行；只有旧服务端（没有 `bill`）才按原来的写法。
- 每个轮次卡片也按账单写这一轮（减免后小计、税、轮次合计），各轮相加就是整桌合计；全部免单时每轮写 $0.00，
  不再写原价 $14.13。客户端读入时核对：菜品 − 减免 − 积分 = 小计，小计 + 税 = 合计，对不上就不显示。
- 店员侧：桌台面板“免单和折扣”列表去掉单独的“税额舍入”行（下面“免单后整桌应付”已是含税总额）；合并桌的
  “整桌账单”税额含舍入、不再另列。订单页的订单明细（按下单时记录）仍保留舍入行，它说明订单原价与账单的关系，
  不是账单本身。
- 受限角色验收 `dining-pay-later-round` 新增：客人读数的小计/税/合计等于店员账单逐轮之和，每轮合计等于店员账单该轮。

## 2. 分单被免单改过时（stale）不再列旧份额

- 店员结账：分单过期（只在一份都没付时才会）时不再列“第 1 份 $14.13 / 第 2 份 $14.12”和“0/2 份已付 · 还差 $14.13”，
  只写“分单以后账单有变化：现在整桌是 $11.30。请重新分单再收款。”
- 客人：服务端在分单过期且未付任何一份时不再给 `splitParts`，“整桌合计”下面不再写“这桌分成 2 份付”。
- 全部免单（$0）时客人写“餐厅已全部免单：没有需要付的钱。”，不再写“这桌最后一起付，含税和小费”；关台后写
  “桌号 X 已关台。”（不再写“已付清”——什么都没付），收据在没有付款时写“无需付款：餐厅已全部免单。”

## 3. 桌台列表的“全部上菜”、标记上菜和“正在核对账单”

- 根因：结账中、$0 或已付的桌，桌台列表的上菜数只来自订单队列；队列没带到这张单（或读得慢）时，列表只按账单说
  “无需付款”，没有“全部上菜”，而关台又要求先上完菜。决定：**结账中的桌，以及订单队列没带到的开台桌，各自再读一次
  这桌的上菜进度**（与桌内“标记上菜”用的是同一个读取，`/merchant/dining/order-progress`，每次列表读取最多 20 桌、
  同时 4 个），有菜在出餐口就显示“N 道菜待上菜”和“全部上菜”；读不到时保留队列的说法。
- 标记上菜：服务端确认后立刻显示已上，不等重读（实测 5–10 秒仍显示“待上菜”，容易再点一次）；重读结果若还没
  跟上，最多 30 秒内仍按已确认显示，之后以服务端为准。没有确认（网络断开）时照旧“再点一次，同一请求只记一次”。
- “正在核对账单”：本机为断网保存的上一次账单（同一桌、在这桌客人入座之后保存）在读取期间写在旁边，例如“正在核对
  账单 · 上次读到：待付 $14.13”；读到账单后只按账单说。不是本桌这一拨客人的就不显示。

## 4. 退款页的现金读数与刷新

- 现金退款同时写两个数：标题写实际从钱箱退出的现金（整 5 分，如 $5.10），下一行写“退款 $5.09，现金按 5 分取整”；
  退还以后同样（“已退还现金”），付款摘要在“已退款 $5.09”旁写“从钱箱退还的现金 $5.10”。服务端在退款列表每条现金
  请求带 `cashGivenBackMinor`（已退还或待退还，与请求状态同一规则），付款读数带 `cashGivenBackMinor`（这笔现金所有
  退款实际退出的合计）。
- 付款页和退款页只有一个“刷新”（在付款金额下面）：同时重读金额、退款请求和每条请求的状态；已记录或结果未知的请求
  仍照原来的方式重读（说明“请求仍已记录”）。每条请求不再有自己的“刷新”，办完的请求只有“详情”。读取失败的
  “重试”和“查看是否已记录”保留。
- 收银员记录刷卡机退款请求后写“由店长或店主在刷卡机上退款，并在付款页记录”，与请求行一致，不再写“在审批里发出”。
- 收回多退的钱金额为 0：服务端答 422 `recovery_amount_zero`（在权限检查之后、什么都不写），页面写“请输入收回的金额，
  必须大于 $0.00。没有记录。”，不再是通用 403。受限角色验收 `counter-cash` 新增该断言。

## 5. 其他读法

- 订单页关台步骤用桌台说法：“开始结账 / 关台”，勾选“我确认顾客已点完菜 / 我确认顾客已离开，可以关台”，
  不再出现 dining session。
- 首页“待关闭的桌台”中文：“5 张桌台已上完菜，顾客离开后关台”（去掉英文模板带来的空格）。
- 选项配方页的过敏原按员工语言显示：服务端随名称给出过敏原代码，中文时按代码写中文名（与菜单页同一张表）。
- 已登出遮罩的“再查一次”：本屏仍带着已结束登录的 CSRF，所以在别的标签页重新登录后检查被拒（403）。现在再读一次
  浏览器当前的登录，若已是新的登录，就用它重新打开本页（停在原来的页面）。“重新登录”会在本标签页记住当前页面
  （15 分钟内、只限本应用页面路径），登录后回到这一页；身份服务的登录回跳地址仍是固定名单，不改。
- 中文“上架内容”的改名行（“改名：A → B”）不加菜名：在员工自己的语言里，旧名就是这道菜的名字；只有改的是另一种
  语言的名字时才带菜名（现状）。不改。
