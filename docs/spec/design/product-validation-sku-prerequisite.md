# Current Product SKU prerequisite in ordinary Validate

WP-2421 milestone119 implements a necessary condition from accepted Section68.9 item3. A supported Product without any owning Active SKU cannot satisfy target-scope publishability. Neither supported Product Type, PreparedFood nor NonAlcoholicBeverage, declares an explicit no-SKU waiver. No new type registry or fixed qualification mapping is introduced; an unsupported type still refuses through the owning parser.

Catalog derives `skuPrerequisite` from the actual parsed current candidate: `NoActiveMember` for an empty or wholly inactive set, `ActiveMemberPresent` when at least one exact owning member is Active. The result transports no SKU identity, names, quantities or content. `ActiveMemberPresent` is deliberately a necessary-condition observation, never a Pass receipt. Product lifecycle, Store/module availability, target scope, references, actual Media readiness, tax, Variant/Option rules and sale qualification remain independent. An Active SKU cannot override their HardError or Warning.

The existing current candidate/UniqueScope composition now carries this minimal observation inside its same fingerprinted result. Native ordinary Validate uses that actual owner result under the original current candidate fields, history fields, Tenant registered identities, typed policy and source fences. Catalog's new `applyCatalogProductCandidateValidation` first uses the existing closed thirteen-field owning UniqueScope binder, requiring the original Tenant/Brand/Product/version/root/content/configuration/intent/policy, full twelve-check receipt and exclusive five-second minimum lease. It then records PublishableSku and HardErrorsCleared as HardError only for `NoActiveMember`. Other checks, evidence, policy, Actor/Reason and their warning acknowledgement remain unchanged. Missing/unknown observations refuse, rather than defaulting to an empty set or qualification. A newly found failure cannot reinterpret an acknowledged SKU warning into an authorized HardError override; an inconsistent closed acknowledgement refuses as unavailable instead of being silently rewritten.

Ordinary successful Validate may record HardError for an incomplete Draft. This does not activate a SKU or authorize publishing. The existing owning lifecycle release guard remains mandatory. Current native/independent complete-field admission, original query/transaction/Actor binding, final source rechecks before COMMIT, failed-use guard, CAS and append-only Audit/Outbox remain in place. Original Unknown recovery requires current write/read admission and returns the original result without reacquiring expired candidate/history/roster/policy facts; no historical lease is renewed.

The existing115 isolated HTTP/SQL helper inserts no SKU rows. Its earlier supplied-Pass-based decision assertion therefore becomes HardError under this new owning prerequisite; every other previous current grant/field/late tentative root2 rollback/root advancement/lost-response/current denial/source-free replay/unknown Region assertion remains required. This is a deliberate behavior correction recorded before implementation, rather than a synthetic Active SKU added to hide the failure. Synthetic lifecycle/mixed-set tests prove necessary membership and no promotion; actual local HTTP/SQL must separately prove stored HardError and original recovery. Other independent check outcomes, authority/governance holders and fixture business identities remain synthetic. Full current PublishableSku target-scope producer, twelve-check source closure, ordinary release screens, Store management, actual source IAM, UAT and formal release remain pending.
