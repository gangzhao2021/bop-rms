# DEC-INV-DIRECT-RECEIPT — 门店直接进货（无采购单入库）

状态：**Accepted**。2026-10-07，Owner 在会话中按“按实际商用出发，不为简便取舍”的原则确认。
执行工作包：[WP-2423](../work-packages/WP-2423.md)。

## 背景

规格 Section 31.15–31.16 与 `INV-GOODS-RECEIPT`（WP-2135）只定义了关联采购单（PO）的进货入库，
采购（Procurement）领域目前按 DEC-FOCUS-01 冻结。单店咖啡/餐饮的实际运营中，大量进货没有正式采购单：
店员到超市现买、供应商直接送货并当场签收、临时补货。若每次进货都必须先建采购单，门店无法日常运营。

## 决定

1. Inventory 增加一种进货类型 **Store Direct Receipt**（门店直接进货），不引用采购单。
2. 它与 PO 入库遵守同样的库存事实规则（Section 30、31.15）：
   - Inventory 是实际收货的唯一事实来源；记录 Stock Site、存放位置（Location）、品项、实收数量与单位、
     批次（Lot）与保质期（Expiry，按品项追踪策略必填）、收货时间、收货人（具名 Actor）。
   - 记录供应商（可为门店登记的供应商，或仅名称）、单价与币种（金额不使用二进制浮点）、
     拒收与损坏数量及原因；拒收、损坏不进入可用库存，且不得静默处理。
   - 品质/温度证据按品项策略记录。
   - 一次提交生成一条不可变的收货事实与对应的入库流水（原子提交、幂等重放）；
     错误只能通过明确的调整或作废事实更正，不修改原记录。
   - 发布 `GoodsReceiptPosted` 同类事件，供日后采购履约与成本核算消费。
3. PO 入库（WP-2135）保留，待采购领域解冻后接入；两种入库共享同一收货事实模型与账本规则。
4. 开业期初库存不通过导入，而是走受控的库存初始化（盘点）流程（Section 72，第 18848、18898 行）。

## 实现（2026-10-07）

- 页面：`INV-RECEIPT-LIST` `/operations/receiving`、`INV-GOODS-RECEIPT` `/operations/receiving/new`（门店直接进货模式）、
  `INV-RECEIPT-DETAIL` `/operations/receiving/:id`；权限 `inventory.receipt.read` / `.post` / `.correct`。
- 一次提交：供应商名称、可选单据号、每行配料 × 存放位置 ×（按追踪方式）批次与到期日、实收/拒收/损坏数量（拒收或损坏须选原因）、
  单价（加元分，每基本单位）、可选到货温度（摄氏，一位小数）。只有实收进入库存（`Receive` 流水）；批次与开业盘点共用登记，
  同一批次号到期日必须一致。
- 更正只经作废：逐行以 `Correction` 流水冲回实收，原因必选；该批货已被使用或预留时拒绝作废（逐行指出），改用调整或损耗。
- 暂未做：采购单入库、供应商主数据、按包装单位收货（目前按基本单位录入）、待检（隔离）库存、`GoodsReceiptPosted` 事件
  （尚无消费者；采购与成本核算解冻后接入）。

## 不改变

不改变 Section 30/31 的其他规则、采购领域的冻结状态，也不授权真实供应商、价格或门店数据进入测试环境。
