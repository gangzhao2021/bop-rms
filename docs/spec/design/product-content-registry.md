# Catalog registered Product content definitions

WP-2421 implements Brand-registered Tags and typed Attribute definitions required by accepted Section68.3. They are Catalog-owned configuration records within the existing Module, without a new Aggregate Root or changed Module dependency. Section68 requires registration; it does not establish a separate approval/publication lifecycle for these definitions. Product publication requires its own full validation and governance.

## Definition and history rules

`CatalogProductContentRegistryV1` binds Tenant, Brand, stable registry identity, version identity, monotonic version, default locale, registration instant and previous actual snapshot digest. Successors preserve every registered Tag, Attribute and Enum-member identity, including retired definitions. Codes, Attribute types and Decimal units cannot be reinterpreted. Identities cannot move between definition kinds or Enum parents. Names and current constraints may change; Active/Inactive transitions are allowed, while Retired is terminal. Registration history supplies no Product sale permission.

Text constraints range from1 through240 characters, matching the existing Product value bound. Boolean values remain Boolean. Decimal values use canonical signed strings and exact BigInt comparison, with up to14 integer and6 fractional digits, optional registered unit and inclusive minimum/maximum. Enum values must refer to a currently Active member of the exact registered Attribute. Current validation refuses missing, Inactive or Retired definitions, wrong type/unit, excessive Text, out-of-range Decimal and unknown Enum members. Variant values with an Attribute reference require a current registered Attribute. Missing complete Product content is unavailable rather than an empty-reference proof.

Public parsing copies property descriptors without invoking accessors, rejects unknown fields, bounds structures and normalizes definition order before canonical fingerprints. Each definition group has at most1000 entries; canonical snapshots have a1MiB limit. Current complete history has at most1000 revisions and8MiB total PostgreSQL command/snapshot text. Writers measure new PostgreSQL jsonb text before append under the source fence. Readers count complete history before fetching JSON and reject excess or gaps instead of truncating. An owning history-compaction design is necessary before exceeding these bounds.

## Owning write and held current read

It uses existing Catalog transactions and approved Audit/Eventing public append contracts; no foreign private-table access is added.

Registration requires an explicitly configured User Actor with current `catalog.manage`, fine action `catalog.content-registry.manage`, exact purpose/fields, expected version, original operation, reason and trusted-clock time. New commands must be less than30 seconds old before append and after final authority. A shared/exclusive owning source barrier serializes CAS and lasts through outer COMMIT. Record, Audit and minimal Outbox event commit atomically. Late authority, expiry or Outbox failure rolls back all three, including the Audit chain head.

Original idempotent recovery checks exact normalized intent, returns its original immutable snapshot under fresh authority and appends nothing. It works after a later registry head and after the original time interval; it does not rebuild old results from current configuration. A read-only source needs no dummy Audit callback. Current User/System reads require the separate `catalog.content-registry.read` action; System registration is denied. Observations bind original caller intent, observedAt and validUntil, last at most30 seconds and are checked around caller work. Missing, foreign, incoherent, revoked or expired sources refuse.

The authority collaborator must hold actual current Brand lifecycle, enabled locales, complete field/purpose permission and authoring policy through outer COMMIT. Its normal owning implementation remains pending. These contracts neither install runtime grants nor accept client permission facts. Normal composition must acquire current authority before the registry barrier; the authoring workflow must preserve that order.
