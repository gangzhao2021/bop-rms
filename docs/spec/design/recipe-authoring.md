# DEC-RECIPE-AUTHORING — 后台配方维护

状态：**Accepted（实现决定）**。2026-10-07，在 Owner 的商用原则（“按实际出发，不要为了简便而做”）与技术选择授权下作出。
执行工作包：[WP-2423](../work-packages/WP-2423.md)（顺序第 6 步）。依赖 [DEC-PERM-BRAND-ROLES](./brand-role-templates.md)。

## 背景

- 配方领域（不可变版本、两位独立审核人、厨房步骤内容、SKU 绑定、订单需求与厨房工单解析）已实现并有验收，
  但只有测试脚本能写入：没有后台入口，没有审核记录的保存，没有人名与步骤文字，SKU 绑定一旦写入无法更换。
- 已发布的版本不能改回草稿；SKU 绑定不可修改。现实中配方会调整（分量、原料、做法），换配方不能中断销售。

## 决定

1. **品牌级、按权限分工**：`recipe.read` 查看，`recipe.update` 写草稿，`recipe.approve` 审核，`recipe.publish` 发布、
   发布厨房说明、指定 SKU、归档。全部按品牌范围判断（品牌角色，DEC-PERM-BRAND-ROLES）。
2. **草稿**：名称、代码（创建后不可改）、产出（`EACH` = 作为 SKU 售卖的一份；`KG/G/L/ML` = 批量半成品）、
   原料（启用且计库存的配料，按基本单位；或已发布的半成品配方，按其产出单位）、损耗 %、标准成本（元/基本单位，
   默认取本店最近一次进货或开业盘点的单价）、厨房步骤（顺序号、说明、时长、厨房工位）。每次保存都是新的不可变版本，
   配料按当时的配置操作固定版本。
3. **审核**：成本与食品安全各一位审核人，二人不同且都不是作者；审核绑定到所审内容的摘要（名称、原料、步骤文字），
   草稿再次保存后需重新审核；驳回必须写明原因。发布时重新确认两位审核人仍持有审核权限且仍是品牌成员。
   审核记录只追加（`recipe_authoring_review`），发布时写入领域的审核证据。
4. **厨房说明**单独审核并发布：领域规则要求厨房内容在配方发布之后撰写、由同样独立的两位审核人确认。发布后厨房工单
   才能显示这些步骤；之前不能把配方指定给 SKU。
5. **SKU 指定**：只有已发布且厨房说明已发布、产出单位与 SKU 销售单位一致（`EACH`）的配方可以指定。可对整个品牌或只对
   当前门店（门店专用优先于品牌）。同一范围内 SKU 原有的配方在同一时刻停止适用（`recipe_scope_binding_end`，只追加），
   之前开始的订单仍按原配方解析。品牌级指定只能被替换，不能移除；门店专用可移除，回到品牌配方。
6. **修订**：已发布配方的修订是同一配方族的新配方（代码加 `-R2` 等），原配方继续使用，直到修订版发布并重新指定 SKU；
   一个配方族同时只能有一个未发布的修订。没有 SKU 和其他配方使用的配方可以归档。
7. 名称、步骤文字、工位与成本保存在 `recipe_version_presentation`（只追加，按版本），领域快照中的显示代码沿用配方代码。

## 尚未覆盖（记录，不在本步）

- 过敏原：原料层面的过敏原声明与证据尚无主数据（目录过敏原登记为空），食品安全审核目前是人工确认；随菜单步骤接入。
- 选项改料（如换燕麦奶）需要配方改料规则及其厨房内容；随菜单与选项步骤接入。
- 厨房工位没有后台维护，页面按现有工位配置显示为“工位 1（全部出品）”。
- 计量单位换算（如按“毫升”录入以“升”为基本单位的配料）未开放，按基本单位录入。
