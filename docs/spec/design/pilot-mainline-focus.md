# DEC-FOCUS-01 — 试点主线聚焦与范围冻结

状态：**Accepted**。2026-10-06，Owner 在设计审查会话中对审查建议回复“按你建议做”。
执行工作包：[WP-2422](../work-packages/WP-2422.md)。

本决定只调整工作优先级和新增工作的范围。它不重开已接受的 Sections 0–97、scoped addenda、
领域所有权或 Section 88 页面契约，也不删除任何代码或已记录证据。

## 为什么需要这项决定

2026-10-06 的仓库审查发现（统计方法与数字见 WP-2422）：

- 以下 7 个包在 `apps/*/src` 和 `tooling/environment` 中没有任何非测试代码引用：
  `@rms/procurement`、`@rms/compliance-food-safety`、`@rms/customer-loyalty`、
  `@rms/reservation-waiting`、`@rms/business-intelligence`、`@bop/notification`、
  `@bop/privacy-governance`。
  其中 Business Intelligence 已有 6 个迁移和多条验收脚本，但没有 API 路由，也没有持久化适配器。
- 商户端 102 个路由中，约 99 个页面在正常（非 demo）模式下不注入数据客户端，默认使用
  `unavailable*Client`，只能显示“不可用”。
- WP-2421 以“完成整个项目”为目标，已推进 130 多个里程碑，后期大多集中在
  Product/Option/Recipe 发布权威的细化。
- 与此同时，试点主线流程虽有本地 InternalTest 证据，但还没有可部署的类型化组装根，
  运行时数据库权限也无法从代码复现（WP-2422 R1/R2）。

每次修改共享契约都要连带维护这些尚未投入使用的代码，投入与试点目标不成比例。

## 决定内容

1. **冻结外围领域**：上面列出的 7 个包不新增功能、迁移、页面、事件或验收脚本。现有代码保留，
   并继续通过类型、lint 和测试检查；只允许做保持共享检查通过所需的最小修改。
2. **冻结未接通页面**：商户端不再新增只依赖 fixture/demo 客户端的页面或功能。只有当试点主线
   需要某个页面时，才把它接到真实 API。现有路由与 Section 88 契约保持不变。
3. **暂停商品发布细化**：暂停 Product/Option/Recipe 发布权威的进一步细化（WP-2420、WP-2421
   中的对应工作线）。试点实际使用的路径出现缺陷时仍可修复。
4. **优先级**，依次为：
   1. 保持[试点验收表](../../runbooks/single-store-pilot.md#current-acceptance-and-remaining-work)中的主线流程可用；
   2. WP-2422 R1：可部署的类型化组装根；
   3. WP-2422 R2：可复现、可校验的运行时数据库权限；
   4. 真实门店上线所需的软件项。

## Owner 确认（2026-10-06）

WP-2421 中的“首个 Brand 设置 / Workforce 入职”和“Brand 配置工作流”两条工作线原先不在暂停
范围内，并作为问题提交 Owner。Owner 于 2026-10-06 答复：Brand 设置不是真实门店上线的前置条件。
因此这两条线同第 3 项一并暂停。已记录的实现与证据保留，未完成的迁移（如 `0200_035`、
`0200_036`）不再继续推进；如需恢复，须由 Owner 另行记录解除。

## 解除

Owner 可以通过新的书面记录，逐项解除上述冻结或暂停。试点主线满足可部署和真实门店上线条件后，
应重新评估本决定。

### 解除记录 2026-10-07（第 3 项：商品发布细化）

WP-2423 在当前迁移目录建成的 v15 数据库上发现：顾客加购返回 `CATALOG_SELECTION_REJECTED`，
当前代码要求商品具备 WP-2420/WP-2421 引入的发布事实，而 v15 中 60 张新的商品/价格/配方表为空。
任何新库要能售卖，都必须先通过新的发布流程产生菜单。Owner 于 2026-10-07 在会话中选择
“恢复暂停的发布线”（选项 2），据此解除第 3 项对 Product/Option/Menu 发布路径的暂停，
范围限于让一家门店的菜单能在后台创建、发布并被顾客下单所必需的工作；由 WP-2423 规划执行。
第 1、2 项冻结与 Brand 设置/Workforce 入职暂停不变。

**更正（2026-10-07，同日）**：上述解除依据的诊断有误。逐步复现表明 v15 上菜单发布、已发布投影、
SKU、规格绑定与目录校验全部通过（`Accepted`）；拒绝来自配方库存检查的 `STOCK_RESERVATION_INSUFFICIENT`：
DEMO 库存 on_hand 100、reserved 100、available 0。顾客下单不依赖那 60 张空的新发布表。
该解除记录待 Owner 重新确认是否保留。

**撤回（2026-10-07）**：Owner 在会话中同意撤回上述解除。第 3 项暂停恢复原状；WP-2423 转为修复
订单完成后库存预留未消耗的问题。

### 解除记录 2026-10-07（商用原则）

Owner 于 2026-10-07 确立“按真实门店运作设计，不为简便取舍”的原则（见 `AGENTS.md` Pilot track），
并同意据此解除：第 3 项商品/规格/菜单发布路径的暂停（门店需在后台维护菜单、价格与上下架），
以及 “首个 Brand 设置 / Workforce 入职” 与真实员工登录的暂停（门店需真实员工账号与增删）。
两者回到 WP-2423 上线清单，按优先级排期；第 1、2 项冻结（外围领域、未接通页面）不变，
但试点主线需要的页面（如订单详情）按需接通。
