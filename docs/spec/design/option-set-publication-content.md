# Option Set immutable publication content and successor

WP-2421 software design applies accepted Handoff71.5. Catalog owns Option Set identities, version content and Product Binding rules. Existing1102 migration bytes and current Draft contracts remain unchanged. This foundation implements supported-content preservation and successor planning only; it is not an owning publication writer or a CurrentPublished source.

The `CatalogSupportedOptionSetDraftContentV1` profile freezes the complete currently supported OptionSet aggregate and its Draft. It binds Tenant/Brand/OptionSet/version, source aggregate revision, original publication operation/intent, actual sealing instant and separately allocated successor Draft version. A source fingerprint covers the full root snapshot. Content covers all supported Draft fields; configuration covers display/selection/quantity rules and Option identity/code/lifecycle/default eligibility/order/trigger/conflict fields. A whole-record fingerprint additionally binds the original operation/intent and other metadata. These fingerprints detect inconsistent recovery data; they do not authenticate a supplied operation or replace the owning database tuple. Prose belongs to content, so a text edit invalidates content while preserving unchanged rule configuration. Refuse more than100 Options, repeated Option IDs or an exhausted int32 source revision, rather than truncating or aliasing content.

Pure materialization must receive the actual locked owning Draft and an already authorized transition. Its parser rejects malformed/tampered snapshots and returns detached immutable data. It does not create validation, approval, current policy, topology, trigger satisfiability, a committed operation or sale authority. `eligibility: NotEvaluated` is mandatory. Existing Draft Option lifecycles are preserved, including disabled choices; Product Binding defaults still pass the accepted disabled-default invariant. A valid frozen shape is insufficient to accept CurrentPublished.

The successor has a distinct server-allocated version, root revision plus one and sealing timestamps, while retaining root/internal-code/creator and every stable Option identity/code/creator. The writer must also prove that the version was never used in actual history. Planning rejects identity collisions observable in the supplied source; it cannot prove global freshness. The original frozen source stays unchanged when later Draft content is edited. No published snapshot is rewritten by Draft replacement or original-operation replay.

## Next owning persistence and current-source implementation

Use a forward Catalog1102 migration; never modify1102_001/002 bytes or another owner's private tables. Extend the version state through an explicit forward constraint change and freeze original version fields. Add an append-only immutable content/operation-result snapshot with exact Brand/OptionSet/version/operation references, fingerprints, forced Brand RLS and no public grant. Preserve the existing globally stable `option_id` identity: later Draft records cannot duplicate it into the current `option` primary key. The frozen version's options must resolve from its immutable snapshot, while current mutable Draft associations may move through the owning writer. Existing Product Bindings remain pinned to their original version and stable IDs. Read current and pinned versions through an additive public source, never by joining the latest mutable Option rows to an older version and calling it published content.

The writer holds the current OptionSet root, Brand barrier/current version graph, Actor/action/field/purpose permissions, applicable Publishing policy and complete current trigger/quantity/conflict/reference validation in one outer transaction. Unknown or incomplete sources refuse before CAS. Independently approved content is required when current policy demands it; stored approval is rechecked at transition. CAS, sealed content, new Draft, append-only original operation result, Audit and Outbox commit together. Late denial/expiry or write failure rolls all back. An authorized retry recovers the original result without reapplying to today's Draft; altered intent conflicts, and current permission remains required. Precise scope/period/current publication resolution and scheduled activation revalidation are separate source-backed behavior, not an automatic newest-version choice.

The present supported Draft omits Option Media/Pricing/Inventory references, conditional-rule payloads and effective scope/period listed in Section71. It cannot be labeled full Option content. Add those software contracts and owning collaborators before full publication validation. Actual Provider/media readiness, Store/Inventory facts, professional/legal requirements and future trigger evidence remain separate gates. No client DTO, supplied Ready/Published state, fixed mapping or synthetic callback may replace their owners.
