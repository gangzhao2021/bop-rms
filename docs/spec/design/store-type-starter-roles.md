# DEC-STORE-TYPE-STARTER-ROLES — 按店型开始的角色组

状态：协调人按 Owner 2026-11-06 原话“预设一些角色与权限，另外允许店家自定义；店家也可以对预设进行增删改”定（技术取舍由协调人决定，见 WP-2423 剩余工作第 18 项）。Owner 可以推翻。

## 问题

角色预设与自建角色已经有了，但每家店开出的都是同样六个预设（店主、店长、区域经理、前台、厨房、库存经理）。奶茶店没有“饮品师”，火锅店没有“传菜”“收银”，店主要自己从空白建角色、逐项勾权限。开店流程和角色页都没有按店型开始的入口。

## 决定

1. **入口两处，同一个组件**：门店设置页底部“谁做什么”（第一家店的一页式开店也显示，不折叠）与角色页顶部“按店型设置角色”。店主选店型 → 看清会添加、保留、移除什么 → “用这些角色”。只有能新建并修改角色的人看得到；读不到时写明没读到并给“再试一次”，不当成没有权限。
2. **店型与角色组**（只用现有权限目录，不提升目录版本，不需要门店角色升级）：

   | 店型                 | 添加             | 保留的预设                             | 无人持有时可移除     |
   | -------------------- | ---------------- | -------------------------------------- | -------------------- |
   | 奶茶店或茶饮店       | 柜台、饮品师     | 店长                                   | 前台、厨房、库存经理 |
   | 甜品店               | 柜台、甜品师     | 店长                                   | 前台、厨房、库存经理 |
   | 火锅店               | 楼面、传菜、收银 | 店长、厨房、库存经理                   | 前台                 |
   | 中餐正餐（桌边服务） | 传菜、收银       | 店长、前台（即服务员）、厨房、库存经理 | —                    |
   | 柜台点单、先付款     | 柜台             | 店长、厨房                             | 前台、库存经理       |
   - **柜台**：前台的同一组权限（点单、收款、自取交付、先付款桌位、售罄、忙时暂停、退款申请、任务），用柜台店自己的叫法。
   - **饮品师 / 甜品师**：出品屏接单、开做、完成、重做（第一份记损耗）、出品异常、售罄、损耗、叫号交付。不点单、不结账。
   - **楼面（火锅）**：带位、桌边点单、接收客人下的单、上菜、售罄、损耗、呼叫。不结账、不申请退款（归收银）。
   - **传菜**：桌台页（需要桌台读取与桌位会话两项，桌台页检查 `dining.operate`）、上菜、呼叫。不点单、不碰出品屏。
   - **收银**：开始结账、刷卡与现金、关闭已付清的桌和订单、外带点单与交付、退款申请、忙时暂停、呼叫。
   - 任何起步角色都不带退款批准/执行/追回、取消、免单、核销、角色批准、员工管理、日结：这些仍只在店长与店主。
   - 区域经理属于多门店品牌，不随店型移除；店主角色永远不动。

3. **它们是店家自己的角色，不是 BOP 预设**：按普通新建走同一套批准（另一位批准人，或一人门店的店主在同一处“我自己批准并启用”，15 分钟二次验证与勾选确认不变）。之后店主照常在角色页修改、移除、恢复、复制。BOP 以后改起步组合，不会写到店家已有的角色上。
4. **一条命令、一个事务**：服务器按店型算出要做的事，每个缺的起步角色以固定内部代码（`starter_counter` 等）新建并送审；勾了“同时移除”时，把这类店用不到、无人持有、无等待申请或改动的预设移除（可恢复）。有员工持有的预设写明“保留：有 N 位员工持有”。
   - 每个起步角色在一家店最多一个：已有（含被店主移除的）就不再加，被移除的不会被另一店型带回来；店里已有同名角色时不加并写明。
   - 重试同一操作号不重复；同一操作号换店型为冲突（409）。共享平板 PIN 会话须先完整登录。
5. **没有新表、新迁移、新授权**：起步信息是代码里的目录常量；记录用现有只追加的角色管理版本、操作与决定（原因码 `ROLE_STARTER_SET`）。

## 停机时

网络、云主机断开时不改角色（运行手册“Role changes”一节不变）：员工保留现有角色，恢复后再按店型添加；命令是一个事务，断在中途不会只做一半，按“再试一次”用同一操作号补齐。

## 不改变

角色批准两人规则与一人门店规则、权限目录 v27 与六个预设内容、店主角色锁定、只追加历史。
