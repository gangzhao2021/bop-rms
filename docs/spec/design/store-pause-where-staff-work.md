# DEC-STORE-PAUSE-WHERE-STAFF-WORK — 暂停点单在员工干活的屏幕上看得见、按得到

状态：协调人按“技术选择自己定”定下（2026-11-11），Owner 可以推翻。来源：v15 batch-5 实测（store-service-controls M30）。

## 问题

1. 以“开启厨房屏”登录的厨房屏，没有“暂停点单”，暂停中也看不到“5 分钟后恢复”的提醒。原因不在页面：厨房屏登录（`NamedKdsOperator`）只允许厨房的几个动作，服务端把暂停的读和写都拒了（403），控件读不到就不显示。同一个人在后台里打开厨房页是能看到的。
2. Orders 上暂停那一行排在“需要处理”（前几天没做完的单）后面；前几天的单一多，这一行和它的提醒就掉到第一屏以下。
3. 只暂停自取时，员工屏写的是“点单已暂停”，看不出堂食扫码点单还开着。

## 决定

- **厨房屏可以暂停、恢复点单。** 厨房屏登录的允许范围加上 `store.service.pause` 和 `store.service.resume`（读暂停状态也靠这两个）。忙到出不了菜的是厨房，按刹车的人应该在厨房屏前面。仍然要这个人的角色本身有“暂停和恢复线上点单”（`operations.ordering.pause`）：店主、店长、前厅、柜台、收银有，厨房、饮品师、甜品师默认没有。暂停不动钱，每次都按这个人的名字记审计。没有加 `store.service.read`：营业时间页的配置仍只给能看门店的人。
  - 不给厨房角色默认加暂停权限：要不要让厨师自己停单是每家店自己的管理决定，店主可以在角色里加；不改权限目录、不升级角色。
  - 厨房屏上没有暂停权限的人，看不到暂停状态。这是已知限制：暂停时厨房本来就收不到新的线上单，告诉厨师“暂停到几点”不是必须的。
- **Orders 把暂停放在最前面。** 暂停行（和“已付订单直接送厨房”那一行）排在“需要处理”之前，1440、1024、390 宽度都在第一屏里，提醒也一样。
- **只停部分服务时说清楚停的是哪个、开着的是哪个**：“自取点单已暂停，到 08:23 · 堂食点单照常”；最后 5 分钟：“自取点单将于 08:23 恢复（还有 4 分钟）。堂食点单照常。” 停的是本店提供的全部服务时，仍说“点单已暂停”。

## 同批的措辞修正

- 客人页：时间本身以 “a.m.” 结尾时，句子不再多一个句号（“8:08 a.m..”）。在客人端 `t()` 填值时处理，所有以时间结尾的句子都受益。
- 员工端：首页保存名字后，侧栏“还没添加名字 · 已登录”立即换成名字（重新读一次，不猜）。
- 中文：作废的报损记录写“已由 你 作废（录入错误）”；报损、收货、开店盘点、盘点里的单位写“升 / 公斤 / 毫升 / 个”，不再是 L/KG；顾客离开结束轮次的说明改成整句（“结束这一轮将在线向顾客退款 $28.25。记录的原因为“顾客已离开”。”）。

## 不改的

- 没有迁移、没有数据库授权、没有权限目录或角色变更；暂停的写入、审计、4 小时上限都不变。
