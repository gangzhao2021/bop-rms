## 决定

1. **两种分法，在结账面板（桌台页）选：**
   - **按人数平均分**：店员输入人数（2–20）。
   - **各付各点的轮次**：每位点过单的客人一份，包含他自己点的轮次；店员替桌下的轮次默认归第一份，店员可以把任何一轮挪到别的份。

   不分单时仍是整桌一份（现有做法）。分法和份数是一条只追加的“分单方案”记录，记下经手人。还没有任何一份付款时可以改分法；有一份付了，方案就锁定。

2. **每份金额由服务器从订单记录算出，浏览器只发分法、人数和轮次归属：**
   - 平均分：整桌应付（各轮合计，已扣免单和删菜）除以人数，余下的分给前几份，每份多 1 分。例如 $100.01 分 3 份，就是 $33.34、$33.34、$33.33。
   - 各付各点：每份就是它那几轮的合计。

   每份的税前小计和税额也同样分摊，规则是按轮依次填满各份，余数按最大余数法分配。这样每轮在各份里的金额加起来，正好等于这一轮的金额。

3. **每份单独付，方式随意：**
   - 刷卡机：照现有的刷卡机记录方式，事后补记；
   - 现金：输入实收，系统算出找零；
   - 客人手机：线上付这一份。

   小费按这一份的税前小计计算（不给、10%、15%、18% 或填金额），不预选。现金取整也按这一份的应付算。所以每份的实付 = 份额 + 小费 + 取整差。

4. **付款记录：**每份是一笔独立的整桌结算，带上份号，和其他份一样按轮拆成几行，只记一次，只追加。同一份不能付两次。同一份有一笔手机付款正在进行时，店员不能在桌边收这一份，别的客人也不能再发起付这一份；其他份不受影响，可以同时付。

5. **关台：**每一份都付清（或经经理核销）才能关台。桌台页、客人本桌页和“今晚”都显示“已付 2/3 份 · 还差 $33.33”。

6. **客人未付离开：**经理一次登记剩下所有没付的份（PIN 确认，原因固定）。核销金额就是这些份的合计。已付的份保持不变。数据库照样保证：同一份不能既付款又核销。

7. **免单、删菜、退款：**
   - 免单和付款前删菜只能在第一份付款之前做。这时分单方案按新的账单重新计算份额，旧方案不保留在新算法里，但保留在记录中。
   - 第一份付了以后，账单就锁定了。之后要改，就对付过的某一份做退款：现金从这一份的现金里退；刷卡机在机器上退，再按份记下；手机付款在支付平台按这一份的那笔交易退款。

8. **对账和报表：**每份算一笔付款，按它的方式进渠道（刷卡机、现金、线上）。手机付的一份在支付平台是一笔交易，按份核对。销售报表、日结、导出和“今晚”里：
   - 按轮的行加起来等于订单；
   - 小费和取整按份累加；
   - 核销单独一行；
   - 不删除、不隐藏任何一份（`AGENTS.md`）。

9. **收据：**每份一张收据：本份的份额、小费、取整、实付、付款方式，注明“第 2 份，共 3 份 · 整桌 $100.01”。整桌收据列出各份和整桌合计。

10. **客人手机：**
    - 客人在本桌页选一份来付（默认下一份没付的），小费按这一份的税前计算。
    - 每次手机付款只付一份；付完以后可以接着替同桌付另一份。
    - 同一份同时只能有一个人在付；不同的份可以同时付。
    - 不显示是谁点的，也不收集名字。

11. **断网：**每份照样可以在纸上记下，之后按“按纸单补录”逐份补记，保留真实收款时间，限 72 小时内。

## 数据（只追加）

新增迁移，内容如下：

- 分单方案（`dining_table_split_plan`）：方案号、订单、分法、份数、方案时的整桌应付、经手人、时间。
- 份（`dining_table_split_part`）：方案号、份号、份额、税前小计、税额。“各付各点”另记每份包含哪些轮次。
- 整桌结算加可空的“方案号 + 份号”，并加两条约束：
  - 不分单时一张订单一笔，分单时一份一笔；
  - 按轮的行改为允许同一轮出现在几份里，但每轮在各份里的金额合计不得超过这一轮。
- 线上付款、核销和现金退款都加上份号，由触发器保证付款和核销互斥到每一份。
