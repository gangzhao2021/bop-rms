# DEC-PRICE-STORE-ASSIGNMENT — 品牌价目表与门店价目

状态：**Accepted（实现决定）**。2026-10-07，在 Owner 的商用原则与技术选择授权下作出。
执行工作包：[WP-2423](../work-packages/WP-2423.md)（顺序第 8 步，切片 ②）。

## 决定

1. **价目表是品牌事实，发布后不变**：沿用 Pricing 价目表服务（草稿 → 发布 → 作废草稿）。改价 = 新建价目表（通常复制门店当前在用的一本），
   改好后由**最后修改草稿者以外**、持有 `pricing.price_book.approve` 的人发布（服务按价目事件的操作人判断草稿作者）。
   试点页面只编辑“品牌范围、所有渠道与就餐方式”的规格单价（分，最多 99,999.99）；未改动的价格保留原条目，改动与新增价格从保存时生效。
2. **门店价目指定**（新表 `rms_pricing.store_price_book_assignment` 及其结束记录，迁移 `2000_013`）：
   把已发布价目表的当前版本指定给门店，立即生效，并以“被替代”结束原指定（结束时刻 = 新指定生效时刻）。只追加；数据库保证只能指定
   已发布版本、同一门店同时只有一条在用指定。指定需要 `pricing.price_book.approve`，并要求该价目表为门店当前已发布菜单上的每个规格
   提供自提与堂食的价格，否则拒绝并列出缺价商品。已报价的订单保留原价。
3. **顾客报价**：每次报价读取门店当前指定的价目表；没有指定则拒绝报价。每行税类取该商品版本的税类（DEC-CAT-PRODUCT-ADMIN），
   不再使用试点配置中的固定税类。
4. 品牌级写入（价目表、事件、审计）在判定权限后恢复品牌范围（门店置空）；草稿作者通过品牌范围读取价目事件确定。

## 页面与接口

- `PRICE-BOOK-LIST` `/app/commerce/pricing`（门店在用价目、新建草稿〔复制来源〕、价目表列表、门店指定历史）；
  `PRICE-BOOK-EDITOR` `/app/commerce/pricing/{id}`（按商品/规格填价、缺价提示、发布、作废草稿、用于本门店）；菜单“Prices”
  （`pricing.price_book.read`）。
- `POST /merchant/commerce/pricing/query|command`（`CreateDraft`、`SaveDraft`、`Publish`、`Discard`、`AssignToStore`）。
- 原 WP-2421 页面 `PriceBookPages` 不再挂路由（待清理）。

- 顾客菜单显示价格（菜单切片 ③ 处理）。

# DEC-INV-EXPIRY-CUTOFF — 批次到期截止

有到期日的批次在门店时区的到期日当天结束前可用（到期日次日本地 0 点起不可预留/扣减，夏令时切换精确）。
试点原先对有到期日的批次一律报错（`INTERNAL_NO_LOT_ONLY`），第 6 步配方使用按批次管理的牛奶后，加购因此失败；
现在加购、下单、付款和追加付款均使用此规则（`storeDayEndExpiryCutoff`）。
