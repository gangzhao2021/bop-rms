# Full Option Draft owning replacement

WP-2421 implements Catalog-owned ReplaceDraft over the [full durable Draft storage](./option-set-draft-content-storage.md). The server factory binds Tenant/Brand/User, trusted clock, transaction runner, current authority and Audit/Event allocation. The closed command contains exact Set/expected root, existing Draft version and complete supported fields, all additional details, original operation/time/reason. The canonical intent binds that full command to server scope/Actor. A client supplies proposed fields, never current permissions, Ready/Published/approval or source eligibility.

Lock the operation and Set source namespaces, owning root/version/options and conflicts in a read-committed outer transaction. Read complete actual owning current fields and reject unavailable, archived, future/microsecond, duplicate/bounded or stale input. Preserve every existing Option ID/code/creator and Draft version/creation time; this writer cannot allocate/delete identities. Root updates and Option writes use affected counts because their existing identity RULEs forbid RETURNING. After all writes, explicitly reread exact full current content and compare its fingerprints/body with the planned result.

Current Brand/User/fine update action, purpose and every changed field are held through outer COMMIT. Authority supplies an exact observation with a deadline of at most30seconds; every later hold narrows the earliest deadline. New requests are younger than30seconds and cannot be future dated. Late current denial, expiry, artifact failure or divergent reread aborts all root/version/Option/conflict, original operation/full snapshot, Audit-chain and Outbox writes. The database runner must roll back callback errors and retain all holds/locks until COMMIT. Missing or duplicate callbacks refuse.

Original retry acquires current authorization first, then validates the exact original operation/full snapshot and complete fingerprints. Matching intent returns its original result without loading today's Draft or reapplying edits/references; altered intent conflicts. A legacy operation without a full result is unavailable. Recovery neither renews the original result/time nor bypasses current permission. History remains append-only.

`OptionSetDraftReplaced:v1` is an additive experimental Catalog event with minimal identifiers/root/content/configuration provenance, classified indirect_identifier. Its declared `catalog.option-set-draft-current:v1` contract invalidates future Draft observations; an implemented projection consumer is not claimed here. Audit and Outbox append through owning BOP public functions in the same transaction. Draft storage, even with a full result and event, retains NotEvaluated reference eligibility. Publication still needs full current references/RuleSatisfiability, actual policy/approval/topology and distinct immutable Published/successor behavior; ordinary UI and new-identity authoring follow separately.

Local SQL uses controlled business seeds, User/field holders and clocks. Actual persistence/CAS/result recovery/Audit/Outbox/locks and rollback evidence must be reported separately from those synthetic authority inputs and from normal HTTP/UI or real operational qualification.

Every holder receives a detached additional-content copy. Original recovery reparses the incoming exact details against the frozen original core and compares the full body, so recomputing unkeyed fingerprints on a changed transport copy cannot substitute another original result. The historical query checks immutable root code/creator/time and current root at least the original result revision, without fetching today's mutable Draft. Fingerprints alone remain consistency checks rather than caller authentication.
