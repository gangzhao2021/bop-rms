WP-2421 implements the forward Catalog1102 storage prerequisite for accepted Handoff71.4/71.5, using [complete V2 content](./option-set-editor-content.md) and [successor materialization](./option-set-publication-content.md). Existing1102_001/002/003 migration bytes remain unchanged. This does not implement application publishing, independent approval, current reference/RuleSatisfiability validation, public CurrentPublished resolution or normal screens.

## Version and stable identity

The owning version row admits Draft and internal Frozen storage states. A partial unique index retains at most one Draft per Set while permitting multiple frozen historical versions. Frozen is not a Publishing approval or sale state. Its content and every version field are immutable; a trigger rejects UPDATE/DELETE, including attempts to return to Draft. Ordinary Draft UPDATE RETURNING remains compatible. Draft version identity, Set/Brand and original creation time cannot be rewritten. Draft-to-Frozen changes only status; sealing time belongs to the separate immutable result.

Stable Option primary keys remain in the current owning Option table. The only supported version-parent move goes from a frozen version to its exact backed Draft successor, with every other Option row field unchanged and identity present in frozen content. The immutable record preserves complete original options and conflicts; a pinned frozen reader must consume that snapshot, never join today's mutable Option rows to an old version. Existing Product Binding foreign keys retain stable IDs. This storage stage does not implement that public reader or new Options added to an existing Set.

## Exact original result

`option_set_publication_content` is append-only ConfigurationMetadata. It binds Tenant/Brand/Set, sealed version, distinct successor version, Publish operation/intent/time, source root and result root plus one, full source/content/configuration/record fingerprints and the complete CatalogFullOptionSetDraftContentV2 body. Its supported and editor source aggregates must agree; profile and eligibility remain explicitly NotEvaluated. Enforce int32 exhaustion, exact UTC milliseconds, one result per sealed version, one owning use of each successor, JSON object/tuple consistency and a one-MiB bound. SQL format/shape checks and stored unkeyed fingerprints are not cryptographic authenticity or semantic qualification; the public parser still verifies complete body fingerprints on recovery.

The original operation uses its existing exact seven-part foreign tuple. A deferred exact foreign tuple also binds the successor full Draft result to the same operation, Tenant/Brand/Set, successor version, Publish action, intent, resulting root and sealing time. The full Draft snapshot admits this additional owning action while Create/ReplaceDraft semantics remain unchanged. A later [current full Draft read](./option-set-current-full-draft-read.md) requires that exact successor provenance just as it does for initial authoring.

## Atomic storage guards

At COMMIT the new immutable content requires the actual root at the result revision/sealing time, the sealed version Frozen, its successor Draft at the sealing timestamps, exact original full source provenance and three matching source fingerprints. Frozen version core/additional fields must match the full source; successor version fields retain that content. Every actual stable Option must appear exactly at the successor with the complete original fields/conflicts. Partial parent movement or unlogged Option/core drift refuses. The original full source may be a prior Create, ReplaceDraft or Publish successor result. The successor full body must retain every source field while changing only aggregate revision, current root update time, version identity and Draft creation/update times according to the accepted pure successor plan. A reciprocal deferred version guard rejects a standalone Frozen version without its immutable content. Foreign keys and deferred guards roll back partial transitions instead of leaving a frozen row or an unbacked new Draft.

These are storage coherence constraints. The application writer must additionally acquire actual current content and source barriers, validate all current owning references/rules/topology/policy, recheck independent approval and Actor/action/fields/purpose through the outer transaction, and perform CAS, Audit/Outbox and original retry recovery. Direct SQL seeds and a stored NotEvaluated result supply none of those facts. No status changes bypass a missing current source.

## Isolation and verification

The new table forces Tenant plus Brand and no Store RLS, with explicit USING/WITH CHECK fail-closed predicates. Revoke all PUBLIC table privileges and each trigger function's PUBLIC execute privilege. Functions use the fixed pg_catalog search path, security invoker and fully qualified owning references; no foreign private table, new production grant or external service is involved. Catalog manifests declare the new append-only table and only owner-repository reads. Actual local SQL uses a unique existing WP-owned isolated database and a narrowly scoped synthetic NOLOGIN role; no real Tenant/Actor/Store facts or credentials are introduced.

The existing six-case current-option database suite checks the five affected old authoring/read consumers plus full immutable round-trip, two frozen histories/one Draft, stable identity movement, complete successor preservation, deferred partial rollback, RLS refusal and immutable enforcement. Schema/permission/ownership scanners and affected metadata/type/lint checks are recorded in WP-2421. Actual application publishing, approval/current-source qualification, HTTP/browser/UAT and release verification follow separately. Storage completion cannot close Product publishing or Store capability management.

The [owning fixed frozen full-content source](./option-set-frozen-full-content-source.md) now verifies actual Frozen core/details, exact immutable Publish tuple and original full Draft provenance, then parses the complete original V2 under held User read authority. This supersedes the missing historical reader only; current publication/reference/rule/policy/independent approval qualification and application publishing remain unfinished.
