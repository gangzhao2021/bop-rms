# DEC-DINING-ANY-PARTICIPANT-SUBMIT — 同桌任一在座客人可下单

状态：**Accepted（Owner 2026-10-13 回复"按你建议做"）**。执行工作包：[WP-2423](../work-packages/WP-2423.md)。

## 问题

堂食加单的封存要求结账承诺的参与者为桌主：同桌其他客人可往共享购物车加菜，但不能提交，只能等桌主。桌主离开或手机没电时整桌无法加单
（`dine-in-journey` 验收测试发现）。

## 决定

1. 当前桌台会话中任一在座参与者（未离桌、会话未关闭）都可提交本桌购物车，谁提交谁付款；付款归属提交人，"本桌"页显示"你/另一位客人"。
2. 同一时刻只有一张进行中的结账（沿用现有购物车版本与结账占用规则），他人提交时其余客人看到"另一位客人正在结账"。
3. 桌主的其他权限不变（被放弃的购物车替换、换桌码等仍按现有规则）。
4. 不改变已付款、取消、退款与收据规则；属于授权变更，按完整证据实现（受限角色验收）。
5. （协调人 2026-10-17，v15 `8c4480dd` M1）本桌各轮次记在同一张堂食订单上，所以同一桌台会话的参与者都可读取该订单的状态页与
   收据（含提交并付款后续轮次的客人），与"本桌"页一致；只认该客人自己桌台会话的订单（订单头 `dining_session_id`），其他桌、
   其他客群与其他门店的订单仍按原规则拒绝；联系信息只给本人。结束后的访问沿用 24 小时内只读收据规则。
