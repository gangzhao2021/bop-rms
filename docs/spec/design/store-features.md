## 要什么

- **模板（取舍 6）：**“正餐”模板默认关掉柜台点单、自取与取餐交付、库存与配方、会员与营销、合规文档；需要时在设置里打开。
- **催菜、叫服务员（取舍 4）：**两个都是门店开关，默认关。
  - 叫服务员已有（Q28 DEC-DINING-STAFF-CALL），只差开关。
  - 催菜放在单桌详情，每道没上的菜旁边一个按钮：后厨那张单变红并响一声，记下催过几次；同一轮几分钟内只能催一次。
- **小费（取舍 11）：**保持 10% / 15% / 18% / 其他金额，不预选，按税前小计算。门店可以自定百分比档位，也可以整个关掉小费。
- **人数与茶位费（取舍 2）：**开台默认不问人数；门店可以打开“开台时问人数”，打开后可以按人头收茶位费。

## 放在哪里

- **页面：**Section 88 已有 `STORE-CAPABILITY`（`/app/organization/stores/{id}/capabilities`，“enabled modules”），菜单名“门店功能”（Store features），权限 `organization.manage`。
  - 完整设计里这一页要“提交→审批→发布”；试点是单店，和单店菜单的“上架”一样，改了就生效。
  - 每次修改都是新的版本，带修改人和时间，只追加（与 `2000_107` 先点后付确认设置同一做法）。
  - 两个人同时改，后保存的人得到 409“已被改过，请刷新”。
- **每个事实只有一个所属领域：**
  - 模块开关（柜台点单、自取、库存与配方等）属于门店（`rms_store`）。
  - 叫服务员、催菜、问人数、茶位费属于堂食（`rms_dining`）。
  - 小费档位属于支付（`rms_payment`）。
  - 页面把三者放在一起显示，各自用自己的命令保存。

## 关掉一个模块意味着什么（不是只藏菜单）

- **柜台点单关：**侧栏不显示，地址转到桌台页，服务端拒绝新的柜台单（同一单重试仍返回原单）。
  - 店员替桌子下单（桌台页的店员轮次）属于堂食，不受影响。
- **客人自取下单关（1b）：**
  - 客人扫自取码，入口回答“本店只做堂食”（`entry_service_not_offered`），说明怎么在店里用餐，不建立会话。
  - 结账和开始付款按同一份“客人现在能下什么单”检查，自取单被拒；读不到设置时不提供自取，堂食不受影响。
  - 已经下了的自取单照常交付。柜台点单开着时，取餐页一直显示（柜台单也在那里交付）；两者都关时取餐页隐藏。关之前页面会再问一次，并提醒先交付还在等候的自取单。
  - 关之前显示“还有 N 张自取单等候交付”：数字来自 Fulfillment 的当前取餐队列（取餐页读的同一个来源，不含已交付）；读不到时说明读不到、不显示数字。只提醒、不拦截，店主随时可以重新打开。
- **库存与配方关：**侧栏不显示库存、库位、收货、盘点、损耗、期初盘点、配方、选项配方。
  - 已有的库存记录和扣减不受影响（关只是不再显示这些页面）；售完仍可在“可售状态”手动设置。
- **会员与营销、合规文档：**试点里没有这些页面（未开放），模板只记录为关，页面上不显示开关（不放没有作用的开关）。
- **过敏原：**永远开着（客人安全），不在开关里。

## 现有门店

- 从没设置过的门店，所有模块保持现状（全开），开关显示为开，直到店主选模板或关掉某项。
- 这样部署后 v15 的柜台点单、取餐不会突然消失。叫服务员是例外：取舍 4 定的是默认关，部署后需要在这一页打开。

## 分段

1. **门店功能页与模块开关：**模板“正餐”、柜台点单、自取与取餐交付、库存与配方；侧栏、地址、服务端三处都按开关。
2. **叫服务员、催菜开关；催菜本身：**后厨单变红、响一声、催过几次、同一轮限频。
3. **小费档位与关闭：**客人结账、店员结账与收据都按门店设置；金额按整数分计算，验收按完整证据。
4. **开台问人数与茶位费：**钱，按完整证据——茶位费进账单、税、当晚小结和报表，退款按整行冲正。
