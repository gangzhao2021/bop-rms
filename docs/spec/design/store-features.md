# DEC-STORE-FEATURES — 店型模板与功能开关（item 8 ⑦）

Owner 2026-10-28 “按建议”，取舍 2、4、6、11（见 WP-2423 “功能取舍”）。协调人 2026-10-29：r 不做，接着做 ⑦。

## 要什么

- **模板（取舍 6）：**“正餐”模板默认关掉柜台点单、自取与取餐交付、库存与配方、会员与营销、合规文档；需要时在设置里打开。
- **催菜、叫服务员（取舍 4）：**两个都是门店开关，默认关。
  - 叫服务员已有（Q28 DEC-DINING-STAFF-CALL），只差开关。
  - 催菜放在单桌详情，每道没上的菜旁边一个按钮：后厨那张单变红并响一声，记下催过几次；同一轮几分钟内只能催一次。
- **小费（取舍 11）：**保持 10% / 15% / 18% / 其他金额，不预选，按税前小计算。门店可以自定百分比档位，也可以整个关掉小费。
- **人数与茶位费（取舍 2）：**开台默认不问人数；门店可以打开“开台时问人数”，打开后可以按人头收茶位费。

## 放在哪里

- **页面：**Section 88 已有 `STORE-CAPABILITY`（`/app/organization/stores/{id}/capabilities`，“enabled modules”），菜单名“门店功能”（Store features），权限 `organization.manage`。
  - 完整设计里这一页要“提交→审批→发布”；试点是单店，和单店菜单的“上架”一样，改了就生效。
  - 每次修改都是新的版本，带修改人和时间，只追加（与 `2000_107` 先点后付确认设置同一做法）。
  - 两个人同时改，后保存的人得到 409“已被改过，请刷新”。
- **每个事实只有一个所属领域：**
  - 模块开关（柜台点单、自取、库存与配方等）属于门店（`rms_store`）。
  - 叫服务员、催菜、问人数、茶位费属于堂食（`rms_dining`）。
  - 小费档位属于支付（`rms_payment`）。
  - 页面把三者放在一起显示，各自用自己的命令保存。

## 关掉一个模块意味着什么（不是只藏菜单）

- **柜台点单关：**侧栏不显示，地址转到桌台页，服务端拒绝新的柜台单（同一单重试仍返回原单）。
  - 店员替桌子下单（桌台页的店员轮次）属于堂食，不受影响。
- **客人自取下单关（1b）：**
  - 客人扫自取码，入口回答“本店只做堂食”（`entry_service_not_offered`），说明怎么在店里用餐，不建立会话。
  - 结账和开始付款按同一份“客人现在能下什么单”检查，自取单被拒；读不到设置时不提供自取，堂食不受影响。
  - 已经下了的自取单照常交付。柜台点单开着时，取餐页一直显示（柜台单也在那里交付）；两者都关时取餐页隐藏。关之前页面会再问一次，并提醒先交付还在等候的自取单。
  - 关之前显示“还有 N 张自取单等候交付”：数字来自 Fulfillment 的当前取餐队列（取餐页读的同一个来源，不含已交付）；读不到时说明读不到、不显示数字。只提醒、不拦截，店主随时可以重新打开。
- **库存与配方关：**侧栏不显示库存、库位、收货、盘点、损耗、期初盘点、配方、选项配方。
  - 已有的库存记录和扣减不受影响（关只是不再显示这些页面）；售完仍可在“可售状态”手动设置。
- **会员与营销、合规文档：**试点里没有这些页面（未开放），模板只记录为关，页面上不显示开关（不放没有作用的开关）。
- **过敏原：**永远开着（客人安全），不在开关里。

## 叫服务员与催菜（第 2 段）

- **开关：**`rms_dining.dining_service_setting`（迁移 `2000_119`），两个开关按版本只追加，默认都关；在门店功能页“桌边服务”里保存，和模块开关各自有版本。
- **叫服务员：**关着时，客人读取呼叫状态和发起呼叫都得到“没有提供”（409），客人页不显示呼叫入口，不记录呼叫；开着之前已经发起的呼叫仍可撤回。
- **催菜：**
  - 单桌页每道还在做的菜（已下单、已接单、制作中）旁边有“催菜”；已经做好的菜是上菜，不是催。
  - 记录在后厨 `rms_kitchen.kitchen_work_chase`（迁移 `2000_120`，只追加）：催的是哪个还在做的后厨工作项、哪一轮、谁、什么时候。
  - 同一轮 5 分钟内只能催一次（“几分钟”定为 5 分钟）：存储先查并告诉服务员几点可以再催；数据库触发器在同一轮的锁内再查一次。已做完或已取消的菜，数据库拒绝催。
  - 同一次催菜重试（同一个操作号）不会再记一次。
  - 后厨看板：被催的菜和它所在的单变红，写“服务员催过 / 催过 N 次 · 时间”；看板开着时有新的催菜就响一声（和新单同一个提示音，跟随看板的声音开关）。
  - 单桌页显示“催过 N 次 · 时间”。

## 小费档位与关闭（第 3 段）

- **设置：**`rms_payment.store_tip_setting`（迁移 `2000_121`），属于支付；开关加三个百分比（1–50 的整数，从低到高），按版本只追加，带修改人和时间。
  - 从没设置过的门店：开着，10% / 15% / 18%。
  - 门店功能页“小费”里保存，和其他开关各自有版本，两人同时改，后保存的人得到 409。
  - 关掉时保留百分比，重新打开时还是原来的三个。
- **客人看到的：**“不加小费”、店里的三个百分比、“其他金额”，都不预选，客人选了才能继续（自取结账、先付后吃的桌子、手机上付整桌）。
  - 小费按税前小计算，继续和付款按钮上写的是含小费的总额。
  - 关掉小费时不显示小费，也不问。
- **店员看到的：**柜台点单和店员替桌子下单从“不加小费”开始，选项是店里的三个百分比和“其他金额”；整桌结账不预选，必须先选。关掉小费时都不显示。
- **服务端：**柜台点单、店员轮次、整桌结账、客人手机付整桌，都按门店当前设置检查。
  - 关着时只收“不加小费”（或金额 0），拒绝时什么都不记、不收款，回答“已关掉小费”（409），页面重新读取设置。
  - 百分比不是店里现在的三个之一，回答“小费选项变了”（409），页面重新读取。
  - 停电后补录的整桌付款，按收款那一刻有效的设置判断。
- **数据库：**关着时，数据库拒绝任何大于 0 的小费：客人或店员选的小费（自取、柜台、店员轮次都记在这里）、客人手机付整桌开始时、店员记录的整桌付款（补录的按收款时间）。
  - 刷卡机付款带的是下单时已经选好的小费，不再检查：真实发生的付款从不拒绝记录。
- **退款与当晚小结：**小费关着时，整桌付款的小费是 0，退款、订单结清、当晚账本和报表照常，小费都是 0（验收覆盖）。
- **刷卡机：**关掉小费的同时，刷卡机上的小费提示也要关掉（页面上写明）；否则客人在机器上加的小费和系统记录不一致。

## 开台问人数与茶位费（第 4 段）

- **4a 人数：**
  - 开关“开台时问人数”属于堂食，放在 `rms_dining.dining_service_setting`（迁移 `2000_122` 加一列，默认关，已有版本读作关），在门店功能页“桌边服务”里和其他两个开关一起保存。
  - 人数记在 `rms_dining.dining_session_party_size`（`2000_122`，只追加）：每张桌的每次修改是下一个版本，1–99 人，带谁、什么时候；按店员看到的版本保存，别人先改了得到 409“已被改过”并重读；同一操作重试返回原记录；桌子关闭或取消后，命令和数据库都拒绝。
  - 桌台页：开关打开时，刚开的桌在桌面板上马上问“几位？”，之后显示“N 位 · 修改”（来人、走人时改）；开关关着时不显示（以前记过的人数仍保留）。
  - 断网时：人数写在纸上，网络恢复后在桌面板上补；人数不影响下单和结账。
- **4b 茶位费（协调人 2026-10-29 同意“不经后厨”方案）：**
  - **不经后厨（通用菜品标记）：**属于后厨（路由是后厨的事），按门店、按菜品记，按版本只追加；菜单编辑页上店主打开“不经后厨”，说明“这道菜不进后厨看板，下单就算已上，不挡结账”，瓶装饮料也能用。
    - 后厨接单时跳过这类菜，不生成工作项。
    - 堂食的出菜进度把它算作已上；结单的出菜证据把它算作已处理（不需要后厨完成记录）。
    - 下单那一刻的标记为准（之后改标记不影响已下的单）。
  - **茶位费设置（4b-2，`2000_124`）：**属于堂食，默认没有；店主在门店功能页“茶位费”里选堂食菜单的一项（通常是隐藏、不经后厨的“茶位”），价格和税由定价决定；页面写明只自动加在吃完再付的桌上，并提醒把这一项标为“不经后厨”。
  - **已知限制（协调人 2026-10-29）：**茶位只自动加在吃完再付的桌上，每轮先付的桌不会自动加。理由：在加拿大收茶位费的主要是粤式茶楼和正餐，基本都是吃完再付；每轮先付的扫码点餐多是快餐和小吃，一般不收茶位。**以后的触发条件：**有每轮先付、又要收茶位的店接入时，再做“第一轮付款时带上茶位”。
  - **自动加与人数变化（4b-2）：**店员在桌面板保存人数后，茶位跟着人数走：少了就作为店员录入的一轮加上差额（署名该店员）；多了就从最新的茶位行开始用已有的“付款前从账单去掉”撤下（原因“客人离开”，记谁、什么时候，原行保留），撤多了再补差额。每一步的操作号由这次同步的操作号决定，重试只会重复、不会多加或多撤。没有撤菜权限的店员减人数时不改账单，桌面板显示“人数比茶位少，请经理去掉多的茶位”。收过钱后不再跟着变，走现有退款或调整。
  - **店员改数量：**有小孩不收等情况，店员可把茶位数量改得和人数不同，同样记谁、什么时候、原因。
  - **客人看到：**本桌页和菜单顶部写“茶位 $X/位”；账单和付款页茶位单独一行；客人不能加或去掉茶位。
  - **断网或设备坏了：**按人数手写茶位，恢复后补录人数（runbook）。
  - **分步提交：**4b-1 不经后厨标记（后厨、堂食进度、结单证据、菜单编辑页）；4b-2 茶位费设置与自动加减、冲减记录；4b-3 店员改数量、客人显示、runbook。每步都有受限角色验收并证明去掉检查会失败。

## 现有门店

- 从没设置过的门店，所有模块保持现状（全开），开关显示为开，直到店主选模板或关掉某项。
- 这样部署后 v15 的柜台点单、取餐不会突然消失。叫服务员是例外：取舍 4 定的是默认关，部署后需要在这一页的“桌边服务”里打开。

## 分段

1. **门店功能页与模块开关：**模板“正餐”、柜台点单、自取与取餐交付、库存与配方；侧栏、地址、服务端三处都按开关。
2. **叫服务员、催菜开关；催菜本身：**后厨单变红、响一声、催过几次、同一轮限频。
3. **小费档位与关闭：**客人结账、店员结账与收据都按门店设置；金额按整数分计算，验收按完整证据。
4. **开台问人数与茶位费：**钱，按完整证据——茶位费进账单、税、当晚小结和报表，退款按整行冲正。
