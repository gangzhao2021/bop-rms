# Atomic full Option content seal writer

WP-2421 milestone49 adds an owning Catalog producer for accepted Handoff71.4/71.5 and the existing [complete V2 content](./option-set-editor-content.md), [immutable storage](./option-set-publication-storage.md) and [current full Draft observation](./option-set-current-full-draft-read.md). It produces an internal Frozen body and successor Draft; it does not produce a Publishing release, current published scope/period qualification or sale eligibility. Every result retains NotEvaluated. Ordinary Product and Option publishing remain unavailable until genuine current admission and Publishing/current-reference composition exist.

The closed command contains Set/current version/expected root, source/content/configuration fingerprints, original operation, UTC millisecond instant and bounded reason. It accepts neither complete content nor Ready/approval/status claims. Server configuration captures Tenant/Brand/User, clock, runner, current publish/read authorities, successor allocator, Audit and Event functions; later object replacement cannot substitute a holder. Missing collaborators refuse before work. The producer supplies the actual parsed owning Draft to the admission holder, using detached copies; callback mutation cannot alter the transition.

Intent requires current User, catalog.manage plus catalog.option_set.publish, publication purpose and complete fields. Apply additionally requires all CurrentReferences, RuleSatisfiability, ScopeTopology, PublishingPolicy and IndependentApproval checks, held current through the outer transaction. These names are obligations, not implemented sources or a stored Satisfied flag. No production admission implementation is configured by this milestone. Isolated acceptance explicitly uses synthetic current Actor/fields/reference/rule/policy/approval holders; their leases are not actual qualification evidence. The true owning source and database transition are exercised separately.

The writer requires READ COMMITTED and exact Tenant plus Brand/no Store RLS context. It takes the original operation advisory lock, then the exclusive full Option source barrier and root/current version locks. The public current full Draft reader checks complete owning content, all stable Option/conflict rows and the exact original full Create/Replace/Publish successor receipt. Command pins must match this source. After current admission it reads the owner again and refuses drift. A server-allocated distinct successor must be unused; exhausted roots, identity collision, stale source/root, absent provenance and unknown authority refuse.

One outer transaction performs root CAS, status-only freezing, complete successor version insertion, original Publish operation and full successor receipt, immutable V2 content, exact stable Option parent movement, Audit and Outbox. The immediate parent guard requires the immutable content proof before movement. All existing deferred exact source/successor/storage guards remain; no migrations or grants change. The new event OptionSetContentSealed:v1 is experimental and contains minimal Tenant/Set/sealed/successor/version/root/operation/content/configuration/record fingerprints. It carries no Option text, references, pricing or qualification. Its declared Draft observation invalidation contract is not an implemented dispatcher/projection consumer.

The original exclusive lease is capped to the shortest current read/admission observation and cannot renew. Backward time, late source/field denial, exclusive expiry, successor drift, Audit/Outbox or outer COMMIT failure must roll back all tentative state. The owning successor is read again after final current admission. Fresh commands also expire after30 seconds; an original retry is not rejected merely because its operation is older.

Recovery reads the append-only original operation and exact frozen row/version tuple, validates complete V2 fingerprints against stored metadata and original command pins, and requires current User/action/purpose/fields again. It neither reads today's mutable Draft nor allocates, reapplies or requalifies original history. Altered intent conflicts. Later actual Draft edits and later seals leave the original content unchanged; original concurrent retries serialize through the operation barrier. Missing/corrupt original data refuses. Recovery is not a current publication observation.

Verification uses existing Catalog content/materialization tests and the isolated current-option suite. Its new seventh scenario creates complete content through the owning writer, commits the seal under a narrow synthetic role, reads the current successor and pinned original, edits later via owning ReplaceDraft, seals again, and recovers original history without changing counts. Negative probes cover current admission/read denial, stale isolation/source/root/version, allocator collision, late denial/expiry/backward clock/drift and Audit/Outbox/outer-commit rollback, plus Tenant/Brand refusal. Exact old six scenarios and accepted event identities remain. WP-2421 records observed results and failures; this design does not assert any unrun check.
