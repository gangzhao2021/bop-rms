Catalog owns the closed structural assessment; the API composes actual public Catalog publication history, Tenant registered Store identities and Publishing current typed policy in one caller transaction. No table, migration, dependency, permission grant, event or ordinary DTO is added.

## Source and authority

The server captures Tenant, Brand and User Actor. Only a parsed `Validate` command is supported. Mandatory current Validate action and complete field authority uses the existing public Product publication authority contract, requiring `catalog.product.read` and `catalog.product.validate` before any source acquisition and after consumer work. History separately requires current `catalog.manage`, `catalog.product.history.read` and complete publication fields. Tenant requires complete Brand reference coverage; Publishing holds current policy fields and exact User context. A history-only caller cannot prepare an assessment.

All three owning factories use the exact outer transaction, Read Committed, explicit Tenant/Brand, blank Store and existing bounded timeouts. Catalog holds its Product source barrier; Tenant holds the same registered-identity fence used by owning Brand/Store triggers; Publishing holds actual governance history. Current authority and the earliest source expiry remain required through outer COMMIT. Late denial or expiry refuses the callback result and rolls back its tentative mutations. An explicit single history/assessment callback guard also refuses a repeated authority-wrapper callback and rolls back its first tentative write.

The assessment binds current Product root, requested version's expected publication head, canonical original command intent, current complete latest publication graph, registered-roster fingerprint, current policy body/reference/version/release and observation. It expires at the earlier of five seconds from Catalog's actual SQL observation or policy expiry. The final action-authority check is followed by another expiry check. Missing, foreign, stale or incoherent owners refuse instead of producing Pass. The pure contract's sourceAuthority remains NotEvaluated; it cannot acquire locks or establish authority from supplied JSON.

This one check evaluates requested prospective scopes. It does not read the current Draft body or prove that an otherwise unknown version is the current Draft. Complete preparation must first use the existing held current validation candidate; the actual SQL writer consumer also checks its owning current Draft/root/version/content/configuration before invoking this check. The standalone assessment never substitutes for that candidate or the complete twelve-check result.

## Conservative rules

Intervals are half-open UTC ranges. Prospective overlap starts no earlier than observation or requested effectiveFrom. Published/Superseded intervals start no earlier than actual publishedAt; actual expiry and supersededAt bound their end. Scheduled heads reserve their prospective intervals. Expired or disjoint periods do not conflict. Empty channel/order restrictions mean all; Channel/OrderType selector references remain restrictions.

Actual current policy supplies the complete precedence order, including Store before Brand. Different ranks retain the narrower Store override and Brand service outside it; no whole-version Superseded state is invented. Potential equal-rank intersecting selectors yield HardError `EQUAL_RANK_REQUIRES_DISPOSITION`. This deliberately conservative refusal does not pick newest, implement a precise disposition, or assert that a shadowed selector pair proves runtime ambiguity. The union of all selectors is retained. Disjoint registered Stores or channel/order restrictions are distinguishable without invented membership.

Inactive Brand, a known empty roster, unknown/inactive Stores and unavailable Region/StoreGroup membership yield HardError. Registered organizational Active state is identity evidence only; it does not prove Store operation, module enablement, dependency satisfaction, Future Trigger or sale eligibility. Pair evaluation refuses beyond10000 comparisons rather than truncating. Publication history retains its existing1000-revision/bounded transport source limit.
