# DEC-STORE-FIRST-OPENING — 新店一页、一个按钮（item 14）

状态：协调人按 Owner 的要求定（“该修就修，不用问”，业务默认值取设计里的建议），**Owner 可以推翻**；三个要 Owner 知道的决定见文末。

## 问题

试开店时，新店主要走完给老店用的设置向导：地址填两遍，约 40 步（很多步骤其实没有选择），还要按对顺序。TEST 工具写的 24 小时营业时间，读漏了就会发布出去。

## 决定

新店只有一页、一个按钮。老店的页面一点不变。

- **谁算新店：**这家店还没有“从门店设置发布的配置”（发布内容带 `setupBasis`）。
  - 店最初的那份配置（不管谁写的、什么原因码）和在它上面改营业时间，都不算。不用 TEST 原因码判断：真实商户的第一份配置没有那个原因码，改一次营业时间也会让判断翻转。
  - Home 的开业清单、这一页、“开业前不报警”的规则都用这一个读取（`hasOwnerPublishedStoreSetup`）。
  - 读失败时写“没读到，再试一次”，向导继续折叠：一时的故障不能把一页换成 40 步。
- **向导没有去掉：**放在“所有设置（分步）”里折叠，打开才读取，特殊的店还能用。

## 店主答什么

13 个输入框，加两个点单方式的勾选（有午市晚市时再多两个时间）。

- **门店（7）：**店名、街道、单元（可不填）、城市、省、邮编、电话。这里电话必填：要写进联系记录，客人也靠它联系门店。
- **收据（2）：**经营名称、GST/HST 号；魁北克多一个 QST，BC、萨省、曼省多一个 PST。
- **堂食、自取：**至少选一个。
- **营业时间：**每天相同或按天不同，每天最多两段，开业的日子，最后点单和备餐分钟数。**不预填** TEST 工具的第一份配置：那是 24 小时带自取，店主一按就可能半夜收单。店主自己存过的或改过的营业时间才预填。
- **小费：**一个开关，就是门店功能里那个，立即生效。

然后读“您要批准的内容”（将发布的全部内容），勾一次，输一次验证码，按一次“发布我的门店设置”。

## 其余自动完成

| 向导里的步骤               | 现在                                                                                   |
| -------------------------- | -------------------------------------------------------------------------------------- |
| 第二遍地址、联系人         | 从对客资料写入；发布前改了资料会写新版本（只追加），发布后不再跟随                     |
| 后厨线                     | 自动，已有就跳过                                                                       |
| 用现有门店设置             | 只带品牌基础、税务引用、特殊日期、容量引用和生效时间；**不带**营业时间、点单方式和收据 |
| 时区、营业日开始           | 取门店自己的值，发布检查只接受这个值                                                   |
| 服务费、配送费             | 关，向导里设过的保留                                                                   |
| 小费                       | 按所选点单方式开（取舍 11）；问不问客人由上面的开关决定                                |
| 支付方式                   | 三个都开，存为规则（见“差距”）                                                         |
| 标准收据                   | 写入、提交、批准、发布；已有可用的就用现有的                                           |
| 过敏原清单                 | 记录并批准；品牌已有就跳过。排在门店配置前面，发布就是最后一步                         |
| 校验                       | 跳过。提交时跑同样的检查，少一次发布写入                                               |
| 生成、提交、批准、发布配置 | 依次执行                                                                               |

- **做法：**浏览器按顺序调用已有并已测试的函数，每一步先恢复自己未完成的请求，再读服务器，已经成立就跳过。按钮中断后再按、换设备再按，都接着做，不重复写。
- **不做成服务端组合：**这些命令依赖预备游标、意图摘要和浏览器日志来恢复结果，放到服务端等于重写一遍。
- **没有新表、新命令、新权限、新授权。**新增的只是读取：`/store/opening-approvers`（每个审批还有谁能批）、开业清单的 `taxRatesSet`、配置工作区的 `goLive`、还没有清单时的过敏原单人状态。

## 审批没有放松

每一步都是同一条命令，权限、版本、15 分钟二次验证、单人经营核对、只追加记录、审计都不变。

- **先看后批：**勾选前，页面先用店主的回答算出将发布的全部内容（门店、营业时间、时间、费用、税、支付、收据、过敏原）。批准前再读服务器记录比一次，不一样就不批准、请店主重读重勾。
- **没有别人能批时：**一个必勾的框，文字写明这也让店主批准自己的价格、菜单、配方、过敏原清单、门店设置和较大的退款。不用另外去开“单人经营”。
- **验证码：**“开单人经营”和后面的自批共用一次验证（读取的是最近一次验证，不分用途；受限角色验收已证明）。
- **两位店主：**第一位按“送审”。另一位打开同一页，看到“等您处理”和内容，按“批准并继续”，不用去向导里找。两人轮流按，每次按到需要对方为止，写的人永远不批自己写的。独立批准今天不要验证码，这里也不要。
- **没有名字的等待不存在：**页面上不会出现“等人批准”却没有人名的情况。

## 只有 BOP 支持能解决的前提

税率或开业许可没有时，按钮是“保存我的信息”：只存店主答的内容，不发布、不问验证码，写明“在等 BOP 支持设置税率”，Home 的开业清单写同样的话。支持人员用的地址就是这次存的。

## 断网、主机或设备出问题

- 新店一般还没有客人：菜单没上架，桌子没有码。中途断开时，店最初的配置继续有效，直到最后一步发布才换。已经保存的店名、地址和小费开关是立即生效的。
- 做过的留着。再按“继续”，这里或另一台设备都行，从服务器状态接着做。
- 主机不可用时，这一步等它恢复。如果这家店已经上架在接客，走 runbook 的 Store outage procedure；这一页本身不需要纸质替代。
- 一次开店有约十次发布写入。如果开店时其他商户出现 503（发布记录锁），之后在非营业时段开店，直到那把锁修好（runbook）。

## 相关小改动

- **Home 开业清单：**门店信息、后厨、收据和发布合成一行“门店信息和设置”，链接到这一页。后面是过敏原清单、菜单、桌码。
- **过敏原页：**还没有清单、单人经营已生效时，记录和批准合成一次按键。批准失败时清单已记录，再按只批准，不重复记录。
- **上架被拒的提示：**按原因说人话，不出现代码、文件名和“运营人员”；没列到的原因写“这次没能上架，稍后再试，再不行告诉 BOP 支持时间”，真实原因进日志。不对客人看到什么下保证：上架中途可能已有新价格生效。

## 差距（已知，不算完成）

- **支付方式：**`customerOnlineCardEnabled`、`staffTerminal*` 目前只有合同、客户端和页面在读，没有业务在用。真有东西读它们时，默认值要重新定。
- **自取容量：**写死每小时 20 单（`pilotDefaultPickupCapacityPolicy`），店主看不到也改不了。这一页如实写“每小时最多 20 单，要改找 BOP 支持”，这是商业保真度上的差距，本决定不设计容量。
- **发布之后的修改：**老店改设置还是走向导的多步。设计评审提过“发布我的修改”一个按钮，和“老店不变”冲突，这次没做。

## 店型步骤的位置

店型和功能模板正在另外设计。它放在收据和点单方式之间，只做预设回答；后面的流程从回答开始，和手填一样，不用改。代码里标了位置（`StoreFirstOpeningPanel.tsx`、`store-first-opening.ts` 的注释）。

## 要 Owner 知道的决定

1. **单人经营不自动打开：**还是一个框加一个验证码。理由：DEC-SOLE-OPERATOR-APPROVAL 定的是显式启用，而且它也放开店主自批退款，涉及钱。有第二位审批人时自动失效，随时可关。
2. **小费按取舍 11：**默认开，一个开关立即生效，不预选，“不加小费”一直都有。服务费和配送费默认关。设计原来建议小费也关，但发布里的“关”会盖过门店功能的开关，店主再去开也不起作用。
3. **一次确认覆盖三项：**新店第一次开业时，一个框可以同时覆盖收据模板、门店设置和过敏原清单，每一项仍然分别记录为单人批准。不同意的话，可以恢复成三个框。
