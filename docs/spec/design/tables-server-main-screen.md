状态：第 1、2 段已实现（2026-10-27）；第 3 段（断网做法）见下。

来源：Owner 定的后续顺序第 2 步（2026-10-26 “同意先点后付，按这个顺序做”）、2026-10-27 决定 2，协调人转达的要求，

Owner 2026-10-27 原话“批准”及四点调整。

## 决定

1. **一张按“需要处理”排序的列表，不做平面图。** 每桌一行：桌名、座位数与已开时长、一个状态（红点 需要人处理、蓝点
   进行中、绿点 已完成）和至多一个下一步按钮。顺序：叫了店员（知道了）→ 已付待接单 / 未付轮次（倒计时）→ 做好待上
   （全部上桌）→ 结账中待收款（收款）→ 已付清待关台 → 待清洁（已清洁）→ 开了很久 → 后厨在做 → 都上齐了。
   空桌在列表下方一行列出，点“开台”即开。标签页：需要处理 / 全部 / 有客 / 空桌 / 待清洁。
   桌子多的店以后可能需要按区域看平面图（Owner 调整 4，记在 WP-2423，不在本步）。
2. **每行的菜品与账单来自系统。** 列表从订单队列（与订单页同一来源）读取每桌待上数量、是否还在后厨、整桌账单；
   页面不计算、不写死金额（Owner 调整 1：总览与详情的金额都从系统读）。
3. **日常操作不确认，说清结果。** 上菜（单道、整轮、整桌）、开台、清洁、关台、知道了都是一按即做，页面写出结果；
   “已清洁”可以撤销（改回待清洁）。上菜、开台、关台没有对应的撤销命令，用结果提示；丢失回复时按钮变成“再试一次”，
   发送同一请求，不会做两次。
4. **涉及钱和取消的才确认。** 收款前再显示一次：刷卡机为账单、小费、实收；现金为账单、小费、应收（按 5 分取整）、
   实收、找零（Owner 调整 3，数值规则沿用 S2）。取消菜品、取消整轮、客人未付离开（核销）、退款、免单/折让保留各自的确认。
5. **小费不预选**（Owner 调整 2）：店员问过客人后再选，没选小费时收款按钮不可用，与客人手机端一致。
6. **权限**：服务员可以开始/取消结账、收刷卡机和现金、关已付清的台（权限目录 v18，见
   [DEC-PERM-CATALOG](permission-catalog-and-store-roles.md)）。核销、取消与退款、客人离开后的轮次处理只给经理；
   服务员看到“由经理处理”的说明。
7. **在桌台页完成，不用跳订单页**：先点后付桌付款前删菜（规则 2）放在每轮下面；替客人点一轮、换加入码、转移桌主、
   设为暂不可用都在单桌面板的“其他操作”里。先付桌的已付菜品取消与退款仍在订单页（经理、涉及钱）。

## 第 2 段：经理免单/折让（决定）

1. **记录**：Ordering 的只追加记录 `rms_ordering.order_item_price_reduction`（迁移 `2000_103`），每道菜一条：谁（经理）、
   哪道菜、方式（免单 / 打折百分比 / 税前减一个金额）、减多少（税前、税、服务费、合计）、原因（菜品质量、上错菜、
   等太久、致歉/好意）、时间；同时写审计（`ORDER_ITEM_COMPED` / `ORDER_ITEM_DISCOUNTED`，金融保留期）。不能修改或删除；
   一道菜只能有一条。菜仍按原价算作卖出，减掉的部分单列，是补偿操作，不是隐藏销售（AGENTS.md）。
2. **金额由系统算**：浏览器只发“哪几道菜、哪种方式、原因”。免单减掉整道菜（含税和服务费）；打折或减金额时，税和服务费
   按比例、四舍五入到分。服务器按菜的价格快照计算，数据库触发器再按同一规则核对，对不上就拒绝。
3. **只给已开做或已上桌的菜**：后厨还没开始的菜改用“付款前删菜”（后厨停做、库存退回）；服务器按后厨状态拒绝。
4. **只在付款前**：已付清或已核销的桌拒绝，改走退款；客人正在手机付款时拒绝。命令先取订单的处置锁再查付款，
   与结账、核销、手机付款按同一把锁排队；结账时账单与订单定价总额核对不一致会要求重读。
5. **账单与结账**：订单定价总额减去免单/折让；整桌账单每道菜写明减了多少，轮次与应付随之减少；付清后订单按减后的
   金额判定为已结清，可以照常关台。
6. **报表与日结**：销售报表的菜品按原价计入毛销售额，“经理免单/折让”单列一行（金额与道数），净销售额与税相应减少，
   并进入汇总与菜品 CSV（`comps_and_discounts_by_manager`、`comps_and_discounts_count`）；报表随付款计入当天。
   日结单列“经理免单/折让”一行，按决定时间计入营业日（只做告知，不是收款或退款）。两者只在跨午夜决定、次日付款时
   日期不同。
7. **权限**：目录 v19 `ordering.order.comp`（Owner、Store Manager），共享平板需经理完整登录确认。

## 分段

1. 桌台页本身、v18 权限、收款确认与小费不预选（本次）。
2. 经理对已开做或已上桌的菜免单或折让：经理确认、选原因，作为补偿记录，付款前从账单减掉；报表与日结单列
   “免单/折让”，不能删除；受限角色验收测试并先证明能对有缺陷的代码报错。
3. 断网时怎么办：写进运行手册，页面上的断网提示链接到它。
