# DEC-GUEST-ENTRY-MULTI-STORE — 一部手机在几家店之间扫码

状态：协调人按“技术选择自己定”定下（2026-11-11），Owner 可以推翻。来源：v15 第 5 批实测（guest-entry-multi-store）。

## 问题

1. 手机在 Test Merchant 2 付了自取单 13，再扫 DEMO 的自取码，页面却显示 Test Merchant 2 的“你的订单 13 · 再点一些”。点“再点一些”其实是在 DEMO 开始点单，按钮说的和做的不一样。
2. 回到 Test Merchant 2 扫码，服务器已经接上了留在手机上的那次点单（200 resumed），页面却只说“可以点单了”，看不到订单 13 和取餐码；要再扫一次才出现。
3. 同一个标签页里打开另一家店的自取链接，只是地址里 `#` 后面变了，浏览器不重新加载，页面还停在上一家店。
4. 没有公开电话的店，自取入口的帮助仍说“打电话或到柜台”。
5. 只看了打烊店的菜单，再进购物车（返回键、书签、刷新），页面说“购物车读不出来，购物车还在”。这台手机在任何店都没有点单，购物车并不存在。多店安装里没有点单的请求，由入口回答 404 `CUSTOMER_STORE_NOT_FOUND`，页面把它当成了故障；而入口读某家店的记录失败时，也被当成“哪家店都没有这次点单”。
6. 顾客页面没有 Content-Security-Policy。
7. 取过自取单的手机扫桌台码，看到的是那张自取单，不是这张桌子。
8. 从来没付款的顾客，到截止时间那一秒看到“付款还在确认中，不要再付一次”，约 10 秒后才变成“已取消，没有扣款”。

## 决定

**扫哪家店、哪张桌子的码，就打开哪里。** 手机现在的点单是自取，扫到的却是别家店的码，或者任何桌台码（同一家店的也算）：直接打开扫到的地方，不先显示那张自取单。自取单留在手机上（服务器本来就会保留），新页面下方写明“你在 X 的订单保留在这部手机上，再扫 X 的自取二维码就能回去”。扫同一家店的自取码，还是和以前一样先显示那张订单。例外（付款截止提醒 M18）：打开扫到的地方之前，先读一次那张自取单（这时手机还在原来那次点单上，读得到）。已付款、已取餐、已取消的单，照上面直接打开；还没付款的，先显示“你的订单 14 · 还未付款，请在 {时间} 前付款，否则会取消，不会扣款”，主按钮“去付款”，另有“改在刚扫的二维码点单”；读不出来的也先显示那张订单，不猜它已付款。顾客选了去新店，新页面下方的提示改成“你在 X 的订单还未付款，请在 {时间} 前付款……再扫 X 的自取二维码就能去付款”。堂食订单不在这次范围内：扫别的码仍先显示堂食订单（Q10 原规则，因为堂食点单不能从保留的点单接回去）。码指向哪家店，只用地址里码的内容来比较（不当作凭证），真正打开什么仍由服务器决定。

**接回保留的点单时，把它的订单一起读回来。** 入口回答 200 resumed 时，页面像刷新一样再读一次这次点单（订单、结账），有订单就直接显示“你的订单 13”，“再点一些”进入这家店的菜单。读不到时点单照样继续，只是不显示订单，不会报错。

**同一个标签页里换了码就重新加载。** 地址里 `#` 后面换成 `#pickup=`、`#qr=` 或测试桌台入口时，页面重新加载一次，启动时照常读取并清掉这个码。

**“打电话”只在门店卡片上真的有号码时才说。** 门店资料里有电话：照旧“打电话或到柜台”；没有电话或还没读到：说“如有过敏，请在下单前到柜台告诉店员”。门店电话的要求（DEC-STORE-PHONE-BEFORE-PICKUP）不变。

**没有点单，购物车就说没有购物车。**

- 还在看打烊店的菜单时进购物车：说“X 现在不接单”、几点开门，给“返回菜单”和“再看一次”，不去读购物车。
- 刷新以后（页面已经不记得在看哪家店）：购物车读取得到 404 `CUSTOMER_STORE_NOT_FOUND`，按“没有购物车”显示空购物车。
- 入口读某家店的记录失败，不再当成“没人有这次点单”：只要有一家店读不出来、其他店也没有，就回答 503，顾客看到的是“读不出来，请再试”。这保证上面的 404 只表示真的没有点单。

**顾客页面在 CSP 下提供。** 只允许本站自己的脚本和样式（启动页本来就没有内联脚本和样式）。银行卡付款用 Stripe.js，只额外允许 Stripe 的脚本、框架和接口地址。不允许别的网站嵌入，不允许插件、改 base 或把表单提交到别处。同一份策略也用在生产构建的浏览器测试（`vite preview`）里，所以顾客浏览器测试都在这份策略下运行。员工后台的页面不在这次范围内。

**到点没付款，立刻说时间到了。** 付款页上卡片表单开着，而这个标签页里没有人提交过卡片（模拟付款、Stripe 提交、重新付款都会记下），到截止时间时页面马上说“付款时间已过。这笔订单正在取消，你没有被扣款。本页会自动更新。”，然后继续读结果；门店取消以后进入结果页（“没有及时完成，已取消，没有扣款”）。提交过卡片，或者结果不清楚的，仍然先读结果，不猜。刷新以后页面不再记得有没有提交过，结果页照旧按服务器的回答显示。

## 不做

- 第二次扫 DEMO 时不再重复“订单保留”的提示。提示出现在开始 DEMO 点单的那一页，这时顾客最需要知道。
- 员工后台页面的 CSP。
